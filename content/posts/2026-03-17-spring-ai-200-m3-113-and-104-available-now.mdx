### "AI 호출이 느려서 서비스가 멈출 뻔했어요"

얼마 전 우리 팀에서 AI 모델을 백엔드에 통합하는 작업을 하다가, 호출 지연 때문에 서비스가 거의 멈출 뻔한 경험이 있었어요. 알고 보니 Spring AI 라이브러리 버전이 오래된 데다 JVM 튜닝도 안 되어 있었죠. 이걸 계기로 최신 Spring AI 2.0.0-M3 버전과 안정화된 1.1.3, 1.0.4 버전을 도입하면서 어떻게 프로덕션 환경에서 안정적이고 빠르게 AI를 운영할 수 있었는지 공유해볼까 합니다.

## Spring AI 2.0.0-M3, 최신 Spring Boot 3.x와 만났을 때 달라진 점

일단 2.0.0-M3 버전은 Spring Boot 3.x와 완벽 호환됩니다. 이게 왜 중요하냐면, Spring Boot 3.x가 자바 17 이상을 기본으로 하면서 성능과 보안이 크게 개선됐기 때문이죠. 2.0.0-M3는 AI 통합에 필요한 프로덕션급 튜닝 옵션과 보안 강화 기능을 대폭 추가했습니다.

예를 들어, AI 모델 호출 시 내부적으로 비동기 처리를 기본 지원하며, 호출 실패 시 재시도 정책과 타임아웃 설정을 세밀하게 조절할 수 있어요. 보안 측면에선 API 키 암호화 저장, 토큰 갱신 로직, 그리고 Spring Security와의 원활한 통합이 한층 강화됐습니다.

이전 버전과 비교하면, 1.1.3과 1.0.4는 주로 안정화 마이너 업데이트로 AI 모델 호출 성능 최적화와 보안 취약점 패치에 집중했어요. 그래서 2.0.0-M3는 새로운 기능과 확장성 면에서 한 단계 도약한 느낌입니다.[Spring Boot Reference Documentation](https://docs.spring.io/spring-boot/reference/)

## Spring Framework 핵심 기술로 AI 호출 로직을 모듈화하는 법

Spring 백엔드 엔지니어라면 익숙한 의존성 주입(DI)과 AOP(관점 지향 프로그래밍)를 AI 호출에 적용해보는 걸 추천합니다. 왜냐하면 AI 호출은 네트워크 IO, 인증, 로깅, 에러 핸들링 등 공통 관심사가 많아서 코드가 금방 지저분해지거든요.

예를 들어, AI 서비스 호출 인터페이스를 만들고 구현체에 OpenAI API 연동 로직을 넣은 뒤, 호출 전후에 AOP로 인증 토큰 갱신이나 호출 시간 측정을 넣을 수 있습니다. 이렇게 하면 핵심 비즈니스 로직과 AI 호출 로직이 깔끔하게 분리되고, 유지보수가 훨씬 쉬워져요.

```java
@Service
public class OpenAiService implements AiService {

    private final RestTemplate restTemplate;
    private final String apiKey;

    public OpenAiService(RestTemplateBuilder builder, @Value("${openai.api.key}") String apiKey) {
        this.restTemplate = builder.build();
        this.apiKey = apiKey;
    }

    @Override
    public String generateText(String prompt) {
        HttpHeaders headers = new HttpHeaders();
        headers.setBearerAuth(apiKey);
        headers.setContentType(MediaType.APPLICATION_JSON);

        Map<String, Object> body = Map.of(
            "model", "gpt-4",
            "prompt", prompt,
            "max_tokens", 500
        );

        HttpEntity<Map<String, Object>> request = new HttpEntity<>(body, headers);

        ResponseEntity<String> response = restTemplate.postForEntity(
            "https://api.openai.com/v1/completions", request, String.class);

        if (response.getStatusCode() == HttpStatus.OK) {
            // 실제 응답 파싱 로직은 생략
            return response.getBody();
        } else {
            throw new RuntimeException("AI 호출 실패: " + response.getStatusCode());
        }
    }
}
```

이 코드는 Spring DI를 활용해 API 키를 외부 설정에서 주입받고, RestTemplate으로 OpenAI API를 호출하는 기본적인 예입니다. 실제론 비동기 호출과 예외 처리, 재시도 로직을 추가하는 게 좋겠죠.

## JVM 튜닝과 비동기 처리로 AI 호출 지연 줄이기

AI 모델 호출은 네트워크와 외부 API 응답에 크게 의존하므로, JVM 튜닝과 비동기 처리가 없으면 지연 시간이 급격히 늘어납니다. 우리 팀도 처음에 힙 메모리를 기본값(512MB)으로 쓰다가, 2GB 이상으로 늘리고 GC 전략을 G1GC로 변경하면서 응답 지연이 30% 이상 감소했어요.

또한, Spring Boot에서 `@Async` 어노테이션과 ThreadPoolTaskExecutor를 활용해 AI 호출을 비동기로 처리하면, 메인 쓰레드가 블로킹되지 않아 전체 처리량이 크게 향상됩니다.

```java
@Configuration
@EnableAsync
public class AsyncConfig {

    @Bean(name = "aiTaskExecutor")
    public Executor aiTaskExecutor() {
        ThreadPoolTaskExecutor executor = new ThreadPoolTaskExecutor();
        executor.setCorePoolSize(10);
        executor.setMaxPoolSize(50);
        executor.setQueueCapacity(100);
        executor.setThreadNamePrefix("AI-Executor-");
        executor.initialize();
        return executor;
    }
}

@Service
public class AiAsyncService {

    @Async("aiTaskExecutor")
    public CompletableFuture<String> generateTextAsync(String prompt) {
        // AI 호출 로직
        String result = openAiService.generateText(prompt);
        return CompletableFuture.completedFuture(result);
    }
}
```

이렇게 하면 AI 호출이 느려도 메인 서비스는 영향받지 않고, 호출 결과는 나중에 받아 처리할 수 있어요.

## OpenAI API 연동 시 보안, 환경 변수 관리 그리고 인증 전략

외부 AI API 키는 서비스의 생명줄입니다. 노출되면 바로 비용 폭탄이나 데이터 유출 위험이 생기죠. 그래서 Spring Security를 활용해 API 키를 안전하게 관리하는 게 필수입니다.

우리 팀은 API 키를 절대 코드에 직접 쓰지 않고, AWS Parameter Store 같은 안전한 비밀 관리 시스템에 보관합니다. 그리고 Spring `@Value`로 환경 변수에서 읽어오고, 호출 시 토큰을 암호화해서 전송하도록 했어요.

또한, API 호출 권한을 세분화하고, 내부 서비스에서만 호출할 수 있게 IP 화이트리스트를 적용했습니다. 인증 실패 시 401 에러 처리도 꼼꼼히 했고요.

```yaml
# application.yml 예시
openai:
  api:
    key: ${OPENAI_API_KEY}

spring:
  security:
    oauth2:
      client:
        registration:
          openai:
            client-id: ${OPENAI_CLIENT_ID}
            client-secret: ${OPENAI_CLIENT_SECRET}
```

이런 환경 변수 기반 설정 덕분에 배포 환경별로 키를 분리하고, 키 변경도 무중단으로 할 수 있었습니다.

[OpenAI API Documentation](https://platform.openai.com/docs/overview)

## 프롬프트 엔지니어링과 대규모 서비스 롤아웃 전략

AI 호출에서 입력 프롬프트 설계는 응답 품질과 속도를 좌우합니다. Anthropic 가이드에 따르면, 명확하고 간결한 프롬프트가 가장 효과적이라고 해요. 우리도 여러 실험 끝에 불필요한 문장이나 중복 질문을 제거하고, 최대 토큰 수를 500으로 제한해 응답 속도를 20% 이상 개선했습니다.

대규모 서비스에 AI 기능을 도입할 때는 롤아웃 전략이 더 중요합니다. 갑자기 모든 사용자에게 AI 기능을 노출하면 장애 위험이 커서, Canary 배포와 블루-그린 배포 방식을 적극 활용했어요. 예를 들어, 10% 사용자에게만 먼저 적용해 모니터링 후 점진적으로 확대하는 식이죠.
