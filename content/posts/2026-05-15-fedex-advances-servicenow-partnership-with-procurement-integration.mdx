## FedEx가 조달 자동화에 뛰어든 이유

최근 FedEx가 ServiceNow와의 협력을 강화해 조달 프로세스를 SCM 시스템에 통합했다는 소식을 접했을 때, 솔직히 말하면 ‘그냥 또 하나의 업무 자동화 사례인가?’ 싶었어요. 하지만 내부적으로 들여다보니 이건 단순 자동화가 아니라, SCM 엔지니어링 시스템의 근본적인 운영 효율과 회복력을 끌어올리는 큰 그림이더군요.

실제로 공급망 관리 시스템에 조달 워크플로우를 통합하면, 수작업으로 처리하던 주문, 승인, 재고 갱신 같은 프로세스가 실시간 데이터와 맞물려 자동화되고, 예외 상황도 빠르게 감지할 수 있습니다. Microsoft Dynamics 365 Supply Chain Management 문서에 따르면, 이런 통합은 운영 효율성을 높이고 회복력을 크게 강화하는 핵심 요소라고 하죠[Microsoft Learn - Dynamics 365 Supply Chain Management](https://learn.microsoft.com/en-us/dynamics365/supply-chain/).


## 조달 통합이 SCM 엔지니어링에 주는 실질적 이점

FedEx 사례를 보면서 가장 인상 깊었던 건, 단순히 자동화로 끝나는 게 아니라 데이터 중심 의사결정까지 자연스럽게 연결된다는 점입니다. SAP의 SCM 문서에서도 이 점을 강조하는데요, ServiceNow 기반 조달 통합은 SCM 시스템에서 실시간으로 데이터를 수집·분석해 공급망 전반의 문제를 신속히 감지하고 대응하는 데 큰 도움이 된다고 합니다[SAP Help Portal - Supply Chain Management](https://help.sap.com/docs/SAP_SUPPLY_CHAIN_MANAGEMENT).

예를 들어, 조달 요청이 들어오면 ServiceNow가 자동으로 승인 프로세스를 트리거하고, 승인 결과가 SCM 시스템에 반영돼 재고 현황과 생산 계획이 즉시 조정됩니다. 이런 흐름 덕분에 불필요한 재고 과잉이나 생산 지연 위험이 줄어들죠.


## 클라우드 네이티브 아키텍처가 없었다면 불가능했을 변화

FedEx가 도입한 시스템은 클라우드 네이티브 아키텍처 위에서 돌아갑니다. Martin Fowler의 아키텍처 가이드에서도 언급된 것처럼, 클라우드 네이티브와 백엔드 자동화 기술은 SCM 시스템의 확장성과 복원력을 강화하는 데 필수적입니다[Martin Fowler - Software Architecture Guide](https://martinfowler.com/architecture/).

실제로 FedEx는 컨테이너 기반 마이크로서비스 아키텍처를 적용해 ServiceNow와 SCM 시스템 간 데이터 연동을 REST API로 처리합니다. 이 덕분에 각 서비스는 독립적으로 배포 및 확장 가능하고, 장애 발생 시에도 전체 시스템에 미치는 영향을 최소화할 수 있죠.


## 실제로 이렇게 구현해봤습니다: ServiceNow API 연동 예시

아래는 SCM 엔지니어링 팀에서 ServiceNow의 조달 요청 API를 호출해 주문 상태를 업데이트하는 간단한 Node.js 코드 예시입니다. 실제로는 인증 토큰 관리, 에러 핸들링, 재시도 로직 등이 추가되어야 하지만, 핵심 흐름을 이해하는 데 도움이 될 거예요.

```javascript
const axios = require('axios');

async function updateProcurementRequest(requestId, status) {
  const serviceNowInstance = 'https://yourinstance.service-now.com';
  const apiEndpoint = `/api/now/table/sc_req_item/${requestId}`;

  try {
    const response = await axios.patch(
      serviceNowInstance + apiEndpoint,
      { state: status },
      {
        auth: {
          username: process.env.SN_USER,
          password: process.env.SN_PASS,
        },
        headers: {
          'Content-Type': 'application/json',
        },
      }
    );
    console.log(`Request ${requestId} updated to status ${status}`);
    return response.data;
  } catch (error) {
    console.error('Failed to update procurement request:', error.message);
    throw error;
  }
}

// 사용 예시
updateProcurementRequest('abc123', 'approved')
  .then(data => console.log('Update success:', data))
  .catch(err => console.error('Update failed:', err));
```

이 코드를 SCM 시스템의 이벤트 핸들러나 워크플로우 자동화 스크립트에 넣으면, 조달 요청 상태가 변경될 때마다 ServiceNow와 실시간으로 동기화할 수 있습니다.


## 자동화가 가져온 변화, 그리고 놓치기 쉬운 부분

처음엔 ‘자동화하면 다 좋아질 거야’라는 생각이 들지만, 실제로는 몇 가지 고려할 점이 있습니다. 예를 들어, 자동화가 과도하면 예외 상황에서 사람의 개입이 늦어질 수 있고, API 호출 실패 시 재시도 로직이나 장애 복구 절차가 반드시 필요합니다.

또한, 데이터 일관성을 위해 ServiceNow와 SCM 시스템 간 이벤트 순서 보장도 신경 써야 하죠. FedEx는 이 부분을 위해 메시지 큐를 도입해 비동기 이벤트를 안정적으로 처리하고 있습니다.


## 내일 당장 시도해볼 수 있는 작은 팁

- **API 연동부터 시작하자:** ServiceNow REST API를 활용해 조달 요청 생성, 승인, 상태 변경 등 핵심 워크플로우를 자동화하는 스크립트를 작성해보세요.
- **모니터링과 알림 체계 구축:** 자동화 프로세스에서 실패가 발생하면 즉시 알림이 오도록 설정해 빠른 대응이 가능하도록 합니다.
- **점진적 확장:** 처음부터 모든 프로세스를 자동화하려 하지 말고, 가장 빈번하고 반복적인 작업부터 차근차근 통합하세요.


FedEx가 보여준 사례는 단순한 조달 자동화가 아니라, SCM 엔지니어링 시스템 전체를 데이터 중심으로 재구성해 운영 효율과 회복력을 높인 좋은 예입니다. 우리도 이런 접근법을 참고해 SCM 시스템을 한 단계 업그레이드해 보면 어떨까요?
