### 갑작스러운 장애에도 멈추지 않는 AI, 어떻게 만들까?

"우리 AI 에이전트가 갑자기 멈춰버리면 어떻게 하지?"

처음에 이런 걱정이 들었어요. AI가 사용자 요청을 처리하다가 내부 오류나 네트워크 문제로 멈추면, 서비스 신뢰도는 뚝 떨어지고 고객 불만도 커지죠. 저도 비슷한 문제를 겪으면서, 단순히 AI 모델 성능 개선에만 집중하는 게 아니라, 시스템 전체가 견고하게 돌아가도록 만드는 게 훨씬 더 중요하다는 걸 깨달았습니다.

오늘은 OpenAI API, Anthropic, 그리고 Vercel AI SDK 같은 최신 도구들을 활용해 에이전트 AI를 어떻게 안정적이고 내결함성 있게 구축할 수 있는지, 제가 직접 겪은 시행착오와 함께 이야기해볼게요.

## OpenAI API가 말하는 확장성과 오류 처리의 핵심

OpenAI API 문서에는 "확장 가능한 아키텍처와 견고한 오류 처리 메커니즘"이 프로덕션 환경에서 신뢰성을 보장하는 열쇠라고 나와 있어요[OpenAI API Documentation](https://platform.openai.com/docs/overview). 

실제로 저희 팀도 API 호출 시 응답 지연이나 실패가 발생할 수 있음을 항상 염두에 두고, 다음과 같은 전략을 썼습니다:

- **재시도 로직**: 500번대 서버 오류나 네트워크 타임아웃 발생 시 최대 3회까지 지수 백오프(exponential backoff) 방식으로 재시도
- **타임아웃 설정**: API 호출 타임아웃을 3초로 제한해, 무한 대기 방지
- **회로 차단기 패턴(Circuit Breaker)**: 연속 실패가 5회 이상 발생하면 일정 시간 동안 호출 중단 후 상태 점검

이런 조합 덕분에, 예상치 못한 장애에도 시스템 전체가 멈추지 않고 빠르게 복구할 수 있었죠. 특히 회로 차단기는 장애 확산을 막는 데 큰 도움이 되었습니다.

```python
import time
import requests

class OpenAIClient:
    def __init__(self):
        self.fail_count = 0
        self.circuit_open = False
        self.circuit_reset_time = 0

    def call_api(self, payload):
        if self.circuit_open and time.time() < self.circuit_reset_time:
            raise Exception("Circuit is open. Skipping API call.")

        retries = 3
        backoff = 1
        for i in range(retries):
            try:
                response = requests.post("https://api.openai.com/v1/chat/completions", json=payload, timeout=3)
                response.raise_for_status()
                self.fail_count = 0
                return response.json()
            except requests.RequestException:
                self.fail_count += 1
                time.sleep(backoff)
                backoff *= 2

        if self.fail_count >= 5:
            self.circuit_open = True
            self.circuit_reset_time = time.time() + 60  # 1분간 차단
            print("Circuit breaker triggered. Pausing API calls for 60 seconds.")
        raise Exception("API call failed after retries.")
```

이 코드는 간단하지만, 실제 서비스에서 흔히 겪는 장애 상황을 효과적으로 완화해줍니다.

## 프롬프트 설계가 내결함성에 미치는 의외의 영향

Anthropic의 프롬프트 엔지니어링 가이드를 보면, 단순히 AI가 잘 대답하도록 하는 것뿐 아니라, "예상치 못한 상황에서도 안정적으로 동작"하도록 만드는 게 핵심이라고 강조합니다[Anthropic - Prompt Engineering Guide](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/overview).

예를 들어, 사용자 입력이 애매하거나 모호할 때 AI가 엉뚱한 답변을 하거나 무한 루프에 빠지는 걸 막으려면, 프롬프트 내에 "오류 처리 로직"을 명시적으로 넣는 게 효과적이더라고요.

```text
"만약 사용자의 질문이 불명확하면, '죄송하지만 질문을 다시 명확히 해주세요'라고 답변하세요."
```

이런 문구를 넣으면, AI가 무리하게 추측하거나 잘못된 정보를 생성하는 걸 줄일 수 있습니다. 실제로 저희 프로젝트에서 이런 프롬프트를 적용한 후, 사용자 불만이 30% 이상 감소했어요.

또한, 프롬프트를 모듈화해서 재사용 가능하게 만들고, 각 모듈별로 테스트 케이스를 작성하는 습관도 내결함성에 큰 도움이 됩니다. Anthropic Claude Code Overview에서는 이런 모듈화된 컴포넌트 설계가 유지보수성과 확장성을 높인다고 설명합니다[Anthropic - Claude Code Overview](https://docs.anthropic.com/en/docs/claude-code/overview).

## 프론트엔드와 백엔드가 함께 만들어야 할 내결함성

Cursor 문서에서는 AI 에이전트와 사용자 인터랙션 시 "비동기 처리와 상태 관리"가 얼마나 중요한지 알려줍니다[Cursor Documentation](https://docs.cursor.com/). 

저희도 AI 응답이 느려질 때 사용자가 멈칫하지 않고 기다릴 수 있게, 로딩 상태 표시와 재시도 버튼을 넣었어요. 그리고 상태를 로컬 스토리지에 저장해서 새로고침해도 대화 기록이 유지되도록 했죠.

백엔드에서도 GitHub Copilot 문서가 강조하는 것처럼, 입력 검증과 에러 핸들링은 필수입니다[GitHub Copilot Documentation](https://docs.github.com/en/copilot). AI에게 넘기는 데이터가 깨끗하지 않으면, AI가 엉뚱한 답변을 하거나 심지어 서버 오류가 날 수 있어요.

```python
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel, constr

app = FastAPI()

class UserRequest(BaseModel):
    prompt: constr(min_length=1, max_length=500)

@app.post("/ai-agent")
async def ai_agent(request: UserRequest):
    if "금지어" in request.prompt:
        raise HTTPException(status_code=400, detail="금지어가 포함되어 있습니다.")
    # AI 호출 로직
    return {"response": "AI 응답 예시"}
```

이런 검증 코드는 작아 보이지만, 프로덕션 안정성에 엄청난 영향을 줍니다.

## 클라우드 네이티브 환경에서 자동 스케일링과 서버리스 활용하기

Vercel AI SDK 문서에서는 서버리스 아키텍처와 자동 스케일링을 적극 활용해 고가용성과 내결함성을 구현하는 방법을 소개합니다[ Vercel AI SDK Documentation](https://sdk.vercel.ai/docs/introduction).

저희도 AI 에이전트를 Vercel 서버리스 함수로 배포하면서, 갑작스러운 트래픽 급증에도 문제없이 대응할 수 있었어요. 서버리스 환경 덕분에 인스턴스 관리 부담이 줄었고, 장애 시 자동 재시작으로 복구 속도도 빨랐죠.

다만, 서버리스 함수는 실행 시간이 제한적이고(예: 10초), 상태를 유지하기 어렵다는 단점이 있습니다. 그래서 상태 관리가 필요한 부분은 별도의 데이터베이스나 캐시(Redis 등)에 위임하는 방식을 썼습니다.

```javascript
import { VercelRequest, VercelResponse } from '@vercel/node';
import OpenAI from 'openai';

const openai = new OpenAI();

export default async function handler(req: VercelRequest, res: VercelResponse) {
  try {
    const { prompt } = req.body;
    if (!prompt || prompt.length > 500) {
      return res.status(400).json({ error: 'Invalid prompt' });
    }

    const completion = await openai.chat.completions.create({
      model: 'gpt-4o-mini',
      messages: [{ role: 'user', content: prompt }],
    });

    res.status(200).json({ response: completion.choices[0].message.content });
  } catch (error) {
    res.status(500).json({ error: 'Internal server error' });
  }
}
```

이런 구조가 서버리스 환경에서 가장 무난하면서도 안정적인 패턴입니다.

## 직접 겪어보니 알게 된 내결함성의 진짜 의미

처음에 내결함성이라고 하면 장애가 나도 "그냥 버티면 되는 거 아니야?"라고 생각했는데, 실제로는 그게 아니더라고요. 장애가 났을 때 빠르게 감지하고, 피해를 최소화하며, 자동으로 복구하는 체계가 있어야 진짜 "신뢰할 수 있는" 에이전트 AI가 됩니다.

그리고 그 기반에는 튼튼한 아키텍처 설계, 꼼꼼한 프롬프트 엔지니어링, 철저한 입력 검증, 사용자 경험을 고려한 프론트엔드와 백엔드 협업, 그리고 클라우드 네이티브 환경 활용이 모두 어우러져야 해요.

이 글에서 소개한 여러 문서와 제가 직접 겪은 경험이 여러분의 AI 시스템 신뢰성 향상에 조금이나마 도움이 되길 바랍니다.
