### "아니, 이게 진짜로 30%나 빨라졌다고?"

최근에 팀에서 Spring Boot 4.1로 마이그레이션하면서 가장 먼저 느낀 건 애플리케이션 시작 시간이 확실히 줄었다는 점이었어요. 이전 버전 대비 20~30% 정도는 체감할 수 있었습니다. 메모리 관리도 훨씬 똑똑해져서, GC 튜닝에 쏟던 시간도 줄었죠. 이건 직접 써봐야 알 수 있는 변화였습니다.

---

## Spring Boot 4, 메모리와 스타트업 타임에 집중한 이유

Spring Boot 4와 4.1은 기본적으로 "생산 환경에서 바로 써도 될 만큼" 튜닝이 잘 되어 나왔어요. 예전에는 스타트업 시간이 길고 메모리 사용이 비효율적인 부분 때문에, 프로덕션 배포 전에 JVM 옵션을 일일이 손봐야 했죠. 하지만 이번 버전부터는 기본 설정만으로도 상당히 최적화돼 있습니다.

예를 들어, `spring.main.lazy-initialization=true` 설정이 기본값으로 바뀌면서 컴포넌트 초기화가 지연되어 시작 속도가 빨라졌고, 메모리 사용도 초기화 단계에서 불필요한 객체 생성을 줄여줍니다. 

```yaml
# application.yaml 예시
spring:
  main:
    lazy-initialization: true
```

이 설정 덕분에 대규모 마이크로서비스 환경에서 빠른 롤아웃이 가능해졌고, JVM 튜닝에 대한 부담이 줄었어요. 물론 모든 상황에 무조건 좋은 건 아니니, 메모리 프로파일링은 꼭 해봐야 합니다.

---

## 보안, 이제는 OAuth 2.0과 OpenID Connect가 기본이다

Spring Boot 4.1에서 보안 쪽도 크게 바뀌었는데요, 특히 OAuth 2.0과 OpenID Connect 통합이 훨씬 간편해졌습니다. 예전에는 직접 설정 파일과 코드로 복잡하게 인증 서버와 연동해야 했는데, 이번 버전부터는 기본 의존성만 추가하면 바로 쓸 수 있는 수준이에요.

예를 들어, `spring-boot-starter-oauth2-client`를 추가하고, application.yaml에 다음처럼 간단히 설정하면 됩니다.

```yaml
spring:
  security:
    oauth2:
      client:
        registration:
          google:
            client-id: your-client-id
            client-secret: your-client-secret
            scope: openid,profile,email
```

이걸로 구글 OAuth 로그인을 바로 적용할 수 있어서, 인증 관련 코드 부담이 크게 줄었죠. 보안 설정이 강화되면서 기본적으로 CSRF 보호도 강화됐고, 최신 프로토콜을 기본 지원하니 보안 사고 걱정도 덜어줬습니다.

---

## 운영 중인 서비스, 점진적 배포와 Canary 전략은 어떻게?

우리 팀이 Spring Boot 4로 바꾸면서 도입한 또 하나의 큰 변화는 롤아웃 전략입니다. Baeldung에서 소개하는 [Spring Boot Performance Tuning](https://www.baeldung.com/spring-boot-performance) 글을 참고해, 점진적 배포와 Canary 배포를 적극 활용했는데요.

Spring Boot 4는 자체적으로 배포 시점에 특정 프로필이나 기능 토글을 쉽게 바꿀 수 있게 해줘서, 새로운 버전을 소수 사용자에게 먼저 노출하고 문제 없으면 점차 확대하는 게 훨씬 수월해졌습니다.

예를 들어, `application-canary.yaml` 프로필을 만들어서 새로운 기능을 켜고, 인프라에서 Canary 트래픽만 이 프로필로 돌리도록 설정할 수 있죠. 이렇게 하면 롤백도 빠르고, 문제 발생 시 전체 서비스 영향을 최소화할 수 있어요.

```yaml
# application-canary.yaml
feature:
  newFeatureEnabled: true
```

코드에서 조건부로 기능을 분기할 때는 Spring의 `@ConditionalOnProperty`를 활용하면 깔끔합니다.

```java
@Configuration
@ConditionalOnProperty(name = "feature.newFeatureEnabled", havingValue = "true")
public class NewFeatureConfig {
    // 새로운 기능 빈 등록
}
```

## Spring Framework 코어 기술과의 시너지, 유지보수성도 챙겼다

Spring Boot 4는 Spring Framework 코어와도 더 긴밀하게 통합됐습니다. 모듈화가 잘 되어 있고, 의존성 주입이 최적화되면서 대규모 백엔드 시스템에서도 유지보수성과 확장성이 눈에 띄게 좋아졌어요.

의존성 주입이 더 가벼워지고, 불필요한 빈 생성이 줄어들면서 런타임 성능도 개선됐죠. 이건 직접 대규모 프로젝트에 적용해보니 확실히 느껴졌습니다. 기존에 복잡하게 얽혀있던 컴포넌트 간 의존성이 깔끔하게 정리되는 느낌이랄까요.

---

### 실제로 써본 코드 예시: OAuth 2.0 간단 설정과 기능 토글

```java
@SpringBootApplication
public class DemoApplication {

    public static void main(String[] args) {
        SpringApplication.run(DemoApplication.class, args);
    }

    @Bean
    @ConditionalOnProperty(name = "feature.newFeatureEnabled", havingValue = "true")
    public CommandLineRunner newFeatureRunner() {
        return args -> System.out.println("New feature is enabled!");
    }
}
```

이런 식으로 프로필별로 기능을 켜고 끄는 게 간단해졌다는 게 진짜 체감 포인트입니다. 운영 환경에서 빠른 테스트와 롤백이 가능해지니, 서비스 안정성도 덩달아 높아졌어요.

---

## 마무리하면서

처음엔 Spring Boot 4와 4.1이 그저 "버전 업" 정도로 생각했는데, 직접 써보니 생산 환경에서 바로 써도 될 만큼 실무 친화적인 개선이 많았습니다. 특히 스타트업 속도와 메모리 최적화, 최신 보안 프로토콜 기본 지원, 그리고 점진적 배포 전략까지 한꺼번에 챙긴 건 꽤 인상적이었어요.

하지만 모든 게 완벽한 건 아니니, 여전히 환경에 맞는 세밀한 튜닝과 모니터링은 필수입니다. 그래도 개발자 입장에서는 기본 세팅만으로도 꽤 많은 고민을 덜 수 있다는 점에서 확실히 매력적인 버전임은 분명합니다.

앞으로도 Spring Boot가 어떻게 진화할지 기대가 큽니다. 혹시 아직 4.x 버전으로 마이그레이션 못 하셨다면, 꼭 한번 실제 프로젝트에 적용해보시길 추천합니다.
