### 갑자기 모델이 이상한 예측을 내놓는다면? 그게 바로 포이즈닝일 수 있습니다

얼마 전 우리 팀에서 운영 중인 추천 시스템이 갑자기 이상한 행동을 하기 시작했어요. 평소라면 잘 걸러내던 스팸성 콘텐츠를 추천 목록 상위에 올려버리더군요. 처음엔 단순 버그라 생각했는데, 조사해보니 훈련 데이터에 악의적인 데이터가 섞여 모델이 일부러 오작동하도록 유도된, 일명 ‘모델 포이즈닝’ 공격이었습니다.

이 경험에서 배운 점을 공유하려고 해요. ML 모델 포이즈닝이 뭔지, 어떻게 백엔드에서 탐지할 수 있는지, 그리고 대응책은 무엇인지 실제 사례와 코드까지 곁들여 이야기해볼게요.

## ML 모델 포이즈닝, 왜 백엔드 엔지니어가 신경 써야 할까?

모델 포이즈닝은 말 그대로 훈련 데이터에 악성 데이터를 주입해서 모델 성능을 떨어뜨리거나 특정 입력에 대해 의도된 오작동을 유발하는 공격입니다. 예를 들어, 자율주행차의 객체 인식 모델에 특정 패턴을 가진 이미지가 포함되면, 정상적인 신호를 인식하지 못하게 만들 수도 있죠.

이 공격이 무서운 이유는, 단순히 모델이 틀리게 예측하는 걸 넘어서 보안 사고로 이어질 수 있다는 점입니다. 그리고 훈련 데이터가 보통 외부 소스나 사용자 입력을 통해 수집되기 때문에, 백엔드 파이프라인에서 이를 검증하지 않으면 공격자가 쉽게 침투할 수 있어요.

GitHub 엔지니어링 블로그에서도 강조하듯, 데이터 무결성 검증과 이상치 탐지 기법을 백엔드 시스템에 통합하는 게 핵심입니다[GitHub Engineering Blog](https://github.blog/category/engineering/).


## 데이터 수집부터 배포까지, ML 파이프라인 전반에 모니터링을 걸어라

백엔드 엔지니어가 할 수 있는 가장 현실적인 방어는 ML 파이프라인의 모든 단계에 모니터링과 로깅을 철저히 하는 겁니다. 데이터 수집 시점부터 모델 학습, 배포 후 예측까지 이상 징후를 감지할 수 있어야 하죠.

Martin Fowler의 아키텍처 가이드에 따르면, 비정상적인 데이터 패턴이나 예측 결과 변화를 빠르게 감지하면 초기 대응이 가능하다고 합니다[Martin Fowler - Software Architecture Guide](https://martinfowler.com/architecture/).

예를 들어, 데이터 수집 파이프라인에서 갑자기 특정 필드에 이상치가 급증하거나, 모델 예측 결과 분포가 평소와 다르게 치우치는 경우 경고를 띄우는 식입니다. 이런 모니터링은 로그 기반으로 하거나, 실시간 스트림 처리 시스템에서 이상 탐지 알고리즘을 돌릴 수도 있어요.


## 클라우드 환경에서 권한 관리와 자동 보안 스캔이 필수인 이유

우리 팀도 클라우드 기반 ML 플랫폼을 쓰는데, 이 환경에서는 데이터와 모델에 대한 접근 권한을 엄격히 관리하는 게 아주 중요합니다. 공격자는 권한이 느슨한 곳을 노리거든요.

Cloudflare 블로그 사례를 보면, 자동화된 보안 스캐닝 도구를 통해 공급망 공격과 모델 포이즈닝 위협을 줄이는 전략을 쓰고 있습니다[Cloudflare Blog - How We Built It](https://blog.cloudflare.com/tag/how-we-built-it/).

예를 들어, 저장소에 데이터셋 업로드 시 자동화된 무결성 검사와 해시 검증을 거치고, 모델 배포 전에는 검증된 서명된 아티팩트만 허용하는 식입니다. 권한은 최소 권한 원칙(Least Privilege)을 적용해, 필요한 서비스나 사용자만 데이터와 모델에 접근할 수 있게 제한하는 게 기본입니다.


## 실시간 이상 탐지와 앙상블 모델로 포이즈닝 신호를 잡아내는 방법

포이즈닝 탐지 기술 중 하나는 모델 입력 분포의 변화를 감지하는 거예요. 예를 들어, 평소에 입력 데이터가 특정 범위 내에 분포했는데 갑자기 이상치가 늘어나면 경고를 줍니다.

또 다른 방법은 여러 모델을 앙상블로 운영하면서, 각 모델의 예측 결과를 비교해 이상 행동을 찾아내는 겁니다. 한 모델만 공격받았을 때 이를 감지하기 좋죠.

InfoQ 아키텍처 가이드에서는 이런 다중 모델 앙상블과 주기적인 재학습 및 검증이 효과적인 탐지 수단이라고 소개합니다[InfoQ - Software Architecture & Design](https://www.infoq.com/architecture-design/).


### 간단한 이상치 탐지 코드 예시 (Python)

```python
import numpy as np
from sklearn.ensemble import IsolationForest

# 평소 입력 데이터 샘플 (예: 특성 3개짜리 데이터 1000개)
normal_data = np.random.normal(0, 1, size=(1000, 3))

# 새로 들어온 입력 데이터
new_data = np.array([[0.1, -0.2, 0.05], [10, 10, 10]])  # 두 번째는 명백한 이상치

# Isolation Forest 모델로 이상치 탐지
clf = IsolationForest(contamination=0.01)
clf.fit(normal_data)

preds = clf.predict(new_data)  # 1은 정상, -1은 이상치

for i, pred in enumerate(preds):
    if pred == -1:
        print(f"입력 데이터 {i}번은 이상치로 탐지되었습니다: {new_data[i]}")
```

이 코드는 백엔드에서 실시간으로 들어오는 입력 데이터 중 이상치를 탐지하는 간단한 예입니다. 실제 서비스에선 더 복잡한 전처리와 모니터링 시스템과 결합해야겠죠.


## 현실적인 트레이드오프: 탐지 민감도와 오탐률 사이에서

포이즈닝 탐지는 완벽할 수 없습니다. 너무 민감하게 설정하면 정상 데이터도 오탐지해서 알람이 잦아지고, 너무 느슨하게 하면 공격을 놓치기 쉽죠.

그래서 주기적인 재학습과 검증, 그리고 여러 탐지 기법을 조합하는 게 중요합니다. 또한, 탐지 후에는 수동 검토 프로세스도 병행해야 해요. 자동화가 다 해결해주진 않거든요.


## 마치며: 백엔드에서 ML 보안은 선택이 아닌 필수

ML 모델이 우리 서비스 핵심에 자리 잡으면서, 모델 포이즈닝 같은 공격도 현실적인 위협이 됐습니다. 백엔드 엔지니어가 데이터 무결성부터 모델 예측 모니터링, 권한 관리까지 전 과정에 신경 써야 하는 이유죠.

우리 팀 경험상, 다음 세 가지를 꼭 챙기면 도움이 됩니다:

- **데이터 수집 단계에서 이상치 및 무결성 검사 자동화**
- **모델 예측 결과 실시간 모니터링과 이상 탐지 경보 체계 구축**
- **클라우드 환경에서 엄격한 권한 관리 및 보안 스캔 도구 활용**

이 글이 여러분 팀의 ML 보안 체계 강화에 조금이나마 도움이 되길 바랍니다.
