## "Spring AI 2.0으로 OpenAI랑 Anthropic API, 진짜 현업에서 써먹으려면?"

최근에 우리 팀에서 OpenAI랑 Anthropic API를 Spring 기반 백엔드에 붙이는 작업을 하면서 꽤 고생했던 기억이 있어요. 단순히 API 호출만 하면 되는 줄 알았는데, 성능 튜닝부터 보안까지 챙길 게 한두 가지가 아니더라고요. 특히 Spring AI 2.0이 나오면서 자동 구성과 빈 관리가 훨씬 편해졌지만, 그걸 어떻게 실무에 맞게 조율하느냐가 관건이었죠.

이번 글에서는 제가 직접 겪은 시행착오와 함께 Spring AI 2.0을 활용한 OpenAI, Anthropic API 통합을 어떻게 하면 생산 환경에서 안정적이고 효율적으로 구현할 수 있는지 현실적인 팁을 공유해보려 합니다.

## Spring AI 2.0, 자동 구성과 빈 관리가 이렇게 편할 줄이야

Spring AI 2.0은 Spring Boot의 자동 구성(auto-configuration) 덕분에 초기 세팅이 정말 간편해졌어요. 예전 같으면 OpenAI나 Anthropic API 클라이언트를 직접 Bean으로 등록하고, 설정값을 일일이 주입해야 했는데, 이제는 의존성만 추가하면 기본적인 빈이 자동으로 만들어집니다. 

예를 들어, `spring-boot-starter-ai` 의존성을 넣으면 OpenAI와 Anthropic API 클라이언트가 자동으로 등록되고, `application.yml`에 API 키만 넣으면 바로 쓸 준비가 끝나죠. 물론 필요하면 `@Bean`을 직접 정의해서 커스터마이징도 가능합니다.

```yaml
spring:
  ai:
    openai:
      api-key: ${OPENAI_API_KEY}
    anthropic:
      api-key: ${ANTHROPIC_API_KEY}
```

이런 식으로 환경변수로 관리하는 게 기본인데, 실제 운영 환경에서는 Spring Security의 `@ConfigurationProperties`와 함께 암호화된 비밀 관리 솔루션을 연동하는 게 필수입니다. 

자동 구성 덕분에 개발 초기 진입 장벽이 확실히 낮아졌고, 빈 관리 패턴 덕분에 API 클라이언트 재사용과 테스트도 훨씬 수월해졌어요. 이 부분은 [Spring Boot Reference Documentation](https://docs.spring.io/spring-boot/reference/)에서 자세히 다루고 있으니 참고하세요.

## OpenAI API, WebClient로 비동기 호출할 때 알아두면 좋은 점

OpenAI API는 RESTful 인터페이스를 제공하는데, Spring에서는 `WebClient`를 써서 비동기 호출하는 게 요즘 대세입니다. `RestTemplate`도 지원하지만, 비동기 흐름과 리액티브 프로그래밍에 더 잘 맞는 `WebClient`가 장기적으로 유지보수에 유리해요.

```java
@Service
public class OpenAIService {

    private final WebClient webClient;

    public OpenAIService(WebClient.Builder webClientBuilder, @Value("${spring.ai.openai.api-key}") String apiKey) {
        this.webClient = webClientBuilder
            .baseUrl("https://api.openai.com/v1")
            .defaultHeader(HttpHeaders.AUTHORIZATION, "Bearer " + apiKey)
            .build();
    }

    public Mono<String> generateCompletion(String prompt) {
        return webClient.post()
            .uri("/completions")
            .bodyValue(Map.of(
                "model", "gpt-4",
                "prompt", prompt,
                "max_tokens", 150
            ))
            .retrieve()
            .bodyToMono(JsonNode.class)
            .map(json -> json.get("choices").get(0).get("text").asText());
    }
}
```

이렇게 하면 API 키를 헤더에 넣고, `gpt-4` 모델로 프롬프트를 보내서 결과를 비동기적으로 받을 수 있죠. 중요한 건 네트워크 지연이나 API 호출 실패에 대비해 재시도 로직과 백오프(backoff) 정책을 꼭 넣어야 한다는 점입니다. 

예를 들어, `resilience4j` 라이브러리를 활용해 3회 재시도에 500ms 간격 백오프로 설정하면, 일시적인 네트워크 문제에도 서비스가 끊기지 않고 견딜 수 있어요. 이런 성능 튜닝 팁은 [Baeldung - Spring Boot Performance Tuning](https://www.baeldung.com/spring-boot-performance)에서 더 자세히 확인할 수 있습니다.

## Anthropic Claude API, 프롬프트 설계에서부터 재사용 가능한 구조 만들기

Anthropic Claude 모델 API는 OpenAI와 비슷하지만, 프롬프트 엔지니어링 가이드가 꽤 구체적이에요. 명확하고 의도에 맞는 프롬프트를 설계하는 게 모델 성능에 큰 영향을 미치기 때문에, Spring 백엔드에서 프롬프트 템플릿을 재사용 가능한 구조로 만드는 게 중요합니다.

예를 들어, 다음처럼 파라미터화된 프롬프트 템플릿 클래스를 만들어서 상황별로 텍스트를 주입할 수 있죠.

```java
@Component
public class ClaudePromptTemplate {

    private static final String BASE_PROMPT = "You are a helpful assistant. Answer concisely: %s";

    public String createPrompt(String userQuery) {
        return String.format(BASE_PROMPT, userQuery);
    }
}

@Service
public class AnthropicService {

    private final WebClient webClient;
    private final ClaudePromptTemplate promptTemplate;

    public AnthropicService(WebClient.Builder webClientBuilder, ClaudePromptTemplate promptTemplate,
                           @Value("${spring.ai.anthropic.api-key}") String apiKey) {
        this.webClient = webClientBuilder
            .baseUrl("https://api.anthropic.com/v1")
            .defaultHeader(HttpHeaders.AUTHORIZATION, "Bearer " + apiKey)
            .build();
        this.promptTemplate = promptTemplate;
    }

    public Mono<String> askClaude(String question) {
        String prompt = promptTemplate.createPrompt(question);
        return webClient.post()
            .uri("/complete")
            .bodyValue(Map.of(
                "model", "claude-v1",
                "prompt", prompt,
                "max_tokens_to_sample", 100
            ))
            .retrieve()
            .bodyToMono(JsonNode.class)
            .map(json -> json.get("completion").asText());
    }
}
```

이렇게 하면 프롬프트 문구를 한 곳에서 관리할 수 있어서, 나중에 모델 변경이나 문구 수정이 필요할 때 훨씬 편하더라고요. Anthropic 가이드도 [Anthropic - Prompt Engineering Guide](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/overview)에서 꼼꼼히 읽어보는 걸 추천합니다.

## API 키 관리와 통신 보안, Spring Security로 한 방에 해결하기

AI API를 쓸 때 가장 신경 쓰이는 게 바로 API 키 보안이죠. 키가 노출되면 비용 폭탄은 물론이고, 데이터 유출 위험까지 생기니까요. Spring Framework의 보안 모듈을 활용하면 API 키를 안전하게 관리하고, OAuth2 또는 토큰 기반 인증으로 외부 통신 권한을 엄격히 검증할 수 있습니다.

예를 들어, `@ConfigurationProperties`로 키를 암호화된 상태로 주입하고, 커스텀 `WebClient` 필터에 인증 헤더를 자동 추가하는 패턴이 있어요.

```java
@ConfigurationProperties(prefix = "spring.ai")
public class AiProperties {
    private String openaiApiKey;
    private String anthropicApiKey;
    // getter, setter
}

@Bean
public WebClient openAiWebClient(AiProperties aiProperties) {
    return WebClient.builder()
        .baseUrl("https://api.openai.com/v1")
        .defaultHeader(HttpHeaders.AUTHORIZATION, "Bearer " + aiProperties.getOpenaiApiKey())
        .filter(authorizationFilter())
        .build();
}

private ExchangeFilterFunction authorizationFilter() {
    return (request, next) -> {
        // 필요시 토큰 갱신 로직 등 추가 가능
        return next.exchange(request);
    };
}
```

또한, 네트워크 통신 시 TLS 암호화는 기본이고, API 키 저장소는 HashiCorp Vault 같은 별도 비밀관리 시스템과 연동하는 게 좋습니다. Spring Security와 연동하면 키 순환 주기 관리도 자동화할 수 있어요. 자세한 내용은 [Spring Framework - Core Technologies](https://docs.spring.io/spring-framework/reference/core.html)를 참고하세요.

## 실제 운영 환경에서 겪은 성능 이슈와 대응 사례

우리 팀은 초기 테스트 때 API 호출이 많아지면서 응답 지연과 타임아웃이 잦았어요. 원인은 커넥션 풀 크기가 너무 작고, 재시도 로직이 없어서 네트워크 장애에 취약했던 거죠.

그래서 다음과 같은 조치를 했습니다.

- WebClient 커넥션 풀을 50개로 늘림 (기본 10개 → 50개)
- `resilience4j`로 재시도 3회, 500~2000ms 백오프 적용
- 요청 결과 캐싱 (Redis)으로 동일 프롬프트 반복 호출 최소화
- 비동기 호출로 스레드 블로킹 방지

이렇게 하니 API 호출 실패율이 0.1% 미만으로 떨어지고, 평균 응답 시간도 900ms에서 350ms로 줄었어요. 물론 캐싱은 프롬프트 결과가 자주 바뀌지 않는 경우에만 효과적이니, 실시간성이 중요한 서비스라면 적절히 조율해야 합니다.

## 마치며: "Spring AI 2.0과 AI API, 그냥 붙이는 것과 제대로 쓰는 건 완전 달라"

처음에 AI API를 백엔드에 붙이는 건 생각보다 간단해 보여도, 실제 프로덕션 환경에서는 성능, 보안, 유지보수성 모두 고려해야 할 게 많아요. Spring AI 2.0은 이런 고민을 많이 덜어주지만, 자동화에만 의존하면 오히려 장애 원인 추적이 어려워질 수 있으니 빈 설정과 호출 흐름을 꼼꼼히 이해하는 게 중요합니다.

- 자동 구성과 빈 관리로 초기 세팅은 빠르게 끝내되, 필요에 따라 직접 빈 커스터마이징하기
- WebClient로 비동기 호출하고, 재시도 및 백오프 정책 꼭 적용하기
- Anthropic 프롬프트는 템플릿화해서 재사용성과 유지보수성 높이기
- API 키는 Spring Security와 비밀관리 솔루션으로 안전하게 관리
- 운영 환경에서 커넥션 풀, 캐싱, 비동기 처리로 성능 최적화하기

이런 팁들을 현업에서 직접 적용해보니, AI 서비스 백엔드 개발이 훨씬 안정적이고 예측 가능해졌어요. 여러분도 Spring AI 2.0과 OpenAI, Anthropic API를 붙일 때 이 글이 도움이 되길 바랍니다.

추가로, 배포 전에는 성능과 안정성뿐 아니라 로그 품질까지 확인해야 합니다. 에러 로그가 충분히 구조화되어 있지 않으면 원인 분석 시간이 길어지고, 같은 장애가 반복될 가능성이 높아집니다. 배포 후 24시간 관찰 구간에서 경보 임계치를 임시로 강화해 두는 것도 실무에서 자주 쓰는 방법입니다.
