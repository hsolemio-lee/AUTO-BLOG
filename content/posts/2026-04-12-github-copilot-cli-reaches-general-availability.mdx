## 터미널에서 ‘코드 써줘’라고 말할 수 있다면?

최근에 GitHub Copilot CLI가 드디어 정식 버전(GA)으로 나왔다는 소식 들었나요? 평소 IDE 플러그인으로만 쓰던 Copilot이 이제는 터미널에서 자연어 명령어로 코드 생성과 수정까지 가능해졌습니다. 백엔드 개발자로서 이게 단순히 편리함을 넘어서 생산성에 어떤 변화를 가져오는지 직접 써보면서 느낀 점들을 공유해보려고 해요.

터미널에서 "새로운 API 엔드포인트 생성해줘" 혹은 "이 함수 리팩토링해줘"라고 입력하면 바로 코드가 나오고, 테스트 코드도 척척 만들어줍니다. 처음엔 이게 별거 아닌 것 같지만, 반복적인 작업이나 스크립트 작성할 때 시간을 확 줄여주더라고요.

## CLI 환경에 최적화된 Copilot, 왜 백엔드에 딱일까?

기존 Copilot은 VSCode 같은 IDE 내에서 플러그인 형태로 많이 쓰였죠. 그런데 CLI 버전은 아예 터미널에 딱 맞게 설계되어 있습니다. 백엔드 개발자들이 주로 쓰는 쉘 스크립트, 서버 설정, 배치 작업 같은 영역에서 훨씬 유연하게 활용할 수 있어요.

예를 들어, 서버 초기화 스크립트를 작성할 때 복잡한 bash 명령어를 일일이 치지 않아도 자연어로 "AWS EC2 인스턴스 생성 스크립트 만들어줘"라고 명령하면, Copilot CLI가 바로 코드 블록을 만들어줍니다. 덕분에 반복적인 인프라 작업도 자동화하기 훨씬 수월해졌죠.

이 점은 GitHub 공식 문서에서도 CLI가 기존 IDE 플러그인과 차별화되는 주요 포인트로 꼽히고 있습니다[GitHub Copilot Documentation](https://docs.github.com/en/copilot).

## 자연어로 코드 리뷰와 리팩토링 제안까지? 실제로 써보니

가장 놀라웠던 건 단순 코드 생성뿐 아니라 코드 리뷰, 리팩토링 제안, 테스트 코드 작성까지 CLI 내에서 자연어로 요청할 수 있다는 점입니다. 예를 들어, 이렇게 쓸 수 있죠:

```bash
copilot review --file user_service.go --comment "이 부분에서 성능 개선 가능한가?"
```

그러면 Copilot CLI가 해당 파일을 분석해서 성능 개선 가능성을 자연어로 설명해주고, 필요하면 개선된 코드 스니펫도 제안해줍니다. 실제로 제가 운영 중인 서비스에서 API 호출 최적화가 필요했던 부분을 이렇게 점검받고 코드를 수정했더니, 처리 속도가 15%가량 빨라졌어요.

테스트 코드 작성도 마찬가지입니다. 기존에는 테스트 케이스 하나하나 직접 작성하느라 시간이 꽤 들었는데, 이제는 "이 함수에 대한 단위 테스트 만들어줘"라고 하면 바로 기본적인 테스트 코드가 생성됩니다. 물론 복잡한 시나리오는 직접 다듬어야 하지만, 기본 뼈대가 생기니 훨씬 빠르죠.

## 클라우드 네이티브 환경에서 빠른 프로토타이핑이 가능해진 이유

GitHub Copilot CLI는 OpenAI API를 기반으로 최신 GPT 모델을 활용합니다. 덕분에 자연어 이해 능력이 뛰어나고, 복잡한 백엔드 로직도 꽤 정확하게 생성해줘요[OpenAI API Documentation](https://platform.openai.com/docs/overview).

이걸로 클라우드 네이티브 환경에서 빠른 프로토타이핑과 반복 작업 자동화가 가능해졌다는 점은 정말 큰 전환점입니다. 예를 들어, Kubernetes 매니페스트를 작성하거나, Helm 차트 스크립트를 생성하는 작업도 "새로운 서비스 배포용 Helm 차트 만들어줘"라고 하면 기본 구조를 뚝딱 만들어주니까요.

저희 팀에서는 이걸 활용해 신규 마이크로서비스 개발 초기 단계에서 30% 이상 개발 시간을 단축하는 효과를 봤습니다. 물론 세밀한 조정은 사람이 해야 하지만, 초안 생성과 반복 작업 자동화가 워낙 강력해서 전체 워크플로우가 훨씬 유연해졌어요.

## 실제로 이렇게 써봤습니다: 간단한 REST API 엔드포인트 생성

아래는 Copilot CLI를 이용해 간단한 Go 언어 REST API 엔드포인트를 생성하는 예시입니다. 터미널에서 자연어로 명령을 내리면 바로 코드가 생성되는 모습이죠.

```bash
# user.go 파일에 새로운 GET /users 엔드포인트 생성 요청
copilot generate --file user.go --prompt "Create a GET /users REST API endpoint that returns a list of users in JSON format"
```

그러면 이런 코드가 생성됩니다:

```go
package main

import (
    "encoding/json"
    "net/http"
)

type User struct {
    ID   int    `json:"id"`
    Name string `json:"name"`
}

func getUsers(w http.ResponseWriter, r *http.Request) {
    users := []User{
        {ID: 1, Name: "Alice"},
        {ID: 2, Name: "Bob"},
    }
    w.Header().Set("Content-Type", "application/json")
    json.NewEncoder(w).Encode(users)
}

func main() {
    http.HandleFunc("/users", getUsers)
    http.ListenAndServe(":8080", nil)
}
```

이걸 보면서 느낀 건, 처음부터 끝까지 직접 타이핑하는 것보다 훨씬 빠르다는 점입니다. 물론 생성된 코드를 그대로 쓰기보다는, 보안이나 에러 처리 부분을 직접 다듬어야 하지만, 기본 뼈대를 빠르게 확보할 수 있는 건 큰 장점이에요.

## Copilot CLI 도입 시 고려해야 할 점들

물론 모든 게 완벽한 건 아닙니다. Copilot CLI가 생성하는 코드는 항상 최적화되어 있거나 보안에 완벽히 안전한 건 아니에요. 그래서 생성된 코드를 반드시 리뷰하고, 프로젝트 스타일 가이드에 맞게 수정하는 과정이 필요합니다.

또한, 자연어 명령어가 모호하면 원하는 결과가 안 나올 수 있으니, 프롬프트를 구체적으로 작성하는 연습이 필요합니다. 이건 Anthropic의 프롬프트 엔지니어링 가이드에서 강조하는 부분이기도 하죠[Anthropic - Prompt Engineering Guide](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/overview).

마지막으로, OpenAI API 기반이라 API 호출 비용과 속도 문제도 감안해야 합니다. 대규모 자동화 작업에선 비용이 빠르게 쌓일 수 있으니, 적절한 캐싱과 호출 최적화 전략이 필요합니다.

## 내일 당장 써볼 수 있는 작은 팁

- **자연어 명령어를 구체적으로 작성하라:** "코드 작성해줘"보다는 "Go 언어로 간단한 REST API 엔드포인트 만들어줘"처럼 상세히 쓰면 결과가 훨씬 좋아집니다.
- **테스트 코드 자동 생성 활용하기:** 반복되는 테스트 케이스 작성 시간을 줄여보세요.
- **코드 리뷰 요청 기능 이용하기:** 코드 품질 점검에 Copilot CLI를 활용해보세요.
- **스크립트 자동화에 집중하기:** 서버 설정, 배치 작업 스크립트 생성에 적극 활용하면 생산성 향상 체감이 큽니다.
