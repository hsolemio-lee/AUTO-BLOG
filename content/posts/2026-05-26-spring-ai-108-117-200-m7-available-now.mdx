# Spring AI 최신 버전, 실제 서비스에 어떻게 적용하고 있나요?

최근에 우리 팀에서 Spring AI 2.0.0-M7로 마이그레이션을 진행하면서 꽤 많은 고민과 시행착오가 있었어요. AI 기능을 백엔드에 통합하는 건 이제 선택이 아니라 필수인데, 최신 버전들이 제공하는 기능과 설정들을 제대로 이해하지 않으면 오히려 성능 저하나 보안 이슈가 생기기 쉽더라고요.

이번 글에서는 Spring AI 1.0.8, 1.1.7, 그리고 2.0.0-M7 버전의 차이점과 실무에서 꼭 알아야 할 성능 튜닝, 보안 설정, 그리고 단계적 롤아웃 전략을 공유해보려고 합니다. 제가 직접 겪은 경험과 공식 문서, 그리고 커뮤니티 팁을 바탕으로 썼으니 참고가 될 거예요.

---

## Spring AI 2.0.0-M7, 왜 마이그레이션이 필요한가?

1.x 버전에서 2.0.0-M7으로 넘어가면서 가장 크게 달라진 점은 보안과 성능 최적화 관련 설정이 대폭 강화됐다는 점입니다. 예를 들어, 1.0.8이나 1.1.7에서는 기본적으로 OpenAI API 키를 단순히 프로퍼티에 넣고 사용하는 수준이었다면, 2.0.0-M7부터는 토큰 갱신 로직과 요청 제한 관리가 내장돼 있어요.

또한, Spring AI가 Spring의 DI(Dependency Injection)와 AOP(Aspect-Oriented Programming) 환경에 더 깊게 통합되면서, AI 호출을 서비스 레이어에 자연스럽게 녹여낼 수 있게 됐죠. 이 덕분에 기존 코드와 충돌 없이 AI 기능을 확장할 수 있었습니다.

실제로 우리 팀에서는 다음과 같은 마이그레이션 포인트를 체크리스트로 만들어 진행했어요.

- `spring.ai.api-key` 프로퍼티 대신 `spring.ai.security.token-refresh-enabled=true` 설정 추가
- AI 호출 시점에 AOP를 활용해 로깅과 예외 처리를 일괄 적용
- API 요청 제한 초과 시 fallback 처리 로직 구현

이 과정에서 공식 [Spring Boot Reference Documentation](https://docs.spring.io/spring-boot/reference/)의 2.0.0-M7 마이그레이션 가이드가 큰 도움이 됐습니다.

## AI 모델 호출, 성능 저하 없이 어떻게 관리할까?

AI 모델 호출은 네트워크 I/O가 많고, 응답 속도가 서비스 전체 지연 시간에 큰 영향을 미칩니다. Baeldung의 [Spring Boot Performance Tuning](https://www.baeldung.com/spring-boot-performance) 가이드에서 강조하는 것처럼, JVM 튜닝과 스레드풀 관리가 필수입니다.

우리 팀에서는 다음과 같은 설정을 적용했어요.

- 스레드풀 크기: CPU 코어 수 * 2 + 1 (예: 8코어 서버면 17개 스레드)
- AI 호출 전용 RestTemplate/HttpClient 빈 생성 후 커넥션 풀 크기 50으로 설정
- 요청 타임아웃 3초, 커넥션 타임아웃 1초로 조정

```java
@Configuration
public class AiClientConfig {

    @Bean
    public RestTemplate aiRestTemplate() {
        HttpComponentsClientHttpRequestFactory factory = new HttpComponentsClientHttpRequestFactory();
        factory.setConnectTimeout(1000); // 1초
        factory.setReadTimeout(3000); // 3초

        PoolingHttpClientConnectionManager cm = new PoolingHttpClientConnectionManager();
        cm.setMaxTotal(50);
        cm.setDefaultMaxPerRoute(50);

        CloseableHttpClient httpClient = HttpClients.custom()
                .setConnectionManager(cm)
                .build();

        factory.setHttpClient(httpClient);

        return new RestTemplate(factory);
    }
}
```

이렇게 하면 AI API 호출 시 네트워크 지연을 최소화하면서도, 스레드가 과도하게 점유되는 문제를 막을 수 있었습니다. 물론, 너무 큰 스레드풀은 GC 부담과 컨텍스트 스위칭 증가로 이어지니 주의해야 해요.

또한, AI 호출 결과를 캐싱하는 전략도 중요합니다. 프롬프트가 동일한 경우 재호출을 줄이기 위해 Redis 캐시를 활용해 5분간 결과를 저장하는 식으로 운영 중입니다.

## AI 통합 시 보안, 생각보다 까다롭다

OpenAI API 키 관리와 요청 제한, 그리고 토큰 갱신은 서비스 안정성에 직결되는 문제입니다. OpenAI 공식 [API Documentation](https://platform.openai.com/docs/overview)에서는 다음과 같은 보안 모범 사례를 권장해요.

- API 키는 절대 코드에 하드코딩하지 말고, 환경 변수나 시크릿 매니저를 활용
- 요청 제한(Rate Limit)을 초과하지 않도록 클라이언트에서 제한 로직 구현
- 토큰 만료 시 자동 갱신 로직을 넣어 서비스 중단 방지

Spring AI 2.0.0-M7부터는 이런 기능들이 기본 지원되면서, 설정 한 줄이면 자동 토큰 갱신이 가능해졌습니다.

```yaml
spring:
  ai:
    security:
      token-refresh-enabled: true
    api-key: ${OPENAI_API_KEY}
```

이 설정을 켜면 내부적으로 토큰 유효성을 주기적으로 검사하고 만료되면 갱신합니다. 덕분에 운영 중인 서비스가 API 키 만료로 갑자기 먹통 되는 사고를 방지할 수 있었죠.

또한, AI 호출 시 민감한 데이터가 포함될 수 있으니, 프록시 서버나 VPN을 통해 네트워크 보안을 강화하는 것도 추천합니다.

## 프롬프트 설계, AI 성능의 숨은 결정자

AI 모델의 답변 품질은 프롬프트 설계에 크게 좌우됩니다. Anthropic의 [Prompt Engineering Guide](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/overview)를 참고하면, 효과적인 프롬프트 작성법과 테스트 전략을 배울 수 있어요.

우리 팀에서는 다음과 같은 방법을 적용했습니다.

- 프롬프트 템플릿을 별도 관리하며, 변수 치환 방식으로 재사용성 확보
- 프롬프트 변경 시마다 A/B 테스트를 통해 응답 품질과 응답 시간 측정
- 부적절한 답변을 걸러내는 후처리 필터링 로직 추가

예를 들어, 고객 문의 자동 응답 AI를 만들 때는 다음과 같은 프롬프트 템플릿을 사용합니다.

```java
String promptTemplate = "고객 문의: %s\n친절하고 정확하게 답변해줘.";

public String buildPrompt(String customerQuestion) {
    return String.format(promptTemplate, customerQuestion);
}
```

이렇게 하면 고객 문의 내용만 바꿔서 일관된 톤과 스타일로 답변을 생성할 수 있죠. 다만, 프롬프트가 너무 길거나 복잡하면 응답 시간이 길어지니 적절한 길이로 조절하는 게 중요합니다.

# 마치며: 실무에서 Spring AI 최신 버전을 활용할 때 꼭 기억할 점

- **마이그레이션은 미리 충분히 테스트할 것**: 2.0.0-M7은 좋은 기능이 많지만, 기존 1.x 버전과 설정 방식이 달라서 바로 적용하면 문제 생길 수 있어요.
- **스레드풀과 타임아웃 설정은 환경에 맞게 조절할 것**: AI 호출은 네트워크 환경에 따라 지연이 크게 달라지니, 프로덕션 환경에서 모니터링하며 조정하세요.
- **보안은 기본 중의 기본**: API 키 관리와 요청 제한은 서비스 안정성에 직결됩니다. 꼭 자동 토큰 갱신과 환경 변수 활용을 습관화하세요.
- **프롬프트는 AI 품질의 핵심**: 단순히 AI 모델에 맡기지 말고, 프롬프트 설계와 테스트를 꾸준히 반복해 최적화하세요.

이 글이 Spring AI 최신 릴리즈를 실무에 적용하는 데 조금이나마 도움이 되었으면 합니다. AI 통합은 이제 시작일 뿐, 앞으로도 계속 진화할 테니 꾸준히 경험을 쌓아가야겠죠?
