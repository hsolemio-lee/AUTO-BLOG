## AI가 고쳐준 코드가 오히려 공격 경로가 될 수 있다고?

얼마 전 Snowflake의 Jira 시스템이 침해당했다는 소식을 접했을 때, 솔직히 처음엔 ‘설마 AI가 원인일까?’ 하는 생각이 들었어요. 그런데 조사 결과, GitHub Copilot의 ‘Autofix’ 기능이 자동으로 제안한 코드 수정이 보안 취약점을 포함한 채로 배포되면서 공격자가 이를 악용할 수 있었다고 하더군요. 이 사건은 AI 코딩 도구가 편리함 뒤에 숨긴 위험성을 다시 한번 일깨워줬습니다.

이 글에서는 실제 사례를 통해 AI 기반 자동 수정 기능이 어떻게 보안 사고로 이어질 수 있는지, 그리고 우리 개발팀이 어떻게 대비해야 할지 현실적인 조언을 나눠보려 합니다.

---

## GitHub Copilot Autofix, 자동 수정이 왜 위험할까?

GitHub Copilot은 AI가 코드 작성뿐 아니라 버그 수정까지 제안하는 ‘Autofix’ 기능을 제공합니다. 개발자가 코드 리뷰 없이 이 제안을 바로 적용하면, 편리함은 크지만 보안상 치명적인 문제가 생길 수 있어요. 

예를 들어, Copilot이 제안한 수정 코드에 인증 우회나 민감 정보 노출 같은 취약점이 숨어있을 수 있습니다. 개발자가 무심코 적용하면, 그 취약점이 그대로 프로덕션에 배포되는 거죠. Snowflake Jira 침해 사건도 이런 흐름에서 발생했습니다. 

GitHub 공식 문서에서도 "Autofix 기능은 자동으로 코드 수정 제안을 제공하지만, 이 과정에서 보안 취약점이 포함될 가능성이 있다"고 명확히 경고합니다[GitHub Copilot Documentation](https://docs.github.com/en/copilot).


## AI가 만든 코드를 무조건 믿으면 안 되는 이유

OpenAI API 문서도 "AI가 생성하는 코드가 항상 최적의 보안 상태를 보장하지 않는다"고 분명히 말합니다. AI 모델은 과거 학습 데이터 기반으로 코드를 생성하기 때문에, 최신 보안 패치나 조직 내 정책을 반영하지 못할 수 있어요. 

특히 자동 수정 기능은 개발자가 직접 코드를 작성하는 것보다 더 빠르게 변경이 일어나므로, 검토 없이 적용하면 악성 코드나 보안 취약점이 들어갈 위험이 높아집니다. 

이런 점에서 AI가 제안한 코드는 반드시 사람이 꼼꼼히 리뷰하고, 보안 테스트를 거쳐야만 안전하다는 게 제 경험과 문서들의 공통된 조언입니다[OpenAI API Documentation](https://platform.openai.com/docs/overview).


## 우리 팀에서 적용해본 AI 자동 수정 보안 강화 방법

제가 몸담은 팀에서는 Copilot의 Autofix 기능을 도입한 후, 다음과 같은 절차를 강화했습니다.

- **자동화된 보안 스캔 통합**: CI/CD 파이프라인에 SAST(Static Application Security Testing) 도구를 넣어, AI가 제안한 수정 코드가 보안 규칙을 위반하는지 자동으로 검사합니다.
- **코드 리뷰 필수화**: AI가 제안한 모든 수정은 최소 2명 이상의 개발자가 검토하도록 했습니다. 특히 보안 관련 부분은 보안 담당자가 직접 확인합니다.
- **변경 내역 투명성 확보**: AI가 만든 수정도 누가 언제 어떤 이유로 적용했는지 로그를 남겨 추적 가능하게 관리합니다.

아래는 GitHub Actions를 활용해 Copilot Autofix 후 자동 보안 스캔을 돌리는 예시 워크플로우입니다.

```yaml
name: CI with Security Scan

on:
  pull_request:
    branches: [main]

jobs:
  build-and-scan:
    runs-on: ubuntu-latest

    steps:
    - uses: actions/checkout@v3
    - name: Set up Node.js
      uses: actions/setup-node@v3
      with:
        node-version: '16'
    - name: Install dependencies
      run: npm install
    - name: Run tests
      run: npm test
    - name: Run SAST scan
      uses: github/codeql-action/analyze@v2
      with:
        category: 'javascript'
```

이렇게 하면 AI가 수정한 코드가 보안 취약점을 포함하는지 자동으로 걸러낼 수 있어, 위험을 크게 줄일 수 있습니다.


## 프롬프트 엔지니어링으로 AI가 보안 정책을 이해하게 만들기

Anthropic의 프롬프트 엔지니어링 가이드에서는 AI에게 명확한 보안 정책과 코딩 가이드라인을 프롬프트에 포함시켜, 처음부터 보안 위험을 줄이는 전략을 추천합니다. 

예를 들어, "이 코드는 사용자 입력을 반드시 검증해야 한다"거나 "비밀번호는 절대 평문으로 저장하면 안 된다"는 문구를 프롬프트에 넣어 AI가 보안 규칙을 인지하게 만드는 식이죠. 

이 방법은 AI가 무작정 코드를 고치려 하기보다는 보안 원칙을 준수하며 제안하도록 유도하는 효과가 있습니다. 물론 100% 완벽하지는 않지만, AI가 보안 컨텍스트를 이해하는 데 큰 도움이 됩니다[Anthropic - Prompt Engineering Guide](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/overview).


## AI 자동 수정 기능, 그래도 쓰고 싶다면 꼭 기억해야 할 점

처음엔 ‘AI가 알아서 고쳐주니까 편하겠지’ 싶지만, 실제로 겪어보면 자동 수정이 가져오는 보안 리스크는 생각보다 큽니다. 그래서 다음 사항은 꼭 지키세요.

- **자동 적용 금지**: AI가 제안한 코드는 무조건 사람이 리뷰하고 테스트 후 병합하세요.
- **보안 스캔 필수**: CI/CD에 보안 스캐너를 넣어 자동으로 취약점 여부를 점검하세요.
- **변경 이력 기록**: 누가 AI 제안을 승인하고 적용했는지 명확히 기록해 추적 가능하게 만드세요.
- **프롬프트에 보안 정책 명시**: AI에게 명확한 보안 지침을 알려줘 위험한 코드를 제안하지 않도록 유도하세요.

이렇게 하면 AI가 제공하는 생산성 향상 효과를 누리면서도, 보안 사고 위험은 최소화할 수 있습니다.

AI 코딩 에이전트는 분명 혁신적인 도구지만, 아직은 ‘보조’ 정도로 생각하고 인간의 검증과 조율이 반드시 필요하다는 점을 다시 한번 실감했습니다. Snowflake Jira 사건이 우리 모두에게 던지는 메시지는 명확합니다. AI가 자동으로 고쳐준다고 무조건 믿지 말고, 보안은 결국 사람이 챙겨야 한다는 것.

참고로, AI 자동 수정 기능을 도입할 때는 조직 내 보안 담당자와 긴밀히 협업하고, 지속적으로 프로세스를 점검하는 게 가장 중요합니다. 저도 우리 팀과 함께 계속 개선해 나가고 있으니, 여러분도 꼭 한번 점검해보시길 바랍니다.
