## AI가 편집한 텍스트, 어떻게 추적할까?

"내가 쓴 문장인데 AI가 어디를 어떻게 바꿨는지 정확히 알고 싶다"는 요청, 요즘 AI 편집 기능을 서비스에 넣으면서 자주 듣는 말입니다. 특히 에이전트가 주도하는 편집(Agentic Editing)에서는 AI가 여러 번에 걸쳐 문장을 다듬고, 심지어 일부는 사람이, 일부는 AI가 쓴 부분도 섞이죠. 이럴 때 단순히 최종 결과만 저장하면 누가, 언제, 왜 바꿨는지 알기 어렵습니다.

그래서 요즘 뜨는 게 바로 **라인 단위 diff 기반 변경 이력 추적**입니다. 텍스트를 줄 단위로 쪼개고, 각 줄이 어떻게 바뀌었는지 기록하는 거죠. 이걸 백엔드에 잘 쌓아두면 감사 추적(audit trail)도 되고, 리스크 관리도 훨씬 수월해집니다.

## OpenAI API로 라인별 diff 이력 만드는 게 생각보다 쉽다

OpenAI API는 텍스트 생성뿐 아니라 편집(edit) 기능도 제공합니다. 특히 `edits` 엔드포인트를 쓰면, 원본 텍스트와 AI가 편집한 결과를 입력으로 주고, 어떤 부분이 수정됐는지 알 수 있는 결과를 받을 수 있어요. 이걸 활용하면 라인 단위 diff를 구현하는 게 훨씬 간단해집니다.

예를 들어, 다음은 Node.js 환경에서 OpenAI의 편집 API를 호출해 라인 단위 변경 내역을 추출하는 간단한 코드입니다:

```javascript
import OpenAI from "openai";

const openai = new OpenAI();

async function getLineDiffs(originalText, editedText) {
  // 편집 API 호출
  const response = await openai.edits.create({
    model: "text-davinci-edit-001",
    input: originalText,
    instruction: "Edit the text as needed.",
    n: 1,
    temperature: 0
  });

  // 실제 편집 결과
  const newText = response.choices[0].text.trim();

  // 원본과 새 텍스트를 줄 단위로 분리
  const originalLines = originalText.split('\n');
  const newLines = newText.split('\n');

  // 간단한 diff 로직 (예: 각 라인 비교)
  const diffs = [];
  const maxLines = Math.max(originalLines.length, newLines.length);
  for (let i = 0; i < maxLines; i++) {
    if (originalLines[i] !== newLines[i]) {
      diffs.push({
        line: i + 1,
        before: originalLines[i] || '',
        after: newLines[i] || ''
      });
    }
  }

  return diffs;
}

// 실제 사용 예
(async () => {
  const original = `Hello world\nThis is a test.\nHave a nice day.`;
  const edited = `Hello world!\nThis is a test.\nHave a great day.`;

  const diffs = await getLineDiffs(original, edited);
  console.log(diffs);
})();
```

이 코드가 완벽한 diff 알고리즘은 아니지만, OpenAI 편집 API와 결합하면 라인별 변경 사항을 쉽게 뽑아낼 수 있다는 게 핵심입니다. 물론 실제 운영 환경에서는 `diff-match-patch` 같은 라이브러리를 써서 좀 더 정교하게 처리하는 게 좋습니다.

## Anthropic Claude는 프롬프트 레벨에서 라인별 변경 추적을 지원한다

Anthropic의 Claude 모델은 에이전트 워크플로우에 특화된 프롬프트 엔지니어링 가이드가 잘 되어 있습니다. 특히 각 편집 단계에서 "이 줄을 이렇게 고쳤다"는 식으로 명확한 라인 단위 변경 내역을 생성하도록 유도할 수 있죠.

예를 들어, 다음과 같은 프롬프트를 사용하면 Claude가 각 라인별 변경 사항을 JSON 형태로 출력하게 할 수 있습니다:

```
원본 텍스트:
1. Hello world
2. This is a test
3. Have a nice day

수정된 텍스트:
1. Hello world!
2. This is a test
3. Have a great day

각 줄별로 변경 내역을 JSON으로 알려줘. 예:
[
  {"line": 1, "before": "Hello world", "after": "Hello world!"},
  {"line": 3, "before": "Have a nice day", "after": "Have a great day"}
]
```

이렇게 하면 AI가 변경 이력을 직접 만들어주니까, 백엔드에서 따로 복잡한 diff 연산을 할 필요가 줄어듭니다. 물론 프롬프트 설계가 까다롭고, AI가 의도대로 안 나올 때도 있지만, 이 방식은 에이전트 편집의 투명성을 크게 높여줍니다.

## Cursor와 GitHub Copilot, Vercel AI SDK가 보여주는 실무 적용 사례

실제 산업 현장에서는 Cursor, GitHub Copilot, Vercel AI SDK 같은 툴들이 라인 단위 diff 추적을 어떻게 활용하는지 참고할 만합니다.

- **Cursor**는 코드와 텍스트 편집에 특화된 diff 기반 변경 추적 기능을 제공해, AI가 편집한 시점부터 상세 변경 내역을 백엔드에 기록합니다. 덕분에 감사와 리스크 관리가 체계적으로 이뤄집니다.[Cursor Documentation](https://docs.cursor.com/)

- **GitHub Copilot**은 AI 코드 보조 도구로, 변경 사항을 실시간으로 라인 단위 추적해 누가 어떤 코드를 AI와 함께 썼는지 명확히 구분할 수 있습니다.[GitHub Copilot Documentation](https://docs.github.com/en/copilot)

- **Vercel AI SDK**는 프론트엔드와 백엔드를 아우르는 통합 환경에서 AI 편집 변경 이력을 저장하고 관리하는 인터페이스를 제공해, 에이전트 편집 시점의 diff 추적과 감사 로그 생성을 지원합니다.[Vercel AI SDK Documentation](https://sdk.vercel.ai/docs/introduction)

이런 사례들을 보면, 단순히 텍스트 생성에 그치지 않고, 변경 이력을 체계적으로 관리하는 게 얼마나 중요한지 알 수 있습니다.

## 라인 단위 diff 추적이 백엔드 감사와 리스크 관리에 주는 이점

처음엔 이게 별거 아닌 것 같지만, 실제로 에이전트 AI 편집을 서비스에 도입하면 왜 라인 단위 변경 이력이 중요한지 뼈저리게 느껴집니다.

- **투명성 확보**: 누가 어떤 부분을 AI가 수정했는지 명확히 알면, 사용자 신뢰도가 올라갑니다.
- **버그 추적과 롤백 용이**: 특정 라인에서 오류가 발생했을 때, 언제 어떤 AI 편집이 들어갔는지 알면 문제 원인 파악이 빨라집니다.
- **컴플라이언스 대응**: 금융, 의료 등 규제가 엄격한 분야에서는 변경 이력 기록이 필수입니다. 라인 단위 diff는 감사를 위한 최적의 단위죠.
- **리스크 관리 강화**: AI가 의도치 않은 변경을 했을 때 빠르게 탐지하고 대응할 수 있습니다.

## 현실적인 한계와 고려해야 할 점

물론 완벽한 솔루션은 없습니다. 라인 단위 diff 추적도 다음과 같은 한계와 트레이드오프가 있죠.

- **성능 부담**: 매 편집마다 diff를 계산하고 저장하면 데이터가 급증합니다. 저장소 설계와 인덱싱 전략이 중요합니다.
- **AI 출력의 불확실성**: AI가 항상 명확한 변경 내역을 주는 게 아니어서, 프롬프트 튜닝과 후처리 로직이 필요합니다.
- **복잡한 편집 내역 표현 문제**: 줄이 추가되거나 삭제되는 경우, 단순 라인 매칭으로는 부족할 수 있습니다.

이런 점들을 감안해, 우리 팀은 다음과 같은 전략을 추천합니다.

- 편집 API + diff 라이브러리 결합
- AI가 변경 내역을 JSON으로 명시하게 하는 프롬프트 설계
- 중요 변경에 한해 상세 diff 저장
- 변경 이력 조회용 API와 UI 제공

## 정리하며: 코드 편집도, 텍스트 편집도 라인 단위 추적은 필수다

AI가 편집하는 시대에, 단순 완성본 저장은 너무 부족합니다. 특히 에이전트가 주도하는 편집에서는 각 단계의 변경 내역을 투명하게 기록하는 게 서비스 신뢰도를 좌우하죠.

OpenAI 편집 API, Anthropic Claude의 프롬프트 기법, 그리고 Cursor, GitHub Copilot, Vercel AI SDK 같은 실무 도구들이 모두 라인 단위 diff 추적을 지원하는 이유도 여기에 있습니다. 우리 백엔드에서 이런 변경 이력을 잘 관리하면, 감사 추적과 리스크 관리가 훨씬 수월해지고, 사용자에게도 신뢰받는 AI 편집 환경을 제공할 수 있습니다.

한번 직접 구현해보면, 왜 라인 단위 diff가 중요한지 뼈저리게 느낄 겁니다. AI와 사람이 함께 만드는 텍스트, 그 변화의 발자취를 놓치지 말자고요.
