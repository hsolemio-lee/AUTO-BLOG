## AI 크롤러가 내 서비스 콘텐츠를 헷갈려할 때가 있다면

"왜 우리 서비스에 AI 크롤러가 들어올 때마다 엉뚱한 데이터만 가져갈까?" 이런 고민 해본 적 있나요? 저도 최근에 비슷한 문제에 부딪혀서 Cloudflare가 새로 내놓은 'Markdown for Agents'와 'Content Signals' 기능을 적용해봤는데, 생각보다 효과가 컸습니다. 이 기능들은 AI 크롤러가 우리 웹 페이지를 더 똑똑하게 이해하도록 돕는 역할을 하죠.

## Cloudflare Markdown, AI 에이전트가 좋아하는 콘텐츠 구조란?

기존에는 AI 크롤러가 웹 페이지의 HTML 구조를 단순히 긁어가면서 중요한 내용을 제대로 구분하지 못하는 경우가 많았어요. Cloudflare가 도입한 Markdown for Agents는 AI 크롤러가 "이 부분은 제목이고, 여긴 요약이며, 여긴 상세 설명"이라고 바로 알 수 있게 명확한 마크업을 제공합니다. 

예를 들어, 다음과 같은 Markdown 문법을 HTTP 헤더나 API 응답에 포함시키면, AI 에이전트가 페이지 내에서 핵심 정보를 빠르게 파악할 수 있습니다.

```markdown
---
title: "우리 서비스의 최신 기능"
summary: "Cloudflare Markdown과 콘텐츠 신호를 활용해 AI 크롤러 최적화하기"
author: "홍길동"
---

# 주요 업데이트
- AI 크롤러 대응력 향상
- 서비스 신뢰성 강화
```

이걸 백엔드 API에서 JSON 대신 Markdown 형태로 제공하거나, HTTP 헤더에 넣어주면 AI 크롤러가 자연스럽게 이 정보를 읽고 활용할 수 있습니다. 덕분에 크롤러가 불필요한 데이터를 긁어가는 일이 줄고, 서비스 품질도 올라가죠.

## 콘텐츠 신호(Content Signals)가 왜 중요한가?

Markdown이 "어떤 정보인지"를 알려준다면, 콘텐츠 신호는 "어떤 정보를 먼저, 어떻게 처리할지" AI 크롤러에게 힌트를 줍니다. 예를 들어, 페이지 내에서 최신 뉴스 섹션에 높은 우선순위를 주거나, 업데이트가 잦은 부분에 더 자주 접근하도록 유도할 수 있어요.

백엔드에서는 이 신호를 API 응답에 메타데이터로 포함시키는 게 핵심입니다. 예를 들어, 다음과 같이 JSON 응답에 우선순위(priority)나 갱신 주기(updateInterval)를 명시할 수 있습니다.

```json
{
  "content": "...",
  "contentSignals": {
    "priority": "high",
    "updateInterval": 3600
  }
}
```

이렇게 하면 AI 크롤러가 "이 콘텐츠는 1시간마다 갱신되고, 꼭 먼저 봐야 할 부분"이라는 걸 인지해서 크롤링 전략을 조정할 수 있죠. 결과적으로 백엔드가 크롤러의 요청을 더 효율적으로 관리할 수 있어 서비스 신뢰성이 높아집니다.

## 백엔드에서 Cloudflare Markdown과 콘텐츠 신호를 어떻게 구현할까?

우리 팀에서는 Node.js 기반 REST API에서 다음과 같은 방식을 적용했습니다. 우선, 클라이언트에게 제공하는 주요 문서 API에 Markdown 메타데이터를 포함시키고, 별도의 헤더로 콘텐츠 신호를 전달합니다.

```typescript
import express from 'express';
const app = express();

app.get('/api/docs/:id', (req, res) => {
  const docId = req.params.id;
  // DB에서 문서 데이터 조회
  const doc = getDocumentFromDB(docId);

  // Markdown for Agents 메타데이터 생성
  const markdownMeta = `---\ntitle: "${doc.title}"\nsummary: "${doc.summary}"\nauthor: "${doc.author}"\n---`;

  // 콘텐츠 신호 헤더 설정
  res.setHeader('X-Content-Signals', JSON.stringify({ priority: 'high', updateInterval: 3600 }));

  res.json({
    markdownMeta,
    content: doc.content
  });
});

app.listen(3000, () => console.log('Server running on port 3000'));
```

이렇게 하면 AI 크롤러가 API 응답에서 바로 문서의 구조와 중요도를 파악할 수 있습니다. 물론, Markdown 메타데이터를 별도의 필드로 분리하는 대신, 문서 본문에 직접 삽입하는 방식도 가능합니다.

## 실제 운영에서 겪은 의외의 문제와 해결책

처음에는 Markdown 메타데이터를 너무 자세하게 넣으려고 하다 보니, API 응답 크기가 커지고 응답 속도가 느려지는 문제가 있었습니다. 그래서 중요한 정보 위주로 최소한의 메타데이터만 남기고, 나머지는 별도의 캐시 서버에서 관리하도록 구조를 바꿨죠.

또한, 콘텐츠 신호를 너무 자주 바꾸면 AI 크롤러가 혼란스러워할 수 있어서, 신호 변경 주기를 1시간 이상으로 고정했습니다. 이 작은 조정 덕분에 크롤러와의 상호작용 안정성이 크게 올라갔습니다.

## Cloudflare 기능 도입 전후, 서비스 신뢰성 변화 체감하기

도입 전에는 AI 크롤러가 우리 페이지를 제대로 이해하지 못해 검색 결과에 이상한 정보가 노출되는 일이 잦았고, 크롤러 트래픽이 급증할 때 서버 부하도 컸습니다. 그런데 Markdown과 콘텐츠 신호를 적용한 후에는 크롤러가 원하는 정보만 선별해서 가져가면서 트래픽이 20% 정도 줄었고, 검색 결과 품질도 눈에 띄게 좋아졌어요.

이 경험은 "AI 크롤러와 소통하는 백엔드"가 얼마나 중요한지 다시 한번 깨닫게 해줬습니다.

## 앞으로 AI 크롤러 대응을 위한 백엔드 설계에 꼭 고려해야 할 점

- **명확한 콘텐츠 구조화**: Markdown for Agents처럼 AI가 이해하기 쉬운 포맷으로 핵심 정보를 제공해야 합니다.
- **우선순위와 갱신 주기 신호**: 콘텐츠 신호를 통해 크롤러가 효율적인 크롤링 전략을 세울 수 있도록 돕습니다.
- **응답 크기와 속도 조절**: 메타데이터 과다 삽입은 오히려 독이 될 수 있으니 최소한으로 유지하세요.
- **신호 변경 주기 관리**: 너무 자주 바꾸면 크롤러가 혼란스러우니 적절한 간격을 유지하는 게 좋습니다.

이제 AI 크롤러는 단순히 페이지를 긁어가는 존재가 아니라, 우리가 제공하는 신호를 해석해 더 똑똑하게 행동하는 파트너라고 생각해야 합니다. Cloudflare의 새로운 기능들이 이 과정을 훨씬 수월하게 만들어주니, 꼭 한번 적용해보길 추천합니다.
