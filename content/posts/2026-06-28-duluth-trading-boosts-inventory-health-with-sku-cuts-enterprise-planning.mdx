# SKU가 너무 많으면 진짜 문제라는 걸 알게 된 이야기

우리 팀에서 재고 데이터가 터무니없이 많아지면서 SCM 시스템이 점점 무거워지고, 수요 예측도 엉망이 된 적이 있었어요. 그때 Duluth Trading이 SKU를 과감히 줄여서 재고 건강을 크게 개선했다는 이야기를 듣고 ‘아, 이게 진짜 핵심이구나’ 싶었죠.

SKU(Stock Keeping Unit)는 단순한 재고 식별자가 아니라, 재고 효율성과 공급망 관리 전체의 신경망과도 같아요. SKU가 너무 많으면 재고 과잉, 데이터 부정확성, 계획 오류가 꼬리를 물고 발생합니다. 이번 글에선 중간 단계 엔지니어 입장에서 Duluth Trading 사례를 참고해, 어떻게 SKU 축소 전략을 실무에 적용해볼 수 있을지 이야기해볼게요.

---

## SKU를 줄이면 재고 건강이 왜 좋아질까?

처음엔 SKU를 줄인다는 게 ‘제품을 줄여서 선택권이 줄어드는 거 아닌가?’ 싶죠. 하지만 실제로는 불필요하거나 판매량이 미미한 SKU를 제거하면서 재고 회전율이 올라가고, 불필요한 재고 유지 비용이 줄어듭니다. Duluth Trading은 SKU를 10~15% 정도 줄이고, 이 과정에서 재고 과잉률을 20% 이상 낮췄다고 해요.

Microsoft의 Dynamics 365 SCM 문서에서도 SKU 감소가 재고 과잉과 복잡성을 줄여서, 계획과 실행 단계에서 데이터 정확성을 높인다고 명시하고 있습니다[Microsoft Learn - Dynamics 365 Supply Chain Management](https://learn.microsoft.com/en-us/dynamics365/supply-chain/).

중간 엔지니어로서 이런 변화를 체감하려면, SKU별 판매 데이터와 재고 회전율을 분석하는 게 첫걸음이에요. 예를 들어, SKU별 6개월 판매량이 전체 SKU 중 하위 10%라면 과감히 SKU 정리 대상에 넣는 식이죠.

---

## 엔터프라이즈 계획에서 SKU 축소가 가져오는 변화

SKU가 많으면 수요 예측 모델이 복잡해지고, 생산 계획도 꼬입니다. Oracle의 SCM 문서에서는 SKU 감소가 수요 예측 정확도를 높이고, 생산 계획을 단순화해 재고 회전율을 개선하는 데 핵심 역할을 한다고 설명합니다[Oracle Docs - SCM and Manufacturing](https://docs.oracle.com/en/cloud/saas/supply-chain-and-manufacturing/).

Duluth Trading은 SKU 축소와 함께 엔터프라이즈 계획 시스템 내 SKU 데이터 정합성을 높이는 작업을 병행했어요. 덕분에 수요 예측 모델이 SKU별로 더 신뢰할 만한 데이터를 받아서, 생산량 조절이 훨씬 정밀해졌죠.

우리도 비슷한 상황이라면, SKU별 수요 예측 정확도를 평가하는 지표(예: MAPE)를 도입해, 낮은 예측 정확도를 보이는 SKU를 줄이거나 통합하는 작업을 해야 합니다. 이렇게 하면 SCM 시스템이 훨씬 가벼워지고, 계획 수립 속도도 빨라집니다.

---

## SAP SCM 도구로 SKU 데이터 분석과 정리하기

SAP SCM 솔루션은 SKU 축소를 지원하는 여러 도구를 제공합니다. 특히 SKU별 판매 추이, 재고 수준, 비용 등을 한눈에 볼 수 있는 대시보드가 있어, 중간 엔지니어가 직접 데이터를 분석하고 불필요한 SKU를 찾아내는 데 큰 도움이 됩니다[ SAP Help Portal - Supply Chain Management](https://help.sap.com/docs/SAP_SUPPLY_CHAIN_MANAGEMENT).

예를 들어, SAP의 Advanced Planning and Optimization(APO) 모듈을 활용하면 SKU별 수요 패턴을 시계열 분석하고, 비효율적인 SKU를 자동으로 식별하는 규칙을 만들 수 있어요. 

```typescript
// TypeScript 예제: SKU별 판매량 필터링 함수
interface SKUData {
  skuId: string;
  salesLast6Months: number;
}

function filterLowPerformingSKUs(skus: SKUData[], threshold: number): SKUData[] {
  return skus.filter(sku => sku.salesLast6Months >= threshold);
}

// 6개월 판매량이 100개 미만인 SKU는 제거 대상
const allSKUs: SKUData[] = [
  { skuId: 'A123', salesLast6Months: 150 },
  { skuId: 'B456', salesLast6Months: 80 },
  { skuId: 'C789', salesLast6Months: 200 },
];

const filteredSKUs = filterLowPerformingSKUs(allSKUs, 100);
console.log(filteredSKUs); // [{ skuId: 'A123', ... }, { skuId: 'C789', ... }]
```

이런 간단한 필터링 로직을 SAP API와 연동해 자동화하면, SKU 관리가 훨씬 효율적입니다. 물론, 실제로는 판매량뿐 아니라 마진, 고객 선호도, 시즌성 등 여러 요소를 복합적으로 고려해야 하니, 단순 필터링만으로는 부족할 수 있다는 점도 기억하세요.

## 클라우드 SCM 플랫폼에서 SKU 최적화 작업을 더 빠르게

Microsoft의 Dynamics 365 같은 클라우드 기반 SCM 플랫폼을 활용하면, SKU 관련 데이터에 실시간으로 접근하고 팀원들과 협업할 수 있어서 SKU 최적화 작업이 훨씬 수월해집니다[Microsoft Learn - Dynamics 365 Supply Chain Management](https://learn.microsoft.com/en-us/dynamics365/supply-chain/).

우리 팀도 SKU 정리 작업을 진행하면서, 클라우드 플랫폼 덕분에 재고 담당자, 영업팀, 생산팀과 실시간으로 데이터를 공유하고 피드백을 받을 수 있었어요. 덕분에 SKU 제거 결정이 더 신속하고 정확해졌죠.

다만, 클라우드 플랫폼 도입 초기에는 데이터 마이그레이션과 권한 설정에 신경 써야 합니다. 예를 들어, SKU 데이터가 여러 시스템에 분산돼 있다면, 통합 과정에서 데이터 불일치가 발생할 수 있으니 사전 점검이 필수예요.

---

## 실무에서 SKU 축소 전략 적용 시 고려할 점

- **데이터 정확성 확보**: SKU별 판매 및 재고 데이터가 정확해야 잘못된 판단을 막을 수 있습니다.
- **비즈니스 영향 평가**: 인기 상품이나 전략적 SKU를 실수로 제거하지 않도록, 영업팀과 긴밀히 협의하세요.
- **점진적 적용**: 한꺼번에 SKU를 대폭 줄이기보다는, 단계별로 모니터링하면서 조정하는 게 안전합니다.
- **자동화 도구 활용**: SAP, Oracle, Microsoft SCM 도구를 적극 활용해 데이터 분석과 의사결정을 지원하세요.

---

SKU 축소는 단순히 SKU 수를 줄이는 작업이 아니라, 재고 건강을 개선하고 SCM 시스템의 효율성을 극대화하는 중요한 전략입니다. Duluth Trading 사례처럼, 중간 수준 엔지니어가 데이터 분석과 도구 활용에 집중하면, 엔터프라이즈 계획 단계에서 큰 효과를 낼 수 있어요. 

처음엔 이게 별거 아닌 것 같지만, 실제로 SKU 하나하나를 꼼꼼히 들여다보고 정리해보면, 시스템이 훨씬 가볍고 예측 정확도가 눈에 띄게 좋아지는 걸 경험할 수 있을 겁니다.
