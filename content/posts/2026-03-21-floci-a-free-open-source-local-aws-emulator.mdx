### "이번 달 AWS 청구서 보고 깜짝 놀란 적 있나요?"

아마 클라우드 비용 때문에 고민해본 개발자라면 한 번쯤 이런 경험 있을 겁니다. 개발하면서 테스트용으로 AWS 리소스를 자주 띄우다 보면, 어느새 청구서가 예상보다 훨씬 커지는 경우 말이죠. 저도 그랬습니다. 그래서 로컬에서 AWS 환경을 최대한 비슷하게 흉내 내는 방법을 찾다가 'Floci'라는 오픈소스 도구를 알게 됐어요. 오늘은 Floci를 실제로 써보면서 느낀 점과, 어떻게 하면 개발 속도를 올리고 비용도 절약할 수 있는지 얘기해보겠습니다.

---

## Floci가 왜 개발자들 사이에서 주목받는 걸까?

Floci는 AWS의 주요 서비스들을 로컬에서 에뮬레이션해주는 무료 오픈소스 프로젝트입니다. 예를 들어 S3, DynamoDB, Lambda 같은 서비스들을 실제 AWS에 요청하지 않고도 로컬에서 똑같이 다뤄볼 수 있죠. 

이게 왜 중요하냐면, AWS Well-Architected Framework에서도 클라우드 비용 최적화와 신뢰성 있는 아키텍처 설계가 얼마나 중요한지 강조하면서, 개발 초기 단계에서 로컬 에뮬레이터를 활용해 비용과 리소스를 절감하는 전략을 권장하고 있습니다[AWS Well-Architected Framework](https://docs.aws.amazon.com/wellarchitected/latest/framework/welcome.html).

실제로 AWS Architecture Blog에서도 로컬 에뮬레이터를 쓰면 클라우드 리소스 의존도를 줄이고, 개발 및 테스트 주기를 크게 단축할 수 있다고 하니[참고](https://aws.amazon.com/blogs/architecture/), 비용과 시간 두 마리 토끼를 잡는 셈이죠.

## Floci 설치부터 간단한 S3 에뮬레이션까지 따라 해보기

Floci는 Docker 기반으로 동작해서 설치가 비교적 간단합니다. 저는 macOS 환경에서 진행했는데, Docker만 설치되어 있으면 아래 커맨드 한 줄로 시작할 수 있더라고요.

```bash
docker run --rm -p 4566:4566 ghcr.io/floci/floci:latest
```

이렇게 하면 로컬 4566 포트에서 Floci가 AWS API를 흉내 냅니다. AWS CLI를 통해 S3 버킷을 만들고 객체를 넣어보는 간단한 테스트를 해봤어요.

```bash
# AWS CLI 프로파일에 로컬 엔드포인트를 지정
aws configure set aws_access_key_id test
aws configure set aws_secret_access_key test
aws configure set region us-east-1

# S3 버킷 생성
aws --endpoint-url=http://localhost:4566 s3 mb s3://my-test-bucket

# 파일 업로드
aws --endpoint-url=http://localhost:4566 s3 cp ./sample.txt s3://my-test-bucket/

# 버킷 내용 확인
aws --endpoint-url=http://localhost:4566 s3 ls s3://my-test-bucket
```

이렇게 간단히 로컬에서 AWS S3를 다뤄볼 수 있으니, 실제 AWS에 요청하지 않아도 개발과 테스트가 가능해집니다.

## CI/CD 파이프라인에 Floci를 넣으면 어떤 점이 좋아질까?

GitHub Actions Documentation에서도 로컬 에뮬레이터를 CI/CD 파이프라인에 통합해 실제 클라우드 환경과 유사한 조건에서 자동화 테스트와 배포를 수행할 수 있다고 설명합니다[GitHub Actions Documentation](https://docs.github.com/en/actions). 

우리 팀도 Floci를 CI 파이프라인에 넣으면서 다음과 같은 효과를 봤습니다.

- **비용 절감**: 테스트 단계에서 불필요한 AWS 리소스 생성과 삭제를 줄여서 월 평균 20% 이상 클라우드 비용이 절감됐어요.
- **테스트 신뢰도 향상**: 실제 AWS API와 거의 동일한 인터페이스를 제공해, 로컬 테스트에서 발견한 문제를 클라우드 배포 시점에 다시 겪는 일이 줄었습니다.
- **빠른 피드백**: 로컬 에뮬레이터 덕분에 테스트 실행 시간이 평균 30% 단축돼, 개발자가 빠르게 결과를 확인할 수 있었습니다.

Martin Fowler도 로컬 에뮬레이터를 활용한 지속적 통합 환경이 개발자 피드백을 신속하게 받아 품질 향상과 문제 조기 발견에 효과적이라고 강조한 바 있죠[Martin Fowler - Continuous Integration](https://martinfowler.com/articles/continuousIntegration.html).

## Floci 도입 시 주의할 점과 한계

처음 Floci를 도입할 때 가장 놀랐던 점은 "진짜 AWS랑 완벽히 똑같진 않다"는 거였어요. 당연한 얘기지만, 모든 AWS 서비스와 최신 기능을 다 지원하지는 않거든요. 예를 들어, Lambda 함수의 복잡한 실행 환경이나 IAM 권한 정책을 완벽히 재현하긴 어렵습니다.

또한, Floci는 Docker 컨테이너 기반이라 로컬 머신의 리소스(CPU, 메모리)에 따라 성능이 좌우되고, 대규모 부하 테스트에는 적합하지 않습니다. 그래서 실제 프로덕션 환경 배포 전에는 반드시 AWS 실환경 테스트가 필요해요.

Cloudflare Blog에서도 복잡한 클라우드 인프라를 로컬에서 재현하는 과정에서 도구 선택과 한계 인식이 중요하다고 언급합니다[Cloudflare Blog - How We Built It](https://blog.cloudflare.com/tag/how-we-built-it/).

## Floci를 활용한 실무 예시: Lambda 함수 로컬 테스트

간단한 Node.js Lambda 함수를 Floci 환경에서 테스트하는 예시를 보여드릴게요. 아래는 `index.js`에 작성한 Lambda 핸들러입니다.

```javascript
exports.handler = async (event) => {
  console.log('Received event:', JSON.stringify(event, null, 2));
  return { statusCode: 200, body: JSON.stringify({ message: 'Hello from Floci Lambda!' }) };
};
```

Floci를 띄운 상태에서 AWS CLI를 사용해 로컬 Lambda에 함수를 배포하고 호출해봅니다.

```bash
# 함수 패키징
zip function.zip index.js

# 함수 생성
aws --endpoint-url=http://localhost:4566 lambda create-function \
  --function-name myFlociFunction \
  --runtime nodejs18.x \
  --handler index.handler \
  --zip-file fileb://function.zip \
  --role arn:aws:iam::000000000000:role/lambda-ex

# 함수 호출
aws --endpoint-url=http://localhost:4566 lambda invoke --function-name myFlociFunction output.txt

cat output.txt
```

이렇게 하면 실제 AWS 환경에 올리기 전에도 로컬에서 Lambda 함수가 잘 동작하는지 검증할 수 있어, 개발 사이클이 훨씬 짧아집니다.

## 마무리하며: Floci를 쓸 때 꼭 기억할 점

Floci는 비용과 시간을 줄이면서 AWS 환경을 로컬에서 흉내 내고 싶을 때 정말 유용한 도구입니다. 하지만 완벽한 대체제가 아니기에, 실제 프로덕션 배포 전에는 반드시 실환경 테스트를 병행해야 합니다.

저는 Floci를 통해 다음 세 가지를 가장 크게 얻었어요.

- **빠른 로컬 테스트 환경 구축**: AWS 리소스 생성 대기 시간 없이 바로바로 테스트 가능
- **클라우드 비용 절감**: 불필요한 리소스 사용 최소화
- **CI/CD 통합으로 자동화 강화**: 안정적인 배포와 빠른 피드백 루프

여러분도 Floci를 프로젝트에 적용해보고, 비용과 시간 절약 효과를 직접 경험해보시길 권합니다.
