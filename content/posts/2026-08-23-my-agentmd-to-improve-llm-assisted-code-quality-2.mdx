## LLM이 만들어준 코드, 믿고 쓸 수 있을까?

최근에 LLM(대형 언어 모델)을 활용해 코드를 자동 생성하는 일이 잦아졌는데요. 처음엔 신기하고 편했지만, 막상 프로젝트에 적용해보니 품질 관리가 쉽지 않더군요. "이 함수가 정말 의도한 대로 동작할까?" "코드 스타일이나 보안 문제는 없을까?" 이런 의문이 계속 들었어요. 그래서 저는 agent.md라는 도구를 도입해 LLM 기반 개발 워크플로우를 체계적으로 관리하기 시작했습니다.

이 글에서는 제가 agent.md를 어떻게 활용해서 코드 품질을 개선했는지, 그리고 어떤 점을 주의해야 하는지 공유하려고 해요. 실제 업무에 바로 써먹을 수 있는 팁과 코드 예시도 포함했습니다.

## agent.md가 LLM 코드 품질 관리에 딱인 이유

agent.md는 이름 그대로 ‘에이전트(Agent)’ 기반 작업을 문서화하고 설계하는 데 특화된 마크다운 포맷입니다. 단순한 문서가 아니라, LLM이 수행할 작업을 단계별로 쪼개고 명확한 역할을 부여해줍니다. 이게 왜 좋냐면, OpenAI API 문서에서도 강조하는 것처럼, LLM 활용 시 명확한 프롬프트 설계와 작업 분할이 오류를 줄이고 품질을 높이는 핵심 전략이거든요[OpenAI API Documentation](https://platform.openai.com/docs/overview).

예를 들어, 단순히 "이 코드를 고쳐줘"라고 묻는 대신, agent.md를 통해 "이 함수가 다음 조건을 만족하는지 검증하고, 보안 취약점은 없는지 점검해줘" 같은 구체적이고 단계적인 작업을 설계할 수 있습니다. Anthropic의 프롬프트 엔지니어링 가이드도 비슷한 맥락에서, LLM 응답을 제어하고 단계별 검토와 피드백 루프를 통해 품질을 높이는 방법론을 소개하고 있죠[Anthropic - Prompt Engineering Guide](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/overview).

즉, agent.md는 LLM이 생성한 코드를 그냥 받아들이는 게 아니라, 자동화된 코드 리뷰와 테스트, 개선 작업을 에이전트 단위로 분리해 관리할 수 있게 해줍니다.

## 내 워크플로우에 agent.md를 어떻게 녹였나

저는 보통 이렇게 씁니다. 먼저 LLM에게 맡길 작업을 크게 세 가지 에이전트로 나눠요.

- **코드 생성 에이전트**: 요구사항을 받아 실제 코드를 작성
- **코드 리뷰 에이전트**: 생성된 코드를 스타일, 보안, 성능 관점에서 검토
- **테스트 작성 에이전트**: 코드에 맞는 단위 테스트 코드를 작성

각 에이전트는 agent.md 문서 내에 명확한 역할과 작업 단계를 적어둡니다. 예를 들어, 코드 리뷰 에이전트는 아래처럼 정의할 수 있어요.

```markdown
# 코드 리뷰 에이전트

## 역할
- 생성된 코드를 읽고, 코드 스타일 가이드(PEP8 등) 준수 여부 확인
- 보안 취약점(예: SQL 인젝션, XSS) 탐지
- 성능 개선 가능성 제안

## 작업 단계
1. 코드를 분석해 스타일 위반 사항 목록 작성
2. 보안 취약점이 의심되는 부분 표시
3. 개선 사항을 포함한 리뷰 코멘트 작성
```

이걸 LLM에게 프롬프트로 넘기면, 단계별로 결과를 내고 피드백 루프를 돌릴 수 있죠. 실제로 이렇게 하니, 한 번에 코드 품질이 확실히 올라가는 걸 느꼈습니다.

## agent.md를 쓸 때 주의할 점, 그리고 한계

처음엔 agent.md 문서 작성이 귀찮게 느껴질 수 있어요. 에이전트별로 역할과 작업을 꼼꼼히 나누려면 시간이 좀 걸립니다. 하지만 이걸 안 하면 LLM이 막 생성한 코드를 그냥 쓰게 돼서, 나중에 버그나 품질 문제로 더 큰 시간을 잃을 수 있어요.

또한, 모든 작업을 LLM에 맡긴다고 해서 완벽한 코드를 기대하면 안 됩니다. 예를 들어, 복잡한 비즈니스 로직이나 도메인 특화된 규칙은 사람이 직접 리뷰하는 게 여전히 중요합니다. Martin Fowler도 에이전트 기반 시스템 설계가 유지보수성에 도움이 되지만, 설계가 복잡해질 수 있다고 경고합니다[Martin Fowler - Software Architecture Guide](https://martinfowler.com/architecture/).

마지막으로, agent.md와 LLM을 같이 쓴다고 해도 완전 자동화된 코드 리뷰 파이프라인을 구축하려면 추가적인 CI/CD 도구 연동과 테스트 자동화가 필요합니다. GitHub 엔지니어링 블로그 사례처럼, LLM 기반 자동화 도구를 기존 워크플로우와 잘 결합하는 게 핵심이죠[GitHub Engineering Blog](https://github.blog/category/engineering/).

## 실제 코드 예시: agent.md를 활용한 간단한 코드 리뷰 프롬프트

아래는 agent.md 문서 일부를 LLM 프롬프트로 변환해 자동 코드 리뷰를 요청하는 예시입니다. Python 코드 리뷰용으로 스타일과 보안 체크를 하도록 설계했어요.

```python
agent_md = '''
# 코드 리뷰 에이전트

## 역할
- Python 코드 스타일 검사 (PEP8 준수 여부)
- 보안 취약점 탐지 (예: 입력 검증 누락)

## 작업 단계
1. 코드 내 스타일 위반 사항 찾기
2. 잠재적 보안 문제 표시
3. 개선 제안 작성
'''

code_to_review = '''
def process_user_input(user_input):
    query = "SELECT * FROM users WHERE name = '" + user_input + "'"
    execute(query)
'''

prompt = f"""
다음 역할과 작업 단계에 따라 아래 코드를 리뷰해줘.
{agent_md}

코드:
{code_to_review}
"""

# OpenAI API 호출 예시 (의사 코드)
response = openai.ChatCompletion.create(
    model="gpt-4",
    messages=[{"role": "user", "content": prompt}],
    temperature=0
)

print(response.choices[0].message.content)
```

이렇게 하면 LLM이 SQL 인젝션 취약점(직접 문자열 결합)과 PEP8 스타일 문제를 찾아내고, 개선 방안을 제안해줍니다. 실제로 이 방식을 팀 내 코드 리뷰 자동화에 적용해 반복적인 실수를 줄였어요.

---

agent.md를 도입하고 나서 느낀 점은, LLM 기반 개발이 단순히 코드를 뽑아내는 걸 넘어서, 어떻게 체계적으로 관리하고 개선할지 고민하는 단계로 넘어갔다는 겁니다. 이 과정에서 agent.md 같은 명확한 작업 설계 문서가 큰 힘이 되더라고요.

만약 여러분도 LLM을 업무에 적극 활용 중이라면, 단순 프롬프트를 넘어서 agent.md를 통해 작업을 쪼개고 문서화해보세요. 처음엔 손이 가지만, 장기적으로 코드 품질과 개발 생산성 모두 확실히 올라갑니다.
