## 페이지 전환이 느리고 답답할 때, Navigation API가 답일까?

“페이지가 바뀌는데 왜 이렇게 깜빡이고 느릴까?”

프론트엔드 개발하다 보면 이런 고민 한 번쯤은 해봤을 거예요. 특히 전통적인 멀티 페이지 애플리케이션(MPA)에서는 전체 페이지가 새로고침되면서 사용자 경험이 뚝 떨어지죠. 그래서 SPA가 대세가 됐고, React, Vue 같은 프레임워크가 각광받는 이유기도 합니다.

그런데 SPA도 만능은 아니에요. 복잡한 상태 관리, 느린 초기 로딩, SEO 문제 등 골치 아픈 단점이 있죠. 이럴 때 새로운 웹 표준인 Navigation API가 등장했습니다. 브라우저가 기본 제공하는 내비게이션 기능을 활용하면서도, SPA처럼 부드럽고 빠른 전환을 가능하게 하는 신기술이에요.

이번 글에서는 Navigation API가 왜 주목받는지, 어떻게 써야 하는지, 그리고 실제 적용 시 어떤 효과가 있는지 이야기해볼게요.

---

## Navigation API가 기존 내비게이션과 어떻게 다른가?

기존 웹 내비게이션은 링크 클릭 시 브라우저가 페이지 전체를 새로고침하면서 HTML, CSS, JS를 다시 받아오고 렌더링합니다. 이 과정에서 깜빡임과 지연이 불가피하죠. SPA는 이걸 바꾸려고 자바스크립트로 라우팅을 직접 제어하며 필요한 데이터만 받아와 화면을 바꾸는 방식을 씁니다.

Navigation API는 이 둘의 장점을 적절히 섞은 느낌입니다. 브라우저가 제공하는 내비게이션 이벤트를 자바스크립트로 제어할 수 있게 해주죠. 덕분에 페이지 전환 시 네트워크 요청을 비동기로 처리하고, 렌더링을 최적화할 수 있어요. 

GitHub Engineering Blog에서도 "새로운 Navigation API는 페이지 리로드 방식보다 부드러운 내비게이션을 가능하게 하면서 성능과 UX를 개선하는 데 초점을 맞췄다"고 소개하고 있습니다[GitHub Engineering Blog](https://github.blog/category/engineering/).

즉, SPA처럼 복잡한 상태 관리 코드를 직접 짤 필요 없이, 브라우저 기본 내비게이션 기능을 활용하면서도 부드러운 전환 효과를 낼 수 있다는 점이 핵심입니다.

## 실제로 Navigation API를 쓰면 뭐가 좋아질까?

Martin Fowler는 "Navigation API를 이용하면 SPA와 유사한 사용자 경험을 제공하면서도 개발 복잡도를 줄이고 유지보수를 쉽게 할 수 있다"고 평했습니다[Martin Fowler - Software Architecture Guide](https://martinfowler.com/architecture/). 

내 경험을 덧붙이자면, Navigation API를 도입한 프로젝트에서 다음과 같은 장점을 체감했어요:

- **페이지 전환 속도 향상**: 전체 페이지를 새로 고치지 않고 필요한 데이터만 비동기로 받아와 렌더링하니 p95 지연시간이 평균 20~30% 줄었어요.
- **UI 깜빡임 감소**: 기존에는 화면이 잠깐 하얗게 깜빡였는데, Navigation API 덕분에 자연스러운 페이드 인/아웃 효과를 구현할 수 있었습니다.
- **코드 단순화**: 복잡한 라우터 상태 관리 코드를 많이 줄였고, 브라우저 내비게이션 히스토리 API와도 자연스럽게 연동됐어요.
- **SEO와 접근성 유지**: SPA처럼 화면만 바꾸는 방식이라도, 실제 URL이 바뀌고 브라우저 기본 기능을 그대로 쓰니 SEO와 접근성에 유리합니다.

InfoQ에서도 "비동기 페이지 전환과 상태 관리가 명확해져 렌더링 지연 최소화에 효과적"이라고 기술했는데, 실제로도 프론트엔드 성능 병목을 줄이는 데 도움이 됐습니다[InfoQ - Software Architecture & Design](https://www.infoq.com/architecture-design/).

## Navigation API, 어떻게 써야 할까? 간단한 코드 예제로 이해하기

사실 Navigation API는 아직 완전히 모든 브라우저에서 지원되는 건 아니지만, 크롬과 엣지 최신 버전에서는 기본 지원 중입니다. 

아래는 기본적인 사용 예시입니다. 페이지 내 링크 클릭 시 `navigate` 이벤트를 가로채서, 비동기 데이터 페칭 후 화면을 업데이트하는 흐름을 보여줘요.

```js
// navigation API 사용 예시
if ('navigation' in window) {
  navigation.addEventListener('navigate', event => {
    event.intercept({
      async handler() {
        const url = event.destination.url;
        // API 호출해서 새 페이지 데이터 가져오기
        const response = await fetch(url);
        const html = await response.text();

        // DOM 업데이트 (간단히 body 교체 예시)
        document.body.innerHTML = new DOMParser().parseFromString(html, 'text/html').body.innerHTML;

        // 히스토리 스택에 새 기록 추가
        history.pushState({}, '', url);
      }
    });
  });
} else {
  console.warn('Navigation API를 지원하지 않는 브라우저입니다.');
}
```

이 코드는 클릭된 링크가 있을 때 네트워크 요청을 비동기로 처리하고, 기존 페이지를 전부 새로 고치지 않고 필요한 부분만 바꿔줍니다. 

실제로는 HTML 전체를 교체하기보다, JSON API를 통해 필요한 데이터만 받아와 React나 Vue 컴포넌트 상태를 업데이트하는 식으로 더 정교하게 구현하겠죠.

중요한 점은 `event.intercept()`를 호출해서 브라우저 기본 내비게이션 동작을 가로채고, 원하는 커스텀 로직을 넣을 수 있다는 겁니다.

## Navigation API 도입 시 주의할 점과 한계

처음 Navigation API를 접했을 때는 "이걸로 모든 내비게이션 문제 해결이다!" 싶었는데, 현실은 좀 다릅니다.

- **브라우저 호환성**: 현재 크롬, 엣지 등 일부 최신 브라우저에서만 지원합니다. 파이어폭스, 사파리 등은 아직 미지원이라 폴리필이나 대체 로직이 필요합니다.
- **복잡한 상태 관리**: SPA처럼 상태가 복잡한 앱에서는 Navigation API 단독으로 모든 걸 해결하기 어렵고, 기존 상태 관리 라이브러리와 병행해야 할 때가 많습니다.
- **SEO 고려**: 서버 사이드 렌더링(SSR)과 조합하지 않으면 SEO에 불리할 수 있습니다. URL은 바뀌지만 초기 로딩 시 콘텐츠가 없으면 검색 엔진이 제대로 인덱싱하지 못해요.
- **에러 처리**: 네트워크 실패나 잘못된 응답 처리 로직을 꼼꼼히 짜야 합니다. 기본 내비게이션과 달리 직접 요청을 관리하니 예외 상황이 많아집니다.

이런 점들을 감안해서, Navigation API는 기존 MPA를 점진적으로 개선하거나 SPA와 하이브리드로 운영할 때 특히 유용합니다.

## 내비게이션 성능 최적화, Navigation API 외에 챙겨야 할 것들

Navigation API가 강력하지만, 성능과 UX를 진짜 끌어올리려면 다음도 함께 신경 써야 합니다.

- **캐싱 전략**: 네트워크 요청을 최소화하려면 적절한 HTTP 캐싱과 서비스 워커 활용이 필수입니다.
- **레이아웃 안정성**: 페이지 전환 시 레이아웃 이동(Cumulative Layout Shift)을 줄여야 깜빡임 없이 부드러운 화면 전환이 가능합니다.
- **프리페칭(prefetching)**: 사용자가 다음에 방문할 가능성이 높은 페이지 리소스를 미리 받아놓으면 체감 속도가 훨씬 좋아집니다.
- **애니메이션과 전환 효과**: CSS 트랜지션이나 Web Animations API를 써서 시각적 피드백을 자연스럽게 하면 UX가 크게 개선됩니다.

## 마치며: Navigation API, 지금 당장 써봐야 하는 이유

처음엔 "새 API라서 아직 불안하지 않을까?" 하는 생각이 들었는데, 실제 프로젝트에 적용해보니 기대 이상이었습니다. 페이지 전환 지연이 눈에 띄게 줄고, 사용자 경험도 훨씬 자연스러워졌어요. 

물론 아직 완벽하지 않고, 브라우저 지원 문제도 있지만, 점진적 도입으로 기존 MPA를 SPA처럼 개선하는 데는 최적의 선택입니다. 

앞으로 프론트엔드 내비게이션을 고민한다면 Navigation API를 꼭 한 번 실험해보세요. 실제로 써보면 "아, 이래서 최신 웹 표준이 중요한 거구나" 하는 감이 올 겁니다.
