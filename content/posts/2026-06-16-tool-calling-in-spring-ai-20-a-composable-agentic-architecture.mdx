### "AI 툴 여러 개를 한꺼번에 조합해서 쓰고 싶은데, 어떻게 구조를 짜야 할까?"

최근에 우리 팀에서 AI 기능을 백엔드에 통합하는 작업을 하면서 이 질문이 계속 머릿속을 맴돌았어요. 특히 Spring Boot 3.0 이상에서 공식 지원하는 Spring AI 2.0의 툴 호출 패턴을 적용해보니, 단순히 API 하나 호출하는 걸 넘어서 여러 AI 도구를 조합하는 에이전트 아키텍처를 어떻게 설계하고, 또 성능은 어떻게 최적화해야 하는지 체감할 수 있었죠.

이번 글에서는 제가 실제 프로젝트에서 겪은 경험을 바탕으로 Spring AI 2.0의 툴 호출을 조합하는 방법과, 성능 튜닝 포인트, 그리고 프롬프트 설계 팁까지 공유하려고 해요.

## Spring AI 2.0 툴 호출 패턴, 왜 모듈화가 중요한가

Spring Boot 3.0 이상부터 AI 통합을 위한 모듈화된 툴 호출 패턴이 공식 지원됩니다. 이게 왜 중요하냐면, 단일 AI API 호출로 끝나는 게 아니라, 여러 AI 도구(예: OpenAI, Anthropic Claude, 자체 ML 모델 등)를 조합해서 복잡한 워크플로우를 구성할 때 구조가 깔끔해지고 유지보수가 쉬워지거든요.

예를 들어, 고객 문의를 처리하는 챗봇을 만든다고 할 때, 간단한 질문은 OpenAI GPT-4로 처리하고, 민감한 개인정보 관련 질문은 별도의 검증 도구를 거치게 할 수도 있죠. 이런 복합 흐름을 한데 묶으려면 툴 호출을 에이전트처럼 조합하는 아키텍처가 필수입니다.

Spring Boot Reference Documentation에서 공식적으로도 이 패턴을 권장하고 있는데, 실제로 우리 팀도 이걸 도입하고 나서 코드가 훨씬 모듈화되고 테스트하기 쉬워졌어요[Spring Boot Reference Documentation](https://docs.spring.io/spring-boot/reference/).


## Spring Framework 코어 기술이 툴 호출 관리에 어떻게 도움을 주나

Spring Framework의 의존성 주입(DI)과 AOP(Aspect-Oriented Programming) 덕분에 AI 에이전트의 툴 호출을 효율적으로 관리할 수 있었어요. 의존성 주입 덕분에 각 AI 툴 클라이언트를 별도의 빈(bean)으로 등록하고, 필요에 따라 쉽게 교체하거나 확장할 수 있죠.

또 AOP를 활용하면 호출 전후에 로깅, 인증, 성능 모니터링 같은 공통 관심사를 한 곳에서 처리할 수 있어서, 툴 호출 코드가 훨씬 깔끔해집니다. 예를 들어, OpenAI API 호출 시 요청/응답을 자동으로 기록하거나, 실패 시 재시도 로직을 AOP로 분리해두면 코드 중복도 줄고 유지보수성이 좋아집니다.

이런 설계 덕분에 우리 팀이 AI 툴을 추가하거나 교체할 때 서비스 전체를 건드리지 않고도 빠르게 대응할 수 있었어요[Spring Framework - Core Technologies](https://docs.spring.io/spring-framework/reference/core.html).


## 실제 코드로 보는 Spring AI 2.0 툴 호출 조합 예시

아래는 OpenAI GPT-4와 자체 문서 검색 도구를 조합해서 질문에 답하는 간단한 에이전트 구현 예시입니다. 핵심은 두 개 이상의 툴을 `@Component`로 분리하고, 서비스에서 이들을 조합해 호출하는 구조예요.

```java
@Component
public class OpenAiTool {
    private final WebClient webClient;

    public OpenAiTool(WebClient.Builder webClientBuilder) {
        this.webClient = webClientBuilder.baseUrl("https://api.openai.com/v1").build();
    }

    public Mono<String> ask(String prompt) {
        // 간단히 POST 요청 보내고, 응답에서 텍스트 추출
        return webClient.post()
                .uri("/chat/completions")
                .header("Authorization", "Bearer " + System.getenv("OPENAI_API_KEY"))
                .bodyValue(Map.of(
                    "model", "gpt-4",
                    "messages", List.of(Map.of("role", "user", "content", prompt))
                ))
                .retrieve()
                .bodyToMono(JsonNode.class)
                .map(json -> json.at("/choices/0/message/content").asText());
    }
}

@Component
public class DocumentSearchTool {
    public Mono<String> search(String query) {
        // 내부 문서 검색 로직
        return Mono.just("검색 결과: ...");
    }
}

@Service
public class AiAgentService {
    private final OpenAiTool openAiTool;
    private final DocumentSearchTool documentSearchTool;

    public AiAgentService(OpenAiTool openAiTool, DocumentSearchTool documentSearchTool) {
        this.openAiTool = openAiTool;
        this.documentSearchTool = documentSearchTool;
    }

    public Mono<String> answerQuestion(String question) {
        // 질문이 특정 키워드를 포함하면 문서 검색 후 답변 생성
        if (question.contains("문서")) {
            return documentSearchTool.search(question)
                    .flatMap(result -> openAiTool.ask("다음 문서 내용을 참고해서 답변해줘: " + result));
        }
        return openAiTool.ask(question);
    }
}
```

위 예시처럼 각 툴을 독립된 컴포넌트로 관리하면, 새로운 AI 툴이 생겨도 `AiAgentService`에만 로직을 추가하면 되니 확장성이 좋습니다.


## 대규모 AI 백엔드에서 꼭 챙겨야 할 성능 최적화 포인트

툴 호출이 많아지면 성능 이슈가 불가피한데요, Spring Boot 애플리케이션에서 AI 툴 호출 성능을 최적화하려면 다음 요소들을 꼭 고려해야 합니다.

- **스레드 풀 설정**: 비동기 호출을 많이 하니, 기본 스레드 풀 크기를 서비스 특성에 맞게 조정해야 해요. 너무 작으면 병목, 너무 크면 오버헤드 발생합니다.
- **캐싱 전략**: 동일 질문에 대해 AI 응답이 자주 중복된다면, Redis 같은 외부 캐시를 활용해 호출 횟수를 줄이는 게 효과적입니다.
- **비동기 처리**: WebClient 같은 논블로킹 HTTP 클라이언트를 적극 활용해 I/O 대기 시간을 최소화하세요.
- **타임아웃과 재시도 정책**: OpenAI API 같은 외부 호출은 네트워크 이슈가 있을 수 있으니 적절한 타임아웃과 재시도 로직을 꼭 넣어야 안정적입니다.

이런 부분들은 Baeldung의 Spring Boot 성능 튜닝 가이드에서 자세히 다루는데, 우리 팀도 스레드 풀을 기본 10개에서 50개로 늘리고, 캐시 TTL을 5분으로 설정해서 호출량 3배 증가에도 안정적으로 대응할 수 있었어요[Baeldung - Spring Boot Performance Tuning](https://www.baeldung.com/spring-boot-performance).


## 프롬프트 설계가 AI 툴 조합의 성공을 좌우한다

툴 호출이 아무리 잘 돼도 AI가 엉뚱한 답변을 하면 의미가 없죠. Anthropic의 프롬프트 엔지니어링 가이드에 따르면, AI 에이전트가 여러 툴을 조합할 때는 각 툴에 맞는 명확하고 구체적인 프롬프트를 설계하는 게 핵심입니다[Anthropic - Prompt Engineering Guide](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/overview).

예를 들어, 문서 검색 결과를 AI가 참고할 땐 "다음 내용을 참고해서 답변해줘" 같은 명령문을 명확히 넣어야 하고, 불확실한 정보는 "모르는 경우 솔직히 모른다고 답변해줘" 같은 조건도 넣으면 답변 정확도가 올라갑니다.

우리 팀에서는 프롬프트를 JSON 포맷으로 관리하면서, 각 툴별로 템플릿을 분리해뒀는데, 덕분에 새로운 AI 모델이 추가돼도 프롬프트만 교체하면 돼서 운영이 훨씬 편해졌어요.


## 마무리하며: Spring AI 2.0 툴 호출 조합, 이렇게 시작해보세요

- Spring Boot 3.0 이상에서 제공하는 모듈화된 툴 호출 패턴을 적극 활용해보세요. 각 AI 툴을 독립 컴포넌트로 관리하면 복잡한 워크플로우도 깔끔하게 설계할 수 있습니다.
- Spring DI와 AOP를 활용해 공통 관심사를 분리하고, 확장성과 유지보수성을 높이세요.
- 성능 최적화는 스레드 풀, 캐싱, 비동기 처리, 타임아웃 설정이 핵심입니다. 실제 운영 환경에서 부하 테스트를 꼭 해보세요.
- 프롬프트 설계에 공을 들이세요. AI가 여러 툴을 조합해서 작업할 때는 명확하고 구체적인 지시가 성공의 열쇠입니다.

처음에는 툴 호출을 단순히 API 하나 호출하는 수준으로 생각했는데, 실제로 여러 AI 도구를 조합하는 에이전트 아키텍처를 구현해보니, 설계와 튜닝의 중요성을 몸소 느꼈습니다. 여러분도 Spring AI 2.0을 시작점으로 복잡한 AI 백엔드 통합을 한 단계 업그레이드해보시길 바랍니다.

추가로, 배포 전에는 성능과 안정성뿐 아니라 로그 품질까지 확인해야 합니다. 에러 로그가 충분히 구조화되어 있지 않으면 원인 분석 시간이 길어지고, 같은 장애가 반복될 가능성이 높아집니다. 배포 후 24시간 관찰 구간에서 경보 임계치를 임시로 강화해 두는 것도 실무에서 자주 쓰는 방법입니다.
