## Spring Boot 3 업그레이드, 왜 이렇게 신경 써야 할까?

얼마 전 우리 팀에서 Spring Boot 2.x에서 3.x로 업그레이드를 진행했는데, 생각보다 복잡한 부분이 많더라고요. 가장 큰 변화는 Java 17 이상이 필수라는 점이었어요. 기존에 Java 11로 돌리던 서비스가 많아서, JDK 버전부터 맞춰야 했죠. 게다가 Spring Boot Reference 문서에서 안내하는 호환성 이슈도 꼼꼼히 체크하지 않으면, 배포 후에 서비스가 엉망이 될 수도 있겠더라고요[Spring Boot Reference Documentation](https://docs.spring.io/spring-boot/reference/).

저도 처음에는 "그냥 라이브러리 버전 올리면 되겠지"라고 생각했는데, 실제로는 Deprecated된 API, 기본 설정 변경, 그리고 새로운 기능들이 많아서 코드 수정과 테스트에 꽤 시간을 썼습니다. 특히, Spring Data JPA나 WebFlux 같은 모듈은 내부 동작 방식이 조금씩 바뀌어서, 기존 코드가 깨지는 경우가 있었어요.

## JVM 튜닝과 커넥션 풀 설정, 프로덕션에서 놓치면 안 되는 부분

업그레이드만큼 중요한 게 프로덕션 환경에서의 성능 최적화입니다. Baeldung의 튜닝 가이드를 참고해서 JVM 옵션을 조정하고, HikariCP 커넥션 풀 설정을 꼼꼼히 손봤어요[Baeldung - Spring Boot Performance Tuning](https://www.baeldung.com/spring-boot-performance).

예를 들어, 기본 힙 메모리 설정을 `-Xms4g -Xmx4g`로 고정하고, GC는 G1GC로 바꿨습니다. GC pause가 줄어들면서 응답 지연이 눈에 띄게 개선됐어요. 커넥션 풀은 `maximumPoolSize`를 50으로 늘렸고, `connectionTimeout`은 3000ms로 설정했더니 DB 커넥션 부족 현상이 거의 사라졌습니다.

캐싱도 Redis를 적극 활용했는데, 자주 조회되는 데이터는 TTL을 10분 정도로 잡아서 DB 부하를 줄였어요. 이런 세밀한 조정이 결국 서비스 안정성과 직결되더라고요.

## DI와 AOP로 보안과 유지보수성 높이기

Spring Framework의 핵심 기술인 DI(Dependency Injection)와 AOP(Aspect-Oriented Programming)를 활용하면 보안 강화와 코드 유지보수가 훨씬 수월해집니다[Spring Framework - Core Technologies](https://docs.spring.io/spring-framework/reference/core.html).

예를 들어, 인증과 권한 검증 로직을 AOP로 분리해서 서비스 코드에 직접 섞이지 않도록 했어요. 이렇게 하면 보안 정책 변경 시 한 곳만 수정하면 되니 유지보수가 훨씬 편해집니다. 코드 예시를 하나 보여드릴게요:

```java
@Aspect
@Component
public class SecurityAspect {

    @Before("@annotation(RequiresRole) && @annotation(roleAnnotation)")
    public void checkRole(JoinPoint joinPoint, RequiresRole roleAnnotation) {
        String requiredRole = roleAnnotation.value();
        Authentication auth = SecurityContextHolder.getContext().getAuthentication();
        if (auth == null || !auth.getAuthorities().stream()
                .anyMatch(a -> a.getAuthority().equals(requiredRole))) {
            throw new AccessDeniedException("권한이 없습니다.");
        }
    }
}

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
public @interface RequiresRole {
    String value();
}
```

이렇게 하면 컨트롤러나 서비스 메서드에 `@RequiresRole("ROLE_ADMIN")` 같은 어노테이션만 붙이면 권한 체크가 자동으로 됩니다. 처음엔 이게 별거 아닌 것 같지만, 프로젝트가 커질수록 보안 로직이 여기저기 흩어지는 걸 막아줘서 정말 유용해요.

## 오픈소스 보안 취약점, 자동 탐지와 빠른 패치 배포가 생명

대규모 오픈소스 프로젝트에서 보안 취약점을 관리하는 게 얼마나 중요한지는 말할 것도 없죠. GitHub Engineering Blog에서 소개한 사례를 보면, 보안 취약점 자동 탐지 시스템과 신속한 패치 배포 프로세스를 도입해서 위험을 최소화하는 전략을 택하고 있어요[GitHub Engineering Blog](https://github.blog/category/engineering/).

우리도 비슷한 시스템을 도입했는데, 예를 들어 Dependabot을 활용해 의존성 라이브러리의 취약점을 자동으로 감지하고 PR을 생성하게 했어요. 그리고 CI/CD 파이프라인에 보안 스캔 단계를 추가해서, 취약점이 발견되면 바로 빌드가 실패하도록 했죠.

이 과정에서 가장 힘들었던 건 "업데이트가 서비스 중단 없이 안전하게 배포되도록 하는 것"이었는데, 마틴 파울러의 아키텍처 가이드에서 권장하는 점진적 업그레이드와 롤백 전략을 참고했습니다[Martin Fowler - Software Architecture Guide](https://martinfowler.com/architecture/).

예를 들어, Canary 배포를 통해 일부 인스턴스에만 새 버전을 먼저 적용하고, 문제가 없으면 점차 전체로 확대하는 방식을 썼어요. 만약 문제가 생기면 즉시 롤백해서 다운타임 없이 대응할 수 있었습니다.

## 클라우드 환경에서 네트워크 보안과 분산 트래픽 관리도 빼놓을 수 없다

Cloudflare Blog 사례를 보면, 클라우드 기반 인프라에서 Spring 백엔드 시스템을 운영할 때 네트워크 보안 강화와 분산 트래픽 관리가 핵심이라고 합니다[Cloudflare Blog - How We Built It](https://blog.cloudflare.com/tag/how-we-built-it/).

우리도 AWS 환경에서 WAF(Web Application Firewall)를 적용하고, API Gateway에서 요청을 필터링하는 방식을 도입했어요. 그리고 트래픽이 갑자기 몰릴 때 대비해서 로드 밸런서와 오토스케일링 정책을 꼼꼼히 설정했습니다.

이런 다층 보안과 트래픽 관리 전략 덕분에 DDoS 공격이나 비정상 트래픽에도 서비스가 안정적으로 유지됐습니다.

### 정리하며

- Spring Boot 3 업그레이드는 Java 17 이상 필수, 호환성 체크는 꼭 해야 한다.
- JVM 옵션과 커넥션 풀, 캐싱 전략을 프로덕션 환경에 맞게 튜닝하면 성능이 크게 개선된다.
- DI와 AOP를 활용해 보안 로직을 분리하면 유지보수성과 보안성이 동시에 올라간다.
- OSS 보안 취약점은 자동 탐지 시스템과 신속한 패치 배포가 관건이며, 점진적 롤아웃과 롤백 전략을 반드시 준비해야 한다.
- 클라우드 환경에서는 네트워크 보안과 분산 트래픽 관리에 투자해야 서비스 안정성을 확보할 수 있다.

업그레이드와 보안 강화는 한 번에 끝나는 작업이 아니고, 계속해서 모니터링하고 개선해야 하는 과정입니다. 하지만 제대로 준비하고 실행하면, 서비스 안정성과 개발 생산성 모두 크게 향상됩니다.
