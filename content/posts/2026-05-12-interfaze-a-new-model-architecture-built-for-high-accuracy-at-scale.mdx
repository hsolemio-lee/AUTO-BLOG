# Interfaze 모델 아키텍처, 프론트엔드에서 어떻게 다르게 접근했나

"왜 우리 UI는 점점 느려질까?" 이 질문, 한 번쯤 해본 적 있죠? 저도 Interfaze 모델 아키텍처를 구현하면서 이 문제와 씨름했습니다. 대규모 데이터와 높은 정확도를 동시에 잡아야 하는 상황에서, 프론트엔드가 병목이 되면 전체 서비스 경험이 무너집니다. 그래서 이번 글에서는 Interfaze의 프론트엔드 구현에서 실제로 적용한 성능 최적화와 UX 품질 개선, 그리고 확장 가능한 컴포넌트 아키텍처를 중점적으로 이야기해보려 합니다.

## 컴포넌트 기반 아키텍처가 중급 개발자에게 주는 힘

Interfaze 프로젝트 초기에 가장 먼저 손댄 부분은 컴포넌트 구조였습니다. 단일 페이지에 수십 개 UI 요소가 얽히다 보니, 유지보수가 점점 힘들어지더군요. 그래서 GitHub Engineering Blog에서 강조하는 컴포넌트 기반 아키텍처를 적극 도입했습니다. 이 아키텍처 덕분에 UI 재사용성이 크게 향상됐고, 코드 중복도 줄었죠[GitHub Engineering Blog](https://github.blog/category/engineering/).

예를 들어, 사용자 프로필 카드 컴포넌트를 만들어 여러 화면에서 재활용했는데, 이 컴포넌트에 상태 관리 로직을 잘 분리해 넣으니 변경 사항이 생겨도 해당 컴포넌트만 고치면 되더군요. 중급 개발자 입장에선 이게 정말 큰 힘이 됩니다. 복잡한 상태를 한 곳에 모으고, UI는 최대한 단순하게 유지하는 게 핵심이었어요.

```jsx
// UserProfileCard.jsx
import React, { useState, useEffect } from 'react';

function UserProfileCard({ userId }) {
  const [userData, setUserData] = useState(null);

  useEffect(() => {
    let isMounted = true;
    fetch(`/api/users/${userId}`)
      .then(res => res.json())
      .then(data => {
        if (isMounted) setUserData(data);
      });
    return () => { isMounted = false; };
  }, [userId]);

  if (!userData) return <div>Loading...</div>;

  return (
    <div className="user-profile-card">
      <img src={userData.avatar} alt={`${userData.name} avatar`} />
      <h3>{userData.name}</h3>
      <p>{userData.bio}</p>
    </div>
  );
}

export default UserProfileCard;
```

이 컴포넌트는 사용자 ID만 바뀌면 자동으로 데이터를 불러와 렌더링합니다. 비동기 처리와 상태 분리가 잘 되어 있어, 다른 컴포넌트에 영향을 주지 않고 독립적으로 유지할 수 있었죠.

## 비동기 데이터 처리와 지연 로딩으로 UX 품질 높이기

Interfaze는 대규모 데이터를 실시간으로 처리해야 하다 보니, 모든 데이터를 한꺼번에 불러오면 초기 로딩이 너무 길어졌습니다. 그래서 GitHub Engineering Blog에서 제안하는 비동기 데이터 처리와 lazy loading 패턴을 적극 활용했어요[GitHub Engineering Blog](https://github.blog/category/engineering/).

예를 들어, 사용자 피드(feed)를 20개씩 쪼개서 불러오고, 사용자가 스크롤할 때마다 다음 20개를 비동기로 요청하는 식입니다. 이렇게 하면 초기 로딩 시간을 3초에서 1.2초로 줄일 수 있었고, 실제 사용자 체감 속도도 크게 개선됐죠.

```jsx
// FeedList.jsx
import React, { useState, useEffect } from 'react';

function FeedList() {
  const [feeds, setFeeds] = useState([]);
  const [page, setPage] = useState(1);
  const [loading, setLoading] = useState(false);

  useEffect(() => {
    setLoading(true);
    fetch(`/api/feeds?page=${page}&limit=20`)
      .then(res => res.json())
      .then(newFeeds => {
        setFeeds(prev => [...prev, ...newFeeds]);
        setLoading(false);
      });
  }, [page]);

  const handleScroll = () => {
    if (window.innerHeight + window.scrollY >= document.body.offsetHeight - 500 && !loading) {
      setPage(prev => prev + 1);
    }
  };

  useEffect(() => {
    window.addEventListener('scroll', handleScroll);
    return () => window.removeEventListener('scroll', handleScroll);
  }, [loading]);

  return (
    <div>
      {feeds.map(feed => (
        <div key={feed.id} className="feed-item">
          {feed.content}
        </div>
      ))}
      {loading && <p>Loading more...</p>}
    </div>
  );
}

export default FeedList;
```

이 패턴은 UX 품질을 높이는 데 정말 효과적이었어요. 사용자가 느끼는 지연 시간이 줄어들면서, 인터랙션이 훨씬 부드러워졌거든요.

## 마이크로서비스 아키텍처와 프론트엔드 경계 설정의 중요성

Interfaze처럼 대규모 애플리케이션에서는 프론트엔드와 백엔드가 명확하게 분리되어야 합니다. Martin Fowler가 설명한 마이크로서비스 아키텍처를 참고해, 프론트엔드와 백엔드 간 경계를 엄격히 나누고 각 서비스별 독립 배포가 가능하도록 설계했죠[Martin Fowler - Microservices](https://martinfowler.com/articles/microservices.html).

이 덕분에 프론트엔드 팀은 UI 개선과 성능 최적화에 집중할 수 있었고, 백엔드 팀은 모델 정확도와 데이터 처리량 향상에 전념할 수 있었습니다. 서로의 변경 사항이 충돌하지 않으니 개발 속도도 빨라졌죠.

또한, 각 서비스가 독립적으로 확장 가능해져서 트래픽 급증 시에도 한쪽만 스케일 아웃하면 돼 비용 효율적이었습니다. 이런 분리 덕분에 Interfaze가 높은 정확도와 대규모 처리량을 동시에 달성할 수 있었던 것 같아요.

## 클라우드 디자인 패턴으로 컴포넌트 확장성과 복원력 확보하기

마지막으로, 클라우드 기반 디자인 패턴을 적용해 프론트엔드 컴포넌트의 확장성과 복원력을 높인 사례를 공유할게요. Microsoft에서 소개하는 패턴을 참고해, 캐싱, 큐, 서킷 브레이커 같은 기법을 적용했습니다[Microsoft - Cloud Design Patterns](https://learn.microsoft.com/en-us/azure/architecture/patterns/).

예를 들어, 사용자 세션 정보를 로컬 스토리지와 서버 캐시를 조합해 관리하면서, 네트워크 지연이나 서버 장애 시에도 UI가 무너지지 않도록 했죠. 또, API 요청 실패 시 자동 재시도 로직과 서킷 브레이커를 넣어 서비스 복원력을 강화했습니다.

이런 패턴 덕분에 대규모 사용자 트래픽이 몰려도 UI가 버벅임 없이 안정적으로 동작했고, 장애 발생 시 빠른 복구가 가능했어요. 클라우드 환경에서 프론트엔드도 단순한 정적 페이지가 아니라, 복잡한 상태를 견뎌내는 탄탄한 시스템임을 다시 한 번 느꼈습니다.

## 마무리하며: Interfaze 프론트엔드에서 꼭 기억할 점

Interfaze 프로젝트를 하면서 배운 건, 단순히 코드만 잘 짜는 게 아니라 아키텍처와 패턴을 잘 설계하는 게 더 중요하다는 점이었어요. 특히 중급 개발자라면 아래 세 가지를 꼭 챙기길 추천합니다.

- **컴포넌트 기반 설계로 재사용성과 유지보수성 확보하기**: UI 요소를 작고 독립적으로 쪼개고, 상태 관리를 명확히 분리하세요.
- **비동기 처리와 지연 로딩으로 UX 체감 속도 높이기**: 초기 로딩 부담을 줄이고, 사용자 인터랙션이 끊기지 않도록 하세요.
- **마이크로서비스와 클라우드 패턴으로 확장성과 복원력 갖추기**: 프론트엔드도 독립된 서비스로 보고, 장애 대응과 스케일링 전략을 미리 세우는 게 중요합니다.

처음엔 이게 별거 아닌 것 같지만, 실제로 대규모 서비스를 운영하다 보면 이 차이가 서비스 품질과 개발 생산성에 엄청난 영향을 미칩니다. Interfaze처럼 높은 정확도와 대규모 처리량을 요구하는 환경에서 프론트엔드가 무너지면 전체가 무너지는 거니까요.

앞으로도 이런 경험을 바탕으로 더 나은 프론트엔드 아키텍처와 최적화 방법을 계속 공유할게요. 혹시 궁금한 점이나 경험 공유하고 싶은 부분 있으면 언제든 댓글로 알려주세요!
