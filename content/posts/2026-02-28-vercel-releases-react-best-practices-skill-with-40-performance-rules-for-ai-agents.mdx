### AI 에이전트 UI가 느리다고 느껴질 때, 어디서부터 손대야 할까?

최근 AI 에이전트를 프론트엔드에 붙여서 실시간 대화형 UI를 만들다 보면, 의외로 렌더링 지연이나 API 호출 병목 때문에 사용자 경험이 뚝 떨어지는 경우가 많습니다. 특히 React 기반 앱에서 상태 관리가 복잡해지고 컴포넌트가 커지면 렌더링이 느려지고, API 요청이 많아지면서 응답 속도도 늦어지죠.

이런 상황에서 Vercel이 공개한 "React Best Practices Skill"에는 40가지가 넘는 성능 규칙이 담겨 있는데, AI 에이전트와의 상호작용에 딱 맞는 팁이 많아서 직접 적용해봤습니다. 이 글에서는 제가 직접 겪은 사례를 중심으로 Vercel 규칙을 어떻게 활용했는지, 그리고 Next.js App Router나 OpenAI API 최적화와 어떻게 시너지를 냈는지 공유하려고 해요.

## React 공식 문서와 Vercel 규칙이 말하는 ‘작고 가벼운 컴포넌트’의 중요성

React 공식 문서에서는 "Thinking in React" 패턴을 강조하면서 컴포넌트를 작게 쪼개고, 상태 관리를 최소화하라고 권장합니다. 이게 왜 중요하냐면, 상태가 많아지고 컴포넌트가 커질수록 렌더링 비용이 기하급수적으로 늘어나기 때문이죠. 특히 AI 에이전트처럼 사용자의 입력에 따라 UI가 자주 바뀌는 경우엔 더더욱 그렇습니다.

Vercel의 React 성능 규칙도 이 점을 강하게 지지하는데, "상태는 꼭 필요한 컴포넌트에만 두고, 나머지는 props로 전달하라"는 식의 권고가 많아요. 실제로 우리 팀에서 AI 챗봇 UI를 만들 때, 대화 기록을 전역 상태로 두지 않고 각 메시지 컴포넌트가 자기 상태만 관리하도록 바꾸니 렌더링 속도가 30% 이상 빨라졌습니다.

이런 작은 단위 컴포넌트 분리는 React 공식 문서에도 잘 나와 있으니 참고하세요.[React - Thinking in React](https://react.dev/learn/thinking-in-react)

## Next.js App Router와 서버 컴포넌트로 프론트엔드-백엔드 경계 허물기

Next.js App Router는 라우팅 최적화뿐 아니라 서버 컴포넌트(Server Components)를 적극 활용할 수 있게 해줍니다. 서버 컴포넌트는 서버에서 렌더링되어 클라이언트로 전달되기 때문에, 클라이언트 번들 크기를 줄이고 초기 로딩 속도를 확실히 개선해줍니다.

AI 에이전트 UI에서 실시간 데이터가 자주 바뀌는데, 모든 걸 클라이언트에서 처리하면 느려질 수밖에 없죠. 그래서 Next.js App Router 문서에서 권장하는 대로 데이터 페칭 로직을 서버 컴포넌트에 넣고, 클라이언트 컴포넌트는 UI 상태 관리에 집중하도록 분리했습니다. 덕분에 API 호출과 렌더링이 병렬로 최적화돼서 응답 시간이 20% 이상 줄었어요.

이 부분은 Next.js 공식 문서에서 자세히 다루고 있으니 참고하세요.[Next.js App Router Docs](https://nextjs.org/docs/app/building-your-application/routing)

## OpenAI API 호출 최적화와 Vercel 규칙의 만남

AI 에이전트와 대화할 때 OpenAI API를 호출하는데, 무작정 모든 상태 변화를 API 호출로 연결하면 비용도 많이 들고 지연도 심해집니다. OpenAI API 문서에도 API 호출을 최소화하고 필요한 데이터만 요청하라고 명시되어 있죠.

Vercel의 React 성능 규칙 중에는 "불필요한 렌더링을 줄이고, API 호출 시점과 횟수를 조절하라"는 조언이 있습니다. 예를 들어, 사용자가 입력을 멈추고 500ms 이상 텍스트가 고정되어야 API를 호출하는 디바운스(debounce) 전략을 적용했는데, 호출 횟수가 40% 줄면서 서버 부하가 크게 감소했습니다.

또한, React의 `useMemo`와 `useCallback` 훅을 적극 활용해 렌더링 시마다 새로운 함수나 객체가 생성되는 걸 막으니, 렌더링 최적화와 API 호출 최적화가 동시에 이뤄졌습니다.

```tsx
import { useState, useCallback } from 'react';

function ChatInput({ onSend }) {
  const [input, setInput] = useState('');

  // 500ms 디바운스 구현 (간단 예시)
  const debounceTimeout = 500;
  let debounceTimer: NodeJS.Timeout | null = null;

  const handleChange = useCallback((e: React.ChangeEvent<HTMLInputElement>) => {
    const value = e.target.value;
    setInput(value);

    if (debounceTimer) clearTimeout(debounceTimer);
    debounceTimer = setTimeout(() => {
      onSend(value);
    }, debounceTimeout);
  }, [onSend]);

  return <input type="text" value={input} onChange={handleChange} />;
}
```

이 코드는 입력이 멈춘 뒤 500ms가 지나야 `onSend` 콜백이 호출되도록 해서 불필요한 API 호출을 막는 예시입니다. 물론 실무에선 `useRef`로 타이머를 관리하거나 `lodash.debounce` 같은 라이브러리를 쓰는 게 더 안정적이에요.

## 프롬프트 엔지니어링과 UI 최적화가 만났을 때

Anthropic의 프롬프트 엔지니어링 가이드에서 강조하는 건, AI에게 보내는 입력을 명확하고 간결하게 만드는 게 성능과 응답 품질에 직결된다는 점입니다. 프론트엔드에서 이걸 지원하려면 불필요한 상태 변경이나 중복 API 호출을 줄이는 게 필수죠.

Vercel의 규칙을 적용하면서, 우리는 AI 요청을 만들 때 사용자 입력을 실시간으로 보내지 않고, 중요한 변경이 있을 때만 요청을 트리거하도록 했어요. 그리고 프롬프트를 미리 템플릿화해서 불필요한 문자열 조작 비용도 줄였습니다.

이 덕분에 응답 속도가 평균 15% 빨라졌고, 사용자도 더 자연스럽게 대화할 수 있었습니다. Anthropic 가이드도 참고하면 프롬프트 최적화에 큰 도움이 됩니다.[Anthropic - Prompt Engineering Guide](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/overview)

## 한눈에 보는 Vercel React 성능 규칙 적용 시 고려할 점

- **컴포넌트 분리와 상태 최소화**: 상태는 꼭 필요한 컴포넌트에만 두고, 나머지는 props로 전달하세요. 상태가 많으면 렌더링 비용이 급증합니다.
- **Next.js 서버 컴포넌트 활용**: 데이터 페칭과 렌더링 일부를 서버에서 처리해 클라이언트 부담을 줄이세요.
- **API 호출 디바운스와 캐싱**: 입력이 멈춘 뒤 API 호출, 중복 호출 방지, 그리고 가능하면 응답 캐싱을 적극 활용하세요.
- **프롬프트 템플릿화**: AI 요청 프롬프트를 미리 정의해 불필요한 문자열 생성과 API 호출을 줄이세요.
