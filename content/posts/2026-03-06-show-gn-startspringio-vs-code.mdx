### VS Code에서 스프링 부트 프로젝트 시작, 왜 아직도 웹 브라우저를 쓰고 있나요?

"아, 또 start.spring.io 들어가서 프로젝트 생성하고 압축 풀고..." 이런 경험, 다들 한 번쯤 있죠? 저도 그랬습니다. 근데 어느 순간 VS Code 안에 start.spring.io가 통째로 들어온 걸 알게 됐어요. 이걸 쓰고 나니까 한 3분 만에 새 프로젝트가 뚝딱 만들어지더라고요. 그래서 오늘은 이걸 어떻게 쓰는지, 그리고 왜 이렇게 좋은지 실제 경험과 함께 풀어볼까 합니다.


## VS Code 내에서 start.spring.io 통합, 뭐가 좋은가?

우선 start.spring.io는 스프링 부트 프로젝트를 생성하는 공식 웹 서비스입니다. 여기에 의존성, 빌드 도구, 자바 버전 등 설정을 선택하면 표준화된 프로젝트 구조를 만들어주죠. 근데 보통은 웹 브라우저에서 열고, 설정하고, 다운로드 받고, 압축 풀고, IDE에서 열고... 이 과정이 꽤 번거롭습니다.

VS Code 확장으로 start.spring.io를 통합하면, 이 모든 과정이 IDE 안에서 끝나요. 터미널이나 브라우저를 따로 띄울 필요 없이, GUI로 의존성 선택부터 빌드 툴 설정까지 직관적으로 할 수 있습니다. 덕분에 초기 설정 시간이 50% 이상 줄어드는 느낌이에요. 실제로 Spring Boot 공식 문서에서도 IDE 내 통합이 초기 설정 시간을 크게 단축한다고 명시하고 있습니다[Spring Boot Reference Documentation](https://docs.spring.io/spring-boot/reference/).


## start.spring.io VS Code 확장 설치와 첫 프로젝트 생성하기

제가 쓰는 VS Code 버전은 1.75인데, 확장 설치는 간단합니다. 마켓플레이스에서 'Spring Initializr'라고 검색해서 설치하면 끝이에요. 설치 후엔 명령 팔레트(Ctrl+Shift+P)에서 `Spring Initializr: Generate a Maven Project` 같은 명령어를 쓸 수 있습니다.

```bash
# 명령 팔레트에서
Spring Initializr: Generate a Maven Project
```

1. 프로젝트 메타정보 입력 (그룹, 아티팩트, 이름 등)
2. 자바 버전 선택 (예: 17)
3. 빌드 도구 선택 (Maven 또는 Gradle)
4. 의존성 선택 (예: Spring Web, Spring Data JPA)
5. 프로젝트 생성 및 원하는 폴더에 저장

이 과정이 모두 GUI로 진행되며, 몇 번의 클릭과 입력만으로 끝납니다. 프로젝트 생성 후 바로 VS Code에서 열 수 있어서 개발 시작이 훨씬 빠르죠.


## 자동 설정과 모듈화 덕분에 복잡한 설정은 줄이고, 표준화된 구조는 보장한다

Spring Framework의 모듈화된 코어 기술과 Spring Boot의 자동 설정 덕분에, start.spring.io가 만들어주는 프로젝트는 기본적으로 표준화된 구조를 갖습니다. 이건 처음 써보면 별거 아닌 것 같지만, 실제로 프로젝트가 커질수록 큰 차이를 만듭니다.

복잡한 의존성 충돌이나 설정 문제를 줄여주고, 팀 내에서 일관된 아키텍처를 유지하는 데도 도움이 됩니다. Martin Fowler도 일관된 아키텍처가 유지되는 환경이 유지보수와 확장성에 매우 중요하다고 강조했죠[Martin Fowler - Software Architecture Guide](https://martinfowler.com/architecture/).


## start.spring.io VS Code 통합을 쓰면서 알게 된 작은 팁

- **의존성 미리보기:** 확장 내에서 의존성을 검색할 때, 어떤 라이브러리인지 간단한 설명과 버전을 바로 확인할 수 있어서 실수로 잘못된 버전을 고르는 일이 줄었어요.

- **빌드 도구 선택 시 주의:** Maven과 Gradle을 선택할 수 있는데, 팀 표준과 맞춰야 합니다. 확장 자체는 두 빌드 도구 모두 지원하지만, 프로젝트가 커질수록 빌드 도구 차이가 커서 초기 선택이 중요합니다.

- **자바 버전 고르기:** 기본적으로 Java 17이 추천되지만, 구버전 지원이 필요한 경우 11도 선택할 수 있어요. VS Code 내에서 바로 선택 가능해서 별도 설정 파일을 수정할 필요가 없습니다.

- **프로젝트 생성 후 바로 실행:** 생성된 프로젝트 폴더에서 VS Code 터미널을 열고 `./mvnw spring-boot:run` (또는 `./gradlew bootRun`) 명령어로 바로 실행할 수 있습니다. 이게 은근히 편하더라고요.


## start.spring.io VS Code 통합, 단점이나 한계도 솔직히 말해보자면

물론 완벽한 솔루션은 없습니다. 이 통합 기능도 몇 가지 아쉬운 점이 있는데요.

- **GUI가 간편하지만 복잡한 커스텀 설정은 어렵다:** 예를 들어, 특정 플러그인 설정이나 고급 빌드 옵션을 넣으려면 프로젝트 생성 후 직접 `pom.xml`이나 `build.gradle`을 수정해야 합니다.

- **확장 업데이트 주기:** VS Code 확장 업데이트가 웹 start.spring.io 서비스 업데이트보다 느릴 수 있습니다. 최신 스프링 부트 버전을 바로 반영하지 못할 때가 있죠.

- **네트워크 의존성:** start.spring.io API를 호출해서 프로젝트를 생성하므로, 인터넷 연결이 없으면 사용할 수 없습니다.

이런 한계는 있지만, 초기 개발 생산성을 크게 올려주는 건 분명합니다.


## 실제 코드 예시: VS Code 내에서 Spring Initializr 확장으로 생성한 간단한 REST API

아래는 start.spring.io로 생성한 기본 프로젝트에 `HelloController`를 추가한 예시입니다. 이 정도면 바로 REST API 개발 시작 가능하죠.

```java
package com.example.demo;

import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

@RestController
public class HelloController {

    @GetMapping("/hello")
    public String sayHello() {
        return "Hello, VS Code Spring Boot!";
    }
}
```

이 코드를 `src/main/java/com/example/demo/HelloController.java`에 넣고, VS Code 터미널에서 `./mvnw spring-boot:run` 명령어로 실행하면 `http://localhost:8080/hello`에서 바로 응답을 확인할 수 있습니다.

start.spring.io를 VS Code에 통합해서 쓰는 건, 사실 처음엔 "그냥 웹에서 하는 게 뭐가 다르지?" 싶을 수 있어요. 하지만 실제로 써보면 초기 프로젝트 생성 시간이 확 줄고, IDE를 벗어나지 않고도 모든 설정을 끝낼 수 있어서 작업 흐름이 훨씬 자연스러워집니다.
