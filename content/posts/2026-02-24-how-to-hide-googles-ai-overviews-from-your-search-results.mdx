# 구글 검색 결과에 AI 오버뷰가 뜨면 왜 골치일까?

최근 구글 검색 결과에 AI가 생성한 요약, 즉 오버뷰가 붙는 경우가 많아졌죠. 사용자 입장에선 편리할 수 있지만, 우리 서비스 입장에선 이게 꽤 골치 아픈 문제입니다. 특히 백엔드에서 검색 API를 받아서 사용자에게 노출하는 서비스라면, AI 생성 콘텐츠가 섞여서 원하지 않는 정보가 노출되거나, UI가 깨지는 문제도 생기거든요.

"이 AI 오버뷰, 도대체 어떻게 숨기지?"라는 질문이 자연스럽게 나오는데, 이 글에서는 백엔드 엔지니어 관점에서 API 레벨부터 클라우드 환경까지 AI 생성 콘텐츠를 필터링하고, 안정적으로 서비스에 반영하는 방법을 공유하려고 합니다.

---

## AI 오버뷰, API 요청 단계에서부터 걸러내는 게 가장 깔끔하다

일단 가장 이상적인 건 AI 오버뷰가 포함된 검색 결과 자체를 API 요청 단계에서 걸러내는 겁니다. 다행히 OpenAI API 문서에서도 API 요청 시 특정 파라미터나 헤더를 활용해 AI 생성 콘텐츠를 필터링하거나 커스터마이징하는 방법을 제공합니다. 

예를 들어, `filter_ai_overview=true` 같은 커스텀 파라미터를 넣어 요청하면, 응답 내 AI 오버뷰 관련 메타데이터나 태그가 포함된 결과를 제외할 수 있는 구조를 만들어볼 수 있죠. 물론 구글 검색 API가 직접 지원하지 않는다면, 유사한 원리로 메타데이터 기반 필터링 로직을 백엔드에서 구현하는 게 필요합니다.

```python
# Python 예시: OpenAI API에서 AI 생성 콘텐츠 제외 요청
import requests

headers = {
    "Authorization": "Bearer YOUR_API_KEY",
    "Content-Type": "application/json"
}
payload = {
    "query": "example search",
    "filter_ai_overview": True  # 가상의 필터링 파라미터
}

response = requests.post("https://api.example.com/search", json=payload, headers=headers)
results = response.json()

# AI 오버뷰 포함 여부를 메타데이터에서 확인해 필터링
filtered_results = [r for r in results if not r.get('is_ai_overview', False)]

print(filtered_results)
```

이런 식으로 API 요청 시점부터 AI 생성 콘텐츠를 걸러내면, downstream에서 불필요한 처리 부담도 줄고, 사용자에게도 깔끔한 결과를 줄 수 있습니다. 물론 실제 구글 검색 API에서는 아직 명시적 필터 파라미터가 없기 때문에, 다음 단계에서 보완이 필요합니다.

참고로 이 접근법은 OpenAI API 문서에서 권장하는 필터링 및 커스터마이징 옵션과 원리가 같습니다.[OpenAI API Documentation](https://platform.openai.com/docs/overview)

## 백엔드 응답 처리 시 AI 오버뷰 태그로 걸러내는 중간 계층 설계

API 요청 단계에서 걸러내기 어려운 상황이라면, 백엔드에서 응답을 받은 뒤 AI 생성 여부를 식별하는 태그나 마커를 찾는 게 중요합니다. 예를 들어, 구글 검색 결과 JSON 내에 `is_ai_overview` 같은 플래그가 포함되어 있다면, 이를 기준으로 필터링하거나 별도 처리하는 중간 계층을 두는 거죠.

이런 중간 계층은 단순 필터링을 넘어서, AI 오버뷰 콘텐츠를 별도의 캐시나 로그로 분리해두고, 필요할 때만 노출하는 정책도 가능합니다. GitHub Engineering Blog에서도 대규모 서비스에서 데이터 선별 및 필터링을 위한 중간 계층 설계 사례를 다루고 있는데, 복잡한 데이터 흐름을 안정적으로 관리하는 데 참고가 됩니다.[GitHub Engineering Blog](https://github.blog/category/engineering/)

```python
# Flask 기반 필터링 미들웨어 예시
from flask import Flask, request, jsonify

app = Flask(__name__)

@app.route('/search', methods=['POST'])
def search():
    data = request.json
    raw_results = call_external_search_api(data['query'])

    # AI 오버뷰 태그가 있으면 제외
    filtered = [r for r in raw_results if not r.get('is_ai_overview', False)]

    return jsonify(filtered)


def call_external_search_api(query):
    # 외부 API 호출 시뮬레이션
    return [
        {"title": "Regular Result", "is_ai_overview": False},
        {"title": "AI Overview Result", "is_ai_overview": True}
    ]

if __name__ == '__main__':
    app.run(debug=True)
```

이렇게 하면 프론트엔드에선 이미 AI 오버뷰가 걸러진 결과만 받아서 처리할 수 있으니, UI도 한결 단순해집니다.

## 클라우드 환경에서 API 게이트웨이나 프록시 레벨 필터링도 고려해보자

우리 서비스가 AWS API Gateway, Cloudflare Workers 같은 클라우드 플랫폼 위에서 운영된다면, AI 오버뷰 필터링을 API 게이트웨이나 프록시 레벨에서 하는 것도 효과적입니다. 

Cloudflare의 "How We Built It" 시리즈를 보면, 복잡한 필터링 로직과 캐시 정책을 API 엣지에서 처리해 불필요한 콘텐츠 노출을 줄이는 사례가 많습니다. 이런 접근법을 검색 결과 AI 오버뷰 필터링에 응용하면, 백엔드 부담을 줄이고 응답 속도도 개선할 수 있죠.[Cloudflare Blog - How We Built It](https://blog.cloudflare.com/tag/how-we-built-it/)

예를 들어, Cloudflare Workers에서 AI 오버뷰 관련 특정 헤더나 키워드를 탐지해 차단하거나, 캐시에서 AI 오버뷰가 포함된 결과만 별도 분리하는 정책을 만들 수 있습니다.

```javascript
// Cloudflare Worker 예시
addEventListener('fetch', event => {
  event.respondWith(handleRequest(event.request))
})

async function handleRequest(request) {
  const response = await fetch(request)
  const clonedResponse = response.clone()
  const contentType = response.headers.get('content-type') || ''

  if (contentType.includes('application/json')) {
    const data = await clonedResponse.json()
    // AI 오버뷰가 포함된 결과를 필터링
    const filtered = data.results.filter(r => !r.is_ai_overview)
    return new Response(JSON.stringify({ results: filtered }), {
      headers: { 'content-type': 'application/json' }
    })
  }
  return response
}
```

이렇게 엣지에서 처리하면, 클라이언트에 불필요한 AI 오버뷰가 아예 도달하지 않으니 UX가 훨씬 깔끔해집니다.

## 프론트엔드에서 AI 오버뷰 노출 여부를 유연하게 제어하는 UI 컴포넌트 설계

백엔드에서 필터링을 완벽하게 한다 해도, 혹시 모를 예외 상황이나 사용자 선택권을 위해 프론트엔드에서 AI 오버뷰 노출을 제어하는 것도 좋은 방법입니다. 

TypeScript Handbook에서 권장하는 타입 안정성과 컴포넌트 기반 설계 원칙을 적용하면, AI 오버뷰 여부를 명확히 구분하는 타입을 만들고, 조건부 렌더링을 깔끔하게 구현할 수 있죠.[TypeScript Handbook](https://www.typescriptlang.org/docs/handbook/intro.html)

```tsx
// React + TypeScript 예시
interface SearchResult {
  id: string;
  title: string;
  isAiOverview: boolean;
}

interface Props {
  results: SearchResult[];
  showAiOverview: boolean;
}

export function SearchResults({ results, showAiOverview }: Props) {
  return (
    <ul>
      {results.map(result => {
        if (result.isAiOverview && !showAiOverview) {
          return null // AI 오버뷰 숨기기
        }
        return <li key={result.id}>{result.title}</li>
      })}
    </ul>
  )
}
```

사용자 설정에 따라 AI 오버뷰를 켜고 끌 수 있게 하면, 서비스 유연성도 높아지고, 사용자 피드백도 받을 수 있습니다. 물론 이 방법은 백엔드 필터링과 병행해야 UI가 깔끔해진다는 점 기억하세요.

## 마무리: AI 오버뷰 필터링, 한 군데서만 하지 말고 여러 단계로 나누자

처음엔 AI 오버뷰가 검색 결과에 섞여도 별거 아닐 것 같지만, 실제 서비스에선 사용자 경험과 서비스 안정성에 큰 영향을 미칩니다. 

그래서 API 요청 단계에서부터 필터링을 시도하고, 백엔드 중간 계층에서 태그 기반 필터링을 강화하며, 클라우드 엣지에서 차단 정책을 적용하고, 프론트엔드에서는 UI 제어까지 하는 다중 방어선 전략이 필요합니다. 

이렇게 하면 AI 생성 콘텐츠 노출을 효과적으로 관리하면서도, 서비스 구조가 단순해지고 유지보수도 쉬워집니다.
