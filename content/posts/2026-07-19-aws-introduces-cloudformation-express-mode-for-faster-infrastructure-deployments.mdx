## "인프라 배포가 너무 느려서 개발 속도가 발목 잡히는데, 방법 없을까?"

이런 고민, 아마 클라우드 인프라를 다루는 백엔드 엔지니어라면 한 번쯤은 해봤을 겁니다. 특히 CloudFormation으로 복잡한 스택을 배포할 때, 리소스 생성과 업데이트가 꽤 오래 걸리는 경험 다들 있죠? AWS가 최근 발표한 CloudFormation Express Mode는 이런 문제를 해결하기 위해 나왔습니다. 기존보다 훨씬 빠른 인프라 배포를 가능하게 해주는데요, 실제로 써보니 어떤 점이 달라졌는지, 그리고 어떻게 활용하면 좋을지 이야기해보겠습니다.


## CloudFormation Express Mode, 왜 이렇게 빠를까?

기존 CloudFormation은 스택 내 리소스를 순차적으로 생성하거나 업데이트하는 경향이 있습니다. 물론 병렬 처리도 일부 지원하지만, 여러 안전 검증과 상태 확인 단계 때문에 시간이 꽤 소요되죠. Express Mode는 이 과정을 대폭 간소화하고, 병렬 처리 범위를 확장해 배포 속도를 비약적으로 올렸습니다.

AWS 공식 블로그에 따르면, Express Mode는 불필요한 상태 확인 단계와 중간 검증을 줄이고, 리소스 생성 시 병렬 실행을 극대화하는 운영 최적화 기능을 포함하고 있습니다. 덕분에 복잡한 백엔드 인프라도 기존 대비 평균 50% 이상 빠르게 배포할 수 있다고 하네요[1].

이건 실제로 써보면 체감 속도가 확실히 달라집니다. 예를 들어, EC2 인스턴스, RDS, S3 버킷, IAM 역할 등 20개 이상의 리소스를 포함하는 스택을 배포할 때, 기존 모드에서는 15분가량 걸렸던 작업이 Express Mode로는 7분 내외로 줄었어요.


## Express Mode 활성화, 이렇게 하면 된다

Express Mode를 활성화하는 건 생각보다 간단합니다. CloudFormation 템플릿을 그대로 쓰되, 스택 생성이나 업데이트 시 `--mode EXPRESS` 옵션만 추가해주면 끝입니다. CLI 기준으로는 아래처럼요:

```bash
aws cloudformation deploy \
  --template-file backend-infra.yaml \
  --stack-name my-backend-stack \
  --mode EXPRESS \
  --capabilities CAPABILITY_NAMED_IAM
```

이 옵션만으로도 배포 속도가 눈에 띄게 빨라집니다. 물론 템플릿 내 리소스 정의는 기존과 동일하게 유지할 수 있어서, 별도의 마이그레이션 작업이 필요 없다는 점도 큰 장점입니다.

다만 Express Mode는 일부 리소스 타입이나 복잡한 조건부 논리를 포함한 템플릿에서는 제한이 있을 수 있으니, AWS 문서에서 지원 범위를 꼭 확인해야 합니다. (예: 일부 리소스는 아직 Express Mode에서 지원하지 않을 수 있음)


## CI/CD 파이프라인에 Express Mode 넣으면 좋은 점

우리 팀은 Jenkins와 GitHub Actions를 이용한 CI/CD 파이프라인에서 인프라 배포를 자동화하고 있는데요, Express Mode 도입 후 반복 배포 속도가 확실히 개선돼서 개발→배포 사이클이 훨씬 짧아졌습니다.

특히, 매번 변경사항을 테스트 환경에 빠르게 반영해야 하는 상황에서 Express Mode가 큰 힘이 됐죠. 예전에는 배포만 10분 넘게 걸려서 개발자들이 기다리는 시간이 길었는데, 지금은 4~5분 내외로 줄어들어 피드백 속도가 빨라졌습니다.

아래는 GitHub Actions 워크플로우 예시입니다. `aws cloudformation deploy` 명령어에 `--mode EXPRESS` 옵션을 넣는 게 핵심입니다.

```yaml
name: Deploy Backend Infra

on:
  push:
    branches:
      - main

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - name: Checkout repo
        uses: actions/checkout@v3

      - name: Configure AWS Credentials
        uses: aws-actions/configure-aws-credentials@v2
        with:
          aws-access-key-id: ${{ secrets.AWS_ACCESS_KEY_ID }}
          aws-secret-access-key: ${{ secrets.AWS_SECRET_ACCESS_KEY }}
          aws-region: ap-northeast-2

      - name: Deploy CloudFormation Stack with Express Mode
        run: |
          aws cloudformation deploy \
            --template-file infra/backend-infra.yaml \
            --stack-name backend-stack \
            --capabilities CAPABILITY_NAMED_IAM \
            --mode EXPRESS
```

이렇게 간단한 설정 변경만으로도 배포 시간을 획기적으로 줄일 수 있으니, CI/CD 환경에 Express Mode 적용은 꼭 고려해볼 만합니다.


## AWS Well-Architected Framework와 함께 Express Mode를 쓸 때 주의할 점

속도가 빨라진다고 무조건 좋기만 한 건 아닙니다. AWS Well-Architected Framework가 강조하는 안정성, 성능 효율성, 운영 우수성 원칙을 지키면서 Express Mode를 써야 하죠[2].

예를 들어, Express Mode는 빠른 배포를 위해 상태 검증 단계를 줄이는데, 이 때문에 배포 실패 시 롤백이 기존보다 복잡할 수 있습니다. 따라서 중요한 프로덕션 환경에서는 스택 변경 전후에 꼼꼼한 테스트와 모니터링이 필수입니다.

또한, 병렬 처리가 늘어나면서 리소스 간 의존성 관리도 더 신경 써야 합니다. 의존성이 명확하지 않으면 예상치 못한 오류가 발생할 수 있으니, 템플릿 작성 시 DependsOn 속성이나 조건문을 적절히 활용해 의존 관계를 명확히 하는 게 좋습니다.

마지막으로, Express Mode가 지원하지 않는 리소스나 기능이 있을 수 있으니, 최신 AWS 문서를 참고해 제한 사항을 미리 파악하는 게 안전합니다.


## 내가 직접 써보고 느낀 Express Mode의 장단점

### 장점

- 배포 속도가 평균 50% 이상 빨라져서 개발→배포 사이클 단축
- 기존 템플릿 호환성 유지로 마이그레이션 부담 없음
- CI/CD 파이프라인에 쉽게 통합 가능

### 단점

- 일부 리소스는 Express Mode 미지원
- 빠른 배포를 위해 검증 단계가 줄어들어 실패 시 디버깅 난이도 상승 가능
- 리소스 의존성 관리에 더 신경 써야 함

처음에는 "배포 시간이 빨라진다고 해서 큰 차이가 있을까?" 싶었는데, 실제로 배포 대기 시간이 줄어드니까 개발자들이 훨씬 쾌적해졌고, 운영팀도 반복 배포 부담이 줄어들어 만족도가 높았습니다.


---

AWS CloudFormation Express Mode는 복잡한 백엔드 인프라를 빠르고 효율적으로 배포할 수 있는 강력한 도구입니다. 물론 모든 환경에 무조건 맞는 건 아니지만, 특히 CI/CD 자동화 환경에서 반복적이고 빠른 배포가 필요한 팀이라면 도입을 적극 추천합니다.

적용 시에는 AWS Well-Architected Framework 가이드라인을 참고해 안정성과 운영 효율성을 놓치지 않는 균형 잡힌 인프라 운영을 고민해보세요.
