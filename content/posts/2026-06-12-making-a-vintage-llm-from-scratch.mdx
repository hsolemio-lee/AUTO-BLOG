## "내 손으로 LLM을 만든다" — 현실적인 첫걸음

"대형 언어 모델? 너무 무겁고 복잡해 보여서 엄두가 안 나는데, 그래도 직접 만들어보면 뭔가 배울 게 많지 않을까?" 이런 생각으로 시작했다. 실제로 최신 LLM은 수십억 파라미터에 수천 GPU가 필요한데, 내 노트북이나 작은 서버에서 돌리기엔 무리다. 그래서 '빈티지 스타일' LLM, 즉 작고 단순한 구조로 핵심만 구현해보자는 목표를 잡았다.

이 과정에서 느낀 건, 모델 크기를 줄이고 단순한 토크나이저와 기본 어텐션만 구현해도 의외로 쓸만한 결과가 나온다는 점이다. 물론 최신 모델과 비교할 순 없지만, 제한된 환경에서 실용적인 성능을 내는 데는 충분했다.

---

## 토크나이저부터 시작하는 게 왜 중요한가

빈티지 LLM의 출발점은 텍스트를 숫자로 바꾸는 토크나이저(tokenizer)다. 최신 LLM은 BPE(Byte Pair Encoding)나 WordPiece 같은 복잡한 토크나이저를 쓰지만, 여기선 단순히 공백 기준 분리 후 알파벳 단위로 쪼개는 방식을 선택했다. 이유는 명확하다. 복잡한 토크나이저를 구현하려면 별도의 학습과 데이터 전처리가 필요한데, 이걸 생략하면 개발 속도가 훨씬 빨라진다.

예를 들어, 아래 코드처럼 아주 간단한 토크나이저를 만들었다:

```python
class SimpleTokenizer:
    def __init__(self):
        self.vocab = {chr(i): i for i in range(32, 127)}  # ASCII 32~126

    def encode(self, text):
        return [self.vocab.get(ch, 0) for ch in text]  # 사전에 없으면 0

    def decode(self, tokens):
        inv_vocab = {v: k for k, v in self.vocab.items()}
        return ''.join(inv_vocab.get(t, '?') for t in tokens)

# 사용 예
tokenizer = SimpleTokenizer()
tokens = tokenizer.encode("Hello, vintage LLM!")
print(tokens)
print(tokenizer.decode(tokens))
```

이렇게 단순한 토크나이저는 정확도가 떨어질 수 있지만, 모델 크기가 작고 학습 데이터가 제한적인 상황에선 오히려 빠르고 직관적이다. 실제로도 이 방식을 쓰니 초기 모델 학습과 디버깅이 훨씬 수월했다.

## 어텐션 메커니즘, 복잡하지 않게 구현하는 팁

빈티지 LLM에서 가장 핵심이지만 까다로운 부분이 어텐션(attention)이다. 최신 트랜스포머 모델은 멀티헤드 어텐션과 복잡한 수학 연산이 들어가는데, 이걸 다 구현하긴 무리였다. 그래서 단일 헤드, 단순 스케일드 닷 프로덕트 어텐션만 구현했다.

간단히 말해, Query, Key, Value 벡터를 각각 선형 변환한 뒤, Query와 Key의 내적을 소프트맥스 처리해 Value에 가중치를 곱하는 구조다. 아래는 파이썬+넘파이로 구현한 예시다:

```python
import numpy as np

def scaled_dot_product_attention(Q, K, V):
    d_k = Q.shape[-1]
    scores = np.matmul(Q, K.T) / np.sqrt(d_k)  # 스케일링
    weights = np.exp(scores - np.max(scores, axis=-1, keepdims=True))
    weights /= np.sum(weights, axis=-1, keepdims=True)
    output = np.matmul(weights, V)
    return output

# 임의의 데이터 예
Q = np.random.rand(5, 64)  # 5개의 쿼리, 64차원
K = np.random.rand(5, 64)
V = np.random.rand(5, 64)

result = scaled_dot_product_attention(Q, K, V)
print(result.shape)  # (5, 64)
```

이렇게 단순화하면 GPU 가속 없이도 CPU에서 충분히 돌릴 수 있고, 디버깅도 쉽다. 물론 성능은 떨어지지만, 제한된 자원에서 돌아가는 빈티지 LLM에선 이런 절충이 필요하다.

## 백엔드 API 서버, RESTful하게 설계하면서 비동기 처리도 꼭 넣자

모델을 실제 서비스로 쓰려면 API 서버가 필수다. 나는 Spring 같은 프레임워크 대신 Python FastAPI로 빠르게 RESTful API를 만들었다. 이유는 비동기 요청 처리가 기본 지원돼서 응답 지연을 최소화할 수 있기 때문이다.

예를 들어, 아래처럼 간단한 추론 API를 만들었다:

```python
from fastapi import FastAPI, Request
import asyncio

app = FastAPI()

@app.post("/infer")
async def infer(request: Request):
    data = await request.json()
    prompt = data.get("prompt", "")
    # 실제론 여기서 토크나이징, 모델 추론, 디코딩 수행
    await asyncio.sleep(0.1)  # 모의 지연
    response = {"result": prompt[::-1]}  # 단순히 문자열 뒤집기 예
    return response
```

비동기 처리를 안 하면 요청이 몰릴 때 서버가 막히기 쉽다. 그리고 자주 쓰는 프롬프트 결과는 메모리 캐시(redis 등)에 저장해 재사용하면 응답 속도가 훨씬 빨라진다. 이런 캐싱 전략과 비동기 처리를 병행하는 게 실제 서비스 운영에 큰 도움이 됐다[Martin Fowler - Software Architecture Guide](https://martinfowler.com/architecture/).

## 프롬프트 엔지니어링, 빈티지 LLM에서도 무시할 수 없는 이유

빈티지 LLM은 모델 크기가 작아 표현력이 떨어지기 때문에, 입력 프롬프트를 잘 설계하는 게 출력 품질을 좌우한다. 명확하고 구조화된 프롬프트는 모델이 의도한 답변을 내도록 돕는다.

예를 들어, 단순한 질문-답변 형식일 때는 이렇게 썼다:

```
Q: 오늘 날씨 어때?
A:
```

이런 식으로 "Q:"와 "A:"를 명시해 모델이 답변 부분만 생성하도록 유도한다. Anthropic의 프롬프트 가이드에서도 이런 명확한 구분이 출력 품질 향상에 중요하다고 한다[Anthropic - Prompt Engineering Guide](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/overview).

## 클라우드에 올려서 확장성과 운영 편의성을 챙기기

작은 모델이라도 서비스로 운영하려면 배포와 확장성이 중요하다. 나는 Docker 컨테이너로 API 서버를 패키징하고, AWS ECS에 올려 자동 스케일링을 적용했다. 이렇게 하면 트래픽 급증에도 대응 가능하고, 비용도 필요한 만큼만 쓴다.

서버리스 아키텍처도 고민했는데, 빈티지 LLM은 추론 시간이 길어 함수 타임아웃에 걸릴 위험이 있어 컨테이너 기반이 더 안정적이었다. Cloudflare 사례처럼 클라우드 플랫폼을 활용하면 빠른 배포와 비용 효율적 운영이 가능하다[Cloudflare Blog - How We Built It](https://blog.cloudflare.com/tag/how-we-built-it/).

## 직접 만들어보니 보이는 소프트웨어 아키텍처의 중요성

빈티지 LLM 프로젝트를 진행하면서 가장 크게 느낀 점 중 하나는 모듈화와 계층화된 설계의 중요성이다. 토크나이저, 인퍼런스 엔진, API 서버를 각각 독립된 모듈로 나누니 개발과 테스트가 훨씬 수월했다. 문제 생겨도 원인 파악이 빠르고, 각 부분을 따로 개선하기도 편했다.

이런 구조는 나중에 모델을 교체하거나 API를 확장할 때도 큰 도움이 된다. InfoQ에서 강조하는 소프트웨어 아키텍처 원칙과도 일맥상통한다[InfoQ - Software Architecture & Design](https://www.infoq.com/architecture-design/).

## 정리하며: 직접 만들어보니 보이는 것들

- **모델 크기를 작게, 토크나이저는 단순하게**: 복잡한 토크나이저 대신 ASCII 기반 간단 토크나이저로 시작해도 충분히 학습 가능하다.
- **어텐션은 단일 헤드, 스케일드 닷 프로덕트로 구현**: 복잡한 멀티헤드 대신 단순화하면 CPU 환경에서도 돌아간다.
- **API 서버는 비동기 처리와 캐싱 필수**: 응답 지연 최소화와 부하 분산을 위해 비동기와 캐시 전략을 병행하자.
- **프롬프트 설계에 신경 쓰기**: 명확하고 구조화된 프롬프트가 작은 모델의 한계를 보완한다.
- **클라우드 컨테이너 배포로 운영 편의성 확보**: 서버리스보단 컨테이너 기반이 안정적이며, 자동 스케일링을 활용하자.
- **모듈화된 아키텍처가 개발 효율성을 높인다**: 각 구성 요소를 독립적으로 관리하면 유지보수가 쉽다.

빈티지 LLM은 최신 대형 모델과 비교하면 부족하지만, 직접 만들어보면 모델 내부 동작 원리와 백엔드 운영의 현실적인 고민을 몸소 체험할 수 있다. 이 경험이 앞으로 더 큰 AI 시스템을 다룰 때 큰 밑거름이 될 거라 확신한다.
