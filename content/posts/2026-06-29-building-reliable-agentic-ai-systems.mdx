# 에이전트형 AI 시스템, 왜 이렇게 설계가 까다로울까?

최근 AI가 단순한 도구를 넘어 스스로 판단하고 행동하는 '에이전트' 역할을 하면서, 시스템 설계 난이도가 훨씬 올라갔다는 걸 느끼고 있다. 예를 들어, 고객 문의를 자동으로 분류하고 적절한 답변을 생성하는 챗봇을 운영한다고 치자. 단순히 질문에 답하는 수준을 넘어서, 상황에 맞게 여러 API를 호출하고, 실패하면 재시도하거나 대체 경로를 선택하는 복잡한 의사결정 로직이 필요하다. 이때 단순한 AI 호출만으로는 부족하고, 안정성과 확장성까지 감안한 아키텍처 설계가 필수다.

내가 최근에 경험한 프로젝트에서 OpenAI API와 Anthropic의 Claude 모델을 활용해 에이전트형 AI를 구축하며 겪은 설계 고민과 해법을 공유해보려 한다. 특히, 프로덕션 환경에서 신뢰성을 보장하기 위한 구체적인 아키텍처 결정과 마이그레이션 전략에 초점을 맞췄다.

## OpenAI API 활용 시 확장성과 안정성을 어떻게 확보했나?

OpenAI API는 다양한 엔드포인트와 인증 메커니즘을 제공해 프로덕션 환경에서 신뢰성을 높이는 데 큰 도움이 됐다. 예를 들어, 단일 API 호출이 실패할 경우 대비해 자동 재시도 로직을 넣었고, 최대 동시 호출 제한(예: 60 RPM, 120,000 TPM)을 감안해 큐잉 시스템을 설계했다.

```python
import openai
import time

openai.api_key = 'sk-xxxx'

MAX_RETRIES = 3


def call_openai_api(prompt):
    for attempt in range(MAX_RETRIES):
        try:
            response = openai.ChatCompletion.create(
                model="gpt-4o-mini",
                messages=[{"role": "user", "content": prompt}],
                temperature=0.7
            )
            return response.choices[0].message.content
        except openai.error.RateLimitError:
            print(f"Rate limit hit, retrying {attempt + 1}/{MAX_RETRIES}...")
            time.sleep(2 ** attempt)  # 지수 백오프
    raise Exception("OpenAI API 호출 실패")
```

이런 식으로 재시도 로직과 백오프 전략을 조합해, 순간적인 트래픽 급증에도 시스템이 무너지지 않도록 했다. 또한, API 호출 결과를 캐싱하는 레이어를 두어 중복 호출을 줄였고, 인증 토큰 관리도 별도 서비스로 분리해 보안을 강화했다.

이 부분은 OpenAI 공식 문서에서 권장하는 아키텍처 패턴과 일치한다[OpenAI API Documentation](https://platform.openai.com/docs/overview).

## Anthropic 프롬프트 설계가 에이전트 신뢰성에 미친 영향

에이전트형 AI는 단순 텍스트 생성과 달리 명확한 의도 파악과 지시 전달이 필수다. Anthropic의 프롬프트 엔지니어링 가이드를 참고해, 프롬프트를 계층화하고 명확한 역할 구분을 넣었다.

예를 들어, 사용자 질문을 요약하는 부분, 내부 API 호출 지시, 오류 처리 지시를 단계별로 분리했다. 이렇게 하니 같은 입력에 대해 일관된 출력을 얻을 확률이 훨씬 높아졌다. 실제로는 아래처럼 프롬프트 템플릿을 썼다.

```text
[시스템 메시지]
너는 고객 지원 AI 어시스턴트야. 사용자의 질문을 요약하고, 필요한 API를 호출해 결과를 제공해야 해.

[사용자 메시지]
{사용자 질문}

[지시사항]
1. 질문을 간결하게 요약해.
2. 필요한 경우 내부 API 호출 명령을 생성해.
3. 오류 발생 시 재시도 또는 대체 경로를 안내해.
```

이런 구조 덕분에 에이전트가 복잡한 작업을 수행할 때도 안정적으로 의도를 해석하고 행동할 수 있었다. 프롬프트 설계에 투자한 시간이 결국 시스템 견고성과 직결된다는 걸 실감했다[Anthropic - Prompt Engineering Guide](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/overview).

## Claude Code를 활용한 코드 생성과 오류 복구 전략

에이전트형 AI가 코드 생성 및 수정 작업을 할 때는, 단순 생성 외에 실행 안정성 확보가 관건이다. Anthropic의 Claude Code 문서에서 제안하는 아키텍처를 참고해, 생성된 코드를 안전하게 실행하고 오류 발생 시 자동으로 롤백하거나 수정하는 메커니즘을 설계했다.

내가 적용한 방법은 다음과 같다.

- 코드 생성 요청 시, 명확한 테스트 케이스를 함께 전달해 테스트 자동화 가능하게 함
- 실행 전 코드 정적 분석 도구를 통과하도록 필터링
- 실행 중 오류 발생 시, 에러 메시지를 다시 AI에게 보내 수정 요청

예를 들어, Python 코드 생성 후 실행하는 간단한 워크플로우는 아래와 같다.

```python
import subprocess

def run_generated_code(code_str):
    with open("temp_code.py", "w") as f:
        f.write(code_str)

    result = subprocess.run(["python3", "temp_code.py"], capture_output=True, text=True)
    if result.returncode != 0:
        # 오류 발생 시 AI에게 수정 요청
        print("코드 실행 오류 발생:", result.stderr)
        # 여기서 AI에게 수정 프롬프트를 보내는 로직 추가
    else:
        print("코드 실행 성공:", result.stdout)
```

이런 구조가 없으면, AI가 생성한 코드가 프로덕션에서 바로 문제를 일으켜 서비스 중단으로 이어질 수 있다. Claude Code 아키텍처 가이드가 이런 점을 잘 짚어준다[Anthropic - Claude Code Overview](https://docs.anthropic.com/en/docs/claude-code/overview).

## 마이그레이션과 협업, Cursor와 Vercel AI SDK의 역할

기존 AI 시스템에서 에이전트형 AI로 전환할 때는 코드베이스와 아키텍처가 크게 바뀌기 때문에, 프론트엔드와 백엔드 간 원활한 협업과 점진적 마이그레이션 전략이 중요하다. 이때 Cursor 플랫폼이 제공하는 실시간 피드백과 협업 도구가 큰 도움이 됐다.

Cursor를 통해 개발자들이 동시에 프롬프트와 API 호출 코드를 조율하고, 변경 사항을 실시간으로 공유할 수 있었다. 덕분에 마이그레이션 기간 동안 발생하는 혼선을 최소화할 수 있었다[Cursor Documentation](https://docs.cursor.com/).

또한, Vercel AI SDK를 활용해 서버리스 환경에서 에이전트 AI를 배포했다. SDK가 제공하는 확장성 및 프론트엔드-백엔드 통합 기능 덕분에, 별도 인프라 구축 부담 없이 빠르게 프로덕션에 올릴 수 있었다. 다만, 서버리스 특성상 콜드 스타트 지연과 상태 관리 한계는 여전히 고민거리다[Vercel AI SDK Documentation](https://sdk.vercel.ai/docs/introduction).

## 마지막으로, GitHub Copilot은 어떻게 도움을 줬나?

에이전트형 AI 시스템은 복잡한 로직과 다양한 API 호출을 포함하므로, 코드 품질 유지가 쉽지 않다. GitHub Copilot을 적극 활용해 반복되는 코드 패턴과 API 호출 템플릿을 빠르게 작성하면서도, 코드 일관성을 유지할 수 있었다.

예를 들어, OpenAI API 호출 함수, 에러 핸들링 로직, 프롬프트 템플릿 생성 코드를 Copilot으로 빠르게 생성하고, 이후 세밀한 튜닝을 하는 방식이었다. Copilot 덕분에 생산성이 올라가면서도 리뷰 때 발견되는 사소한 버그가 줄어드는 효과를 봤다[GitHub Copilot Documentation](https://docs.github.com/en/copilot).

# 정리하며

에이전트형 AI 시스템은 단순히 AI 모델 호출만으로 끝나는 게 아니라, 안정적인 서비스 운영을 위한 다층적 설계가 필수다. OpenAI API의 확장성, Anthropic의 프롬프트 설계와 코드 실행 안정화, Cursor와 Vercel AI SDK를 활용한 협업 및 배포 전략, 그리고 GitHub Copilot으로 코드 품질을 유지하는 여러 요소가 서로 맞물려야 제대로 된 프로덕션 시스템이 완성된다.

처음엔 ‘AI가 알아서 다 해주겠지’ 싶지만, 실제로는 이런 세밀한 설계와 운영 노하우가 없으면 금방 장애나 성능 저하를 겪는다. 그래서 내가 추천하는 건 다음과 같다.

- API 호출 시 재시도와 백오프 전략은 기본 중 기본
- 프롬프트는 계층화해서 명확한 역할 분리하기
- 코드 생성 AI는 실행 전후 검증 로직 반드시 넣기
- 마이그레이션은 협업 도구 적극 활용해 단계적 진행
- 생산성 도구(GitHub Copilot 등)로 코드 일관성 유지

이 조합을 잘 맞추면, 에이전트형 AI 시스템도 충분히 신뢰할 수 있는 프로덕션 서비스가 될 수 있다. 실제로 내가 겪은 시행착오와 성공 사례가 여러분께 작은 도움이 되길 바란다.
