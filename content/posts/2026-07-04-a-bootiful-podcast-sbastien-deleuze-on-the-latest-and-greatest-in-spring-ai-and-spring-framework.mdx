## AI 호출, 그냥 하면 왜 안 될까?

최근에 우리 팀에서 Spring Boot 3.x 기반 서비스에 OpenAI API를 붙여보는 작업을 했는데, 생각보다 쉽지 않았어요. 단순히 API 호출만 하면 될 줄 알았는데, 응답 지연, 네트워크 비용, 보안 문제까지 신경 쓸 게 한두 가지가 아니더라고요. Sébastien Deleuze가 출연한 'A Bootiful Podcast'를 듣고 나서야 왜 Spring AI와 Spring Framework 6가 이런 문제를 해결하는 데 최적화되어 있는지 감이 잡혔습니다.

## Spring Boot 3.x, AI 통합이 이렇게 쉬워졌다고?

Spring Boot 3.x부터는 AI 통합을 위한 새로운 모듈이 기본으로 추가됐어요. 예를 들어 OpenAI API 같은 외부 AI 서비스와 연동할 때, 기존에는 RestTemplate이나 WebClient를 직접 설정하고, 토큰 관리, 요청 제한 처리, 캐싱 등을 일일이 구현해야 했죠. 그런데 이제는 Spring AI 모듈 덕분에 이런 작업이 훨씬 간편해졌습니다.

```java
// Spring AI 클라이언트 빈 등록 예시
@Bean
public OpenAIClient openAIClient(OpenAIProperties properties) {
    return OpenAIClient.builder()
            .apiKey(properties.getApiKey())
            .build();
}

// 서비스에서 AI 호출
public String generateText(String prompt) {
    CompletionRequest request = CompletionRequest.builder()
            .prompt(prompt)
            .maxTokens(100)
            .build();
    return openAIClient.createCompletion(request).choices().get(0).text();
}
```

이렇게만 해도 기본적인 AI 호출이 가능하지만, 실제 프로덕션에서는 호출 지연이나 실패에 대비한 타임아웃, 재시도, 캐시 전략을 꼭 넣어야 합니다. [Spring Boot Reference Documentation](https://docs.spring.io/spring-boot/reference/)에서 자세한 가이드가 나와 있는데, 특히 WebClient 설정에서 `responseTimeout`을 2초 정도로 잡고, 캐시는 Redis 같은 외부 저장소를 활용하는 게 일반적입니다.

## Java 17 이상 필수, Spring Framework 6의 모듈화와 네이티브 이미지 지원

Spring Framework 6는 자바 17 이상을 요구하는데, 이게 단순히 버전 업이 아니라 성능과 안정성에 큰 영향을 줍니다. 모듈화 덕분에 필요한 부분만 딱딱 가져다 쓸 수 있고, GraalVM 네이티브 이미지 지원도 강화돼서 스타트업 타임과 메모리 사용량을 크게 줄일 수 있어요.

실제로 AI 모델과 복잡한 비즈니스 로직을 동시에 돌릴 때, 이런 최적화가 없으면 지연시간이 눈에 띄게 늘어나는데, Spring Framework 6는 그런 부분을 많이 개선했습니다. [Spring Framework - Core Technologies](https://docs.spring.io/spring-framework/reference/core.html) 문서에서 네이티브 이미지 빌드 관련 섹션을 보면, 실제 프로덕션 환경에서 어떻게 활용할지 사례도 소개되어 있습니다.

## AI 통합 시 성능 튜닝, JVM 옵션만 조정하면 끝?

처음엔 JVM 옵션만 조절하면 충분할 거라 생각했는데, AI 호출이 네트워크를 타고 가는 만큼, 커넥션 풀과 캐싱 전략이 훨씬 중요하더군요. Baeldung의 [Spring Boot Performance Tuning](https://www.baeldung.com/spring-boot-performance) 글을 참고해서 우리 팀에서 적용한 핵심 설정은 다음과 같습니다.

- **JVM 옵션**: `-Xms2g -Xmx4g -XX:+UseG1GC`로 GC 튜닝
- **커넥션 풀**: HikariCP 최대 풀 크기 30, 타임아웃 3000ms
- **캐싱**: AI 응답은 5분 TTL로 Redis에 저장
- **비동기 처리**: AI 호출은 `@Async`로 처리해 메인 쓰레드 블로킹 최소화

이 중 캐싱이 가장 효과적이었는데, AI 호출 비용과 지연시간을 동시에 줄여주더라고요. 단, 캐시 만료 시간을 너무 길게 잡으면 최신 정보 반영이 늦어질 수 있으니 서비스 특성에 맞게 조절해야 합니다.

## OpenAI API 키, 그냥 환경변수에 두면 위험하지 않나?

API 키 보안은 생각보다 까다롭습니다. OpenAI 공식 문서에 따르면, 키를 코드에 하드코딩하는 건 절대 금지하고, Spring Security와 연동해서 안전하게 관리할 것을 권장합니다. 예를 들어, Spring Vault나 AWS Secrets Manager 같은 비밀 관리 시스템을 활용하는 게 좋죠.

```yaml
# application.yaml 예시
spring:
  security:
    oauth2:
      client:
        registration:
          openai:
            client-id: ${OPENAI_CLIENT_ID}
            client-secret: ${OPENAI_API_KEY}
```

그리고 API 호출 시에는 요청 제한(rate limiting) 정책도 꼭 지켜야 합니다. 너무 많은 요청이 몰리면 서비스가 차단될 수 있어요. 이를 위해 Spring Cloud Gateway 같은 API 게이트웨이에서 요청 수를 제한하거나, Resilience4j 같은 라이브러리로 회로 차단기(Circuit Breaker)를 적용하는 게 현실적인 방법입니다.

## 프롬프트 엔지니어링, 백엔드에서 어떻게 관리할까?

Anthropic의 프롬프트 엔지니어링 가이드를 보면, AI 모델의 출력 품질은 프롬프트 구조와 문맥에 크게 좌우된다고 합니다. 즉, 단순히 문자열을 넘기는 게 아니라, 동적으로 프롬프트를 생성하고 검증하는 로직이 필요해요.

우리 팀에서는 다음과 같은 방식을 적용했습니다.

1. **템플릿 기반 프롬프트 생성**: Thymeleaf 같은 템플릿 엔진으로 기본 문장을 만들고,
2. **사용자 입력 검증**: 입력값 길이와 금지어 필터링,
3. **컨텍스트 추가**: 이전 대화 내용이나 사용자 프로필을 포함해 문맥 강화

```java
public String buildPrompt(UserInput input, ConversationContext context) {
    String baseTemplate = "안녕하세요, {{name}}님! 오늘의 질문은 '{{question}}'입니다.";
    Map<String, String> variables = Map.of(
        "name", context.getUserName(),
        "question", input.getQuestion()
    );
    return templateEngine.process(baseTemplate, new Context(Locale.KOREAN, variables));
}
```

이렇게 하면 프롬프트 품질을 일정하게 유지할 수 있고, AI 모델이 더 정확한 답변을 하게 됩니다. 물론 템플릿 엔진을 쓰면 성능 비용이 조금 들긴 하지만, 품질 향상을 생각하면 충분히 감수할 만합니다.

## 결론: AI와 함께하는 Spring 백엔드, 이걸 기억하자

- Spring Boot 3.x와 Spring Framework 6는 AI 통합을 위한 최신 기능과 성능 최적화가 잘 되어 있다.
- AI 호출은 네트워크 비용과 지연을 고려해 캐싱, 타임아웃, 비동기 처리가 필수다.
- API 키는 절대 코드에 노출하지 말고, Spring Security나 별도 비밀 관리 시스템으로 안전하게 다뤄야 한다.
- 프롬프트 엔지니어링은 백엔드에서 템플릿과 검증 로직으로 체계적으로 관리하는 게 좋다.

처음엔 AI 통합이 단순한 API 호출처럼 보이지만, 실제 운영 환경에서는 생각보다 많은 세심한 조정이 필요합니다. Sébastien Deleuze가 말한 것처럼, "좋은 AI 기능은 좋은 백엔드 설계에서 시작된다"는 걸 꼭 기억하세요.
