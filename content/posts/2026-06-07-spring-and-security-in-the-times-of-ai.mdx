### AI 기능을 붙였는데, 보안은 어떻게 챙겨야 할까?

최근 우리 팀에도 AI 기능을 백엔드에 붙여야 하는 일이 생겼다. OpenAI API나 Anthropic 같은 AI 서비스가 워낙 강력해지면서, 단순히 호출만 하는 게 아니라 민감한 데이터도 다뤄야 하고, 권한도 꼼꼼히 따져야 하더라. 그런데 막상 Spring Boot에서 AI API를 호출할 때 보안을 어떻게 설계해야 할지 막막했다. 단순히 API 키 숨기고 끝낼 일이 아니었다.

내가 겪은 시행착오와 함께, Spring Security와 OAuth2, JWT를 활용해 AI 기능을 안전하게 백엔드에 통합하는 법을 정리해보려고 한다. 특히 AI 호출 비용과 지연 문제를 고려한 비동기 처리, 캐싱 전략도 함께 살펴보자.

---

## Spring Security와 OAuth2, JWT로 AI API 접근을 단단하게 막는 법

AI API는 보통 외부 서비스라 API 키나 토큰으로 인증한다. 그런데 우리 백엔드가 AI API 호출을 중계하는 구조라면, 내부 사용자 인증과 AI API 호출 권한을 분명히 해야 한다. Spring Boot는 Spring Security 모듈과 OAuth2, JWT를 기본 지원해서 이 부분을 꽤 깔끔하게 처리할 수 있다.

예를 들어, 사용자가 AI 기능을 쓰려면 JWT로 인증된 상태여야 하고, AI 호출 권한이 있는지 권한 검사를 해야 한다. Spring Security 설정에서 다음과 같이 OAuth2 Resource Server 설정을 추가해 JWT 인증을 처리할 수 있다:

```java
@Configuration
@EnableWebSecurity
public class SecurityConfig extends WebSecurityConfigurerAdapter {

    @Override
    protected void configure(HttpSecurity http) throws Exception {
        http
            .authorizeRequests()
                .antMatchers("/api/ai/**").hasRole("AI_USER")
                .anyRequest().authenticated()
            .and()
            .oauth2ResourceServer()
                .jwt();
    }
}
```

이렇게 하면 `/api/ai/**` 경로에 대해 `AI_USER` 권한이 있는 사용자만 접근 가능하다. 내부에서 AI API를 호출할 때는 별도의 서비스 계정 토큰을 안전하게 관리하고, 호출 시점에 헤더에 넣어준다. Spring Boot 공식 문서에서도 이런 인증 방식을 권장하고 있다[Spring Boot Reference Documentation](https://docs.spring.io/spring-boot/reference/).

## AI 호출 시점에 권한 검사와 로깅을 놓치지 않는 방법

AI API 호출은 비용과 민감한 데이터 처리 때문에 호출 시점마다 권한과 호출 이력을 꼼꼼히 관리해야 한다. Spring Framework의 의존성 주입(DI)과 AOP(Aspect Oriented Programming)를 활용하면 이걸 깔끔하게 분리할 수 있다.

예를 들어, AI 호출 서비스에 권한 검사와 로깅을 AOP로 넣으면, 실제 비즈니스 로직과 보안 로직이 섞이지 않아 유지보수가 편하다. 아래는 간단한 AOP 예시다:

```java
@Aspect
@Component
public class AiSecurityAspect {

    @Before("execution(* com.example.ai.AiService.call*(..))")
    public void checkPermission(JoinPoint joinPoint) {
        Authentication auth = SecurityContextHolder.getContext().getAuthentication();
        if (auth == null || !auth.getAuthorities().contains(new SimpleGrantedAuthority("ROLE_AI_USER"))) {
            throw new AccessDeniedException("AI 호출 권한이 없습니다.");
        }
    }

    @AfterReturning(pointcut = "execution(* com.example.ai.AiService.call*(..))", returning = "result")
    public void logCall(JoinPoint joinPoint, Object result) {
        // 호출 로그 기록
        System.out.println("AI API 호출 완료: " + joinPoint.getSignature().getName());
    }
}
```

이런 구조는 권한 검사 코드를 여러 서비스에 반복하지 않아도 되고, AI 호출 관련 보안 정책이 바뀌면 Aspect만 수정하면 돼서 편하다[Spring Framework - Core Technologies](https://docs.spring.io/spring-framework/reference/core.html).

## AI API 호출 지연과 비용 문제, 비동기 처리와 캐싱으로 해결하기

AI API는 응답 시간이 길고 호출당 비용이 꽤 나간다. 그래서 동기 호출로 바로 응답을 기다리면 사용자 경험이 나빠지고 비용도 통제가 어렵다. Baeldung의 Spring Boot 성능 튜닝 가이드에 따르면, 비동기 처리와 캐싱을 적극 활용하는 게 좋다[Baeldung - Spring Boot Performance Tuning](https://www.baeldung.com/spring-boot-performance).

Spring Boot에서는 `@Async` 애노테이션과 `CompletableFuture`를 이용해 쉽게 비동기 호출을 구현할 수 있다. 예를 들어:

```java
@Service
public class AiService {

    @Async
    public CompletableFuture<String> callAiApiAsync(String prompt) {
        // AI API 호출 코드 (예: OpenAI REST 호출)
        String response = callExternalAiApi(prompt);
        return CompletableFuture.completedFuture(response);
    }

    private String callExternalAiApi(String prompt) {
        // 실제 HTTP 요청 및 응답 처리
        // ...
        return "AI 응답 결과";
    }
}
```

컨트롤러에서는 이렇게 비동기 결과를 받을 수 있다:

```java
@GetMapping("/api/ai/generate")
public CompletableFuture<ResponseEntity<String>> generate(@RequestParam String prompt) {
    return aiService.callAiApiAsync(prompt)
        .thenApply(response -> ResponseEntity.ok(response));
}
```

또한, 같은 프롬프트에 대해 반복 호출을 줄이려면 캐싱을 적용하는 게 핵심이다. Spring Cache를 사용해 메모리나 Redis에 결과를 저장하면, 비용과 응답 속도를 크게 개선할 수 있다.

```java
@Cacheable(value = "aiResponses", key = "#prompt")
public String callExternalAiApi(String prompt) {
    // ...
}
```

## AI 요청 전처리와 민감 정보 필터링, Anthropic 가이드에서 배운 점

AI 모델에 보내는 프롬프트는 보안상 취약점이 될 수 있다. 민감한 개인정보가 포함되면 안 되고, 악의적인 입력으로 모델이 이상 동작할 수도 있다. Anthropic의 프롬프트 엔지니어링 가이드에서는 입력값 검증과 민감 정보 필터링을 반드시 하라고 권장한다[Anthropic - Prompt Engineering Guide](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/overview).

우리 팀은 AI 요청 전에 다음과 같은 검증 로직을 넣었다:

- 입력 길이 제한 (예: 최대 1000자)
- 금지어 필터링 (예: 개인정보, API 키, 내부 코드 등)
- 특수문자나 스크립트 삽입 방지

간단한 예시로, Spring Validator를 활용해 프롬프트 길이와 패턴을 체크하는 코드는 다음과 같다:

```java
@Component
public class PromptValidator implements Validator {

    private static final int MAX_LENGTH = 1000;
    private static final Pattern FORBIDDEN_PATTERN = Pattern.compile("(api_key|password|secret)", Pattern.CASE_INSENSITIVE);

    @Override
    public boolean supports(Class<?> clazz) {
        return String.class.equals(clazz);
    }

    @Override
    public void validate(Object target, Errors errors) {
        String prompt = (String) target;
        if (prompt.length() > MAX_LENGTH) {
            errors.rejectValue("prompt", "length", "프롬프트가 너무 깁니다.");
        }
        if (FORBIDDEN_PATTERN.matcher(prompt).find()) {
            errors.rejectValue("prompt", "forbidden", "민감한 정보가 포함되어 있습니다.");
        }
    }
}
```

이 검증기를 컨트롤러에 적용해 AI 호출 전에 무조건 필터링한다.

## 대규모 서비스에서 AI 기능 점진적 롤아웃과 모니터링 전략

AI 기능은 한 번에 전체 서비스에 풀로 적용하면 위험하다. GitHub 엔지니어링 블로그에서는 점진적 롤아웃과 실시간 모니터링, 피드백 루프를 통해 문제를 조기에 발견하고 대응하는 전략을 소개한다[GitHub Engineering Blog](https://github.blog/category/engineering/).

우리도 다음과 같은 절차를 따랐다:

1. 내부 직원 일부 그룹에만 AI 기능 베타 테스트 오픈
2. 호출 로그, 응답 지연, 오류율, 비용 지표를 실시간 대시보드로 모니터링
3. 이상 징후 발견 시 즉시 롤백하거나 호출 제한 강화
4. 사용자 피드백을 받아 프롬프트 필터링과 권한 정책 보완

이 과정에서 Spring Actuator와 Micrometer를 활용해 메트릭을 수집하고, Prometheus와 Grafana로 시각화했다. 이게 없으면 AI 호출 비용 폭증이나 보안 사고를 놓치기 쉽다.

## 마무리하며: AI 통합, 보안과 성능은 함께 챙겨야 한다

처음엔 AI API 호출만 하면 끝날 줄 알았는데, 실제로는 보안, 성능, 운영 측면에서 신경 쓸 게 한두 가지가 아니었다. Spring Security와 OAuth2, JWT를 활용해 권한과 인증을 단단히 하고, AOP로 보안 로직을 분리하며, 비동기 처리와 캐싱으로 비용과 응답 속도를 최적화하는 게 핵심이다.

또한, Anthropic 가이드처럼 프롬프트 검증과 민감 정보 필터링을 반드시 넣어야 하고, GitHub 사례처럼 점진적 롤아웃과 모니터링 체계를 갖춰야 한다. 이걸 안 하면 작은 문제라도 서비스 전체에 큰 피해를 줄 수 있다.

실제로 우리 팀에서 이 방법들을 적용한 뒤 AI 기능 도입 초기 비용을 30% 이상 절감했고, 보안 사고 없이 안정적으로 운영 중이다. 여러분도 AI 기능 붙일 때 꼭 보안과 운영 전략을 함께 고민해보길 권한다.
