## AI 모델 통합, 그냥 API 호출만 하면 끝일까?

최근 우리 팀에서 OpenAI와 Anthropic의 최신 AI 모델을 Spring AI 2.0 기반 백엔드에 붙이는 작업을 진행하면서 느낀 건, 단순히 API 호출만 한다고 끝나는 게 아니라는 점이었다. 특히 프로덕션 환경에서 안정성과 성능, 그리고 보안까지 챙기려면 생각보다 손볼 부분이 많다. 이번 글에서는 내가 실제로 겪은 시행착오와 노하우를 중심으로, Spring AI 2.0과 두 AI 플랫폼을 어떻게 효율적으로 결합했는지 구체적으로 얘기해보려 한다.

## Spring AI 2.0, 왜 지금 도입해야 할까?

Spring AI 2.0은 Spring Boot와 Spring Framework 최신 버전을 기반으로 만들어져 있다. 덕분에 기존에 우리가 익숙한 DI(Dependency Injection)와 AOP(Aspect-Oriented Programming) 같은 핵심 기술을 그대로 활용하면서 AI 모델 호출 로직을 모듈화할 수 있다. 이게 왜 중요하냐면, 예를 들어 API 호출 시 보안 토큰 관리나 로깅, 예외 처리 같은 횡단 관심사를 AOP로 깔끔하게 분리할 수 있기 때문이다. 

실제로 우리 팀은 Spring AI 2.0 덕분에 OpenAI와 Anthropic API 호출 부분을 별도의 서비스 레이어로 분리하고, 보안 관련 Aspect를 적용해 토큰 만료 시 자동 갱신 로직을 넣을 수 있었다. 이렇게 하면 코드가 훨씬 깔끔해지고, 나중에 유지보수할 때도 편하다.

> Spring AI 2.0은 생산 환경에 적합한 백엔드 아키텍처 패턴과 보안 롤아웃 전략을 기본 지원한다는 점이 큰 장점이다[Spring Boot Reference Documentation](https://docs.spring.io/spring-boot/reference/).

## JVM 튜닝과 비동기 처리로 AI API 호출 지연 최소화하기

AI API 호출은 네트워크 왕복과 모델 처리 시간이 있어서 기본적으로 지연 시간이 꽤 있다. 우리 서비스는 사용자 경험에 민감해서 최대한 응답 속도를 줄여야 했다. 그래서 JVM 튜닝과 스레드 관리, 캐싱, 비동기 처리에 집중했다.

먼저 JVM 옵션부터 살펴보면, 기본 힙 메모리 설정을 서비스 규모에 맞게 2G로 잡고, G1 GC를 사용했다. G1 GC는 짧고 예측 가능한 GC 시간을 보장해서 API 호출 중간에 멈춤 현상을 줄여준다. 

스레드 풀은 CPU 코어 수의 2배로 맞추고, AI API 호출은 `@Async` 어노테이션을 써서 비동기로 처리했다. 이렇게 하면 메인 요청 쓰레드가 블로킹되지 않고, 응답을 기다리는 동안 다른 작업을 처리할 수 있다.

```java
@Service
public class OpenAIService {

    private final RestTemplate restTemplate;
    private final String openAiApiKey;

    public OpenAIService(@Value("${openai.api.key}") String apiKey) {
        this.restTemplate = new RestTemplate();
        this.openAiApiKey = apiKey;
    }

    @Async
    public CompletableFuture<String> callOpenAI(String prompt) {
        HttpHeaders headers = new HttpHeaders();
        headers.setBearerAuth(openAiApiKey);
        headers.setContentType(MediaType.APPLICATION_JSON);

        Map<String, Object> body = Map.of(
            "model", "gpt-4",
            "prompt", prompt,
            "max_tokens", 500
        );

        HttpEntity<Map<String, Object>> request = new HttpEntity<>(body, headers);

        ResponseEntity<String> response = restTemplate.postForEntity(
            "https://api.openai.com/v1/completions", request, String.class);

        return CompletableFuture.completedFuture(response.getBody());
    }
}
```

위 코드처럼 `@Async`를 붙이면 호출하는 쪽에서 `CompletableFuture`로 결과를 비동기적으로 받을 수 있다. 다만, 비동기 처리 시 예외 처리가 복잡해질 수 있으니 적절한 예외 핸들링과 타임아웃 설정은 필수다.

또한, 자주 쓰는 프롬프트 결과는 Redis 캐시에 저장해서 동일 요청에 대한 불필요한 API 호출을 줄였다. 캐시 TTL은 5분으로 설정했는데, 실제로 이 정도면 최신성도 유지하면서 호출 비용을 크게 줄일 수 있었다.

> JVM 설정과 스레드 풀, 캐싱, 비동기 처리 최적화는 OpenAI 및 Anthropic API 통합에서 지연 시간을 최소화하는 데 핵심이다[Baeldung - Spring Boot Performance Tuning](https://www.baeldung.com/spring-boot-performance).

## Anthropic Claude 모델과 프롬프트 엔지니어링: 백엔드에서 어떻게 관리할까?

Anthropic Claude 모델은 OpenAI와 달리 프롬프트 엔지니어링에 더 신경 써야 하는 편이다. 명확한 지침과 컨텍스트 유지가 모델 성능에 큰 영향을 미치기 때문이다. 우리 팀은 Spring AI 2.0 모듈을 활용해 프롬프트 템플릿을 관리하고, 입력 검증과 안전성 검증 로직을 백엔드에 통합했다.

예를 들어, 사용자가 입력한 내용 중 민감한 정보가 포함됐는지 검사하고, 프롬프트에 자동으로 필터링 문구를 추가하는 식이다. 이렇게 하면 모델이 불필요한 편향이나 부적절한 응답을 줄일 수 있다.

```java
@Component
public class ClaudePromptService {

    public String buildPrompt(String userInput) {
        // 기본 프롬프트 템플릿
        String basePrompt = "You are Claude, an AI assistant. Please answer clearly and politely.";

        // 민감 정보 필터링
        if (containsSensitiveInfo(userInput)) {
            userInput = filterSensitiveInfo(userInput);
        }

        return basePrompt + "\nUser: " + userInput + "\nClaude:";
    }

    private boolean containsSensitiveInfo(String input) {
        // 간단한 예시: 주민등록번호 형식 체크
        return input.matches(".*\\d{6}-\\d{7}.*");
    }

    private String filterSensitiveInfo(String input) {
        return input.replaceAll("\\d{6}-\\d{7}", "[REDACTED]");
    }
}
```

이런 프롬프트 관리 모듈 덕분에, Anthropic API 호출 시 일관된 품질과 안전성을 유지할 수 있었다. 물론 프롬프트 튜닝은 계속 반복해야 하는 작업이라, 개발 초기에는 여러 차례 테스트와 조정이 필요하다.

> Anthropic Claude 모델과 Spring AI 2.0 결합 시, 프롬프트 엔지니어링과 안전성 검증 모듈 통합이 권장된다[Anthropic - Prompt Engineering Guide](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/overview).

## 보안 롤아웃 전략과 API 호출 제한 관리

AI API는 호출량에 따라 비용과 서비스 안정성이 크게 달라진다. 그래서 우리 팀은 Spring AOP를 활용해 API 호출 전후에 토큰 유효성 검사, 호출 제한 체크, 실패 시 재시도 로직을 넣었다. 

특히 OpenAI API는 토큰 관리가 까다로운데, 토큰이 만료되면 자동으로 재발급하도록 구현해 서비스 다운타임을 방지했다. 아래는 AOP를 활용한 호출 제한 체크 예시다.

```java
@Aspect
@Component
public class ApiRateLimitAspect {

    private final RateLimiter rateLimiter = RateLimiter.create(10.0); // 초당 10회 제한

    @Around("execution(* com.example.ai.*Service.*(..))")
    public Object limitApiCalls(ProceedingJoinPoint pjp) throws Throwable {
        if (!rateLimiter.tryAcquire(1, TimeUnit.SECONDS)) {
            throw new RuntimeException("API 호출 제한 초과");
        }
        return pjp.proceed();
    }
}
```

이렇게 하면 AI API 호출을 초당 10회로 제한해서 과금 폭탄이나 서비스 장애를 예방할 수 있다. 물론 실제 서비스에서는 좀 더 정교한 분산 카운터나 외부 API 게이트웨이와 연동하는 방법도 고려해야 한다.

> Spring Framework의 DI와 AOP는 보안 및 로깅 기능 확장에 아주 유용하며, API 호출 제한과 토큰 관리에 효과적이다[Spring Framework - Core Technologies](https://docs.spring.io/spring-framework/reference/core.html).

## 마치며: AI 통합, 실무에서 꼭 챙겨야 할 것들

이번 프로젝트를 통해 내가 느낀 건, AI 모델 통합은 단순히 API 호출만 잘 하는 게 아니라는 점이다. JVM 튜닝, 비동기 처리, 캐싱, 프롬프트 엔지니어링, 보안 롤아웃까지 모두 신경 써야 진짜 프로덕션급 서비스가 나온다.

- **JVM과 스레드 풀 설정**: G1 GC, 힙 메모리 2G, CPU 코어 수 2배 스레드 풀로 응답 지연 최소화
- **비동기 API 호출**: `@Async`와 `CompletableFuture`로 메인 쓰레드 블로킹 방지
- **프롬프트 관리 모듈**: Anthropic Claude에 맞는 입력 필터링과 템플릿 관리
- **AOP 활용 보안/로깅**: 토큰 만료 자동 갱신, 호출 제한, 예외 처리 일원화
- **캐싱 전략**: Redis로 프롬프트 결과 5분 TTL 캐시해 비용 절감

이 중 한두 개만 빼먹어도 예상치 못한 장애나 비용 폭탄이 날 수 있으니, 꼭 꼼꼼히 챙기길 바란다. 그리고 Spring AI 2.0은 이런 패턴을 기본 제공해주니, 아직 안 써봤다면 지금 당장 시도해보는 걸 추천한다.
