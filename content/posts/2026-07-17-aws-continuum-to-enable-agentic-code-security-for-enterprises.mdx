## "우리 코드가 스스로 보안을 지킨다? AWS Continuum 도입 현장에서 느낀 점"

최근 우리 팀에서는 AWS Continuum을 도입해 에이전틱 코드 보안을 한 단계 끌어올리는 작업을 진행했어요. “에이전틱 코드(Agentic Code)”라는 말 자체가 아직 낯설 수도 있지만, 쉽게 말해 코드가 자율적으로 보안 위협을 감지하고 대응하는 능력을 갖춘다는 뜻이죠. 그런데 이걸 실제 엔터프라이즈 환경에 적용하려니, 단순히 AI 에이전트를 붙이는 것만으론 부족하다는 걸 뼈저리게 느꼈습니다.

특히 백엔드 아키텍처와 운영 방식을 어떻게 설계하느냐에 따라 보안 효과가 천차만별이더라고요. 그래서 이번 글에서는 AWS Continuum을 활용해 에이전틱 코드 보안을 실무에서 어떻게 구현할 수 있는지, 제가 직접 겪은 경험과 함께 공유하려 합니다.

---

## AWS Well-Architected Framework가 말하는 보안 중심 아키텍처란?

AWS Continuum을 도입하면서 가장 먼저 참고한 게 바로 [AWS Well-Architected Framework](https://docs.aws.amazon.com/wellarchitected/latest/framework/welcome.html)입니다. 이 프레임워크는 엔터프라이즈 환경에서 보안, 신뢰성, 성능, 비용, 운영 우수성을 보장하기 위한 아키텍처 설계 원칙을 제시하는데, 특히 보안 부분이 에이전틱 코드 보안 강화에 필수적이었어요.

예를 들어, IAM(Identity and Access Management) 역할을 엄격히 분리하고 최소 권한 원칙을 적용하는 게 기본 중 기본입니다. 우리 팀도 AWS Continuum과 연동하는 마이크로서비스별로 역할을 세분화해서, 각 서비스가 필요한 리소스에만 접근하도록 제한했어요. 덕분에 내부 위협이나 권한 남용 가능성을 크게 줄일 수 있었습니다.

또한, 로그와 모니터링 체계를 잘 갖춰야 하는데, AWS CloudTrail과 CloudWatch를 적극 활용해 에이전틱 코드가 수행하는 모든 행위를 실시간으로 감시할 수 있게 했죠. 이게 실제로 문제가 생겼을 때 원인 분석과 대응 시간을 줄이는 데 큰 도움이 됐습니다.

## 마이크로서비스와 이벤트 기반 패턴으로 실시간 위협 감지 구현하기

AWS Architecture Blog에 따르면, AWS Continuum을 통합한 백엔드 시스템에서는 [마이크로서비스 아키텍처와 이벤트 기반 패턴](https://aws.amazon.com/blogs/architecture/)을 활용해 에이전틱 코드 보안을 자동화하고 실시간 위협 감지를 구현하는 게 핵심이라고 합니다.

우리도 이 방식을 그대로 적용했는데요, 예를 들어 보안 이벤트가 발생하면 해당 이벤트를 SNS나 EventBridge로 발행하고, 이를 구독하는 별도의 보안 모니터링 서비스가 즉시 분석 및 대응 조치를 수행하도록 했어요. 이렇게 하면 단일 장애 지점 없이 보안 위협에 빠르게 대응할 수 있습니다.

아래는 간단한 이벤트 발행 예시입니다.

```python
import boto3

sns_client = boto3.client('sns')

SECURITY_TOPIC_ARN = 'arn:aws:sns:ap-northeast-2:123456789012:SecurityEvents'

def publish_security_event(event_type, details):
    message = {
        'eventType': event_type,
        'details': details
    }
    response = sns_client.publish(
        TopicArn=SECURITY_TOPIC_ARN,
        Message=str(message)
    )
    return response

# 예: 비정상 로그인 시도 감지 시 호출
publish_security_event('UnauthorizedAccess', {'ip': '203.0.113.42', 'userId': 'alice'})
```

이벤트 기반으로 분리된 아키텍처 덕분에 보안 담당 팀과 개발 팀 간에도 역할이 명확해지고, 대응 속도도 눈에 띄게 빨라졌어요.

## OpenAI API와 AWS Continuum 연동 시 주의할 점

AWS Continuum은 AI 기반 에이전트를 활용하는 만큼, OpenAI API 같은 외부 AI 서비스와의 연동도 필수적입니다. [OpenAI API Documentation](https://platform.openai.com/docs/overview)을 보면, API 호출 최적화와 인증, 권한 부여, 데이터 프라이버시 보호가 백엔드 구현의 핵심이라고 명시되어 있죠.

우리 팀은 다음과 같은 점에 특히 신경 썼어요.

- **보안 토큰 관리:** API 키를 AWS Secrets Manager에 안전하게 저장하고, Lambda 함수에서 호출 시마다 동적으로 가져오도록 했습니다.
- **요청 제한 정책:** OpenAI API는 호출량 제한이 있으니, 내부 큐잉 시스템과 캐싱을 도입해 불필요한 중복 호출을 줄였죠.
- **데이터 프라이버시:** 민감 데이터는 AI 에이전트에 넘기기 전에 암호화하거나 익명화 처리했습니다.

이런 조치 덕분에 AI 에이전트가 실시간으로 코드를 분석하고 보안 취약점을 탐지하는 데 무리 없이 연동할 수 있었어요.

## 프롬프트 설계도 보안의 시작, Anthropic 가이드에서 배운 점

AI 에이전트가 안전하고 정확하게 동작하려면 프롬프트 설계도 중요합니다. [Anthropic의 Prompt Engineering Guide](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/overview)에서는 AI 에이전트가 실행할 코드에 대해 명확하고 안전한 지침을 주는 게 보안 강화에 필수라고 강조하죠.

우리도 AWS Continuum과 연동하는 백엔드 서비스에서, AI에게 코드를 생성하거나 수정하도록 요청할 때 다음과 같은 정책을 적용했습니다.

- 실행 가능한 코드 범위 제한
- 민감 정보 접근 금지
- 의심스러운 패턴 탐지 후 자동 검증 프로세스 연계

이 과정에서 프롬프트 내에 보안 정책을 명시적으로 포함시키고, AI가 생성한 코드를 다시 한번 내부 보안 검사 모듈에서 검증하는 흐름을 만들었어요. 처음에는 번거로웠지만, 이게 실제로 보안 사고를 예방하는 데 큰 역할을 했습니다.

## 실시간 코드 분석과 자동 완성으로 개발 생산성도 챙기기

보안 강화만큼 중요한 게 개발 생산성 유지죠. [Cursor Documentation](https://docs.cursor.com/)에 따르면, AI 기반 코드 보안 도구를 통합하면 코드 자동 완성, 오류 탐지 기능으로 개발 속도를 높이면서 보안 취약점도 사전에 잡을 수 있다고 합니다.

우리 팀도 AWS Continuum과 결합해 실시간 코드 분석 아키텍처를 구축했는데, 예를 들어 Pull Request가 생성되면 AI가 자동으로 코드를 스캔해서 잠재적 취약점을 알려줍니다. 그리고 개발자는 Cursor와 같은 AI 도구의 자동 완성 기능을 활용해 보안 권장 코드를 빠르게 작성할 수 있죠.

이런 워크플로우는 코드 품질 향상뿐 아니라, 보안 교육 효과도 겸해서 신입 개발자들이 빠르게 보안 감각을 익히는 데 도움을 줬어요.

## 실제로 AWS Continuum 도입할 때 꼭 기억해야 할 점

마지막으로, AWS Continuum을 엔터프라이즈 백엔드에 도입하면서 경험한 몇 가지 중요한 팁을 공유할게요.

1. **권한 분리와 최소 권한 원칙은 필수**
   - IAM 역할을 세분화하지 않으면 에이전틱 코드가 오히려 공격 표면이 될 수 있습니다.

2. **이벤트 기반 아키텍처로 유연한 대응 체계 구축**
   - 단일 장애점 없이 보안 이벤트를 실시간 감지하고 대응할 수 있어야 합니다.

3. **AI API 연동 시 보안 토큰과 요청 제한 정책을 반드시 설계**
   - 무분별한 호출은 비용과 보안 모두에 악영향을 미칩니다.

4. **프롬프트에 보안 정책을 녹여내고, 결과 코드에 대한 재검증 프로세스 마련**
   - AI가 생성한 코드도 사람이 검증하는 단계가 반드시 필요합니다.

5. **개발 생산성 도구와 보안 도구의 조화**
   - AI 기반 자동 완성, 오류 탐지 기능과 보안 스캔을 함께 활용하면 보안과 개발 속도를 모두 잡을 수 있습니다.

---

AWS Continuum은 단순한 AI 도구가 아니라, 엔터프라이즈 백엔드 아키텍처와 운영 방식을 근본적으로 재설계할 수 있는 기회입니다. 물론 초기 도입과정에서 복잡하고 까다로운 부분이 많지만, 제대로 구축하면 에이전틱 코드 보안이 현실이 된다는 점에서 투자할 가치가 충분하다고 생각해요.

혹시 AWS Continuum 도입이나 에이전틱 코드 보안에 대해 더 궁금한 점 있으면 언제든 편하게 연락 주세요. 같이 고민해보면 좋겠습니다!
