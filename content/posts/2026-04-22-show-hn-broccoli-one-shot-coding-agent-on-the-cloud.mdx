## Broccoli를 처음 만난 날, 내 작업 환경이 바뀌었다

"코드 한 줄 수정하는 데 매번 에디터와 콘솔을 왔다갔다하는 게 너무 번거롭다" 이런 생각, 다들 한 번쯤 해봤을 겁니다. 나도 그랬고요. 그런데 Broccoli라는 원샷(one shot) 코딩 에이전트를 클라우드 환경에 올려서 써보니, 그 번거로움이 꽤 줄더라고요. 원샷 코딩이란 말 그대로 한 번의 프롬프트로 원하는 코드를 생성하거나 수정하는 방식인데, Broccoli는 이걸 클라우드에서 바로 처리해 줍니다. 덕분에 로컬 세팅 없이도 빠르게 코드를 얻을 수 있었죠.

## 원샷 코딩 에이전트가 클라우드에서 왜 더 빛나는가

Broccoli 같은 AI 코딩 에이전트는 클라우드와 찰떡궁합입니다. 이유는 간단해요. 클라우드 환경은 이미 네트워크 연결과 API 호출에 최적화되어 있고, 대규모 컴퓨팅 리소스를 활용할 수 있거든요. 예를 들어, OpenAI API 문서에서 말하는 것처럼 원샷 프롬프트를 통해 빠르게 코드를 생성하거나 수정하는 게 가능해요. 실제로 Broccoli도 이런 접근법을 활용하는데, 한 번의 명령으로 복잡한 함수나 설정 파일을 만들어내는 데 1~2초면 충분했습니다[OpenAI API Documentation](https://platform.openai.com/docs/overview).

이걸 로컬에서 직접 하려면 환경 세팅부터 시작해서, 라이브러리 충돌, 버전 문제 등으로 시간 잡아먹기 십상인데, 클라우드에서 바로 처리하니 개발 흐름이 끊기지 않더라고요. 특히 팀 단위로 작업할 때도 환경 차이 걱정 없이 같은 AI 에이전트를 쓸 수 있다는 점이 큰 장점입니다.

## Broccoli를 쓰면서 직접 마주친 보안 이슈와 대응법

하지만 클라우드에서 AI 코딩 에이전트를 쓸 때 보안은 절대 간과할 수 없는 부분입니다. API 키 같은 민감 정보가 노출되면 곤란하니까요. OpenAI 공식 문서에서도 API 키는 절대 코드에 하드코딩하지 말고 환경 변수나 시크릿 매니저를 통해 안전하게 관리하라고 강조합니다[OpenAI API Documentation](https://platform.openai.com/docs/overview).

Broccoli를 도입하면서 우리 팀도 이런 보안 모범 사례를 철저히 지켰습니다. 예를 들어, AWS Secrets Manager를 써서 API 키를 관리했고, Broccoli가 호출하는 서버리스 함수 내에서는 키를 직접 노출하지 않고 토큰 기반 인증을 추가했죠. 이렇게 하니 외부 공격에 대한 걱정이 한결 줄었습니다.

또 한 가지는, AI가 생성하는 코드에 민감한 정보가 포함되지 않도록 프롬프트 설계에도 신경 썼습니다. GitHub Copilot도 비슷한 고민을 하면서 코드 스니펫 검토 기능을 강화하고 있는데, Broccoli도 앞으로 이런 보안 기능을 추가하면 좋겠더라고요[GitHub Copilot Documentation](https://docs.github.com/en/copilot).

## Anthropic Claude Code에서 배운 프롬프트 엔지니어링의 중요성

Broccoli가 원샷 코딩을 잘한다고 해도, 결국 프롬프트가 얼마나 잘 짜여 있느냐가 결과 품질을 좌우합니다. Anthropic의 Claude Code 문서를 보면, 프롬프트 엔지니어링을 통해 정확도와 코드 품질을 크게 높일 수 있다고 하죠[Anthropic - Claude Code Overview](https://docs.anthropic.com/en/docs/claude-code/overview).

우리도 Broccoli에 "이 함수는 입력값 검증을 반드시 포함하고, 예외 처리를 명확히 하라" 같은 구체적인 지시를 넣으니, 처음보다 훨씬 안정적인 코드를 뽑아내더라고요. 예를 들어, 아래처럼 간단한 원샷 프롬프트를 써봤습니다:

```python
# Broccoli에게 보내는 프롬프트 예시
prompt = '''
Write a Python function named `safe_divide` that takes two parameters `a` and `b`. 
It should return the division result of `a / b`. 
Include input validation to check if `b` is zero and raise a ValueError in that case.
'''

response = broccoli.generate_code(prompt)
print(response)
```

이렇게 하면 Broccoli가 바로 예외 처리가 포함된 안전한 코드를 생성해 주죠. 물론, 프롬프트가 너무 길거나 모호하면 오히려 결과가 안 좋아지니, 적절한 길이와 명확한 지시가 관건입니다.

## Vercel AI SDK와 함께 쓰면 더 편리한 Broccoli

Broccoli를 그냥 API 호출로만 쓰는 것도 좋은데, Vercel AI SDK를 활용하면 클라우드 플랫폼에서 AI 기능을 훨씬 쉽게 통합할 수 있습니다. Vercel AI SDK는 프론트엔드와 백엔드 모두에서 AI 호출을 간편하게 만들어 주는데, Broccoli 같은 에이전트를 클라우드 함수와 연결할 때 특히 유용하죠[ Vercel AI SDK Documentation](https://sdk.vercel.ai/docs/introduction).

우리 팀은 Next.js 프로젝트에 Broccoli를 붙일 때 Vercel AI SDK를 써서, UI에서 바로 코드 생성 요청을 보내고 결과를 받아볼 수 있게 했습니다. 이렇게 하니 개발자뿐 아니라 디자이너, PM도 간단한 코드 요청을 할 수 있어 협업이 훨씬 수월해졌어요.

## Broccoli 도입 후 느낀 생산성 변화와 현실적인 한계

Broccoli를 쓰면서 가장 크게 느낀 건, "코드 작성 속도가 체감상 30~40%는 빨라졌다"는 점입니다. 특히 반복적인 CRUD 코드나 설정 파일 작성, 테스트 코드 생성 같은 작업에서 효과가 컸어요. 원샷 프롬프트 한 번에 원하는 결과를 얻으니, 여러 번 수정하고 테스트하는 시간이 확 줄었죠.

하지만 모든 게 완벽한 건 아닙니다. AI가 생성한 코드를 무조건 믿으면 안 되고, 반드시 리뷰하고 테스트해야 합니다. 때로는 프롬프트가 미묘하게 잘못되면 엉뚱한 코드가 나오기도 하고, 복잡한 비즈니스 로직은 아직 사람이 직접 짜는 게 낫더라고요.

그리고 클라우드 API 호출 비용도 무시 못 합니다. 우리 팀은 하루 1000회 호출 제한과 월 100달러 예산을 정해놓고 쓰는데, 이 범위 내에서 잘 관리하는 게 중요해요.

## 나만의 Broccoli 활용 팁

- **프롬프트는 최대 3문장, 구체적이고 명확하게**: 너무 길면 AI가 집중을 못 합니다.
- **API 키는 환경 변수 + 시크릿 매니저로 안전하게 보관**: 절대 코드에 직접 쓰지 말 것.
- **코드 리뷰는 필수, AI가 틀릴 수 있다는 전제하에 사용**
- **Vercel AI SDK 같은 툴로 UI와 연동하면 협업 생산성 UP**
- **비용 모니터링은 꼭, 호출 횟수와 예산 한도 설정 필수**
