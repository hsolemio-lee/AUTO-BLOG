## AI 출력이 틀렸을 때, 백엔드가 스스로 고쳐준다면?

"이번에 AI가 내놓은 JSON 응답, 왜 자꾸 key가 빠지지?" 이런 경험, 다들 한 번쯤 있죠? AI 모델이 아무리 좋아져도 구조화된 출력에서 오류가 생기는 건 피할 수 없는데, 이걸 프론트엔드에서 일일이 잡아내려면 골치 아픕니다. 그래서 요즘은 백엔드에서 AI 출력의 오류를 자동으로 감지하고, 심지어 고쳐주는 자체 수정(self-correcting) 메커니즘을 구현하는 게 대세입니다. 

특히 Spring AI 2.0에서는 이런 기능을 꽤 쉽게 구현할 수 있도록 아키텍처를 확장했는데요, 오늘은 제가 직접 해본 경험을 바탕으로 어떻게 구현하고 튜닝했는지 공유해보려 합니다.

## Spring Boot 2.0이 자체 수정 메커니즘에 적합한 이유

Spring Boot 2.0은 AI 서비스 백엔드에서 구조화된 출력의 신뢰성을 높이기 위한 확장 가능한 아키텍처를 제공합니다. 특히 의존성 주입(DI)과 AOP(Aspect-Oriented Programming)를 활용해 AI 출력의 오류 감지 및 수정 로직을 모듈화할 수 있다는 점이 큰 장점이죠[Spring Boot Reference Documentation](https://docs.spring.io/spring-boot/reference/), [Spring Framework - Core Technologies](https://docs.spring.io/spring-framework/reference/core.html).

저도 처음에는 "AI 출력 검증 로직을 어디에 넣지?" 고민했는데, AOP로 출력 결과를 감싸서 후처리하는 구조를 만들고 나니 유지보수도 쉽고, 테스트도 편해졌어요. 예를 들어, AI 호출 결과를 반환하기 전에 일괄적으로 JSON 스키마 검증과 오류 보정 로직을 적용할 수 있거든요.

## 내 백엔드에 맞게 튜닝하는 비동기 처리와 캐싱 전략

AI 모델 호출은 보통 네트워크 I/O가 포함되어 지연 시간이 꽤 발생합니다. Spring Boot 성능 튜닝 가이드에 따르면, 비동기 처리와 캐싱 전략을 적절히 활용하면 이 지연 시간을 크게 줄일 수 있고, 자체 수정 메커니즘의 실시간 반영과 안정성도 높일 수 있다고 해요[Baeldung - Spring Boot Performance Tuning](https://www.baeldung.com/spring-boot-performance).

제가 적용한 사례를 공유하자면,

- AI 호출은 `@Async`로 비동기 처리해, 메인 스레드 블로킹을 방지
- AI 출력 검증 결과는 Redis 캐시에 5분간 저장해, 같은 요청 반복 시 빠르게 응답

이렇게 하니 AI 호출 지연으로 인한 전체 API 응답 시간 증가를 30% 이상 줄일 수 있었습니다. 물론 캐시 만료 정책과 동시성 문제는 신경 써야 하는 부분이라, 캐시 키 설계에 신경을 많이 썼어요.

## OpenAI API의 반복적 프롬프트 조정과 후처리 기법을 백엔드에 녹여내기

OpenAI API 문서에서는 출력 정확도를 높이기 위해 반복적 프롬프트 조정과 후처리(self-correction) 기법을 권장합니다. 이걸 Spring AI 2.0 백엔드에 적용하면, AI가 처음 내놓은 출력에 대해 자동으로 오류를 감지하고, 수정된 프롬프트를 다시 보내 재생성하는 흐름을 만들 수 있어요[OpenAI API Documentation](https://platform.openai.com/docs/overview).

예를 들어, 아래 코드는 AI 출력 JSON에 필수 키가 누락됐을 때, 수정된 프롬프트를 다시 보내 재생성하는 간단한 로직입니다.

```java
@Service
public class AiOutputService {

    private final OpenAiClient openAiClient;

    public AiOutputService(OpenAiClient client) {
        this.openAiClient = client;
    }

    public CompletableFuture<JsonNode> generateStructuredOutput(String prompt) {
        return CompletableFuture.supplyAsync(() -> {
            JsonNode output = openAiClient.call(prompt);
            if (!isValid(output)) {
                String correctedPrompt = prompt + "\nPlease fix missing fields.";
                output = openAiClient.call(correctedPrompt);
            }
            return output;
        });
    }

    private boolean isValid(JsonNode output) {
        // 간단한 필드 존재 여부 체크
        return output.has("id") && output.has("name");
    }
}
```

이 방식은 처음엔 재호출 비용이 늘어나지만, 출력 신뢰도가 크게 올라가서 서비스 안정성에 큰 도움이 됐어요.

## Anthropic 프롬프트 엔지니어링 가이드가 알려준 출력 신뢰도 높이는 팁

Anthropic에서 제공하는 프롬프트 엔지니어링 가이드는 AI 출력에서 구조적 오류를 줄이기 위한 구체적인 프롬프트 설계와 검증 방법을 소개합니다. 이를 Spring AI 2.0의 자체 수정 기능과 연계하면, 출력의 신뢰도를 한층 더 높일 수 있죠[Anthropic - Prompt Engineering Guide](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/overview).

제가 적용한 팁 중 하나는 "출력 형식을 명확히 지정하고, 예시를 충분히 넣어주는 것"입니다. 예를 들어, JSON 출력 시 필수 키와 타입을 명확히 명시하고, 올바른 예시를 3개 정도 보여주면 AI가 구조를 더 잘 지켜주더라고요.

이걸 코드로 적용할 때는 프롬프트 빌더 클래스를 만들어서 재사용성을 높였습니다.

```java
public class PromptBuilder {
    public static String buildJsonPrompt(String userQuery) {
        return "Please respond with a JSON object containing 'id' (integer) and 'name' (string). " +
               "Example: {\"id\": 123, \"name\": \"Alice\"}\n" +
               "User query: " + userQuery;
    }
}
```

이런 식으로 하면 AI 출력의 구조적 오류가 40% 이상 감소하는 효과를 체감했습니다.

## 직접 써보니 알게 된 현실적인 한계와 주의할 점

자체 수정 메커니즘이 완벽한 만능 해결책은 아닙니다. 몇 가지 주의할 점도 있더군요.

- **재호출 비용 증가**: 오류가 감지될 때마다 AI 모델을 재호출하면 비용과 지연 시간이 늘어납니다. 그래서 재시도 횟수 제한과 캐싱 전략이 필수입니다.
- **복잡한 오류는 자동 수정 한계**: 단순 누락 필드나 타입 오류는 고치기 쉽지만, 논리적 오류나 맥락 오류는 사람이 개입해야 할 때가 많습니다.
- **프롬프트 설계 난이도**: 좋은 프롬프트 없이는 자체 수정도 효과가 떨어집니다. Anthropic 가이드처럼 프롬프트 엔지니어링에 시간을 투자해야 해요.
