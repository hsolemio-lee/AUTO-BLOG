### AI 기능 붙이다가 보안 구멍 뚫릴 뻔한 경험, 다들 있죠?

최근 우리 팀에서 AI 챗봇 기능을 Spring Boot 백엔드에 붙이면서 겪은 일입니다. OpenAI API를 호출하는 부분은 금방 만들었는데, 정작 보안과 트래픽 급증 대응에서 어려움을 겪었죠. AI 모델 호출이 외부 API라서 인증 문제도 있고, 요청량이 갑자기 늘면 서버가 버티질 못했습니다. 이걸 어떻게 해결했는지, 그리고 실제 운영 환경에서 꼭 챙겨야 할 부분들을 정리해 봤어요.

## Spring Boot로 OpenAI API 연동, 비동기 호출이 답이다

우선 AI 기능은 대부분 외부 API 호출이 기본입니다. OpenAI API 같은 경우 REST 기반이라 Spring Boot에서 `WebClient`를 쓰면 편리한데요. 특히 비동기 호출을 통해 서버 리소스 낭비를 줄이고, 응답 지연도 최소화할 수 있습니다.

```java
@Service
public class OpenAiService {

    private final WebClient webClient;
    private final String apiKey = "sk-***"; // 실제론 환경변수로 관리

    public OpenAiService(WebClient.Builder builder) {
        this.webClient = builder.baseUrl("https://api.openai.com/v1")
                                .defaultHeader(HttpHeaders.AUTHORIZATION, "Bearer " + apiKey)
                                .build();
    }

    public Mono<String> generateText(String prompt) {
        Map<String, Object> requestBody = Map.of(
            "model", "gpt-4",
            "prompt", prompt,
            "max_tokens", 150
        );

        return webClient.post()
                .uri("/completions")
                .bodyValue(requestBody)
                .retrieve()
                .bodyToMono(JsonNode.class)
                .map(json -> json.get("choices").get(0).get("text").asText())
                .onErrorResume(e -> {
                    // 에러 로깅 및 기본 응답 처리
                    return Mono.just("죄송합니다, 현재 AI 응답을 처리할 수 없습니다.");
                });
    }
}
```

이렇게 하면 호출하는 쪽에서 `Mono<String>`을 받아서 논블로킹 방식으로 응답을 처리할 수 있어요. 실무에서 AI 호출 API가 느려질 때 서버 전체가 멈추는 걸 방지하는 데 꼭 필요합니다.[Spring Boot Reference Documentation](https://docs.spring.io/spring-boot/reference/)

## AI 호출 시 인증과 권한, Spring Security로 어떻게 지킬까?

AI API 호출은 단순히 외부 서비스 요청뿐 아니라, 우리 서비스 내에서 누가 어떤 AI 기능을 쓸지 철저히 관리해야 합니다. 예를 들어, 요금제별로 호출 횟수 제한을 두거나, 민감한 데이터 접근 권한을 구분할 때죠.

Spring Security는 OAuth 2.0과 JWT 기반 인증을 기본으로 지원해서, AI 기능 호출 시 안전한 접근 제어를 쉽게 구현할 수 있습니다. 예를 들어, JWT 토큰에 AI 기능 사용 권한을 담고, 필터에서 검증하는 식이죠.

```java
@EnableWebSecurity
public class SecurityConfig extends WebSecurityConfigurerAdapter {

    @Override
    protected void configure(HttpSecurity http) throws Exception {
        http
            .authorizeRequests()
                .antMatchers("/api/ai/**").hasAuthority("SCOPE_ai:use")
                .anyRequest().authenticated()
            .and()
            .oauth2ResourceServer()
                .jwt();
    }
}
```

이렇게 하면 `SCOPE_ai:use` 권한이 있는 사용자만 AI API를 호출할 수 있습니다. JWT 토큰은 OAuth 2.0 서버에서 발급받아야 하는데, 이 부분은 기존 인증 인프라와 통합하는 게 가장 좋습니다.[Spring Framework - Core Technologies](https://docs.spring.io/spring-framework/reference/core.html)

## AI 호출 급증, 성능 튜닝 없으면 서버가 버틴다?

AI API 요청은 일반 API보다 무겁고, 갑자기 트래픽이 몰릴 수 있어요. 우리 팀도 출시 초기에 AI 기능이 인기 많아지면서 서버가 느려지고, 심지어 타임아웃이 잦아졌습니다.

그래서 Spring Boot에서 스레드 풀, 캐싱, 비동기 처리를 적극 활용했습니다. 예를 들어, `TaskExecutor`를 커스텀해서 AI 호출용 스레드 풀을 따로 만들고, Redis 캐시로 동일 프롬프트에 대한 응답을 일정 시간 저장했죠.

```java
@Bean(name = "aiTaskExecutor")
public ThreadPoolTaskExecutor aiTaskExecutor() {
    ThreadPoolTaskExecutor executor = new ThreadPoolTaskExecutor();
    executor.setCorePoolSize(10);
    executor.setMaxPoolSize(50);
    executor.setQueueCapacity(100);
    executor.setThreadNamePrefix("ai-exec-");
    executor.initialize();
    return executor;
}
```

이걸 AI 호출 서비스에 주입해서 비동기로 실행하면, 메인 스레드가 막히지 않고 안정적인 응답을 유지할 수 있습니다. 캐시 전략도 프롬프트별로 5분 정도 TTL을 줘서 비용과 응답 속도 모두 잡았어요.[Baeldung - Spring Boot Performance Tuning](https://www.baeldung.com/spring-boot-performance)

## AI 프롬프트 설계, 비용과 품질을 동시에 잡는 법

AI API 호출 비용은 토큰 사용량에 비례해서 청구되기 때문에, 무작정 긴 프롬프트를 보내면 비용 폭탄 맞기 쉽습니다. OpenAI 공식 문서에서는 명확하고 구체적인 프롬프트 설계를 권장합니다.

예를 들어, "Write a Java method to reverse a string" 대신 "Write a Java method named `reverseString` that takes a `String` input and returns the reversed string"처럼 구체적으로 지시하는 게 좋죠. 이렇게 하면 AI가 더 정확한 답변을 주고, 불필요한 토큰 낭비를 줄일 수 있습니다.[OpenAI API Documentation](https://platform.openai.com/docs/overview)

Anthropic의 프롬프트 엔지니어링 가이드도 참고할 만한데, 안전성 측면에서 부적절한 답변을 막기 위한 명확한 지시문 작성법을 소개합니다. AI 응답 품질을 높이고, 의도치 않은 결과를 줄이는 데 큰 도움이 되었어요.[Anthropic - Prompt Engineering Guide](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/overview)

## 마이크로서비스와 클라우드 네이티브 보안으로 한 단계 업그레이드

AI 기능이 커지면 단일 백엔드에 다 몰아넣기보다, 마이크로서비스로 분리하는 게 유리합니다. GitHub 엔지니어링 블로그 사례처럼, AI 호출 서비스만 독립시키고 Kubernetes 같은 클라우드 네이티브 환경에서 오토스케일링과 네트워크 정책을 적용하면 확장성과 보안성을 동시에 잡을 수 있죠.

이때 서비스 간 인증은 mTLS, API Gateway에서 JWT 검증, 그리고 네트워크 레벨 방화벽 설정을 적극 활용해야 합니다. 이렇게 하면 AI 기능이 공격 벡터가 되지 않고, 전체 시스템 보안이 강화됩니다.[GitHub Engineering Blog](https://github.blog/category/engineering/)

### 마무리하며

처음 AI 기능 붙일 땐 "그냥 API 호출만 하면 되겠지" 했는데, 실제로는 보안, 성능, 비용 관리까지 챙겨야 할 게 한두 가지가 아니더라고요. 특히 Spring Boot와 Spring Security가 제공하는 인증·비동기·성능 튜닝 기능을 잘 활용하면, AI 기능을 안정적으로 운영할 수 있습니다.

프롬프트 설계도 단순히 문장 잘 쓰는 걸 넘어서 시스템 비용과 품질에 직결된다는 점, 꼭 기억하세요. 그리고 서비스가 커지면 마이크로서비스 아키텍처와 클라우드 네이티브 보안 전략을 고민하는 게 필수입니다.

이 글이 AI 시대에 Spring 백엔드 개발하면서 겪는 고민에 조금이나마 도움이 되길 바랍니다.
