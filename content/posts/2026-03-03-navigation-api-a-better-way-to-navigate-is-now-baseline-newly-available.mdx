## 페이지 전환, 아직도 느리다고 느껴지나요?

"페이지가 바뀌는데 왜 이렇게 오래 걸리지?" 이런 경험 한 번쯤은 다들 있을 겁니다. 특히 SPA(Single Page Application) 환경에서 라우팅과 데이터 로딩이 꼬이면 사용자 경험이 급격히 떨어지죠. 저도 최근 프로젝트에서 네비게이션 성능 문제로 골머리를 앓다가, 새로 나온 Navigation API를 도입해봤는데요. 이게 생각보다 훨씬 깔끔하고 강력해서 공유하고자 합니다.

## Navigation API가 기존 라우팅과 뭐가 다를까?

기존에는 React Router, Vue Router 같은 라이브러리 위주로 라우팅을 처리했는데, 이 방식은 복잡한 상태 관리와 비동기 데이터 로딩을 통합하기가 쉽지 않았어요. Navigation API는 이런 문제를 해결하기 위해 설계됐습니다. 간단히 말하면, 브라우저의 네비게이션 이벤트를 더 세밀하게 제어할 수 있게 해주고, 상태 관리와 비동기 작업을 자연스럽게 엮을 수 있도록 도와줍니다.

Martin Fowler가 말한 소프트웨어 아키텍처 가이드에도 등장하는 이 API는 실제로 대규모 서비스에서 성능과 유지보수성을 크게 개선했다고 합니다[Martin Fowler - Software Architecture Guide](https://martinfowler.com/architecture/).

## 실제로 GitHub와 Cloudflare는 어떻게 활용했을까?

GitHub 엔지니어링 팀은 이 Navigation API를 도입해 수백만 명의 사용자 트래픽을 처리하는 과정에서 페이지 로드 시간을 눈에 띄게 줄였다고 해요. 특히 렌더링 지연 문제를 줄이고, 사용자 인터랙션이 끊기지 않도록 최적화했다고 합니다[GitHub Engineering Blog](https://github.blog/category/engineering/).

Cloudflare도 프론트엔드 컴포넌트 간 데이터 흐름과 상태 관리를 Navigation API 덕분에 훨씬 깔끔하게 관리할 수 있었다고 하네요. 덕분에 개발 복잡도가 줄고 사용자 경험이 개선됐다고 합니다[Cloudflare Blog - How We Built It](https://blog.cloudflare.com/tag/how-we-built-it/).

## Navigation API로 간단한 페이지 전환 구현해보기

아래는 React 환경에서 Navigation API를 활용해 페이지 전환을 처리하는 간단한 예제입니다. 기존에 useEffect로 데이터 로딩과 상태 관리를 하던 부분을 Navigation API의 이벤트와 상태 관리 기능으로 대체한 모습이죠.

```jsx
import React, { useState, useEffect } from 'react';

function useNavigation() {
  const [state, setState] = useState({ loading: false, data: null });

  useEffect(() => {
    const handleNavigation = async (event) => {
      event.preventDefault();
      setState({ loading: true, data: null });

      try {
        const response = await fetch(event.target.href);
        const data = await response.json();
        setState({ loading: false, data });
      } catch (error) {
        setState({ loading: false, data: null });
        console.error('Navigation failed', error);
      }
    };

    window.addEventListener('navigate', handleNavigation);
    return () => window.removeEventListener('navigate', handleNavigation);
  }, []);

  return state;
}

export default function App() {
  const { loading, data } = useNavigation();

  return (
    <div>
      <nav>
        <a href="/page1" onClick={(e) => window.dispatchEvent(new CustomEvent('navigate', { detail: e }))}>Page 1</a>
        <a href="/page2" onClick={(e) => window.dispatchEvent(new CustomEvent('navigate', { detail: e }))}>Page 2</a>
      </nav>

      {loading && <p>Loading...</p>}
      {data && <pre>{JSON.stringify(data, null, 2)}</pre>}
    </div>
  );
}
```

이 예제는 실제 서비스용으로는 좀 더 다듬어야 하지만, Navigation API가 비동기 데이터 로딩과 사용자 인터랙션을 자연스럽게 연결하는 데 얼마나 유용한지 보여줍니다. 특히 이벤트를 직접 제어할 수 있어서, 복잡한 라우팅 로직을 훨씬 단순하게 만들 수 있죠.

## Navigation API 도입 시 고려해야 할 점

처음엔 이 API가 너무 만능 같아 보여도, 몇 가지 트레이드오프는 존재합니다. 예를 들어, 브라우저 호환성 문제를 꼼꼼히 체크해야 하고, 기존 라우팅 라이브러리와 섞어 쓸 때 충돌이 발생할 수 있습니다. 또, 이벤트 기반으로 상태를 관리하다 보니, 상태 동기화가 꼬일 위험도 있으니 주의가 필요해요.

하지만 이런 단점들은 충분히 감수할 만한 가치가 있습니다. 특히 대규모 프로젝트에서 네비게이션 성능과 유지보수성을 동시에 잡고 싶다면요.

## 우리 팀에서 Navigation API를 도입한 후 변화

저희 팀은 최근 대형 SPA 프로젝트에 Navigation API를 적용했는데, 페이지 전환 속도가 평균 300ms에서 150ms로 거의 반으로 줄었어요. 사용자 피드백도 "훨씬 부드럽다"는 반응이 많았습니다. 그리고 컴포넌트 설계도 훨씬 모듈화되어, 새 기능 추가나 버그 수정이 빨라졌죠.

특히 비동기 데이터 로딩과 UI 상태를 한 군데서 관리할 수 있어서, 코드가 깔끔해지고 테스트 커버리지도 높일 수 있었습니다.

### 마무리하며

Navigation API는 단순히 "새로운 라우팅 방법"이 아니라, 프론트엔드 아키텍처 전반을 개선할 수 있는 강력한 도구입니다. 물론 모든 프로젝트에 무조건 맞는 건 아니지만, 복잡한 상태 관리와 비동기 데이터 처리 때문에 고민 중이라면 한 번쯤 도입을 고려해볼 만합니다.

꼭 직접 써보면서 성능과 유지보수성 변화를 체감해보세요. 그리고 무엇보다, 복잡한 라우팅 코드를 깔끔하게 정리할 수 있다는 점이 정말 매력적입니다.
