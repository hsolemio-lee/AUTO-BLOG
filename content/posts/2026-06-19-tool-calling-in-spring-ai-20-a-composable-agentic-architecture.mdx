### "도구 여러 개를 어떻게 자연스럽게 엮을 수 있을까?" 

최근에 Spring AI 2.0을 만지면서 가장 흥미로웠던 부분 중 하나가 바로 ‘도구(tool) 호출 패턴’이었다. AI 모델 하나만 덜컥 쓰는 게 아니라, 여러 도구를 조합해서 마치 에이전트처럼 협업시키는 구조를 지원한다는 점이었는데, 이걸 실제 서비스에 적용하려니 생각보다 고민할 게 많더라. 

특히, 복잡한 AI 작업을 분산 처리하면서도 유지보수가 쉽고, 보안과 성능까지 챙겨야 하니까 말이다. 오늘은 내가 직접 겪은 경험을 바탕으로 Spring AI 2.0에서 어떻게 도구 호출을 조합하는지, 그리고 프로덕션 환경에 맞게 튜닝하고 보안을 강화하는 방법을 풀어보려고 한다.

## Spring AI 2.0의 에이전트 아키텍처, 왜 ‘조합 가능’이 중요한가

Spring AI 2.0은 단순히 AI 모델 호출 라이브러리가 아니다. 여러 도구를 각각 독립된 컴포넌트로 관리하고, 필요에 따라 조합해서 호출하는 모듈화된(agentic) 아키텍처를 지원한다. 

이게 왜 중요하냐면, AI 작업이 점점 복잡해지면서 한 가지 모델만 쓰기엔 한계가 분명하기 때문이다. 예를 들어, 문서 요약은 GPT-4로, 데이터 추출은 별도 커스텀 모델로, 그 외 검색 도구나 DB 질의 도구를 함께 쓴다고 하자. 이때 각각의 도구를 하나의 큰 덩어리로 묶는 게 아니라, 독립적으로 관리하면서도 유기적으로 연결할 수 있어야 한다.

Spring AI 2.0은 이런 요구를 충족시키기 위해 ‘에이전트(agent)’라는 개념을 도입했다. 각 도구는 ‘역할’을 가진 하나의 에이전트로서, 필요에 따라 호출되고 결과를 조합한다. 덕분에 복잡한 AI 워크플로우도 재사용 가능하고 유지보수하기 쉬운 구조로 설계할 수 있다.

이 아키텍처는 Spring Boot의 의존성 주입과 AOP(Aspect-Oriented Programming)를 적극 활용해, 각 도구 호출 시점에 보안 정책이나 로깅, 성능 모니터링 같은 부가 기능을 자연스럽게 끼워 넣을 수 있다[Spring Framework - Core Technologies](https://docs.spring.io/spring-framework/reference/core.html).

## 실제로 도구 호출을 조합할 때 고려해야 할 점들

내가 직접 구현하면서 느낀 건, 단순히 여러 도구를 묶는다고 끝나는 게 아니라는 점이다. 다음 세 가지를 꼭 챙겨야 한다.

1. **비동기 처리와 커넥션 풀링**

   AI 도구 호출은 네트워크 I/O가 많다. 따라서 동기 호출만 하다 보면 응답 지연이 심해지고, 전체 서비스 성능이 떨어진다. Spring Boot에서는 `@Async` 어노테이션과 `ThreadPoolTaskExecutor`를 활용해 비동기 호출을 쉽게 구현할 수 있다. 

   또, 외부 API 호출 시 커넥션 풀을 적절히 설정해야 한다. 기본값으로 두면 동시 요청이 몰릴 때 병목이 생기기 쉽다. 내 경험상, 최소 50~100 커넥션 정도로 풀 크기를 설정하는 게 안정적이었다[Baeldung - Spring Boot Performance Tuning](https://www.baeldung.com/spring-boot-performance).

2. **보안 토큰 관리와 요청 제한**

   OpenAI나 Anthropic 같은 AI API는 인증 토큰과 요청 제한(rate limiting)을 엄격히 관리한다. Spring AI 2.0에서는 이런 토큰을 `@ConfigurationProperties`로 안전하게 관리하고, AOP로 호출 전 토큰 유효성 검사와 요청 제한 로직을 삽입할 수 있다.

   이 부분을 놓치면 서비스가 갑자기 차단되거나, 토큰이 노출되는 사고가 발생할 수 있다[OpenAI API Documentation](https://platform.openai.com/docs/overview).

3. **프롬프트 설계와 에이전트 간 협업**

   AI 도구 호출에서 프롬프트 설계는 성능만큼이나 중요하다. Anthropic 가이드에서 강조하는 것처럼, 명확하고 구조화된 프롬프트를 설계해야 AI가 정확한 답변을 준다. 

   Spring AI 2.0은 이런 프롬프트를 컴포저블하게 관리할 수 있게 도와주는데, 이를 통해 여러 에이전트가 협업하는 복잡한 시나리오도 깔끔하게 구현 가능하다[Anthropic - Prompt Engineering Guide](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/overview).

## 코드로 보는 Spring AI 2.0 도구 호출 조합 예제

아래는 간단한 예제다. 두 가지 도구(예: 문서 요약용 GPT 에이전트, 데이터 추출용 커스텀 에이전트)를 조합해 호출하는 구조를 보여준다.

```java
@Service
public class CompositeAgentService {

    private final GptSummaryAgent summaryAgent;
    private final CustomExtractionAgent extractionAgent;

    public CompositeAgentService(GptSummaryAgent summaryAgent, CustomExtractionAgent extractionAgent) {
        this.summaryAgent = summaryAgent;
        this.extractionAgent = extractionAgent;
    }

    @Async
    public CompletableFuture<CompositeResult> processDocumentAsync(String document) {
        CompletableFuture<String> summaryFuture = summaryAgent.summarize(document);
        CompletableFuture<Map<String, Object>> extractionFuture = extractionAgent.extractData(document);

        return summaryFuture.thenCombine(extractionFuture, (summary, extraction) -> {
            CompositeResult result = new CompositeResult();
            result.setSummary(summary);
            result.setExtraction(extraction);
            return result;
        });
    }
}

// 에이전트 인터페이스 예시
public interface GptSummaryAgent {
    CompletableFuture<String> summarize(String text);
}

public interface CustomExtractionAgent {
    CompletableFuture<Map<String, Object>> extractData(String text);
}
```

이 예제에서 `@Async`와 `CompletableFuture`를 써서 두 도구를 병렬 호출한다. 실제 운영 환경에선 API 호출 시 커넥션 풀 설정과 재시도 로직, 타임아웃 설정도 꼭 추가해야 한다.

## 프로덕션 환경에서 꼭 챙겨야 할 성능과 보안 팁

처음엔 이게 별거 아닌 것 같지만, 실제 서비스에선 다음 설정들이 없으면 금방 문제에 봉착한다.

- **커넥션 풀 크기 조정**: 기본 10~20 커넥션은 너무 적다. AI API 호출량에 따라 50~100 이상으로 늘려야 안정적.

- **적절한 타임아웃 설정**: 외부 API가 느려질 때 무한 대기하지 않도록 3~5초 내외로 타임아웃 설정 권장.

- **재시도 정책 적용**: 네트워크 오류나 일시적 장애에 대비해 3회 정도 재시도 로직 넣기.

- **인증 토큰 자동 갱신 및 암호화 저장**: 토큰 만료 시 자동 갱신하고, 환경변수나 Vault 같은 안전한 저장소에 보관하기.

- **AOP로 호출 전후 로깅 및 모니터링**: 호출 시간, 응답 상태, 에러 로그를 남겨 문제 발생 시 빠르게 대응 가능.

이런 튜닝 덕분에 우리 팀은 AI 기반 기능을 24시간 무중단으로 안정 운영할 수 있었다[Baeldung - Spring Boot Performance Tuning](https://www.baeldung.com/spring-boot-performance).

## 마치며: Spring AI 2.0 도구 호출, 어디까지 가능할까?

Spring AI 2.0의 에이전트 기반 도구 호출 패턴은 단순히 AI 모델을 쓰는 걸 넘어서, 복잡한 AI 워크플로우를 모듈화하고 재사용 가능하게 만든다는 점에서 큰 의미가 있다. 

하지만 이걸 실제 서비스에 적용하려면, 단순한 코드 작성만으로는 부족하다. 비동기 처리, 커넥션 풀링, 인증과 보안, 프롬프트 설계까지 꼼꼼히 챙겨야 한다. 

내가 직접 겪어보니, 이런 부분을 제대로 세팅하면 AI 서비스의 안정성과 확장성이 확실히 달라진다. 그리고 에이전트 간 협업 구조 덕분에 새로운 도구를 추가하거나 변경하는 것도 훨씬 수월해진다.

혹시 Spring AI 2.0으로 복잡한 AI 도구 호출을 고민 중이라면, 꼭 이 글에서 소개한 점들을 참고해서 설계해보길 바란다. 작은 설정 차이가 서비스 전체 품질을 좌우한다는 걸 경험으로 말해주고 싶다.
