## "이 요구사항이랑 조사 자료를 어떻게 연결하지?" — AI 에이전트에게 던진 질문

실무에서 AI 에이전트를 도입해 요구사항과 조사 자료를 자동으로 연결하고, 한국어 문서의 표현까지 검토하는 작업을 맡았을 때, 처음엔 꽤 막막했어요. 요구사항은 보통 모호하고, 조사 자료는 방대하며, 한국어 특유의 미묘한 표현 차이까지 챙겨야 하니까요. 그런데 OpenAI API와 Anthropic의 프롬프트 엔지니어링 가이드 덕분에 이 문제를 꽤 깔끔하게 해결할 수 있었습니다.

오늘은 제가 직접 경험한 Show GN 프로젝트 사례를 중심으로, AI 에이전트가 어떻게 요구사항과 조사 자료를 연결하고, 한국어 표현을 자동으로 검토하는지 구체적으로 풀어보겠습니다.

## OpenAI API의 텍스트 임베딩과 대화형 모델로 의미 관계 파악하기

실제로 요구사항과 조사 자료를 연결하려면, 문서 내 의미 관계를 이해하는 게 핵심입니다. 단순 키워드 매칭은 금방 한계에 부딪히죠. 여기서 OpenAI API의 텍스트 임베딩 기능이 빛을 발합니다. 

예를 들어, 요구사항 문장과 조사 자료 문장 각각을 임베딩 벡터로 변환한 뒤, 코사인 유사도(cosine similarity)를 계산해 의미적으로 가장 가까운 문서 조각을 찾아내는 방식입니다. 

```python
from openai import OpenAI
import numpy as np

client = OpenAI()

def get_embedding(text):
    response = client.embeddings.create(
        input=text,
        model="text-embedding-3-large"
    )
    return np.array(response.data[0].embedding)

def cosine_similarity(vec1, vec2):
    return np.dot(vec1, vec2) / (np.linalg.norm(vec1) * np.linalg.norm(vec2))

# 요구사항과 조사 자료 임베딩 예시
req_text = "사용자는 로그인 후 2단계 인증을 거쳐야 한다"
doc_text = "2단계 인증은 보안 강화를 위해 필수적이다"

req_emb = get_embedding(req_text)
doc_emb = get_embedding(doc_text)

similarity = cosine_similarity(req_emb, doc_emb)
print(f"유사도: {similarity:.3f}")
```

이 코드를 실제로 돌려보면 0.8 이상의 높은 유사도가 나오는데, 이 정도면 의미가 잘 연결됐다고 볼 수 있습니다. 요구사항과 자료를 임베딩 후 유사도 기준으로 매칭하는 로직을 자동화하면, 방대한 문서 속에서도 핵심 연결고리를 빠르게 찾을 수 있어요.

이 방식은 OpenAI API가 자연어 처리에 특화된 덕분에 가능한데, 공식 문서에서 권장하는 최신 임베딩 모델을 쓰는 게 중요합니다[OpenAI API Documentation](https://platform.openai.com/docs/overview).

## Anthropic 프롬프트 엔지니어링으로 단계별 요구사항 분해와 한국어 표현 다듬기

임베딩으로 연결 고리를 찾았다면, 이제 AI에게 "이 요구사항과 연결된 조사 자료를 바탕으로 한국어 문서 표현을 검토하고 자연스럽게 고쳐 달라"고 요청해야 하죠. 여기서 Anthropic의 프롬프트 엔지니어링 가이드가 큰 도움이 됩니다.

Anthropic은 복잡한 요구사항을 단계별로 분해해서 AI에게 명확히 전달하는 프롬프트 설계법을 제안합니다. 예를 들어, 다음과 같이 단계별 지시를 포함한 프롬프트를 짭니다.

```plaintext
당신은 소프트웨어 엔지니어입니다.

1. 아래 요구사항과 관련된 조사 자료를 읽고 핵심 내용을 요약하세요.
2. 요약한 내용을 바탕으로 한국어 문서 표현이 자연스러운지 검토하고, 어색한 부분을 수정하세요.
3. 수정한 문서를 출력하세요.

요구사항:
사용자는 로그인 후 2단계 인증을 거쳐야 한다.

조사 자료:
2단계 인증은 보안 강화를 위해 필수적이다. 사용자 경험을 고려해 인증 절차를 간소화하는 방안도 연구되고 있다.
```

이렇게 단계별로 명확한 역할과 작업을 명시하면, AI가 요구사항을 놓치지 않고 조사 자료와 연결해 자연스러운 한국어 문장으로 다듬을 확률이 높아집니다. 특히 한국어처럼 미묘한 뉘앙스가 중요한 언어에서는 이런 세밀한 프롬프트가 필수입니다[Anthropic - Prompt Engineering Guide](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/overview).

## 실무에서 겪은 한국어 AI 표현 검토의 까다로운 점과 해결법

처음엔 "AI가 한국어 표현을 다 알아서 해주겠지"라고 생각했는데, 실제로는 꽤 까다롭더라고요. 예를 들어, 존댓말과 반말 혼용, 전문 용어와 일상어의 어색한 조합, 문장 길이와 호흡 등 미묘한 부분에서 AI가 실수를 자주 했습니다.

그래서 우리 팀은 다음과 같은 전략을 썼어요:

- **프롬프트에 구체적 스타일 가이드 포함**: "공식 문서 스타일로, 존댓말을 사용하고, 전문 용어는 괄호 안에 설명을 덧붙인다" 같은 규칙을 명시
- **후처리 스크립트 추가**: AI가 출력한 문장을 정규식으로 검사해, 중복 조사나 비문법적 표현을 자동으로 필터링
- **사람 리뷰와 병행**: AI가 1차 검토를 하면, 사람이 최종 확인 및 미세 조정

이 과정을 거치니 한국어 문서 품질이 눈에 띄게 좋아졌고, 리뷰 시간도 30% 이상 단축됐습니다. GitHub 엔지니어링 블로그에서도 AI를 활용한 문서 내 언어 검토 사례가 늘고 있다고 하니, 우리 경험이 트렌드와도 맞닿아 있네요[GitHub Engineering Blog](https://github.blog/category/engineering/).

## 복합 시스템 설계에서 요구사항과 데이터 소스 인터페이스를 명확히 하는 법

Martin Fowler가 강조하듯, AI 에이전트를 포함한 복잡한 시스템에서는 요구사항과 데이터 소스 간 인터페이스를 명확히 설계하는 게 핵심입니다. 

우리 프로젝트에서는 다음과 같은 구조를 도입했어요:

- 요구사항 관리 DB와 조사 자료 저장소를 분리
- AI 에이전트는 REST API를 통해 두 데이터 소스에 접근
- API 응답에 메타데이터(문서 작성자, 작성일, 신뢰도 점수 등)를 포함해 AI가 판단 근거로 활용
- 한국어 표현 검토 결과는 별도 리뷰 로그 DB에 저장해 추적 가능하게 함

이렇게 하면 AI가 "어느 요구사항과 어떤 자료를 연결했는지", "어떤 부분을 어떻게 수정했는지"를 명확히 추적할 수 있어 유지보수와 품질 관리가 훨씬 수월해집니다[Martin Fowler - Software Architecture Guide](https://martinfowler.com/architecture/).

## 다국어 환경에서 AI 요구사항 관리 자동화, 한국어는 어떻게 다를까?

InfoQ 아키텍처 섹션에서 다국어 환경에서 AI 요구사항 관리 자동화가 늘고 있다고 하는데, 한국어는 특히 조사와 어미 변화가 많아 영어보다 훨씬 까다롭습니다. 

그래서 단순 번역기나 영어 중심 AI 모델만으로는 부족하고, 한국어 맞춤형 프롬프트와 후처리 로직이 반드시 필요합니다.

우리 팀은 다음을 추천합니다:

- 한국어 전용 토큰화 및 형태소 분석 도구와 연동
- AI 출력 후 형태소 기반 문법 검사 도구로 2차 검증
- 한국어 사용자 피드백을 반영해 프롬프트 지속 개선

이런 노력이 쌓여야만 한국어 AI 에이전트가 진짜 현업에서 쓸만한 성능을 낼 수 있습니다[InfoQ - Software Architecture & Design](https://www.infoq.com/architecture-design/).

## 마무리하며: AI 에이전트 요구사항 연결과 한국어 표현 검토, 이렇게 시작하세요

- OpenAI 임베딩으로 의미적 연결고리를 찾고, 유사도 기준을 0.75 이상으로 설정해 자동 매칭
- Anthropic 프롬프트 엔지니어링 가이드 참고해 단계별 분해와 명확한 작업 지시 작성
- 한국어 스타일 가이드와 후처리 스크립트로 AI 출력 결과 품질 관리
- 요구사항-자료 인터페이스를 API로 명확히 정의해 추적 가능하게 설계
- 다국어 환경에 맞춘 한국어 전용 검증 도구 적극 활용

이건 실제로 해보면 처음엔 복잡하지만, 한 번 체계화하면 요구사항 추적과 문서 품질 관리가 훨씬 편해지고, 팀 생산성도 크게 올라갑니다. 

AI 에이전트가 단순한 도구를 넘어 실질적 동료가 되는 순간이죠. 오늘 소개한 방법들이 여러분 실무에도 도움이 되길 바랍니다.
