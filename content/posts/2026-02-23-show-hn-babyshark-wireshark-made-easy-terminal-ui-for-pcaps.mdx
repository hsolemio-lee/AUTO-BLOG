## 갑자기 터미널에서 PCAP을 보고 싶어진 이유

"와, 이 패킷 어디서 터졌지?"라는 질문, 네트워크 문제를 디버깅할 때 한 번쯤은 꼭 해봤을 겁니다. 특히 프론트엔드 쪽에서 API 호출이 느려지거나 실패할 때, 네트워크 트래픽을 들여다보는 건 필수죠. 그런데 Wireshark 같은 GUI 도구는 무겁고, 원격 서버에서 쓰기엔 불편할 때가 많습니다. 그래서 터미널에서 바로 PCAP 파일을 분석할 수 있는 Babyshark를 만들어봤어요. 이게 생각보다 네트워크 문제를 훨씬 빠르게 찾는 데 도움이 되더라고요.


## 터미널 UI가 네트워크 디버깅 워크플로우를 어떻게 바꾸는가

터미널 UI 기반 PCAP 분석 도구가 왜 유용하냐면, 일단 SSH 접속만으로 어디서든 네트워크 트래픽을 바로 볼 수 있다는 점입니다. GUI 툴을 띄우려면 X11 포워딩이나 별도 환경 세팅이 필요한데, 그게 번거롭죠. Babyshark는 이런 불편함을 없애고, CLI 환경에 익숙한 개발자에게 자연스러운 인터페이스를 제공합니다.

실제로 GitHub 엔지니어링 블로그에서도 터미널 UI가 네트워크 디버깅 워크플로우를 간소화하고, 프론트엔드 엔지니어가 빠르게 문제를 식별할 수 있게 도와준다고 했어요[GitHub Engineering Blog](https://github.blog/category/engineering/).


## Babyshark 구현에서 가장 신경 쓴 부분: 실시간성과 직관성

Cloudflare가 네트워크 분석 도구를 만들면서 가장 중요하게 생각한 게 사용자 경험과 실시간 데이터 처리였다고 합니다. Babyshark도 이 점을 참고해서, PCAP 파일을 한 번에 다 읽는 게 아니라 스트리밍 방식으로 처리하고 있어요. 이렇게 하면 대용량 파일도 메모리 부담 없이 다룰 수 있죠[Cloudflare Blog - How We Built It](https://blog.cloudflare.com/tag/how-we-built-it/).

UI는 터미널에서 키보드로 빠르게 탐색할 수 있게 설계했는데, 패킷 리스트와 상세 정보 뷰를 탭으로 전환하면서 볼 수 있게 했어요. 실제로 개발하면서 느낀 건, 처음엔 터미널 UI가 복잡할 것 같지만, 키 바인딩만 익히면 오히려 GUI보다 빠르게 원하는 정보를 찾을 수 있다는 점입니다.


## Babyshark 핵심 코드 예시: PCAP 스트리밍 파싱과 이벤트 기반 UI

```go
package main

import (
    "fmt"
    "os"

    "github.com/google/gopacket"
    "github.com/google/gopacket/pcap"
    "github.com/gdamore/tcell/v2"
    "github.com/rivo/tview"
)

func main() {
    if len(os.Args) < 2 {
        fmt.Println("Usage: babyshark <pcap file>")
        os.Exit(1)
    }
    handle, err := pcap.OpenOffline(os.Args[1])
    if err != nil {
        panic(err)
    }
    packetSource := gopacket.NewPacketSource(handle, handle.LinkType())

    app := tview.NewApplication()
    table := tview.NewTable().SetSelectable(true, false)

    // 헤더 설정
    headers := []string{"No", "Time", "Src IP", "Dst IP", "Protocol", "Length"}
    for i, h := range headers {
        table.SetCell(0, i, tview.NewTableCell(h).SetAttributes(tcell.AttrBold))
    }

    row := 1
    for packet := range packetSource.Packets() {
        netLayer := packet.NetworkLayer()
        if netLayer == nil {
            continue
        }
        src, dst := netLayer.NetworkFlow().Endpoints()
        proto := packet.TransportLayer()
        protoName := ""
        if proto != nil {
            protoName = proto.LayerType().String()
        }
        table.SetCell(row, 0, tview.NewTableCell(fmt.Sprintf("%d", row)))
        table.SetCell(row, 1, tview.NewTableCell(packet.Metadata().Timestamp.Format("15:04:05.000")))
        table.SetCell(row, 2, tview.NewTableCell(src.String()))
        table.SetCell(row, 3, tview.NewTableCell(dst.String()))
        table.SetCell(row, 4, tview.NewTableCell(protoName))
        table.SetCell(row, 5, tview.NewTableCell(fmt.Sprintf("%d", len(packet.Data()))))
        row++
        if row > 1000 { // 메모리 과부하 방지
            break
        }
    }

    app.SetRoot(table, true).EnableMouse(true)
    if err := app.Run(); err != nil {
        panic(err)
    }
}
```

이 코드는 Go 언어로 PCAP 파일을 열어 스트리밍으로 패킷을 읽고, 터미널 UI 라이브러리 tview를 활용해 테이블로 보여줍니다. 1000개 패킷까지만 표시하는 건 메모리와 렌더링 부담을 줄이기 위한 안전장치죠. 실제로 이 정도면 대부분 네트워크 문제 원인 파악에 충분합니다.


## 모듈화와 이벤트 기반 아키텍처가 유지보수에 얼마나 도움 되는지

Martin Fowler의 아키텍처 가이드에서도 모듈화와 이벤트 기반 설계가 확장성과 유지보수성을 높인다고 강조합니다. Babyshark도 PCAP 파싱, UI 렌더링, 사용자 입력 처리 등을 독립된 모듈로 나누고, 이벤트 루프로 연결해 관리합니다. 이 구조 덕분에 새로운 기능 추가나 버그 수정이 훨씬 수월했어요[Martin Fowler - Software Architecture Guide](https://martinfowler.com/architecture/).

InfoQ 가이드에 따르면, 네트워크 분석 도구에서 비동기 처리와 사용자 인터랙션 최적화가 핵심인데, Babyshark도 키 입력 이벤트를 비동기로 처리해 UI 반응성을 높였습니다. 이게 실제로 체감 성능에 큰 영향을 주더라고요[InfoQ - Software Architecture & Design](https://www.infoq.com/architecture-design/).


## Babyshark를 프론트엔드 네트워크 디버깅에 통합해보니

우리 팀에서는 프론트엔드에서 API 호출 문제를 조사할 때, Chrome DevTools 네트워크 탭과 함께 Babyshark를 병행해서 씁니다. 특히 원격 서버에서 발생하는 문제는 Babyshark로 PCAP 파일을 바로 분석하니까 훨씬 빠르게 원인 패킷을 찾을 수 있었어요. 터미널에서 바로 볼 수 있으니 디버깅 사이클도 짧아졌고요.

처음엔 "터미널 UI라서 불편하지 않을까?" 했는데, 실제로 써보면 키보드만으로 빠르게 탐색 가능해서 오히려 GUI보다 효율적입니다. 물론 Wireshark처럼 모든 기능을 다 제공하지는 않지만, 빠른 문제 식별용으로는 충분하죠.


## Babyshark를 만들면서 깨달은 한계와 앞으로 개선할 점

- **대용량 PCAP 처리 시 성능 최적화 필요**: 현재는 1000개 패킷까지만 보여주는데, 필터링과 페이징 기능을 추가하면 더 큰 파일도 무리 없이 다룰 수 있을 것 같아요.
- **프로토콜 디코딩 한계**: TCP, UDP 기본 정보까지만 보여주는데, HTTP, DNS 등 고수준 프로토콜 디코딩을 넣으면 더 유용할 겁니다.
- **멀티플랫폼 지원**: Windows, MacOS 터미널 환경에서 UI 호환성 테스트가 더 필요합니다.

이런 한계들을 하나씩 개선해 나가면, 프론트엔드 개발자뿐 아니라 네트워크 엔지니어, 운영팀에도 유용한 도구가 될 거라고 믿어요.


## 마무리하며: 터미널 UI PCAP 분석, 꼭 써보세요

Babyshark를 직접 구현해보면서 느낀 건, 터미널 UI가 네트워크 디버깅에 생각보다 큰 힘이 된다는 겁니다. 복잡한 GUI 없이도 빠르고 직관적으로 패킷을 분석할 수 있으니까요. 특히 프론트엔드 엔지니어가 네트워크 문제를 더 빠르게 찾고 대응하는 데 큰 도움이 됩니다.

앞으로는 Babyshark 같은 도구가 더 많아지고, 네트워크 디버깅이 개발자 일상에 자연스럽게 녹아들었으면 좋겠네요. 관심 있는 분들은 Babyshark 프로젝트에 기여해보는 것도 추천합니다. 터미널 UI와 네트워크 분석, 두 마리 토끼를 잡는 재미가 쏠쏠할 겁니다.
