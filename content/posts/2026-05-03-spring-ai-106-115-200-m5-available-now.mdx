# AI가 백엔드에 들어온다, 그런데 이걸 어떻게 붙여야 할까?

최근 우리 팀에서 Spring AI 1.0.6 버전부터 2.0.0-M5까지 차근차근 업그레이드하면서 느낀 점이 있어요. AI 모델 호출이 단순히 API 한 번 던지고 끝나는 게 아니라, 실제 생산 환경에서는 응답 지연, 비용, 보안 문제까지 골치 아프더라고요. 그래서 이번 글에서는 최신 Spring AI 버전을 백엔드에 안정적이고 효율적으로 통합하는 방법을 공유하려고 합니다.

---

## Spring AI, 왜 이제서야 제대로 쓸 수 있나?

Spring Boot 3.x부터 공식적으로 Spring AI 모듈을 지원하게 됐어요. 이게 왜 중요한지 아세요? 기존에는 AI 호출을 직접 HTTP 클라이언트로 관리하거나, 별도의 라이브러리를 붙여야 했는데, 이제는 Spring의 의존성 주입(DI)과 AOP 기능을 활용해 AI 모델 호출을 깔끔하게 추상화할 수 있거든요. 

예를 들어, AI API를 호출하는 서비스 클래스를 만들 때, Spring AI가 내부적으로 비동기 호출과 토큰 관리를 처리해주니 코드가 훨씬 간결해지고 유지보수가 쉬워집니다. 

```java
@Service
public class ChatService {

    private final OpenAIClient openAIClient;

    public ChatService(OpenAIClient openAIClient) {
        this.openAIClient = openAIClient;
    }

    public Mono<String> askQuestion(String question) {
        ChatCompletionRequest request = ChatCompletionRequest.builder()
                .model("gpt-4")
                .messages(List.of(new ChatMessage("user", question)))
                .build();

        return openAIClient.chatCompletion(request)
                .map(response -> response.getChoices().get(0).getMessage().getContent());
    }
}
```

위 코드는 Spring AI 2.0.0-M5 기준인데, `OpenAIClient`가 Spring Bean으로 관리되면서 API 호출이 리액티브하게 처리됩니다. 이 덕분에 네트워크 I/O를 효율적으로 다룰 수 있죠.[Spring Boot Reference Documentation](https://docs.spring.io/spring-boot/reference/)


## OpenAI API 연동에서 꼭 챙겨야 할 비동기 호출과 토큰 관리

실제로 OpenAI API를 호출할 때, 동기 방식으로 하면 요청마다 블로킹이 발생해 전체 서비스 응답 속도가 뚝 떨어집니다. 그래서 Spring AI는 비동기 호출을 기본으로 지원하는데, 이걸 제대로 활용해야 해요.

예를 들어, `Mono`나 `Flux` 같은 리액티브 타입을 활용하면, 여러 AI 요청을 동시에 처리하면서도 서버 리소스를 낭비하지 않습니다. 그리고 토큰 관리도 중요한데, OpenAI API는 토큰 사용량에 따라 비용이 달라지니까요.

토큰을 효율적으로 관리하려면, 요청 프롬프트를 최대한 압축하고, 불필요한 반복 호출을 줄여야 합니다. Anthropic의 프롬프트 엔지니어링 가이드에서도 강조하듯이, 프롬프트를 잘 다듬으면 API 호출 횟수를 줄이고 응답 정확도도 높일 수 있어요.[OpenAI API Documentation](https://platform.openai.com/docs/overview), [Anthropic - Prompt Engineering Guide](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/overview)


## JVM 튜닝과 캐싱 전략으로 AI 백엔드 성능 끌어올리기

AI 호출은 보통 네트워크 I/O가 병목이지만, JVM 튜닝과 캐싱 없이는 CPU나 GC가 병목이 될 수도 있습니다. Baeldung의 Spring Boot 성능 튜닝 가이드에 따르면, 다음 세 가지를 꼭 챙기라고 하더군요:

- **JVM 힙 사이즈 조절:** AI 호출 결과를 캐싱할 때 메모리 부족이 발생하지 않도록 적당히 넉넉하게 잡기
- **비동기 스레드 풀 최적화:** AI API 호출용 스레드 풀 크기를 CPU 코어 수의 2~3배 정도로 설정
- **응답 캐싱:** 동일 질문에 대해 자주 호출된다면 Redis 같은 분산 캐시를 활용해 API 호출 횟수 절감

예를 들어, 아래처럼 `ThreadPoolTaskExecutor`를 설정할 수 있습니다.

```java
@Configuration
public class AsyncConfig {

    @Bean(name = "aiExecutor")
    public ThreadPoolTaskExecutor aiExecutor() {
        ThreadPoolTaskExecutor executor = new ThreadPoolTaskExecutor();
        executor.setCorePoolSize(10); // CPU 코어 수가 4라면 2~3배
        executor.setMaxPoolSize(20);
        executor.setQueueCapacity(100);
        executor.setThreadNamePrefix("AI-Executor-");
        executor.initialize();
        return executor;
    }
}
```

그리고 AI 호출 메서드에 `@Async("aiExecutor")`를 붙이면, 호출이 비동기 스레드 풀에서 처리돼 메인 워커 스레드가 막히지 않습니다.[Baeldung - Spring Boot Performance Tuning](https://www.baeldung.com/spring-boot-performance)


## AI API 토큰과 권한, Spring Security로 안전하게 관리하기

AI API 키는 서비스의 생명줄과 같아요. 한 번 노출되면 비용 폭탄 맞기 십상입니다. Spring Framework Core Technologies 문서에 따르면, OAuth 2.0이나 JWT 기반 인증을 적극 활용해 토큰을 안전하게 저장하고, API 요청 시마다 검증하는 게 필수입니다.

실제로 우리 팀은 Spring Security와 연동해 다음과 같은 구조를 씁니다:

- AI API 키는 AWS Secrets Manager 같은 안전한 저장소에 보관
- 서비스 시작 시 키를 읽어 Spring Bean으로 등록
- AI 호출 시, 요청 헤더에 키를 직접 넣지 않고, 내부 서비스 토큰으로 변환 후 사용
- 사용자 권한에 따라 AI 호출 권한을 제한

아래는 Spring Security 설정 일부 예시입니다.

```java
@EnableWebSecurity
public class SecurityConfig extends WebSecurityConfigurerAdapter {

    @Override
    protected void configure(HttpSecurity http) throws Exception {
        http
            .authorizeRequests()
                .antMatchers("/api/ai/**").hasRole("AI_USER")
                .anyRequest().authenticated()
            .and()
            .oauth2ResourceServer()
                .jwt();
    }
}
```

이렇게 하면 AI 관련 API 경로에 대해 JWT 토큰 기반 인증을 강제할 수 있어요.[Spring Framework - Core Technologies](https://docs.spring.io/spring-framework/reference/core.html)


## 실제 현장에서 겪은 작은 함정들

처음엔 AI API 호출이 단순해서 별거 아닐 줄 알았는데, 막상 운영 환경에서 겪어보니 이런 문제가 있었어요:

- **응답 지연 문제:** 동기 호출로 처리하다가 전체 서비스가 느려짐
- **비용 폭탄:** 프롬프트를 비효율적으로 짜서 토큰 사용량 급증
- **보안 사고 위험:** API 키를 코드에 하드코딩해서 노출 위험 발생

이걸 해결하려면 비동기 호출, 프롬프트 최적화, 그리고 보안 정책 강화가 필수입니다. 특히 프롬프트는 매번 새로 짜기보다 템플릿화해서 재사용하는 게 비용 절감에 큰 도움이 되더라고요.

# 마무리하며

Spring AI 1.0.6부터 2.0.0-M5까지의 발전은 AI를 백엔드에 붙일 때 겪는 고질적인 문제를 많이 해소해줍니다. 하지만 여전히 개발자가 직접 성능 튜닝, 비동기 처리, 보안 관리를 꼼꼼히 챙겨야 하죠.

- Spring AI는 Spring Boot 3.x와 찰떡궁합, DI와 AOP로 AI 호출을 깔끔하게
- OpenAI API는 비동기 호출과 토큰 관리가 핵심, 프롬프트 최적화로 비용 절감
- JVM 튜닝과 스레드 풀 조절로 AI 호출 병목 최소화
- Spring Security와 OAuth 2.0/JWT로 API 키 안전하게 보호

실제 서비스에 AI를 붙일 때는 꼭 위 사항들을 하나씩 점검해보세요. 그리고 프롬프트는 꼭 여러 번 다듬으면서 비용과 품질 두 마리 토끼를 잡으시길 바랍니다.
