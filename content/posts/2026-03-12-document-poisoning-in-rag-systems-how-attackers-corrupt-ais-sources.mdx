## "내 AI가 이상한 답변을 해" — 문서 중독 공격, 백엔드가 답이다

"최근 우리 RAG 시스템에서 AI가 이상한 정보를 생성하는 일이 잦아졌어. 분명히 데이터 소스는 같은데 왜 이럴까?" 이런 경험, 혹시 해본 적 있나요? RAG(검색 기반 생성) 시스템은 외부 문서를 AI가 참고해 답변을 만드는 구조라, 악의적으로 조작된 문서가 데이터베이스에 섞이면 AI가 틀린 정보를 내놓는 문제, 즉 문서 중독(document poisoning) 공격에 노출됩니다. 

이 문제는 단순히 AI 모델 튜닝만으로 해결되지 않아요. 백엔드 데이터 파이프라인에서부터 출처 검증, 무결성 검사, 이상 탐지까지 다단계로 방어막을 쳐야 하죠. 오늘은 제가 실제로 RAG 시스템 백엔드에서 겪은 문서 중독 공격 대응 경험과 실무에서 쓸 수 있는 방법들을 풀어보겠습니다.

---

## 문서 중독 공격, 왜 백엔드가 제일 먼저 나서야 할까?

RAG 시스템은 검색된 문서를 AI 모델에 제공해 답변을 생성하는 구조입니다. 여기서 악성 문서가 섞이면 AI가 잘못된 지식을 학습하거나 참고해 엉뚱한 답변을 내놓게 되죠. 

Martin Fowler가 말한 소프트웨어 아키텍처 원칙처럼, 신뢰할 수 없는 데이터를 AI에 그대로 넘기는 건 치명적입니다. 백엔드에서 문서의 출처 신뢰도를 평가하고, 데이터 무결성을 검증하는 단계가 반드시 필요해요[Martin Fowler - Software Architecture Guide](https://martinfowler.com/architecture/).

이건 단순히 데이터 저장소에 문서를 넣는 것과 다릅니다. 문서가 들어오는 순간부터 해시 검증, 메타데이터 기반 신뢰도 평가, 이상치 탐지 알고리즘이 실시간으로 돌아가야 하죠. 이런 다단계 필터링 없이는 AI가 악성 문서에 속아 잘못된 답변을 내놓는 걸 막을 수 없습니다.

## 무결성 검사와 출처 신뢰도 평가, 구체적으로 어떻게 할까?

실제로 우리 팀에서는 문서가 RAG 파이프라인에 들어오기 전에 다음 절차를 거칩니다.

1. **해시 검증**: 문서가 전달될 때마다 SHA-256 같은 해시값을 생성해 이전에 저장된 값과 비교합니다. 변조 여부를 빠르게 판단할 수 있죠.

2. **메타데이터 기반 출처 평가**: 문서 출처 URL, 작성자 정보, 발행일, 도메인 신뢰도 점수 등을 수집해 점수화합니다. 예를 들어, 신뢰할 수 있는 도메인(예: .edu, .gov)에서 온 문서에 높은 점수를 주고, 신규 도메인이나 의심스러운 출처는 낮은 점수를 줍니다.

3. **이상치 탐지**: 문서 내용의 통계적 특징이나 키워드 빈도, 문서 길이 분포 등을 분석해 정상 범위를 벗어난 문서를 자동으로 플래그 처리합니다.

아래는 Python으로 해시 검증과 메타데이터 신뢰도 평가를 간단히 구현한 예시입니다.

```python
import hashlib
import requests

# 문서 해시 생성 함수

def generate_sha256(text: str) -> str:
    return hashlib.sha256(text.encode('utf-8')).hexdigest()

# 출처 신뢰도 평가 (예시로 도메인 기반 점수)
trusted_domains = {
    'example.edu': 0.9,
    'trusted.gov': 0.95,
    'unknown.com': 0.3
}

def evaluate_source_trust(url: str) -> float:
    domain = url.split('/')[2]  # 간단 도메인 추출
    return trusted_domains.get(domain, 0.1)  # 기본 낮은 점수

# 문서 저장 전 검증 절차

def validate_document(text: str, source_url: str, known_hashes: set) -> bool:
    doc_hash = generate_sha256(text)
    if doc_hash in known_hashes:
        print("이미 존재하는 문서입니다.")
        return False

    trust_score = evaluate_source_trust(source_url)
    if trust_score < 0.5:
        print("출처 신뢰도가 너무 낮습니다.")
        return False

    # 추가 이상치 탐지 로직 삽입 가능

    known_hashes.add(doc_hash)
    print("문서 검증 통과")
    return True

# 테스트
known_hashes = set()
text = "이 문서는 안전한 출처에서 왔습니다."
source_url = "https://example.edu/article/123"
validate_document(text, source_url, known_hashes)
```

이 코드를 RAG 문서 수집 파이프라인에 넣으면, 변조된 문서나 의심스러운 출처 문서는 걸러낼 수 있습니다.

## 클라우드 환경에서 권한 관리와 로그 모니터링이 왜 중요한가?

Cloudflare 같은 대규모 클라우드 플랫폼 사례를 보면, 문서 중독 공격 방어는 단순 필터링을 넘어서 권한 관리와 접근 제어가 핵심입니다. 누가 어떤 문서에 접근하거나 수정했는지 세밀한 로그 기록과 실시간 모니터링 체계 없이는 내부자 공격이나 권한 탈취 시도를 막기 어렵죠[Cloudflare Blog - How We Built It](https://blog.cloudflare.com/tag/how-we-built-it/).

우리도 AWS S3 버킷에 저장된 문서에 대해 IAM 정책을 엄격히 설정하고, CloudTrail 로그를 통해 문서 접근 내역을 모두 기록합니다. 또한, 변조 시도를 탐지하는 무결성 검사 도구(예: AWS Macie)를 통합해 문서가 예상치 못하게 변경되면 즉시 알람이 울리도록 했습니다.

이런 조치는 단순히 문서가 악성인지 아닌지를 넘어서, 누가 언제 어떤 행위를 했는지 추적 가능하게 만들어 줍니다. RAG 시스템에서 데이터 신뢰성을 유지하는 데 필수적입니다.

## 프롬프트 엔지니어링 관점에서 문서 중독 방어는 어떻게 달라지나?

Anthropic의 프롬프트 엔지니어링 가이드에 따르면, RAG 시스템에 AI 모델로 전달되는 문서 입력은 사전 필터링이 필수입니다. 악성 문서가 AI에게 전달되면, AI가 아무리 똑똑해도 잘못된 답변을 내놓을 수밖에 없기 때문이죠[Anthropic - Prompt Engineering Guide](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/overview).

사전 필터링 단계에서는 룰 기반 필터링(rule-based filtering)을 적용해, 명백한 악성 키워드나 패턴이 포함된 문서는 자동 차단합니다. 예를 들어, 특정 정치적 선동 문서, 허위 정보 패턴, 혹은 명백한 스팸 문서 등이 여기에 해당합니다.

이런 룰은 정적 룰셋뿐 아니라, 머신러닝 기반 이상 탐지 모델과 결합해 점점 진화시켜야 합니다. 그렇지 않으면 공격자는 룰을 우회하는 새로운 악성 문서를 지속적으로 만들어낼 수 있거든요.

## 실제 운영하면서 겪은 문제와 그 해결법

처음엔 해시 검증만 도입했는데, 문서가 조금이라도 수정되면 해시가 달라져서 중복 검출이 잘 안 됐어요. 그래서 문서 내용의 핵심을 요약해서 요약문에 대한 해시를 추가로 만들어 중복 검출 범위를 넓혔습니다.

또, 출처 신뢰도 점수는 처음에 너무 단순하게 도메인만 봤는데, 내부적으로는 IP 평판, TLS 인증서 정보, 그리고 문서 작성자 신원 확인까지 통합해서 점수를 계산하도록 고도화했습니다.

마지막으로, 이상치 탐지 시스템은 처음에 통계 기반으로만 돌렸는데, 최근에는 NLP 기반 임베딩 벡터를 활용해 문서 의미의 이상 여부를 탐지하는 방향으로 발전시키고 있습니다.

## 정리하며: 문서 중독 방어, 백엔드에서부터 시작하자

- RAG 시스템에서 문서 중독은 AI 답변 신뢰도를 무너뜨리는 심각한 위협
- 백엔드 데이터 파이프라인에 해시 무결성 검사, 출처 신뢰도 평가, 이상치 탐지 다단계 필터링 필수
- 클라우드 환경에서는 권한 관리, 접근 로그, 변조 탐지 도구를 반드시 통합해야 함
- 프롬프트 엔지니어링 단계에서도 악성 문서 필터링 룰을 강화해 AI 입력을 깨끗하게 유지해야 함

처음엔 이게 별거 아닌 것 같지만, 실제로 문서 중독 공격을 당해보면 얼마나 치명적인지 금방 깨닫게 됩니다. AI가 똑똑해질수록, 그 AI가 참고하는 데이터 신뢰성을 지키는 백엔드 시스템의 역할이 더 중요해지는 시대입니다.
