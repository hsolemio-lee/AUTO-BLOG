### ‘이거 도대체 어디서부터 봐야 하지?’ 복잡한 코드베이스에서 길을 잃은 적 있나요?

최근에 대규모 레거시 프로젝트를 맡으면서 느낀 점인데, 그냥 에디터에서 함수 이름 검색하고 클래스 다 뒤져보는 방식으론 한계가 확실히 있더라고요. 특히 팀원이 바뀌거나 신규 입사자가 빠르게 프로젝트에 적응해야 할 때는 더더욱요. 그래서 LLM(대형 언어 모델)과 AST(추상 구문 트리)를 결합한 Onboard-CLI라는 도구를 써봤는데, 이게 생각보다 꽤 쓸만했습니다.

---

## LLM과 AST가 만나면 코드베이스 탐색이 이렇게 달라진다

일단 AST는 소스코드를 트리 구조로 표현해서 함수, 클래스, 변수 같은 코드 구성 요소들의 관계를 한눈에 볼 수 있게 해줍니다. 근데 AST만 있으면 너무 기술적이고 복잡해서, 초보자나 비전문가가 보기엔 여전히 부담스럽죠. 여기서 LLM이 자연어로 코드를 설명하거나 쿼리를 해석해주니까, "이 함수가 어디서 호출되는지", "이 클래스가 어떤 역할인지"를 자연어로 물어보고 바로 시각화해서 보여줄 수 있어요.

Martin Fowler가 말한 것처럼, 이런 LLM 기반 AST 도구는 복잡한 코드 구조를 빠르게 이해하고 탐색하는 데 큰 도움을 줍니다[Martin Fowler - Software Architecture Guide](https://martinfowler.com/architecture/).

제가 직접 써보니, 기존에는 수십 분 걸리던 코드 흐름 파악을 5분 이내로 줄일 수 있더라고요. 특히 신규 입사자가 처음 보는 코드베이스를 빠르게 훑는 데 효과적이었어요.


## OpenAI API로 자연어 쿼리 기반 코드 탐색 인터페이스 만들기

Onboard-CLI는 OpenAI API를 활용해 LLM 기능을 통합했습니다. OpenAI API는 자연어 처리와 코드 이해에 최적화돼 있어서, "이 함수가 어디서 호출돼?", "이 클래스가 어떤 의존성을 갖고 있어?" 같은 질문을 자연어로 던지면 AST 정보를 바탕으로 답변과 시각화를 동시에 내줍니다.

예를 들어, 아래는 Node.js 환경에서 OpenAI API를 호출해 특정 함수의 호출 위치를 AST 기반으로 찾아내는 간단한 코드입니다:

```javascript
import { Configuration, OpenAIApi } from "openai";
import fs from "fs";

const configuration = new Configuration({
  apiKey: process.env.OPENAI_API_KEY,
});
const openai = new OpenAIApi(configuration);

async function queryFunctionCalls(functionName, sourceCode) {
  const prompt = `
  다음 JavaScript 코드에서 함수 '${functionName}'가 호출되는 위치를 AST 기반으로 찾아서 설명해줘:
  ```js
  ${sourceCode}
  ```
  `;

  const response = await openai.createChatCompletion({
    model: "gpt-4",
    messages: [{ role: "user", content: prompt }],
    temperature: 0,
  });

  return response.data.choices[0].message.content;
}

// 실제 사용 예시
const code = fs.readFileSync("./example.js", "utf-8");
queryFunctionCalls("calculateTotal", code).then(console.log);
```

이 코드는 OpenAI API에 AST 분석을 요청하는 프롬프트를 보내고, 함수 호출 위치를 자연어로 설명받습니다. 실제 Onboard-CLI는 여기에 시각화 UI까지 결합해 훨씬 직관적인 경험을 제공합니다.

OpenAI API 문서에서 볼 수 있듯이, 이런 자연어 + 코드 쿼리 인터페이스는 LLM 덕분에 훨씬 쉽게 구현할 수 있습니다[OpenAI API Documentation](https://platform.openai.com/docs/overview).


## Prompt engineering이 시각화 정확도와 효율성을 좌우한다

LLM에게 AST 정보를 제대로 전달하는 게 생각보다 까다로웠어요. 그냥 코드 덩어리만 던지면 원하는 결과가 안 나오더라고요. 그래서 Anthropic의 프롬프트 엔지니어링 가이드에서 배운 기법을 적용해봤습니다. 예를 들어,

- AST 노드 타입을 명확히 구분해서 설명
- 함수, 클래스, 변수 이름과 위치를 구조화된 리스트로 제공
- 자연어 쿼리와 AST 데이터를 분리해서 단계별로 처리

이런 식으로 프롬프트를 최적화하니, LLM이 더 정확하고 일관된 시각화 결과를 내줬습니다. 처음엔 이게 별거 아닌 것 같지만, 실제로 써보면 프롬프트 설계가 얼마나 중요한지 체감하게 됩니다.

```text
"다음은 AST 노드 리스트입니다. 각 노드는 타입, 이름, 위치를 포함합니다. 아래 함수 이름 'foo'가 호출되는 모든 곳을 찾아 설명해 주세요."
```

이런 식으로 명확한 지침을 주면, LLM이 더 좋은 답변을 하더라고요.

Anthropic의 가이드가 이런 프롬프트 설계에 큰 도움이 됩니다[Anthropic - Prompt Engineering Guide](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/overview).


## 클라우드 환경에서 대규모 코드베이스 실시간 시각화도 가능하다

우리 회사처럼 분산 개발팀이 많고, 코드베이스가 수백만 줄에 달하는 경우엔 로컬에서 AST 분석과 시각화를 돌리기 버거운 게 현실입니다. Onboard-CLI는 클라우드 플랫폼과도 잘 어울리는데, LLM API와 AST 파싱을 클라우드에서 처리하면서 실시간으로 결과를 뿌려줍니다.

Cloudflare 사례를 보면, 이런 아키텍처가 분산 팀 간 협업 효율성을 크게 높였다고 해요. 코드 변경 영향 분석, 리팩토링 제안까지 LLM이 도와주니 생산성이 눈에 띄게 올라갑니다[Cloudflare Blog - How We Built It](https://blog.cloudflare.com/tag/how-we-built-it/).

실제로 우리 팀도 Onboard-CLI를 도입하고 나서 코드 리뷰 시간이 평균 30% 이상 단축됐고, 신규 입사자 온보딩 기간도 2주에서 1주일로 줄었어요.


## LLM 기반 AST 시각화 도구, 무조건 좋은 것만은 아니다

솔직히 말하면 단점도 있습니다. 우선 LLM API 호출 비용이 만만치 않아요. 매일 수백 건씩 쿼리를 돌리면 비용이 금방 증가합니다. 그리고 AST 파싱이 완벽하지 않은 언어나 복잡한 매크로, 동적 코드에선 시각화가 부정확할 수 있어요.

또, 프롬프트 설계에 따라 결과가 크게 달라지기 때문에 초기 셋업에 시간과 노력이 꽤 들어갑니다. 그리고 모든 개발자가 자연어 쿼리에 익숙한 것도 아니어서, 팀 내 교육도 필요하죠.

하지만 이런 단점들을 감수할 만큼 생산성 향상 효과가 크다는 게 제 개인적인 결론입니다.

# 마무리하며

Onboard-CLI 같은 LLM과 AST 결합 도구는 복잡한 코드베이스를 빠르게 이해하고 탐색하는 데 정말 큰 도움이 됩니다. 특히 신규 입사자 온보딩, 코드 리뷰, 리팩토링 시나리오에서 효과적이었어요.

- OpenAI API를 활용해 자연어 쿼리 기반 인터페이스를 만들고
- 프롬프트 엔지니어링으로 LLM에게 AST 정보를 효율적으로 전달하며
- 클라우드 환경에서 실시간 시각화까지 고려하면

개발 생산성을 크게 끌어올릴 수 있습니다.

물론 비용과 초기 셋업 난이도는 감안해야 하지만, 직접 써보면 분명 가치가 있다고 느낄 겁니다. 저도 앞으로 더 다양한 프로젝트에 적용해보려고요. 혹시 비슷한 고민하는 분 있다면 한 번 써보길 추천합니다.
