## AI API 호출, 생각보다 쉽지만 놓치기 쉬운 부분들

최근에 AI 기능을 우리 서비스에 붙여야 할 일이 생겼는데, 막상 시작해보니 단순히 API 호출하는 것 이상으로 챙겨야 할 게 많더라고요. 특히 Spring 백엔드에서 AI API를 통합할 때는 성능, 보안, 운영까지 고려해야 해서 그냥 예제 코드 따라 치는 수준으론 부족하다는 걸 깨달았습니다. 이번에 [Spring Office Hours Podcast S5E20](https://docs.spring.io/spring-boot/reference/)에서 Danny Thompson이 직접 얘기한 내용을 듣고, 실제로 우리 팀에서 적용해본 경험을 바탕으로 정리해봤어요.

---

## Spring Boot HTTP 클라이언트와 비동기 처리로 AI API 연동하기

Spring Boot는 AI API 호출을 위한 HTTP 클라이언트 구성이 정말 편리합니다. `WebClient`를 쓰면 RESTful 호출을 비동기로 처리할 수 있어서, AI 모델 응답을 기다리는 동안 서버 스레드를 낭비하지 않아요. 예를 들어 OpenAI API를 호출할 때는 이렇게 간단하게 구성할 수 있습니다:

```java
@Service
public class OpenAiService {

    private final WebClient webClient;

    public OpenAiService(WebClient.Builder webClientBuilder) {
        this.webClient = webClientBuilder
            .baseUrl("https://api.openai.com/v1")
            .defaultHeader(HttpHeaders.AUTHORIZATION, "Bearer " + System.getenv("OPENAI_API_KEY"))
            .build();
    }

    public Mono<String> generateText(String prompt) {
        Map<String, Object> body = Map.of(
            "model", "gpt-4",
            "prompt", prompt,
            "max_tokens", 100
        );

        return webClient.post()
            .uri("/completions")
            .contentType(MediaType.APPLICATION_JSON)
            .bodyValue(body)
            .retrieve()
            .bodyToMono(JsonNode.class)
            .map(json -> json.get("choices").get(0).get("text").asText());
    }
}
```

이렇게 하면 호출 시점에 스레드를 블로킹하지 않고, Reactor 기반 비동기 스트림으로 응답을 받을 수 있어요. 대규모 AI 요청이 몰려도 서버가 버벅이지 않게 관리할 수 있다는 점이 가장 큰 장점입니다. [Spring Boot Reference Documentation](https://docs.spring.io/spring-boot/reference/)에서도 이 부분을 강력히 권장하고 있죠.


## AI 호출 시 보안과 로깅, 트랜잭션 관리까지 놓치면 안 되는 이유

AI API 통합은 단순히 호출만 하는 게 아니라, 보안과 운영 측면에서 고려할 게 많습니다. Spring Framework의 의존성 주입(DI)과 AOP 기능을 활용하면, AI 모델 호출을 감싸는 공통 관심사를 깔끔하게 분리할 수 있어요. 예를 들어, API 키 인증 검증, 호출 로깅, 트랜잭션 경계 설정을 모두 AOP로 처리하면 메인 비즈니스 로직이 훨씬 깔끔해집니다.

```java
@Aspect
@Component
public class AiApiAspect {

    private static final Logger logger = LoggerFactory.getLogger(AiApiAspect.class);

    @Around("execution(* com.example.ai.OpenAiService.*(..))")
    public Object aroundAiCall(ProceedingJoinPoint pjp) throws Throwable {
        // 1. 인증 검증 (예: API 키 유효성 체크)
        // 2. 호출 시작 시간 기록
        long start = System.currentTimeMillis();

        try {
            Object result = pjp.proceed();
            return result;
        } finally {
            long duration = System.currentTimeMillis() - start;
            logger.info("AI API 호출 메서드: {} 실행 시간: {}ms", pjp.getSignature().getName(), duration);
            // 3. 필요하면 트랜잭션 커밋/롤백 처리
        }
    }
}
```

이렇게 하면 AI 호출 관련 로직이 분산되지 않고 한곳에서 관리돼서, 보안 정책 변경이나 로깅 방식 수정도 훨씬 수월해집니다. 특히 OpenAI API는 API 키 기반 인증과 요청 제한(rate limiting)이 필수인데, Spring Security와 연계해 API 키를 관리하면 안전하게 운영할 수 있어요. [OpenAI API Documentation](https://platform.openai.com/docs/overview)에서 권장하는 방식입니다.


## AI API 호출 성능 병목, 커넥션 풀과 타임아웃 설정으로 잡기

AI API는 외부 네트워크 호출이라 지연이 불가피한데, 이걸 제대로 튜닝하지 않으면 전체 서비스 응답 속도가 뚝 떨어집니다. 제가 겪은 사례를 하나 들자면, 기본 커넥션 풀 설정으로 AI API를 호출했더니 1000 TPS 급 부하에서 커넥션 부족으로 타임아웃이 빈번히 발생했어요. 그래서 다음과 같이 커넥션 풀 최대 크기를 100, 커넥션 타임아웃을 2초, 읽기 타임아웃을 5초로 조정했습니다.

```java
@Bean
public WebClient webClient(WebClient.Builder builder) {
    TcpClient tcpClient = TcpClient.create()
        .option(ChannelOption.CONNECT_TIMEOUT_MILLIS, 2000)
        .doOnConnected(conn ->
            conn.addHandlerLast(new ReadTimeoutHandler(5))
        );

    ClientHttpConnector connector = new ReactorClientHttpConnector(HttpClient.from(tcpClient));

    return builder
        .clientConnector(connector)
        .baseUrl("https://api.openai.com/v1")
        .build();
}
```

이 설정 덕분에 네트워크 지연으로 인한 병목이 크게 줄었고, 실패율이 0.5% 미만으로 떨어졌습니다. 또한 AI 응답 결과를 Redis 캐시에 10분간 저장해 중복 요청을 줄이는 전략도 병행했는데, 이 역시 성능 안정화에 큰 도움이 됐죠. 이런 튜닝 팁은 [Baeldung - Spring Boot Performance Tuning](https://www.baeldung.com/spring-boot-performance)에서 자세히 다루고 있습니다.


## 프롬프트 엔지니어링, 그리고 점진적 AI 기능 롤아웃 전략

AI 통합에서 의외로 간과하기 쉬운 게 바로 ‘프롬프트 설계’입니다. Anthropic 가이드에 따르면, 명확하고 구체적인 프롬프트가 AI 응답 품질을 결정짓는 핵심이라고 하더라고요. 그래서 우리 팀은 Spring에서 프롬프트 템플릿을 관리하는 별도 컴포넌트를 만들어, 상황별로 동적으로 문구를 조합하는 방식을 썼습니다.

```java
@Component
public class PromptBuilder {

    public String buildPrompt(String userInput, Map<String, String> context) {
        String basePrompt = "You are a helpful assistant. Answer concisely.";
        String contextInfo = context.entrySet().stream()
            .map(e -> e.getKey() + ": " + e.getValue())
            .collect(Collectors.joining("\n"));

        return basePrompt + "\nContext:\n" + contextInfo + "\nUser: " + userInput;
    }
}
```

이렇게 하면 AI가 더 정확한 답변을 하도록 유도할 수 있고, 프롬프트 변경도 코드 수정 없이 쉽게 할 수 있어요. 물론 프롬프트가 길어지면 토큰 비용이 올라가니 적절한 균형이 필요합니다.

그리고 AI 기능을 한 번에 전체 서비스에 적용하는 건 위험해서, 점진적 롤아웃을 권장합니다. GitHub 엔지니어링 블로그에서 강조한 것처럼, Spring Actuator와 메트릭 수집 도구(Prometheus, Grafana 등)를 활용해 AI 호출 성공률, 응답 시간, 에러율을 실시간 모니터링하면서 점진적으로 트래픽을 늘려가는 게 안전합니다. 문제가 생기면 즉시 롤백하거나 조치를 취할 수 있거든요. [GitHub Engineering Blog](https://github.blog/category/engineering/)에서 관련 사례를 참고해보세요.


## 마치며: AI 통합, 준비된 패턴과 튜닝 없이는 쉽지 않다

AI 기능을 우리 서비스에 붙이는 건 단순히 API 호출 몇 줄 넣는 것보다 훨씬 복잡합니다. Spring Boot의 강력한 HTTP 클라이언트와 DI, AOP 기능을 적극 활용해서 보안, 로깅, 트랜잭션 관리까지 깔끔하게 처리하고, 네트워크 튜닝과 캐싱 전략으로 성능 병목을 줄여야죠.

또 프롬프트 설계처럼 AI 특유의 요구사항도 신경 써야 하고, 점진적 롤아웃으로 위험을 최소화하는 운영 노하우도 필수입니다. 이번 팟캐스트에서 Danny Thompson이 말한 것처럼, 이런 실전 패턴과 튜닝 가이드가 없으면 AI 통합은 금방 복잡해지고 유지보수도 어려워집니다.

동료 개발자분들도 AI 백엔드 작업할 때 이 글에서 다룬 내용을 참고해서, 시행착오를 줄이고 안정적인 AI 서비스 운영에 도움 되길 바랍니다.
