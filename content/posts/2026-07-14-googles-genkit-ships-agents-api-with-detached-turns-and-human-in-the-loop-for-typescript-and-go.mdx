AI 에이전트를 백엔드에서 다루다 보면, 대화가 꼬이거나 중간에 사람이 개입해야 하는 경우가 꽤 많습니다. 예를 들어, 자동화된 챗봇이 고객 문의를 처리하다가 복잡한 상황에서는 사람이 판단을 내려야 할 때, 어떻게 자연스럽게 시스템에 반영할 수 있을까요? 최근 Google이 내놓은 Genkit의 Agents API는 바로 이런 문제를 해결하는 데 초점을 맞췄습니다. 특히 TypeScript와 Go를 공식 지원하면서, 대화의 독립된 턴(detached turns) 관리와 인간-in-the-loop(human-in-the-loop) 워크플로우를 쉽게 구축할 수 있게 해줍니다.

## Google Genkit Agents API가 대화 턴을 분리하는 이유

대화형 AI를 만들 때 가장 골치 아픈 부분 중 하나가 상태 관리입니다. 전통적인 챗봇은 대화가 순차적으로 이어지는 걸 전제로 하지만, 실제 서비스에서는 사용자가 중간에 다른 질문을 던지거나, 인간 상담원에게 연결되는 등 대화 흐름이 복잡하게 꼬일 수 있죠. Genkit Agents API는 이런 상황을 위해 "detached turns" 개념을 도입했습니다. 각 턴을 독립적으로 처리해서, 이전 대화와 완전히 분리된 상태로 AI가 응답할 수 있도록 하는 거죠.

이 덕분에 백엔드에서는 각 턴을 별도의 이벤트처럼 받아 처리하고, 필요하면 인간 개입 단계로 넘길 수 있습니다. 예를 들어, 고객이 "내 주문 상태를 알려줘"라고 물었는데 AI가 정보가 부족하면, 자동으로 인간 상담원에게 연결하는 워크플로우를 쉽게 설계할 수 있죠. 이런 분리 덕분에 시스템 복잡도가 크게 줄고, 확장성도 좋아집니다.

## TypeScript 5.x와 Genkit Agents API, 왜 찰떡궁합일까?

TypeScript 5.x 버전은 최신 언어 기능과 성능 개선을 포함해, 복잡한 비동기 작업과 타입 안정성이 중요한 AI 백엔드 개발에 최적화되어 있습니다. Genkit Agents API처럼 비동기 API 호출과 상태 관리가 핵심인 환경에서, TypeScript의 견고한 타입 시스템은 개발자 경험을 크게 향상시킵니다.

예를 들어, Agents API의 각 턴은 다양한 상태와 이벤트를 포함하는데, TypeScript 인터페이스로 엄격하게 타입을 정의하면 런타임 에러를 줄이고 코드 완성도를 높일 수 있습니다. TypeScript 핸드북에서도 Genkit과 같은 복잡한 API를 다룰 때, 명확한 타입 정의와 인터페이스 설계가 얼마나 중요한지 강조하고 있죠[TypeScript Handbook](https://www.typescriptlang.org/docs/handbook/intro.html).

```typescript
// Genkit Agents API 턴 인터페이스 예시
interface AgentTurn {
  id: string;
  input: string;
  context?: Record<string, any>;
  humanInterventionRequired: boolean;
  response?: string;
}

async function handleTurn(turn: AgentTurn): Promise<AgentTurn> {
  if (turn.humanInterventionRequired) {
    // 사람 개입 워크플로우 트리거
    await notifyHumanOperator(turn);
    return turn;
  }
  // AI 응답 생성
  turn.response = await generateAIResponse(turn.input, turn.context);
  return turn;
}
```

위 코드는 턴 하나를 처리하는 간단한 예시입니다. humanInterventionRequired 플래그로 사람 개입 여부를 판단해, 필요하면 알림을 보내고 그렇지 않으면 AI가 응답을 생성합니다. 이런 구조 덕분에 복잡한 대화 흐름도 깔끔하게 관리할 수 있습니다.

## 인간-in-the-loop 워크플로우가 실제로 어떻게 도움이 될까?

AI가 모든 걸 다 처리하면 좋겠지만, 현실은 그렇지 않습니다. 특히 금융, 의료, 법률 같은 분야에서는 AI가 판단을 내리기 어려운 예외 상황이 많죠. Genkit Agents API는 이런 상황을 위해 인간-in-the-loop 기능을 기본으로 제공합니다. AI가 자동으로 처리하기 어려운 단계에서 사람의 판단을 개입시켜 신뢰성과 유연성을 크게 높일 수 있습니다.

실제로 GitHub 엔지니어링 블로그에서도 이런 인간 개입 워크플로우가 AI 에이전트 신뢰도를 끌어올리는 핵심 기능이라고 소개했는데[GitHub Engineering Blog](https://github.blog/category/engineering/), 우리도 비슷한 경험을 했습니다. 예를 들어, 고객 문의 중 민감한 개인정보가 포함된 경우 AI가 자동으로 답변하지 않고, 담당자가 직접 검토 후 응답하도록 워크플로우를 설계했습니다.

이런 구조는 단순히 안전성뿐 아니라, AI가 학습하는 피드백 루프로도 활용할 수 있습니다. 사람이 개입한 데이터를 다시 AI 학습에 반영해 점점 더 정확한 에이전트를 만들 수 있죠.

## Cloudflare 사례에서 배우는 확장 가능한 인간-인-루프 설계

Cloudflare가 운영하는 "How We Built It" 블로그에서는 대규모 클라우드 플랫폼에서 AI 에이전트와 인간 개입 인터랙션을 안전하고 확장 가능하게 구현한 사례를 다룹니다[Cloudflare Blog - How We Built It](https://blog.cloudflare.com/tag/how-we-built-it/). 여기서 인상 깊었던 점은, 단순히 사람을 붙이는 게 아니라, 시스템이 언제 어떻게 인간 개입을 요청할지 명확한 규칙과 상태 전이를 설계했다는 겁니다.

Genkit Agents API의 detached turns와 인간-in-the-loop 기능도 이런 설계 철학을 반영한 것으로 보입니다. 즉, AI와 사람이 각각 독립된 상태 머신으로 작동하다가, 특정 조건에서만 연결되는 구조죠. 이 덕분에 서비스가 커져도 복잡도가 폭발하지 않고, 운영도 수월합니다.

## 실제로 TypeScript와 Go에서 Agents API를 어떻게 써볼까?

TypeScript 예시를 앞서 봤는데, Go에서도 비슷한 패턴으로 사용할 수 있습니다. Go의 강력한 타입 시스템과 고루틴을 활용해 비동기 턴 처리를 깔끔하게 구현할 수 있죠.

```go
package main

import (
	"context"
	"fmt"
	"time"
)

type AgentTurn struct {
	ID                    string
	Input                 string
	Context               map[string]interface{}
	HumanInterventionNeeded bool
	Response              string
}

func handleTurn(ctx context.Context, turn *AgentTurn) error {
	if turn.HumanInterventionNeeded {
		// 사람 개입 알림
		fmt.Printf("Human intervention needed for turn %s\n", turn.ID)
		// 예: 알림 큐에 전송하거나 담당자에게 전달
		return nil
	}
	// AI 응답 생성 시뮬레이션
	turn.Response = "AI generated response for: " + turn.Input
	return nil
}

func main() {
	turn := &AgentTurn{
		ID: "turn-123",
		Input: "주문 상태 알려줘",
		HumanInterventionNeeded: false,
	}
	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()
	
	err := handleTurn(ctx, turn)
	if err != nil {
		panic(err)
	}
	fmt.Println(turn.Response)
}
```

Go 코드도 TypeScript와 마찬가지로 턴 단위로 처리하면서, 필요하면 인간 개입 플래그로 분기합니다. 실제 서비스에서는 이 부분에 메시지 큐, 상태 저장소, 알림 시스템 등을 연결해 확장하면 됩니다.

## 처음 써보면 헷갈릴 수 있는 점들

처음 Genkit Agents API를 써보면 detached turns 개념이 익숙하지 않아, 대화 상태를 어디에 저장해야 할지 고민이 될 수 있습니다. 각 턴을 독립적으로 처리한다고 해서 완전히 상태를 버리는 게 아니라, 필요한 컨텍스트는 별도의 저장소(DB, 캐시 등)에 보관하고, 턴마다 적절히 불러오는 패턴이 필요합니다.

또 인간-in-the-loop 워크플로우는 단순히 "사람이 개입한다"는 것보다, 언제 개입 요청을 보내고, 사람이 응답하면 어떻게 다시 AI 프로세스에 연결할지 명확한 상태 전이 설계가 중요합니다. 여기서 Cloudflare 사례를 참고하면 큰 도움이 됩니다.

마지막으로 TypeScript 5.x의 최신 기능을 적극 활용하는 게 좋습니다. 예를 들어, 제네릭 타입과 조건부 타입으로 API 응답을 더 정확히 모델링하면, 런타임 오류를 줄이고 개발 속도를 높일 수 있습니다[TypeScript 5.x Release Notes](https://devblogs.microsoft.com/typescript/announcing-typescript-5-4/).

새로운 AI 에이전트 프로젝트를 준비 중이라면, Genkit Agents API를 한번 시도해보세요. 처음엔 상태 관리와 인간-in-the-loop 설계가 복잡해 보일 수 있지만, 익숙해지면 대화형 AI 백엔드 개발이 훨씬 수월해질 겁니다.
