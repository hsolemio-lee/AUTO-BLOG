# Spring AI 2.0, OpenAI와 Anthropic API를 백엔드에 네이티브하게 녹여내다

"우리 서비스에 AI를 붙이고 싶은데, OpenAI랑 Anthropic API를 어떻게 효율적으로 다뤄야 할까?" 최근에 이런 질문을 많이 받았어요. 특히 Spring Boot 3.x 환경에서 AI API를 호출할 때 성능과 유지보수성 모두 챙기는 게 쉽지 않죠. 

이번에 Spring Office Hours Podcast S5E18을 듣고 나서, Spring AI 2.0이 이 고민을 어떻게 해결하는지 감이 잡혔습니다. 오늘은 그 내용을 풀어보려고 해요.

---

## Spring AI 2.0이 OpenAI와 Anthropic API를 네이티브하게 지원한다는 게 무슨 뜻일까?

처음엔 ‘네이티브하게 지원’이라는 말이 뭔가 거창해 보였는데, 실제로 써보니 Spring AI 2.0이 OpenAI와 Anthropic API를 호출하는 데 필요한 인증, 요청/응답 매핑, 에러 핸들링 같은 반복 작업을 프레임워크 차원에서 다 처리해준다는 뜻이었어요.

예를 들어 OpenAI API는 RESTful 디자인에 토큰 기반 인증을 쓰는데, Spring AI 2.0은 이런 인증 과정을 자동으로 처리하고, API 호출을 위한 클라이언트 객체를 빈으로 등록해줍니다. 덕분에 개발자는 비즈니스 로직에만 집중할 수 있죠[OpenAI API Documentation](https://platform.openai.com/docs/overview), [Spring Boot Reference Documentation](https://docs.spring.io/spring-boot/reference/).

Anthropic API도 마찬가지예요. Claude 모델용 프롬프트 설계 가이드가 꽤 까다로운데, Spring AI 2.0은 이를 반영한 통합 패턴과 유틸리티를 제공해서 프롬프트 엔지니어링을 훨씬 수월하게 만들어줍니다[Anthropic - Prompt Engineering Guide](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/overview).

## 비동기 WebClient로 OpenAI와 Anthropic 호출, 성능과 확장성은 어떻게 챙겼나?

Spring Boot 3.x 기반 AI 2.0에서 가장 마음에 들었던 부분은 바로 비동기 프로그래밍 모델이에요. AI API 호출은 네트워크 I/O가 많아서 동기 방식으로 하면 애플리케이션 전체가 느려질 수 있거든요.

Spring AI 2.0은 WebClient를 기본으로 사용하고, Mono/Flux 같은 리액티브 타입으로 응답을 처리해요. 덕분에 API 호출이 블로킹 없이 진행되고, 대량 요청에도 JVM 자원을 효율적으로 쓸 수 있죠.

예를 들어 아래 코드를 보면, OpenAI GPT-4 모델에 비동기 요청을 보내는 간단한 예시입니다. 

```java
@Service
public class OpenAiService {
    private final OpenAIClient openAIClient;

    public OpenAiService(OpenAIClient openAIClient) {
        this.openAIClient = openAIClient;
    }

    public Mono<String> generateText(String prompt) {
        ChatCompletionRequest request = ChatCompletionRequest.builder()
            .model("gpt-4")
            .messages(List.of(new ChatMessage("user", prompt)))
            .build();

        return openAIClient.chatCompletion(request)
            .map(response -> response.getChoices().get(0).getMessage().getContent());
    }
}
```

이 코드는 OpenAIClient가 Spring AI 2.0에서 제공하는 빈으로, 내부적으로 WebClient를 쓰고 있어요. 호출 결과를 Mono로 받기 때문에, 호출하는 쪽에서 `subscribe()`하거나 리액티브 스트림으로 연결해 비동기 처리가 가능합니다.

이런 구조 덕분에 API 호출 시 병목이 줄고, 서버가 한꺼번에 많은 요청을 무리 없이 처리할 수 있었습니다[Baeldung - Spring Boot Performance Tuning](https://www.baeldung.com/spring-boot-performance).

## DI와 AOP로 AI 호출 로직을 깔끔하게 분리하는 게 얼마나 큰 차이를 만드는지

처음 AI API를 도입할 때, 인증 토큰 관리, 호출 로깅, 에러 재시도 같은 부가 기능들을 서비스 코드에 직접 넣었는데, 금세 코드가 복잡해지더라고요. Spring AI 2.0은 이 부분도 신경 써서 DI(Dependency Injection)와 AOP(Aspect-Oriented Programming)를 적극 활용합니다[Spring Framework - Core Technologies](https://docs.spring.io/spring-framework/reference/core.html).

예를 들어, API 호출 전후에 자동으로 요청 로깅을 하거나, 실패 시 재시도 로직을 AOP로 분리할 수 있습니다. 이렇게 하면 비즈니스 로직은 깔끔해지고, 유지보수도 훨씬 편해지죠.

```java
@Aspect
@Component
public class OpenAiLoggingAspect {

    @Around("execution(* com.example.ai.OpenAiService.*(..))")
    public Object logAround(ProceedingJoinPoint joinPoint) throws Throwable {
        System.out.println("OpenAI 호출 시작: " + joinPoint.getSignature());
        Object result = joinPoint.proceed();
        System.out.println("OpenAI 호출 종료");
        return result;
    }
}
```

이런 식으로 AOP를 활용하면, AI API 호출 관련 부가 기능을 한 곳에 모아 관리할 수 있어요. 처음엔 이게 별거 아닌 것 같지만, API 호출이 많아지고 복잡해질수록 효과가 확실히 느껴집니다.

## 클라우드 네이티브 설계로 AI 기능을 마이크로서비스에 자연스럽게 녹여내기

Spring AI 2.0은 클라우드 네이티브 설계 원칙을 따르기 때문에, Kubernetes 같은 환경에서 AI 기능을 마이크로서비스 형태로 쉽게 확장할 수 있어요. 

실제로 우리 팀도 AI 기능을 별도 서비스로 분리해 운영하는데, Spring Boot 3.x와 Spring AI 2.0 덕분에 배포와 스케일링이 한결 수월해졌습니다. 예를 들어, AI 호출 빈은 ConfigMap이나 Secret으로 토큰을 관리하고, 서비스 인스턴스 수를 탄력적으로 조절할 수 있죠.

이런 설계는 AI API 호출량이 급증할 때도 서비스가 안정적으로 대응할 수 있게 해줍니다. 물론 클라우드 네이티브 설계가 처음엔 진입 장벽이 있을 수 있지만, 장기적으로 보면 확장성과 유지보수에서 엄청난 차이가 납니다[Spring Boot Reference Documentation](https://docs.spring.io/spring-boot/reference/).

## 마무리하며: Spring AI 2.0으로 AI 백엔드 개발할 때 꼭 기억할 점

- **API 호출은 무조건 비동기**로! WebClient와 리액티브 타입을 적극 활용하세요. 동기 호출은 대량 트래픽에서 치명적입니다.
- **DI와 AOP로 공통 로직 분리**는 선택이 아니라 필수입니다. 인증, 로깅, 재시도 같은 부가 기능이 많아질수록 코드가 깔끔해집니다.
- **프롬프트 엔지니어링 가이드 참고**는 꼭 하세요. Anthropic Claude 모델은 특히 프롬프트 설계가 성능에 큰 영향을 줍니다.
- **클라우드 네이티브 마인드셋**으로 설계하세요. AI 기능은 점점 더 확장성이 중요해집니다.

처음엔 Spring AI 2.0이 뭐가 다를까 반신반의했는데, 직접 써보니 확실히 AI API 통합이 훨씬 편해졌어요. AI를 백엔드에 붙이고 싶다면, 이번 기회에 Spring AI 2.0을 꼭 한번 써보시길 권합니다.
