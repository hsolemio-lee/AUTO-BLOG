### "내 코드가 갑자기 이상한 동작을? Word 문서에서 온 AI 웜이라니?"

최근에 동료가 겪은 일이에요. 회사 내에서 공유된 Word 문서에 AI 코딩 에이전트가 해석할 수 있는 악성 코드 스니펫이 숨겨져 있었고, 이걸 AI가 읽고 실행하면서 코드가 이상하게 변조됐다는 거죠. 처음엔 농담인 줄 알았는데, 실제로 AI 기반 코드 생성 도구들이 외부 입력을 통해 자가 전파하는 웜 형태 공격에 취약할 수 있다는 걸 알게 됐어요.

이게 왜 문제냐면, 우리가 흔히 쓰는 GitHub Copilot 같은 AI 에이전트는 기본적으로 코드 자동 완성과 생성 기능을 제공하지만, Word 문서 같은 외부 입력에서 악성 스크립트를 자동으로 완벽히 차단하지는 못해요. 즉, AI가 문서 내 숨겨진 명령어를 그대로 받아들여 실행하는 순간, 웜이 퍼질 가능성이 생깁니다.

## AI 코딩 에이전트가 Word 문서 기반 웜에 취약한 이유

AI 코딩 에이전트들은 자연어 프롬프트와 코드 컨텍스트를 해석해서 코드를 생성해요. 그런데 이 과정에서 Word 문서 내에 숨어있는 악성 명령어나 코드 스니펫을 AI가 인식하면, 그걸 기반으로 악성 코드를 생성하거나 실행할 수 있죠. 

예를 들어, 문서에 "이 코드를 프로젝트에 붙여넣어 실행해 봐" 같은 문장이 있으면, AI가 이를 실제 코드로 변환해 버릴 수도 있습니다. 이게 반복되면, AI가 스스로 악성 코드를 확산시키는 웜이 되는 거죠.

GitHub Copilot 문서에 따르면, 기본적으로 이런 자가 전파 공격 벡터를 막기 위한 보안 메커니즘이 내장돼 있지만 아직 완전하지 않다고 해요. 그래서 실무에서는 AI가 생성하는 코드를 수동으로 검토하고, 안전한 실행 환경을 구축하는 게 필수입니다[GitHub Copilot Documentation](https://docs.github.com/en/copilot).

## Anthropic Claude의 프롬프트 엔지니어링으로 방어하기

Anthropic의 Claude AI는 이런 문제를 해결하려고 프롬프트 엔지니어링 가이드에서 외부 입력에 대한 엄격한 검증과 제약 조건 설정을 권장합니다. 즉, AI가 받아들이는 입력 자체를 제한해서 악성 코드 실행 가능성을 줄이는 거죠.

예를 들어, 입력된 문서에서 코드 블록이나 명령어를 감지하면 자동으로 무시하거나, 실행 전에 반드시 특정 패턴을 확인하도록 하는 식이에요. 이런 방식은 AI가 의도치 않은 악성 코드를 생성하는 걸 막는 데 효과적입니다.

실제로 Anthropic 가이드에서는 "외부 입력은 반드시 화이트리스트 기반 검증을 거쳐야 하며, 실행 가능한 코드 생성은 최소화해야 한다"고 명시하고 있어요[Anthropic - Prompt Engineering Guide](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/overview).

## 클라우드 백엔드와 프론트엔드 권한 분리로 AI 웜 확산 막기

Cursor와 Vercel AI SDK 문서에서는 AI 기반 코드 생성 도구들이 클라우드 백엔드와 프론트엔드에서 엄격한 보안 정책과 권한 관리를 통해 AI 웜 확산을 방지할 수 있다고 설명합니다.

예를 들어, AI가 생성한 코드를 바로 프로덕션 환경에 배포하지 않고, 별도의 샌드박스 환경에서 실행하거나 API 호출 제한 정책을 둬서 악성 코드가 무작위로 퍼지는 걸 막는 거죠.

Spring 백엔드 환경에서는 특히 입력값 검증, 권한 분리, API 호출 제한 같은 방어 전략을 강화할 수 있습니다. 예를 들어, AI가 생성한 코드를 바로 실행하는 게 아니라, 다음과 같이 검증하는 코드를 넣을 수 있어요.

```java
@RestController
@RequestMapping("/ai-code")
public class AiCodeController {

    @PostMapping("/execute")
    public ResponseEntity<String> executeCode(@RequestBody String code) {
        if (!isSafeCode(code)) {
            return ResponseEntity.status(HttpStatus.FORBIDDEN).body("Unsafe code detected");
        }
        // 제한된 환경에서 코드 실행
        String result = sandboxedExecute(code);
        return ResponseEntity.ok(result);
    }

    private boolean isSafeCode(String code) {
        // 단순 예시: 특정 위험 키워드 차단
        return !code.contains("Runtime.getRuntime().exec") && !code.contains("System.exit");
    }

    private String sandboxedExecute(String code) {
        // 실제 환경에선 더 복잡한 샌드박스 로직 필요
        return "Executed safely";
    }
}
```

이런 식으로 AI가 생성한 코드가 위험한 명령을 포함하는지 간단히라도 체크하고, 제한된 샌드박스에서만 실행하도록 하는 게 중요합니다[Vercel AI SDK Documentation](https://sdk.vercel.ai/docs/introduction), [Cursor Documentation](https://docs.cursor.com/).

## 실무에서 AI 웜 위협에 대응하며 느낀 점

처음엔 AI 코딩 에이전트가 이렇게 복잡한 보안 위협을 만들 줄 몰랐어요. 단순히 코드 자동 완성 도구인 줄 알았는데, 외부 입력에 따라 악성 코드가 퍼질 수도 있다는 점이 충격적이었죠.

하지만 이걸 직접 겪으면서, AI가 생성하는 코드를 무조건 신뢰하면 안 된다는 걸 뼈저리게 느꼈습니다. 특히 Word 문서 같은 비정형 데이터에서 AI가 코드를 생성할 때는 더욱 조심해야 해요. 

그리고 보안은 한 겹으로 막는 게 아니라, 다층 방어가 필요하다는 것도 깨달았죠. AI 자체의 보안 메커니즘, 입력 검증, 실행 환경 분리, 그리고 수동 코드 리뷰까지 모두 합쳐야 안전합니다.

## 정리하며: AI 코딩 에이전트 보안, 이렇게 접근하세요

- **AI가 받아들이는 입력을 엄격히 검증하세요.** 특히 Word 문서 같은 외부 문서에서 직접 코드를 생성하는 경우 위험합니다.
- **프롬프트 엔지니어링으로 악성 코드 실행 가능성을 줄이세요.** Anthropic 가이드처럼 화이트리스트와 제약 조건을 적극 활용하세요.
- **코드 실행 환경을 샌드박스화하고 권한을 최소화하세요.** Spring 백엔드에서 API 호출 제한과 권한 분리 정책을 적용하는 게 효과적입니다.
- **AI가 생성한 코드는 반드시 수동으로 리뷰하고 테스트하세요.** 자동화된 도구만 믿으면 위험합니다.

이건 실제로 겪어보면 꽤 번거로운 과정이지만, AI가 우리 개발 환경에 깊숙이 들어온 이상 반드시 필요한 단계입니다. 앞으로 AI 코딩 에이전트를 쓸 때마다 보안 관점에서 한 번 더 점검하는 습관을 들이길 추천합니다.
