# 관세가 갑자기 오르면, 우리 시스템은 어떻게 반응해야 할까?

작년 혼다(Honda)가 미국과 중국 간 관세 인상에 맞서 물류 경로와 조달 방식을 재빠르게 조정했다는 소식, 혹시 들어봤나? 이게 단순히 물류팀의 현장 대응만이 아니라, 우리 같은 백엔드 엔지니어와 클라우드 플랫폼 운영자에게도 시사하는 바가 크다. 관세라는 외부 변수 때문에 공급망 전체가 흔들릴 때, 시스템은 어떻게 설계되고 운영되어야 할까?

내가 최근에 공부하면서 느낀 점과, 실제로 현업에서 적용 가능한 아이디어들을 공유해보려고 한다. 특히 계획(planning), 조달(procurement), 재고(inventory), 이행(fulfillment) 시스템 전반에 걸쳐 어떻게 물류와 조달 전략을 바꿔야 하는지, 그리고 그게 백엔드 아키텍처와 클라우드 플랫폼에서 어떤 엔지니어링 결정으로 이어지는지 이야기해보자.

## 관세 영향 최소화를 위한 공급망 전략, 왜 백엔드가 신경 써야 할까?

혼다는 관세가 오르자마자 중국산 부품 대신 미국 내 공급처를 늘리고, 물류 경로를 재설계했다. 여기서 중요한 건, 이런 전략 변화가 단순히 ‘사람들이 수작업으로 바꾸는’ 게 아니라, 데이터 시스템에 즉각 반영되어야 한다는 점이다. 

예를 들어, 기존에 중국에서 직배송하던 부품을 미국 내 물류센터로 우회시키려면, 재고 시스템과 주문 처리 로직, 심지어 비용 계산까지 전부 바뀌어야 한다. 이 과정이 자동화되어 있지 않으면 실시간 대응은 불가능하다.

Microsoft의 Dynamics 365 Supply Chain Management 문서에 따르면, 계획, 조달, 재고, 이행 시스템 간의 긴밀한 연동과 전략적 조정이 효과적인 공급망 관리를 위해 필수적이라고 한다[Microsoft Learn - Dynamics 365 Supply Chain Management](https://learn.microsoft.com/en-us/dynamics365/supply-chain/). 

즉, 백엔드 시스템에서 이런 전략 변화를 반영할 수 있도록 API, 데이터 모델, 이벤트 처리 등을 설계하는 게 엔지니어의 몫이다.

## 클라우드 SCM 솔루션이 관세 문제에 어떻게 대응하는지

클라우드 기반 SCM 솔루션은 실시간 데이터 통합과 분석 기능 덕분에 관세 인상 같은 복잡한 문제에 빠르게 대응할 수 있다. Oracle의 클라우드 SCM 문서에서는 실시간 재고 현황, 공급업체 성과, 물류 경로 데이터를 통합 분석해 민첩한 의사결정을 지원한다고 설명한다[Oracle Docs - SCM and Manufacturing](https://docs.oracle.com/en/cloud/saas/supply-chain-and-manufacturing/).

우리도 이런 아키텍처를 참고해보자. 예를 들어, AWS Lambda나 Azure Functions 같은 서버리스 컴퓨팅을 활용해 공급망 이벤트(관세 변동, 운송 지연 등)를 감지하고, 그에 맞춰 조달 우선순위를 자동 조정하는 워크플로우를 만들 수 있다.

### 간단한 예시 코드 (TypeScript, AWS Lambda)
```typescript
import { DynamoDBClient, UpdateItemCommand } from "@aws-sdk/client-dynamodb";

const ddb = new DynamoDBClient({ region: "us-east-1" });

exports.handler = async (event: any) => {
  // 관세 인상 이벤트가 들어왔다고 가정
  const affectedSupplierId = event.supplierId;

  // 해당 공급처 우선순위 낮추기
  const params = {
    TableName: "ProcurementPriorities",
    Key: { "SupplierId": { S: affectedSupplierId } },
    UpdateExpression: "SET Priority = :p",
    ExpressionAttributeValues: { ":p": { N: "10" } }, // 낮은 우선순위 숫자
  };

  try {
    await ddb.send(new UpdateItemCommand(params));
    console.log(`Updated priority for supplier ${affectedSupplierId}`);
  } catch (err) {
    console.error(err);
  }
};
```

이렇게 하면 관세 이슈가 감지되는 즉시 조달 우선순위를 바꿔서 다른 공급처로 빠르게 전환할 수 있다. 물론, 이 과정에서 재고 수준, 납기 일정 등도 함께 고려해야 한다.

## SAP SCM 시스템에서 보는 관세 대응과 재고 조정

SAP SCM은 다양한 공급업체와 물류 경로를 최적화하는 데 강점이 있다. 관세나 무역장벽이 생기면, 단순히 비용이 높은 공급처를 배제하는 게 아니라 재고 수준과 주문 이행 전략을 함께 조정한다. 

예를 들어, 관세가 오른 국가에서 들어오는 부품은 재고를 평소보다 더 많이 쌓아두거나, 반대로 빠른 대체 공급처가 확보되면 재고를 줄이는 식이다. 이런 전략은 SAP Help Portal 문서에도 잘 나와 있다[ SAP Help Portal - Supply Chain Management](https://help.sap.com/docs/SAP_SUPPLY_CHAIN_MANAGEMENT).

우리 시스템에서도 이런 재고 조정 로직을 코드화해두면 좋다. 예를 들어, 재고 임계치를 관세 변화에 따라 동적으로 조정하는 기능을 생각해볼 수 있다.

### 재고 임계치 동적 조정 예시 (의사코드)
```typescript
function adjustReorderPoint(tariffRate: number, baseReorderPoint: number): number {
  // 관세율이 10% 이상이면 재고를 20% 더 쌓는다
  if (tariffRate >= 0.1) {
    return Math.ceil(baseReorderPoint * 1.2);
  }
  return baseReorderPoint;
}

// 사용 예
const currentTariff = 0.15; // 15%
const baseROP = 100;
const newROP = adjustReorderPoint(currentTariff, baseROP);
console.log(`새 재주문 기준점: ${newROP}`); // 120
```

이런 간단한 로직 하나가 재고 부족으로 인한 생산 차질을 막는 데 큰 도움이 된다.

## 백엔드와 클라우드 플랫폼에서 SCM 자동화와 최적화, 현실적인 고민

공급망 관리는 단순히 비즈니스 로직만 잘 짜면 끝나는 게 아니다. 백엔드 아키텍처와 클라우드 플랫폼이 얼마나 유연하고 확장성 있게 설계되어 있느냐에 따라 대응 속도와 정확도가 달라진다. 

Microsoft Learn 문서에서도 SCM 시스템이 백엔드와 클라우드 플랫폼 간 원활한 통합을 통해 조달과 물류 프로세스의 자동화 및 최적화를 지원해야 한다고 강조한다[Microsoft Learn - Dynamics 365 Supply Chain Management](https://learn.microsoft.com/en-us/dynamics365/supply-chain/).

하지만 현실에서는 다음과 같은 고민들이 있다.

- **데이터 신뢰성:** 관세 정보, 물류 상태, 재고 수량 등 데이터가 실시간으로 정확히 반영되어야 한다.
- **시스템 복잡성:** 여러 시스템이 얽혀있어 변경이 쉽지 않다. 작은 로직 변경에도 테스트와 배포 부담이 크다.
- **비용과 성능 트레이드오프:** 실시간 처리와 대용량 데이터 분석을 위해 클라우드 리소스를 많이 쓰면 비용이 급증한다.

그래서 엔지니어는 이런 현실을 감안해, 예를 들어 이벤트 기반 아키텍처로 각 시스템을 느슨하게 결합하거나, 캐싱과 배치 처리의 적절한 조합을 찾아야 한다.

# 마치며: 우리 팀 SCM 시스템에 관세 충격 대응 기능을 추가한다면

1. **관세 변동 이벤트를 실시간으로 감지하고, 관련 공급처 우선순위와 물류 경로 정보를 자동 업데이트하는 API를 설계하자.**

2. **재고 임계치와 주문 정책을 관세율에 따라 동적으로 조정하는 비즈니스 로직을 백엔드에 구현하자.**

3. **클라우드 플랫폼의 서버리스 컴퓨팅과 메시지 큐를 활용해 공급망 이벤트 처리 파이프라인을 구축하자.**

4. **데이터 신뢰성과 시스템 확장성을 위해 이벤트 소싱과 CQRS 패턴 도입도 고려해보자.**

처음엔 이런 변화가 복잡해 보일 수 있지만, 실제로 관세나 무역장벽 같은 외부 충격에 빠르게 대응할 수 있는 SCM 시스템은 비즈니스 경쟁력의 핵심이다. 혼다 사례처럼 우리도 물류와 조달의 작은 조정을 시스템적으로 뒷받침하는 엔지니어링 역량을 키워야 하지 않을까?
