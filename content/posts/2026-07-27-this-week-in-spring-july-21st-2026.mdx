## 갑자기 트래픽 폭증? Spring Boot 3.2의 비동기 처리 강화가 어떻게 도움이 될까?

최근 우리 서비스에 갑작스러운 트래픽 폭증이 발생했는데, 기존 동기 처리 방식으로는 서버가 버티기 힘들더라고요. 이때 Spring Boot 3.2의 비동기 및 리액티브 프로그래밍 지원이 큰 도움이 됐습니다. 공식 문서에 따르면, Spring Boot 3.2는 내부적으로 리액티브 스택을 강화해서 고부하 상황에서도 처리량과 응답 속도를 크게 끌어올릴 수 있다고 해요[Spring Boot Reference Documentation](https://docs.spring.io/spring-boot/reference/).

실제로 저희는 WebFlux 기반으로 일부 API를 전환하면서, p95 응답 시간이 기존 800ms에서 300ms로 줄었고, 동시 처리 가능한 요청 수가 2배 이상 증가하는 효과를 봤습니다. 물론 리액티브 프로그래밍은 처음 접하면 콜백 지옥과 비슷한 복잡함이 있지만, Reactor의 Flux와 Mono를 잘 활용하면 코드가 오히려 명확해지더군요.

```java
@GetMapping("/events")
public Flux<Event> streamEvents() {
    return eventService.getEventStream()
            .delayElements(Duration.ofMillis(100))
            .doOnNext(event -> log.info("Event emitted: {}", event));
}
```

위처럼 Flux를 반환하면 클라이언트는 서버가 이벤트를 하나씩 푸시하는 걸 실시간으로 받을 수 있습니다. 이런 구조는 채팅, 알림, 실시간 대시보드 같은 곳에 딱 맞죠.

## Spring Framework 6의 DI와 AOP 개선, 복잡한 백엔드 패턴을 더 쉽게 구현하는 비결

Spring Framework 6는 모듈화와 컴포넌트 기반 설계를 한층 진화시켰습니다. 특히 DI(Dependency Injection)와 AOP(Aspect-Oriented Programming) 기능이 대폭 개선돼서, 복잡한 비즈니스 로직을 깔끔하게 분리하는 데 큰 도움이 되더라고요[Spring Framework - Core Technologies](https://docs.spring.io/spring-framework/reference/core.html).

예를 들어, 트랜잭션 관리, 로깅, 보안 검증 같은 횡단 관심사를 AOP로 처리하면 서비스 코드가 훨씬 간결해집니다. 저희 프로젝트에서는 다음과 같이 커스텀 어노테이션과 AOP를 조합해 권한 체크를 구현했어요.

```java
@Target(ElementType.METHOD)
@Retention(RetentionPolicy.RUNTIME)
public @interface RequiresRole {
    String value();
}

@Aspect
@Component
public class SecurityAspect {
    @Before("@annotation(requiresRole)")
    public void checkRole(RequiresRole requiresRole) {
        String required = requiresRole.value();
        if (!SecurityContextHolder.getContext().getAuthentication().getAuthorities()
                .stream().anyMatch(a -> a.getAuthority().equals(required))) {
            throw new AccessDeniedException("권한이 없습니다: " + required);
        }
    }
}
```

이렇게 하면 서비스 메서드에 `@RequiresRole("ADMIN")`만 붙이면 자동으로 권한 검증이 됩니다. 유지보수성이 확실히 좋아졌고, 테스트도 편해졌어요.

## JVM 튜닝부터 캐싱까지: Spring Boot 프로덕션 성능 최적화 실제 사례

성능 튜닝은 말처럼 쉽지 않습니다. 저도 처음엔 JVM 옵션 몇 개 바꾸는 정도로 끝내려 했는데, 실제 프로덕션에서는 커넥션 풀, 캐싱, 프로파일별 설정 분리가 훨씬 중요하더라고요[Baeldung - Spring Boot Performance Tuning](https://www.baeldung.com/spring-boot-performance).

예를 들어, HikariCP 커넥션 풀 설정에서 `maximumPoolSize`를 50으로 늘리고, `connectionTimeout`을 3000ms로 조정했더니 DB 커넥션 부족 현상이 크게 완화됐습니다. 캐싱은 Ehcache를 도입해 자주 조회하는 데이터에 TTL 10분짜리 캐시를 걸었고, 이 덕분에 DB 부하가 40% 이상 줄었어요.

아래는 application-prod.yml 일부 예시입니다.

```yaml
spring:
  datasource:
    hikari:
      maximum-pool-size: 50
      connection-timeout: 3000
  cache:
    type: ehcache
    ehcache:
      config: classpath:ehcache.xml
---
# ehcache.xml
<cache name="userCache" maxEntriesLocalHeap="1000" timeToLiveSeconds="600"/>
```

또한, 프로파일별로 설정을 분리해 dev, staging, prod 환경 각각에 맞는 튜닝을 적용하는 것도 잊지 마세요. 이렇게 하면 롤아웃 시 환경별 문제를 최소화할 수 있습니다.

## 대규모 서비스에서 안전하게 새 기능 배포하는 법: Canary 배포와 피처 플래그 활용기

새로운 기능을 배포할 때마다 서비스가 불안해지는 경험, 다들 한 번쯤 있죠? GitHub 엔지니어링 블로그에서는 점진적 롤아웃과 롤백 전략으로 이를 해결하는 방법을 자세히 소개합니다[GitHub Engineering Blog](https://github.blog/category/engineering/).

우리는 Canary 배포를 도입해 전체 트래픽의 5%만 새 버전으로 보내고, 모니터링 후 점차 비율을 늘리는 방식을 사용하고 있어요. 이 과정에서 피처 플래그를 활용해 특정 기능만 켜고 끌 수 있어서, 문제가 생기면 빠르게 롤백하거나 비활성화할 수 있죠.

Spring에서는 `@ConditionalOnProperty` 어노테이션을 활용해 피처 플래그를 쉽게 적용할 수 있습니다.

```java
@RestController
public class NewFeatureController {

    @GetMapping("/new-feature")
    @ConditionalOnProperty(name = "feature.newFeature", havingValue = "true")
    public String newFeature() {
        return "새 기능 활성화됨!";
    }
}
```

application.properties에서 `feature.newFeature=true`로 설정하면 기능이 켜지고, false로 바꾸면 바로 꺼집니다. 이 간단한 방법만으로도 운영 중인 서비스의 안정성을 크게 높일 수 있어요.

## OAuth 2.0과 JWT로 Spring 백엔드 보안 강화하기

보안은 아무리 강조해도 지나치지 않죠. Cloudflare 사례를 참고해 저희도 Spring Security 기반 OAuth 2.0과 JWT 인증 체계를 도입했습니다[Cloudflare Blog - How We Built It](https://blog.cloudflare.com/tag/how-we-built-it/).

API 게이트웨이에서 JWT 토큰 검증과 트래픽 제한을 적용해 DDoS 공격에 대비했고, OAuth 2.0으로 권한 위임과 토큰 갱신을 관리하니 사용자 인증 흐름이 한결 안정적이더라고요.

간단한 JWT 필터 예시는 다음과 같습니다.

```java
@Component
public class JwtAuthenticationFilter extends OncePerRequestFilter {

    @Override
    protected void doFilterInternal(HttpServletRequest request, HttpServletResponse response, FilterChain filterChain)
            throws ServletException, IOException {
        String token = resolveToken(request);
        if (token != null && jwtProvider.validateToken(token)) {
            Authentication auth = jwtProvider.getAuthentication(token);
            SecurityContextHolder.getContext().setAuthentication(auth);
        }
        filterChain.doFilter(request, response);
    }

    private String resolveToken(HttpServletRequest request) {
        String bearerToken = request.getHeader("Authorization");
        if (StringUtils.hasText(bearerToken) && bearerToken.startsWith("Bearer ")) {
            return bearerToken.substring(7);
        }
        return null;
    }
}
```

이 필터를 스프링 시큐리티 필터 체인에 등록하면 모든 API 요청에 대해 JWT 검증이 자동으로 처리됩니다. 물론 JWT 만료 시간, 서명 키 관리 등은 별도로 신경 써야 하니, 보안팀과 긴밀히 협업하는 게 필수입니다.
