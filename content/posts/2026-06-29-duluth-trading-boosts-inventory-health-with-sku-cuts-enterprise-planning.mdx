## SKU 수 줄이기가 재고 건강에 미치는 영향, 직접 경험해보니

얼마 전 Duluth Trading이 재고 건강도를 크게 개선했다는 뉴스를 접했어요. 핵심 전략은 SKU 수를 줄이고, 엔터프라이즈 계획 시스템을 도입해 수요 예측과 생산 계획을 통합한 거였죠. 이게 실제로 어떤 의미냐면, 불필요하게 쌓여 있던 재고가 줄고 회전율이 확 올라갔다는 겁니다. 

저도 비슷한 프로젝트를 진행하면서 느낀 건데, SKU를 줄인다는 게 단순히 품목을 없애는 게 아니에요. 재고 관리가 훨씬 단순해지고, 데이터 기반 의사결정이 쉬워지면서 백엔드 시스템도 덩달아 가벼워지고 빠르게 변할 수 있더라고요. Microsoft의 Dynamics 365 SCM 문서에서도 SKU 축소가 재고 비용 절감과 회전율 개선에 핵심이라고 명확히 짚고 있죠[Microsoft Learn - Dynamics 365 Supply Chain Management](https://learn.microsoft.com/en-us/dynamics365/supply-chain/).


## 엔터프라이즈 계획 시스템, 백엔드 아키텍처에선 어떻게 다뤄야 할까?

Duluth Trading처럼 엔터프라이즈 계획(Enterprise Planning) 시스템을 도입하면, 수요 예측부터 생산, 재고 관리까지 한 번에 관리할 수 있어요. 이걸 우리 백엔드에 적용하려면 단순한 CRUD API 이상이 필요하죠. 

제가 일했던 곳에서는 수요 예측 데이터를 외부 AI 서비스에서 받아와서, 생산 계획 모듈과 재고 관리 모듈이 서로 이벤트로 소통하게 했습니다. 예를 들어, 수요 예측이 바뀌면 `DemandUpdated` 이벤트가 발생하고, 생산 계획 서비스가 이를 구독해서 생산량을 조정하는 식이었죠. 

이런 아키텍처는 Oracle의 SCM 문서에서도 강조하는 부분인데, 통합된 계획 시스템은 모듈화된 서비스와 데이터 연동으로 구현되어야 주문 처리와 물류 최적화를 효과적으로 지원할 수 있다고 해요[Oracle Docs - SCM and Manufacturing](https://docs.oracle.com/en/cloud/saas/supply-chain-and-manufacturing/).


## SAP 사례에서 본 AI 수요 예측과 클라우드 확장성

SAP SCM 솔루션은 AI 기반 수요 예측과 실시간 데이터 분석으로 재고 건강도를 올리는 데 집중해요. 우리도 비슷한 걸 하려면, AI 모델에서 나온 예측 결과를 실시간으로 백엔드에 반영할 수 있어야 하죠. 

예를 들어, AWS Lambda 같은 서버리스 환경에서 AI 예측 결과를 받아 DynamoDB에 저장하고, 재고 관리 마이크로서비스가 이를 구독해 재고 수량을 조정하는 구조를 생각해볼 수 있어요. 이렇게 하면 급격한 수요 변화에도 빠르게 대응할 수 있죠. 

SAP가 강조하는 건 이런 시스템이 클라우드 플랫폼과 연동되어 확장 가능해야 한다는 점입니다. 즉, 트래픽 급증이나 데이터 증가에 유연하게 대응할 수 있어야 한다는 거죠[ SAP Help Portal - Supply Chain Management](https://help.sap.com/docs/SAP_SUPPLY_CHAIN_MANAGEMENT).


## 백엔드 엔지니어가 직접 구현해본 재고 최적화용 이벤트 기반 마이크로서비스 예시

아래는 TypeScript와 Node.js 환경에서 이벤트 기반으로 재고 수량을 관리하는 간단한 마이크로서비스 예시입니다. 이 코드는 수요 예측 이벤트를 받아 재고를 조정하는 핵심 로직을 담고 있어요.

```typescript
import { EventEmitter } from 'events';

interface DemandUpdatedEvent {
  sku: string;
  forecastQuantity: number;
}

class InventoryService extends EventEmitter {
  private stockMap: Map<string, number> = new Map();

  constructor() {
    super();
    this.on('DemandUpdated', this.handleDemandUpdated.bind(this));
  }

  handleDemandUpdated(event: DemandUpdatedEvent) {
    const currentStock = this.stockMap.get(event.sku) || 0;
    // 예측 수요에 맞춰 재고를 조정하는 간단한 로직
    const adjustedStock = Math.max(currentStock, event.forecastQuantity);
    this.stockMap.set(event.sku, adjustedStock);
    console.log(`SKU ${event.sku} 재고가 ${adjustedStock}로 조정되었습니다.`);
  }

  getStock(sku: string) {
    return this.stockMap.get(sku) || 0;
  }
}

// 실제 사용 예
const inventoryService = new InventoryService();

// AI 수요 예측에서 온 이벤트 시뮬레이션
inventoryService.emit('DemandUpdated', { sku: 'DULUTH-1234', forecastQuantity: 150 });

console.log(`현재 재고: ${inventoryService.getStock('DULUTH-1234')}`);
```

이 코드는 단순하지만, 실제 환경에선 이벤트 버스(Kafka, RabbitMQ 등)를 쓰고, 여러 마이크로서비스가 협업하는 복잡한 구조가 될 겁니다. 하지만 기본 개념은 이렇습니다. 수요 예측 이벤트가 들어오면 재고 수량을 동적으로 조정하는 거죠.


## 우리 시스템에 바로 적용하려면 어떤 점을 고민해야 할까?

처음엔 이게 별거 아닌 것 같지만, 실무에서 SKU를 줄이고 엔터프라이즈 계획을 도입하는 건 꽤 큰 변화입니다. 

- **데이터 정합성**: 여러 서비스가 동시에 재고를 변경하니 일관성 유지가 쉽지 않아요. 이벤트 소싱이나 CQRS 패턴을 고민해야 할 때가 많죠.
- **모델링 난이도**: SKU 축소가 단순히 품목을 없애는 게 아니라, 어떤 SKU를 유지할지 결정하는 비즈니스 로직이 복잡합니다.
- **확장성**: AI 예측 데이터가 많아지고 트래픽이 급증할 때, 클라우드 기반 확장 아키텍처가 필수입니다.

이런 부분들은 GitHub 엔지니어링 블로그에서도 언급하는데, SCM 최적화는 단순히 알고리즘이나 UI를 고치는 게 아니라, 데이터 파이프라인과 이벤트 기반 아키텍처, 마이크로서비스 설계가 핵심이라고 하더라고요[GitHub Engineering Blog](https://github.blog/category/engineering/).


## 마무리하며: 재고 최적화, 백엔드가 놓치면 안 되는 포인트

Duluth Trading 사례를 보면서 느낀 건, SCM 재고 최적화는 단순한 비즈니스 전략이 아니라, 백엔드 시스템 설계와도 직결된다는 점입니다. 

- SKU 수를 줄이면 재고 회전율이 올라가고, 백엔드 서비스는 더 단순해지고 빠르게 변할 수 있다.
- 엔터프라이즈 계획 시스템은 마이크로서비스와 이벤트 기반 아키텍처로 구현해야 실시간 주문 처리와 물류 최적화가 가능하다.
- AI 기반 수요 예측과 클라우드 확장성은 현대 SCM 백엔드의 필수 요소다.

실제로 저도 위 예시처럼 이벤트 기반 재고 조정 서비스를 만들어보면서, 작은 코드 한 줄이 전체 공급망 효율에 얼마나 큰 영향을 미치는지 체감했습니다. 

다음 프로젝트에서 재고 최적화 고민할 때, 이 글에서 다룬 실무적 조언들이 조금이라도 도움이 되길 바랍니다.
