## "우리 서비스에 AI를 붙이려는데, 최신 모델은 어떻게 써야 할까?"

최근에 우리 팀에서 AI를 백엔드에 붙이면서 가장 많이 들었던 질문이에요. OpenAI와 Anthropic에서 새로 나온 모델들이 쏟아져 나오는데, 그냥 API 호출만 하면 되는 건지, 아니면 뭔가 더 신경 써야 할 게 있는지 헷갈리더라고요. 실제로 Spring AI 2.0이 나와서 Spring Boot 애플리케이션에 AI 통합이 훨씬 쉬워졌다고는 하지만, "쉽다"와 "잘 운영된다"는 완전히 다른 이야기죠.

오늘은 Spring Office Hours Podcast S5E18에서 다룬 최신 AI 모델 통합 이야기를 바탕으로, OpenAI와 Anthropic AI를 Spring AI 2.0 백엔드에 어떻게 붙이고, 운영 환경에서 어떤 점을 꼭 챙겨야 하는지 현실적인 팁을 공유해보려고 해요.

## Spring AI 2.0, 왜 Spring Boot와 찰떡 궁합일까?

Spring AI 2.0은 Spring Boot 기반 백엔드에 AI 모델을 통합하는 데 최적화된 프레임워크입니다. Spring Boot의 모듈화된 구조 덕분에 OpenAI와 Anthropic 같은 외부 AI 서비스와도 유연하게 연동할 수 있죠. 예를 들어, Spring Boot의 `WebClient`를 활용해서 비동기 API 호출을 자연스럽게 처리할 수 있고, 필요하면 `RestTemplate` 같은 동기 호출도 지원합니다.

이게 왜 중요한지 체감하려면, 우리 서비스가 하루 100만 건 이상의 AI 요청을 받는다고 가정해보세요. 동기 호출만 쓰면 응답 지연이 심해지고, 서버 리소스가 금세 바닥나죠. 반면 `WebClient`를 쓰면 논블로킹 방식으로 처리해 훨씬 효율적입니다.

```java
@Bean
public WebClient openAiWebClient() {
    return WebClient.builder()
            .baseUrl("https://api.openai.com/v1")
            .defaultHeader(HttpHeaders.AUTHORIZATION, "Bearer " + openAiApiKey)
            .build();
}

public Mono<String> callOpenAi(String prompt) {
    return openAiWebClient().post()
            .uri("/chat/completions")
            .bodyValue(Map.of(
                "model", "gpt-4",
                "messages", List.of(Map.of("role", "user", "content", prompt))
            ))
            .retrieve()
            .bodyToMono(String.class);
}
```

이 코드는 Spring Boot에서 OpenAI API를 비동기 방식으로 호출하는 간단한 예시입니다. `WebClient`를 빈으로 등록해 재사용하고, API 키는 환경변수나 안전한 저장소에서 관리하는 게 좋습니다.

[Spring Boot Reference Documentation](https://docs.spring.io/spring-boot/reference/)에서 자세한 설정법을 참고할 수 있어요.

## Anthropic Claude 모델, 프롬프트 엔지니어링으로 안정성 높이기

Anthropic의 Claude 모델은 단순히 API를 호출하는 것만으로는 원하는 품질의 답변을 얻기 어려울 때가 많아요. 그래서 프롬프트 엔지니어링이 필수인데, Spring 백엔드에서는 프롬프트 템플릿을 관리하고 파라미터를 조절하는 기능을 직접 구현하는 걸 추천합니다.

예를 들어, 사용자 질문에 따라 프롬프트 앞부분에 "친절하게 설명해줘" 같은 지시문을 넣거나, 최대 토큰 수, 온도(temperature) 값을 조절해서 응답의 창의성이나 일관성을 조정하는 식이죠.

```java
public String buildClaudePrompt(String userQuestion) {
    String systemInstruction = "You are a helpful assistant.";
    return systemInstruction + "\nUser: " + userQuestion + "\nAssistant:";
}

public Mono<String> callClaudeApi(String prompt) {
    return webClient.post()
            .uri("/v1/claude/completions")
            .bodyValue(Map.of(
                "prompt", prompt,
                "max_tokens_to_sample", 300,
                "temperature", 0.7
            ))
            .retrieve()
            .bodyToMono(String.class);
}
```

이처럼 프롬프트를 템플릿화해 관리하면, 나중에 모델 업데이트나 튜닝할 때도 일괄적으로 적용하기 편해져요. Anthropic 공식 문서에서 권장하는 프롬프트 엔지니어링 가이드도 꼭 참고하세요.[Anthropic - Prompt Engineering Guide](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/overview)

## AI 호출 보안, OAuth2와 API 키 관리 없인 운영 못 한다

AI API 호출할 때 보안을 안 챙기면 큰일 납니다. API 키가 유출되면 비용 폭탄 맞거나, 악의적 사용자가 서비스 장애를 일으킬 수 있거든요. Spring AI 2.0에서는 Spring Security와 연동해 OAuth2 기반 인증을 적용하거나, API 키를 안전하게 관리하는 구조를 권장합니다.

또한, AI 요청과 응답 로그에 민감한 정보가 포함될 수 있으니, 로그 필터링과 암호화도 필수입니다. 예를 들어, 개인정보가 포함된 프롬프트나 결과는 로그에 평문으로 남기지 말고, 암호화하거나 익명화해야 해요.

```java
@Configuration
@EnableWebSecurity
public class SecurityConfig extends WebSecurityConfigurerAdapter {
    @Override
    protected void configure(HttpSecurity http) throws Exception {
        http
            .authorizeRequests(authz -> authz
                .antMatchers("/api/ai/**").authenticated()
                .anyRequest().permitAll()
            )
            .oauth2ResourceServer(OAuth2ResourceServerConfigurer::jwt);
    }
}
```

이 코드는 Spring Security로 AI API 엔드포인트를 JWT 기반 OAuth2 인증으로 보호하는 예입니다. 실제 운영 환경에서는 API 키 회전 정책과 함께, 권한 부여도 엄격하게 관리해야 하죠.

[Spring Framework - Core Technologies](https://docs.spring.io/spring-framework/reference/core.html)에서 보안 관련 심층 내용을 확인할 수 있습니다.

## 운영 환경에서 AI 통합 성능을 어떻게 챙길까?

AI 호출은 네트워크 지연과 외부 서비스 의존성이 크기 때문에, 성능 최적화가 필수입니다. Spring Boot 애플리케이션에서는 다음 세 가지를 꼭 고려하세요.

1. **커넥션 풀링**: `WebClient`와 HTTP 클라이언트에 커넥션 풀을 설정해 재사용하면, 매 요청마다 TCP 연결을 새로 만드는 비용을 줄일 수 있습니다.

2. **비동기 처리**: AI 호출은 I/O 작업이므로, `Mono`나 `Flux` 같은 리액티브 타입을 활용해 쓰레드 차단 없이 처리하는 게 효율적입니다.

3. **캐싱 전략**: 동일한 질문에 대해 자주 호출하는 경우, 응답을 캐싱해서 API 호출 횟수를 줄이고 응답 속도를 높일 수 있습니다.

```java
@Bean
public WebClient openAiWebClient() {
    HttpClient httpClient = HttpClient.create()
        .tcpConfiguration(tcpClient ->
            tcpClient.option(ChannelOption.CONNECT_TIMEOUT_MILLIS, 5000)
                     .doOnConnected(conn ->
                         conn.addHandlerLast(new ReadTimeoutHandler(5))
                             .addHandlerLast(new WriteTimeoutHandler(5))));

    return WebClient.builder()
        .clientConnector(new ReactorClientHttpConnector(httpClient))
        .baseUrl("https://api.openai.com/v1")
        .defaultHeader(HttpHeaders.AUTHORIZATION, "Bearer " + openAiApiKey)
        .build();
}
```

위 예시는 커넥션 타임아웃과 읽기/쓰기 타임아웃을 5초로 설정해, 네트워크 문제 시 빠르게 실패하도록 만든 설정입니다. 이런 튜닝은 실제 서비스 안정성에 큰 영향을 줍니다.

더불어, Baeldung의 [Spring Boot Performance Tuning](https://www.baeldung.com/spring-boot-performance) 가이드도 꼭 참고해서, CPU, 메모리, GC 튜닝과 쓰레드 풀 설정까지 챙기면 좋습니다.

## 마무리하며: AI 통합, "쉽다"와 "잘한다"는 다르다

OpenAI와 Anthropic 최신 AI 모델을 Spring AI 2.0에 붙이는 건 이제 기술적으로 크게 어렵지 않습니다. 하지만 진짜 도전은 "운영 환경에서 안정적이고 효율적으로, 그리고 안전하게" 서비스하는 거예요.

- API 호출은 비동기 방식으로 처리하고
- 프롬프트 템플릿과 파라미터를 관리해 모델 응답 품질을 높이며
- OAuth2와 API 키 관리로 보안을 강화하고
- 커넥션 풀링, 타임아웃, 캐싱 등으로 성능을 최적화하는 것

이 모든 걸 한꺼번에 챙겨야 진짜 프로덕션급 AI 백엔드가 됩니다. 처음엔 복잡해 보여도, 한 단계씩 적용해보면 생각보다 금방 익숙해져요.

우리 팀도 Spring AI 2.0 도입 후 이런 원칙을 지키면서 AI 서비스 안정성을 크게 높일 수 있었습니다. 혹시 AI 백엔드 통합 고민 중이라면, 이번 글과 함께 Spring Office Hours Podcast S5E18도 한번 들어보시길 추천합니다.
