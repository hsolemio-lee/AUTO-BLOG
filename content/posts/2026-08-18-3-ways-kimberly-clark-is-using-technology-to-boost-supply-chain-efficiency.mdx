# 공급망이 막힐 때마다 느껴본 적 있나요? Kimberly-Clark는 기술로 답을 찾았다

공장 가동이 멈추고, 고객 주문이 밀리고, 재고가 부족해지는 순간을 경험해본 적 있나요? 저도 여러 번 겪어봤는데, 이럴 때마다 기술이 얼마나 중요한지 뼈저리게 느낍니다. Kimberly-Clark가 어떻게 최신 기술로 공급망 전반의 효율성을 끌어올렸는지, 특히 엔지니어링 관점에서 배울 점이 많아 공유하려고 합니다.

## 계획 수립부터 최적화까지, 데이터 기반 수요 예측 시스템 도입

Kimberly-Clark는 과거 경험과 시장 데이터를 바탕으로 수요 예측을 했는데, 이게 생각보다 부정확해서 재고 과잉 혹은 부족 현상이 자주 발생했어요. 그래서 머신러닝 기반 예측 시스템을 도입했습니다. 

이 시스템은 과거 판매 데이터, 계절성, 프로모션 일정, 심지어 날씨 데이터까지 반영해 수요를 예측하는데, 예측 정확도가 20% 이상 개선됐다고 하더군요. 

기술적으론 AWS Sagemaker 같은 클라우드 ML 서비스를 활용해 모델을 주기적으로 재학습시키고, 예측 결과를 API로 공급망 관리 시스템에 연결해 실시간으로 반영합니다.

```python
# 예측 결과를 SCM 시스템에 업데이트하는 간단한 예시
import requests

PREDICTION_API = 'https://api.kimberlyclark.com/supplychain/demand-prediction'

new_forecast = {
    'product_id': 'KC12345',
    'week': '2024-W27',
    'predicted_demand': 15000
}

response = requests.post(PREDICTION_API, json=new_forecast)
if response.status_code == 200:
    print('수요 예측 업데이트 성공')
else:
    print('업데이트 실패:', response.text)
```

이렇게 점진적으로 예측 결과를 반영하는데, 작은 범위의 점진적 배포 전략을 써서 운영 리스크를 줄였다고 합니다. 실제로 신규 기능을 한 번에 다 밀어넣는 게 아니라, 특정 라인이나 지역에만 먼저 적용해 문제를 조기에 발견하는 방식이죠. 이 부분은 OpenAI API 문서에서도 작은 범위 배포가 운영 리스크를 줄인다는 점을 강조하고 있어요[OpenAI API Documentation](https://platform.openai.com/docs/overview).

## 조달 프로세스 자동화로 납기 지연 최소화

조달 단계에서 가장 골치 아픈 건 납기 지연과 소통 문제입니다. Kimberly-Clark는 조달 담당자와 공급업체 간 커뮤니케이션을 자동화하는 챗봇과 알림 시스템을 도입했어요. 

이 챗봇은 주문 상태, 예상 납기일 변경, 긴급 요청 등을 실시간으로 파악해 담당자에게 알려주고, 공급업체에는 자동으로 리마인드 메시지를 보냅니다. 덕분에 납기 지연 건수가 15% 감소했다고 하네요.

기술적으로는 Microsoft Dynamics 365 Supply Chain Management를 기반으로 API 연동과 이벤트 기반 알림 시스템을 구축했습니다. 이벤트 소싱 패턴을 적용해 주문 상태 변경 이벤트를 캡처하고, 이를 트리거로 알림과 챗봇 응답을 처리하는 구조입니다[Microsoft Learn - Dynamics 365 Supply Chain Management](https://learn.microsoft.com/en-us/dynamics365/supply-chain/).

이 과정에서 실패 유형을 초기에 계측하는 로깅과 모니터링을 강화했는데, 장애 대응 속도가 눈에 띄게 빨라졌어요. 이 부분은 Anthropic의 프롬프트 엔지니어링 가이드에서 실패 유형 초기 계측이 유지보수성과 장애 대응에 도움 된다는 점과 맥락이 닿습니다[Anthropic - Prompt Engineering Guide](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/overview).

## 주문 이행 자동화와 실시간 재고 추적 시스템

마지막으로, 주문 이행 과정에서의 병목 현상을 해결하기 위해 자동화 로봇과 실시간 재고 추적 시스템을 도입했습니다. 

창고 내 로봇이 주문 상품을 자동으로 집어 포장대까지 운반하고, RFID 태그와 IoT 센서를 활용해 재고 위치와 수량을 실시간으로 파악합니다. 

이 시스템 덕분에 주문 처리 속도가 30% 빨라졌고, 재고 오류가 25% 줄었다고 합니다. 

기술 스택은 SAP Supply Chain Management와 자체 개발한 IoT 플랫폼을 결합했는데, SAP API를 통해 재고 데이터와 주문 데이터를 통합 관리합니다[SAP Help Portal - Supply Chain Management](https://help.sap.com/docs/SAP_SUPPLY_CHAIN_MANAGEMENT).

```java
// SAP API를 활용한 재고 조회 예시
import com.sap.conn.jco.*;

public class InventoryChecker {
    public static void main(String[] args) throws JCoException {
        JCoDestination destination = JCoDestinationManager.getDestination("MY_SAP_DEST");
        JCoFunction function = destination.getRepository().getFunction("BAPI_MATERIAL_STOCK_REQ_LIST");

        function.getImportParameterList().setValue("MATERIAL", "KC12345");
        function.getImportParameterList().setValue("PLANT", "1000");

        function.execute(destination);

        JCoTable stockList = function.getTableParameterList().getTable("STOCK_REQ_LIST");
        for (int i = 0; i < stockList.getNumRows(); i++) {
            stockList.setRow(i);
            System.out.println("재고 위치: " + stockList.getString("STGE_LOC") + ", 수량: " + stockList.getInt("REQ_QTY"));
        }
    }
}
```

자동화와 실시간 데이터가 결합되니, 예기치 않은 재고 부족이나 주문 지연 상황을 미리 감지해 대응할 수 있어 현실적인 효과가 컸습니다.

## 기술 도입 뒤에 숨은 현실적인 고민들

이렇게 멋진 기술 도입 뒤에는 항상 현실적인 고민이 따릅니다. 

- **데이터 품질 문제**: 머신러닝 예측의 정확도는 데이터 품질에 직결됩니다. Kimberly-Clark도 초기에는 데이터 정합성 문제로 예측이 엉망이었어요. 그래서 데이터 클렌징과 ETL 파이프라인에 상당한 투자를 했습니다.

- **시스템 통합 난이도**: 기존 레거시 시스템과 클라우드 기반 신기술을 연결하는 과정에서 API 호환성 문제, 데이터 포맷 차이 등으로 고생 많았다고 합니다.

- **운영 리스크 관리**: 신규 기능을 한 번에 다 적용하면 장애가 날 확률이 높죠. 그래서 점진적 배포 전략을 엄격히 적용해 안정성을 확보했습니다.

이런 점들은 우리도 개발하면서 자주 겪는 문제라 Kimberly-Clark 사례가 더 와닿더군요.

또, 실패 유형을 초기에 잘 계측해서 문제를 빠르게 파악하고 대응하는 시스템 설계가 얼마나 중요한지도 다시 한 번 느꼈습니다.
