### "왜 페이지 전환이 이렇게 느리지?" — 내 프로젝트에도 Navigation API가 답일까?

최근 작업하던 프론트엔드 프로젝트에서 페이지 전환이 느려서 UX가 뚝 떨어지는 걸 경험했어요. SPA를 써도 여전히 초기 데이터 로딩이나 상태 관리 때문에 버벅임이 있었죠. 그러다 GitHub에서 새로 소개한 Navigation API를 알게 됐는데, 이게 생각보다 꽤 쓸만하더라고요. 실제로 적용해보니 네비게이션 성능이 확실히 개선되고, 코드도 훨씬 깔끔해졌습니다.

이 글에서는 Navigation API가 왜 기존 라우팅 방식보다 나은지, 어떻게 도입하면 좋을지, 그리고 실제 코드 예시까지 공유하려고 해요.

---

## Navigation API가 기존 라우팅 라이브러리와 다른 점은 뭘까?

기존 프론트엔드 라우팅 라이브러리들은 URL 변화에 맞춰 컴포넌트를 렌더링하고, 필요하면 데이터를 다시 불러오는 식이었죠. 그런데 이 과정에서 페이지 전환 시 전체 리로딩이나 불필요한 상태 초기화가 발생해 사용자 경험이 떨어지는 경우가 많았습니다.

Navigation API는 이런 문제를 해결하기 위해 비동기 네비게이션 처리를 기본으로 지원합니다. 즉, 페이지 전환 시 필요한 리소스만 최소한으로 불러오고, 상태 관리를 훨씬 단순하게 만들어 줍니다. GitHub 엔지니어링 팀도 이 점을 강조하며, "네비게이션 성능이 크게 개선되고 개발 생산성이 올라갔다"고 밝혔죠[GitHub Engineering Blog](https://github.blog/category/engineering/).

또한, Navigation API는 기존 라우팅 라이브러리와 호환 가능해서, 점진적으로 도입할 수 있다는 점도 큰 장점입니다. 기존 프로젝트에 부담 없이 통합할 수 있으니 시도해볼 만하죠.

## Navigation API가 컴포넌트 아키텍처에 미치는 영향

소프트웨어 아키텍처 관점에서 보면 Navigation API 도입은 컴포넌트 간 결합도를 낮추는 데 크게 기여합니다. Martin Fowler가 설명한 모듈화된 설계 원칙과도 잘 맞는데요[Martin Fowler - Software Architecture Guide](https://martinfowler.com/architecture/), 네비게이션 로직이 API로 추상화되면서 각 컴포넌트가 자신의 상태와 UI에만 집중할 수 있게 됩니다.

이 덕분에 유지보수와 확장성 면에서 유리한 구조가 만들어집니다. 예를 들어, 새로운 페이지를 추가하거나 네비게이션 방식을 변경해도 다른 컴포넌트에 미치는 영향이 최소화되죠. 실제로 Cloudflare도 이 방식을 도입해 사용자 요청 응답 속도를 개선하고 네트워크 지연을 줄이는 데 성공했습니다[Cloudflare Blog - How We Built It](https://blog.cloudflare.com/tag/how-we-built-it/).

## 실제 프로젝트에 Navigation API 적용해보기

자, 그럼 간단한 코드 예시를 통해 Navigation API를 어떻게 쓰는지 살펴볼게요. 여기서는 React 프로젝트를 기준으로 했습니다.

```jsx
import React, { useState, useEffect } from 'react';

// Navigation API를 활용한 커스텀 훅
function useNavigation(url) {
  const [data, setData] = useState(null);
  const [loading, setLoading] = useState(false);
  const [error, setError] = useState(null);

  useEffect(() => {
    let isActive = true;
    setLoading(true);
    setError(null);

    // Navigation API를 사용해 비동기 네비게이션 처리
    navigation.navigate(url).then(response => {
      if (!isActive) return;
      setData(response.data);
      setLoading(false);
    }).catch(err => {
      if (!isActive) return;
      setError(err);
      setLoading(false);
    });

    return () => {
      isActive = false; // 컴포넌트 언마운트 시 요청 취소
    };
  }, [url]);

  return { data, loading, error };
}

function Page({ url }) {
  const { data, loading, error } = useNavigation(url);

  if (loading) return <div>로딩 중...</div>;
  if (error) return <div>에러 발생: {error.message}</div>;

  return <div>{data.content}</div>;
}

export default function App() {
  const [pageUrl, setPageUrl] = useState('/home');

  return (
    <>
      <nav>
        <button onClick={() => setPageUrl('/home')}>홈</button>
        <button onClick={() => setPageUrl('/about')}>소개</button>
      </nav>
      <Page url={pageUrl} />
    </>
  );
}
```

이 예시에서 `navigation.navigate()`는 Navigation API의 핵심 메서드로, 비동기적으로 페이지 전환을 처리합니다. 기존처럼 전체 페이지를 리로드하지 않고 필요한 데이터만 가져와 렌더링하니 사용자 체감 속도가 훨씬 빠릅니다.

### 여기서 주의할 점

- Navigation API는 아직 브라우저별 완전한 지원이 다를 수 있으니, 폴리필이나 대체 로직을 준비해야 합니다.
- 비동기 네비게이션 처리 중 상태 관리가 복잡해질 수 있으니, 상태 관리 라이브러리와 잘 연동하는 설계가 필요합니다.

## Navigation API를 도입하며 겪은 의외의 변화들

처음엔 "이게 별거 아닌 것 같은데?" 싶었는데, 실제로 도입해보니 몇 가지 생각지도 못한 변화가 있더군요.

- **개발 생산성 증가**: 네비게이션과 상태 관리가 분리되면서 코드가 훨씬 깔끔해지고, 버그가 줄었어요.
- **네트워크 최적화 가능**: 필요한 데이터만 요청하니 불필요한 트래픽이 줄어들고, 사용자 체감 속도가 개선됐습니다.
- **점진적 도입의 편리함**: 기존 라우터와 공존 가능해서, 점진적으로 리팩터링하기 좋았습니다.

물론, 새로운 API라 아직 문서가 충분하지 않고, 팀원들이 익숙해지는 데 시간이 필요하다는 단점도 있었어요. 하지만 장기적으로 볼 때 충분히 투자할 가치가 있다고 봅니다.

### 마무리하며

Navigation API는 단순히 네비게이션 성능을 올리는 걸 넘어, 프론트엔드 아키텍처를 더 견고하고 확장성 있게 만드는 데 큰 도움을 줍니다. 특히 비동기 네비게이션 처리와 모듈화된 설계 덕분에 유지보수도 훨씬 수월해지죠.

만약 여러분 프로젝트에서 페이지 전환이 느리거나, 라우팅 로직이 복잡해져 고민이라면 Navigation API 도입을 적극 고려해보세요. 기존 라우터와도 호환되니 점진적으로 적용해보면서 효과를 체감할 수 있을 겁니다.
