### "왜 내 Spring MVC 앱은 부하만 걸리면 느려질까?"

한 번쯤은 겪어봤을 겁니다. 개발 환경에선 빠르던 API가 프로덕션에 배포하니 부하가 조금만 올라가도 응답이 뚝뚝 끊기고, 심지어 타임아웃도 발생하는 상황 말이죠. 저도 이런 경험이 여러 번 있었는데, 그때마다 "Spring MVC 설정을 조금만 더 꼼꼼히 하면 충분히 개선할 수 있겠다"는 생각이 들더라고요. 이번 글에서는 실제로 프로덕션에서 체감할 수 있는 Spring MVC 백엔드 성능과 보안 최적화 팁을 공유하려고 합니다.

## Spring Boot 스타트업 최적화, 그냥 넘어가지 말아야 할 부분

Spring Boot는 편리한 만큼 자동 구성이 많아 스타트업 시간이 길어질 수 있는데, 프로덕션에서는 이게 꽤 큰 병목이 될 수 있습니다. 예를 들어, 불필요한 자동 구성을 비활성화하면 시작 시간을 크게 줄일 수 있어요. 

application.properties에 다음과 같이 설정해 보세요:

```properties
spring.autoconfigure.exclude=org.springframework.boot.autoconfigure.jdbc.DataSourceAutoConfiguration
```

이 설정은 데이터 소스 자동 구성을 비활성화하는 예시인데, 만약 데이터베이스가 없거나 별도로 관리한다면 스타트업 시간을 아낄 수 있습니다. 실제로 제 프로젝트에서는 이런 불필요한 자동 구성을 줄이고 나서 스타트업 시간이 20% 이상 단축됐어요.

또한, Spring Boot Actuator를 꼭 활용하세요. Actuator는 애플리케이션 상태, 메트릭, 쓰레드 덤프 등을 실시간으로 보여줘서 병목 지점 파악에 큰 도움을 줍니다. 예를 들어, `/actuator/metrics` 엔드포인트를 통해 CPU 사용률, GC 활동 등을 모니터링하면서 성능 튜닝 방향을 잡을 수 있죠.

참고로, Actuator는 기본적으로 `/actuator` 경로에 여러 기능을 묶어두는데, 보안 설정도 꼭 병행해야 합니다.

## DispatcherServlet 비동기 요청 처리로 스레드 낭비 줄이기

Spring MVC의 DispatcherServlet은 기본적으로 동기 방식으로 요청을 처리합니다. 그런데 고부하 상황에서는 스레드가 요청 처리에 꽉 차서 대기열이 길어지고, 응답 지연이 발생하죠. 이때 비동기 요청 처리를 활용하면 스레드 자원을 훨씬 효율적으로 쓸 수 있습니다.

아래는 간단한 예시입니다:

```java
@GetMapping("/async")
public Callable<String> asyncEndpoint() {
    return () -> {
        Thread.sleep(2000); // 외부 API 호출 등 시간이 걸리는 작업
        return "비동기 처리 완료";
    };
}
```

이렇게 하면 요청 스레드는 Callable 객체를 반환하는 즉시 반환되고, 실제 작업은 별도의 스레드에서 처리됩니다. 덕분에 서버 스레드 풀이 꽉 차는 걸 막고, 더 많은 요청을 동시에 처리할 수 있어요.

단, 비동기 처리는 스레드 풀 크기 설정과 모니터링이 필수입니다. 기본적으로 Spring MVC는 `TaskExecutor` 빈을 사용하니, 적절한 스레드 수(예: CPU 코어 수 × 2)로 조절해야 합니다.

## 데이터베이스 커넥션 풀과 캐시, 세션 관리로 응답 속도 올리기

성능 튜닝에서 빠질 수 없는 부분이 데이터베이스 커넥션 풀 설정입니다. 커넥션 풀 크기가 너무 작으면 요청이 DB 연결 대기열에 걸리고, 너무 크면 오버헤드가 발생하죠.

보통 CPU 코어 수 × 2 ~ 4 정도로 설정하는 게 무난합니다. 예를 들어 HikariCP를 쓴다면 `application.properties`에 이렇게 설정할 수 있어요:

```properties
spring.datasource.hikari.maximum-pool-size=20
```

이 숫자는 서비스 트래픽과 DB 성능에 따라 다르니, 모니터링하며 조절해야 합니다.

캐시도 필수입니다. Spring Cache 추상화를 쓰면 Redis, Ehcache 등 다양한 구현체를 쉽게 붙일 수 있는데, 자주 조회하는 데이터는 캐싱해 응답 시간을 50% 이상 줄인 경험도 있습니다.

그리고 HTTP 세션 관리를 최적화하는 것도 잊지 마세요. 예를 들어, 세션 타임아웃을 너무 길게 잡으면 메모리 누수가 발생하고, 너무 짧으면 사용자가 자주 로그아웃되는 문제가 생깁니다. 보통 15~30분 사이가 무난합니다:

```properties
server.servlet.session.timeout=20m
```

## Spring Security로 프로덕션 보안 강화, 꼭 챙겨야 할 설정

성능도 중요하지만 보안 없이는 프로덕션이 무너집니다. Spring Security 설정에서 꼭 챙겨야 할 게 몇 가지 있어요.

먼저 CSRF 보호는 기본적으로 활성화되어 있는데, REST API 서버라면 CSRF 토큰 검증을 비활성화하는 대신 JWT 같은 토큰 기반 인증을 쓰는 게 일반적입니다.

그리고 세션 고정 공격(Session Fixation)을 막으려면 로그인 성공 후 세션을 새로 발급하는 설정이 필요합니다. Spring Security에서는 기본적으로 이 기능을 제공하지만, 커스텀 설정 시 빠뜨리기 쉽습니다.

마지막으로 인증 토큰 만료 정책도 중요합니다. 너무 길게 잡으면 탈취 위험이 커지고, 너무 짧으면 사용자 불편이 커지죠. 보통 JWT는 15분~1시간 사이로 만료 시간을 설정합니다.

예를 들어, SecurityConfig에서 JWT 필터를 추가할 때 만료 시간을 이렇게 설정할 수 있습니다:

```java
public class JwtTokenProvider {
    private final long validityInMilliseconds = 3600000; // 1시간

    public String createToken(String username) {
        Date now = new Date();
        Date validity = new Date(now.getTime() + validityInMilliseconds);

        return Jwts.builder()
            .setSubject(username)
            .setIssuedAt(now)
            .setExpiration(validity)
            .signWith(SignatureAlgorithm.HS256, secretKey)
            .compact();
    }
}
```

## HTTP/2와 정적 리소스 압축으로 네트워크 병목 줄이기

마지막으로, 네트워크 대역폭을 아끼는 것도 프로덕션 성능 최적화에 큰 도움이 됩니다. Spring Boot에서는 HTTP/2 프로토콜을 지원하는데, 이를 활성화하면 멀티플렉싱 덕분에 여러 요청을 동시에 처리해 대기 시간을 줄일 수 있어요.

또한, 정적 리소스(HTML, CSS, JS 등)를 압축(Gzip, Brotli)하면 전송량을 70% 이상 줄일 수 있습니다. Spring Boot에서는 `application.properties`에 다음과 같이 설정할 수 있습니다:

```properties
server.compression.enabled=true
server.compression.mime-types=text/html,text/xml,text/plain,text/css,application/javascript,application/json
server.compression.min-response-size=1024
```

이렇게 하면 1KB 이상 응답에 대해 압축이 자동으로 적용됩니다. 단, 압축은 CPU 부하가 약간 늘어날 수 있으니 서버 사양과 트래픽 패턴을 고려해 적용하세요.

### 마무리하며

처음엔 Spring MVC 최적화가 거창해 보이지만, 실제로는 스타트업 시간 줄이기, 비동기 처리, 커넥션 풀 조절, 보안 설정, 그리고 네트워크 최적화 같은 작은 조각들을 하나씩 맞춰가는 과정입니다. 이걸 꾸준히 해나가면 트래픽 폭주에도 끄떡없는 견고한 백엔드를 만들 수 있어요.

저도 위 팁들을 현업에서 적용하면서 성능과 안정성이 눈에 띄게 좋아진 경험이 많습니다. 특히 Actuator로 모니터링하면서 병목을 찾고, DispatcherServlet 비동기 처리로 스레드 낭비를 줄인 부분은 정말 효과적이었어요.

여러분도 이번 기회에 프로덕션 환경에서 Spring MVC 백엔드를 좀 더 날렵하게 다듬어 보시길 바랍니다.
