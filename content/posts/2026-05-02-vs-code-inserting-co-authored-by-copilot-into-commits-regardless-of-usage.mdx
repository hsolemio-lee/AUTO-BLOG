### "내가 Copilot 안 썼는데 왜 내 커밋에 Co-Authored-by Copilot이 붙지?"

최근 우리 팀에서 이런 질문이 종종 나왔어요. VS Code에서 GitHub Copilot 확장 기능을 켜놓고 개발하는데, 실제로 Copilot의 제안을 거의 안 쓰거나, 그냥 참고만 했는데도 커밋 메시지에 `Co-Authored-by: Copilot`이 자동으로 붙는다는 거죠. 처음엔 버그인가 싶었는데, 공식 문서와 여러 개발자 커뮤니티를 뒤져보니 꽤 알려진 현상이더라고요.

이게 왜 문제가 될까요? 팀에서 AI 기여도를 명확히 하려는 상황에서, 실제로 AI 도움을 받지 않았는데도 자동으로 태그가 붙으면 오해가 생길 수 있거든요. 오늘은 이 현상의 원인과 실무에서 어떻게 대응할 수 있을지, 그리고 팀 단위로 AI 기여 표기를 관리하는 팁까지 공유해보겠습니다.

---

## GitHub Copilot은 원래 어떻게 커밋에 기여자 태그를 다나?

GitHub 공식 문서에 따르면, Copilot은 사용자가 AI가 제안한 코드를 실제로 수락하거나 수정해서 커밋에 포함시켰을 때만 `Co-Authored-by: Copilot` 태그를 자동으로 커밋 메시지에 붙입니다. 즉, AI가 코드 제안을 했다고 무조건 붙는 게 아니라, "내가 이걸 썼다"는 신호가 있을 때만 붙는 거죠.[GitHub Copilot Documentation](https://docs.github.com/en/copilot)

이 기능은 AI 기여도를 투명하게 기록하려는 의도에서 나온 건데, 팀에서 AI 도움을 얼마나 받았는지 추적할 때 꽤 유용합니다. 하지만 현실은 조금 달라요.


## VS Code에서 Copilot 태그가 자동으로 붙는 이유는 뭘까?

실제 개발 현장에서는 VS Code에서 Copilot 확장 기능이 켜져있기만 해도, 그리고 실제 AI 제안을 거의 안 받아들여도 커밋 메시지에 태그가 붙는 사례가 보고되고 있습니다. 이건 공식 문서에도 "일부 개발자들 사이에서 보고되고 있다"고 하네요.[GitHub Copilot Documentation](https://docs.github.com/en/copilot)

왜 이런 일이 벌어질까요? 내부적으로 Copilot 확장 프로그램이 커밋 생성 시점에 AI 제안 사용 여부를 완벽히 감지하지 못하거나, VS Code Git 인터페이스와의 통합 과정에서 자동 태그 삽입 로직이 과도하게 작동하는 경우가 있다는 분석이 있습니다. 

이게 실제로 개발자 워크플로우에 미치는 영향은 생각보다 큽니다. 예를 들어, 코드 리뷰어가 "이 부분은 AI가 쓴 코드니까 더 꼼꼼히 보자"고 판단할 수 있는데, AI 도움 없이 작성한 코드에도 태그가 붙으면 불필요한 혼란이 생기죠.


## 이걸 그냥 두면 어떤 문제가 생길까?

- **팀 내 AI 기여도 왜곡**: 누가 AI 도움을 받았고 누가 안 받았는지 구분이 어려워집니다.
- **커밋 히스토리 신뢰도 저하**: 자동으로 붙는 태그가 많아지면, 커밋 메시지의 진정한 의미가 흐려집니다.
- **코드 리뷰 과정 복잡화**: 리뷰어가 AI 기여 여부를 기준으로 리뷰 전략을 세우는 경우, 잘못된 정보로 인해 리뷰 품질이 떨어질 수 있습니다.

처음엔 "그냥 사소한 태그 하나 붙는 거 아니야?"라고 생각할 수 있지만, 팀 규모가 커지고 AI 도구 활용이 늘어날수록 이런 작은 혼란들이 누적돼서 의사소통 비용이 커집니다.


## VS Code에서 Copilot 자동 태그 삽입 끄는 방법

다행히 VS Code 설정에서 이 자동 태그 삽입 기능을 제어할 수 있습니다. 다음과 같이 설정해보세요.

```json
// settings.json 예시
{
  "github.copilot.commitMessage.enableCoAuthor": false
}
```

이 옵션을 `false`로 설정하면, Copilot이 자동으로 `Co-Authored-by` 태그를 커밋 메시지에 붙이지 않습니다. 대신, 필요할 때 수동으로 태그를 넣어야 하죠.

또한, Git 커밋 메시지 작성 시 아래처럼 직접 태그를 추가하거나 제거하는 것도 가능합니다.

```bash
git commit -m "Fix login bug"
# 또는
# AI 기여가 있을 때만 수동으로 태그 추가
git commit -m "Add new auth flow

Co-Authored-by: Copilot <copilot@github.com>"
```

자동 삽입이 불필요한 경우라면 이 방법이 가장 확실합니다.


## 팀 단위로 AI 기여 표기 정책을 어떻게 세울까?

우리 팀도 AI 코드 어시스턴트 사용이 점점 늘면서, "누가 AI 도움을 받았는지 어떻게 명확히 할까"가 고민이었어요. 그래서 다음과 같은 정책을 도입했습니다.

1. **Copilot 자동 태그 삽입 기능은 팀 내 기본적으로 비활성화**
   - 개발자 각자가 필요할 때만 수동으로 태그를 붙입니다.

2. **커밋 메시지 템플릿에 AI 기여 여부 확인란 추가**
   - 예를 들어, 커밋 메시지 작성 시 아래처럼 질문을 포함합니다.

   ```
   # 이 커밋에 AI 코드 어시스턴트 기여가 있나요? (Y/N)
   # Y인 경우, Co-Authored-by 태그를 꼭 추가해주세요.
   ```

3. **코드 리뷰 시 AI 기여 여부 확인 절차 도입**
   - 리뷰어가 AI 기여 부분을 별도로 확인하고, 필요한 경우 추가 검증을 합니다.

4. **정기적으로 AI 기여 태그 사용 현황 점검**
   - 태그가 과도하게 붙거나 누락된 커밋이 없는지 모니터링합니다.

이 정책 덕분에 AI 도움을 받은 코드와 그렇지 않은 코드를 명확히 구분할 수 있었고, 리뷰 품질도 유지할 수 있었습니다.


## 실제로 이렇게 써봤더니...

우리 팀에서는 자동 태그 붙는 문제 때문에 한동안 커밋 메시지에 불필요한 `Co-Authored-by: Copilot`가 붙어 있었어요. 이게 코드 리뷰 때 "이거 AI가 쓴 거야?"라는 질문을 계속 낳아서, 결국 위에서 말한 설정을 끄고 수동 태그 정책을 도입했습니다.

초기에는 "귀찮아지지 않을까?" 걱정했는데, 의외로 커밋 메시지 작성할 때 AI 기여 여부를 한 번 더 생각하게 되면서 코드 품질 관리에도 도움이 되더라고요. 그리고 팀원들끼리 AI 도움을 받았던 부분을 공유하는 문화도 자연스럽게 생겼습니다.


## 요약하며

- GitHub Copilot은 원칙적으로 AI 제안 수락 시에만 `Co-Authored-by` 태그를 붙입니다.
- 하지만 VS Code에서 Copilot 확장 기능이 켜져 있으면, 실제 사용 여부와 상관없이 자동으로 태그가 붙는 현상이 있습니다.
- 이로 인해 팀 내 AI 기여도 파악이 어려워지고, 커밋 메시지 신뢰도도 떨어질 수 있습니다.
- VS Code 설정에서 `github.copilot.commitMessage.enableCoAuthor` 옵션을 `false`로 바꾸거나, 커밋 메시지 작성 시 수동으로 태그를 관리하는 게 가장 현실적인 해결책입니다.
- 팀 단위로 AI 기여 표기 정책과 리뷰 절차를 마련하는 것도 장기적으로 도움이 됩니다.
