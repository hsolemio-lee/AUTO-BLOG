### "이 챗봇, 진짜 고객 말투를 제대로 이해할까?"

고객 지원 챗봇을 운영하다 보면 이런 의문이 끊임없이 듭니다. 특히 DoorDash 같은 대형 플랫폼에서는 수백만 건의 주문과 문의가 매일 쏟아지니, 챗봇이 다양한 고객 의도와 복잡한 상황을 제대로 처리하는지 검증하는 게 쉽지 않죠. 그런데 DoorDash가 최근 발표한 대규모 LLM 대화 시뮬레이터 구축 사례를 보니, 이 문제를 꽤 근본적으로 해결할 수 있겠다는 생각이 들더군요.

이번 글에서는 DoorDash가 어떻게 LLM(대형 언어 모델)을 활용해 실제 고객 대화와 유사한 시뮬레이션을 자동 생성하고, 이를 백엔드 테스트 파이프라인에 통합해 챗봇의 응답 정확성과 신뢰성을 높였는지 살펴보겠습니다. 그리고 TypeScript 5.x를 활용한 구현 팁과 프롬프트 설계의 중요성도 함께 다뤄볼게요.

## DoorDash가 LLM 대화 시뮬레이터를 만든 이유

DoorDash처럼 주문량이 많고 고객 문의 유형도 다양한 서비스는 챗봇 테스트가 정말 까다롭습니다. 단순히 정해진 시나리오 몇 개로 테스트하는 수준으로는 실제 고객 대화의 변수를 다 커버할 수 없어요. 그래서 DoorDash는 다음과 같은 문제에 부딪혔습니다.

- 고객 문의가 매우 다양해 일일이 시나리오 작성이 불가능
- 챗봇 응답의 정확성, 일관성, 예외 처리 능력을 폭넓게 검증해야 함
- 테스트 자동화가 안 되면 릴리스 주기가 느려지고, 품질 저하 위험 증가

이걸 해결하기 위해 DoorDash는 LLM을 활용한 대화 시뮬레이터를 만들었는데, 이게 꽤 인상적입니다. LLM이 실제 고객과 비슷한 대화 흐름을 생성해주니, 수천~수만 건 단위의 시뮬레이션 테스트가 가능해졌거든요.

## OpenAI API로 대화 시뮬레이터 쉽게 만드는 법

DoorDash 사례에서 핵심은 OpenAI API 같은 강력한 LLM 인터페이스를 백엔드에 통합한 점입니다. OpenAI API는 RESTful 방식으로 간단히 호출할 수 있고, 다양한 모델과 파라미터 조합을 지원해 대화 시뮬레이션에 최적화되어 있죠.

예를 들어, 고객이 "주문이 아직 안 왔어요"라고 문의했을 때, LLM이 다양한 고객 감정(불만, 당황, 단순 문의 등)을 반영한 여러 답변 시나리오를 생성할 수 있습니다. 이를 자동화 테스트 파이프라인에 넣으면 챗봇이 각 시나리오에 올바르게 대응하는지 검증할 수 있죠.

아래는 TypeScript 5.x 환경에서 OpenAI API를 호출해 간단한 대화 시뮬레이션을 만드는 코드 예시입니다. 실제로는 이걸 여러 시나리오에 반복 적용해 대규모 테스트를 돌립니다.

```typescript
import OpenAI from "openai";

const openai = new OpenAI();

interface ConversationTurn {
  role: "user" | "assistant";
  content: string;
}

async function simulateConversation(userInput: string): Promise<string> {
  const messages: ConversationTurn[] = [
    { role: "system", content: "You are a helpful customer support assistant." },
    { role: "user", content: userInput },
  ];

  const response = await openai.chat.completions.create({
    model: "gpt-4o-mini",
    messages,
    temperature: 0.7,
    max_tokens: 150,
  });

  return response.choices[0].message?.content ?? "";
}

(async () => {
  const userQuery = "내 주문이 아직 안 도착했어요.";
  const reply = await simulateConversation(userQuery);
  console.log("챗봇 시뮬레이션 응답:", reply);
})();
```

이 코드를 기반으로 다양한 고객 문의 문장을 넣고, 챗봇 응답을 비교하는 자동화 테스트를 구축하면 됩니다. TypeScript 5.x가 타입 안정성을 높여줘서 대규모 테스트 코드를 유지보수하기도 한결 편해요[TypeScript 5.x Release Notes](https://devblogs.microsoft.com/typescript/announcing-typescript-5-4/).

## 프롬프트 설계가 시뮬레이터 품질을 좌우한다

Anthropic의 프롬프트 엔지니어링 가이드를 보면, LLM 기반 대화 시뮬레이터에서 프롬프트 설계가 얼마나 중요한지 알 수 있습니다. 단순히 "고객이 이렇게 말하면 이렇게 답해" 식으로만 하면 대화가 부자연스럽고, 실제 고객 의도 파악이 어려워지거든요.

DoorDash도 다양한 고객 감정, 의도, 상황을 반영한 정교한 프롬프트를 만들어서 시뮬레이터가 현실감 있는 대화를 생성하도록 했습니다. 예를 들어, 고객이 "주문이 늦어서 화가 났어요"라고 했을 때, 시뮬레이터가 단순히 사과만 하는 게 아니라 상황 설명, 보상 제안 등 다양한 대응을 만들어내게끔 유도하는 거죠.

이 과정에서 다음과 같은 팁이 유용합니다:

- 시스템 메시지에 역할과 톤을 명확히 지정
- 고객 감정과 상황을 구체적으로 묘사
- 예상되는 고객 반응과 챗봇 답변 예시를 함께 제공

이런 프롬프트 설계는 시뮬레이터가 생성하는 대화의 품질을 결정짓는 핵심 요소입니다[Anthropic - Prompt Engineering Guide](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/overview).

## 대규모 테스트 자동화, 분산 시스템에서 신뢰성 확보하기

DoorDash처럼 대규모 서비스를 운영하다 보면, 시뮬레이터를 단순히 한두 번 돌리는 수준을 넘어 수천~수만 건 단위로 반복 테스트해야 합니다. 이때 중요한 건 분산 처리와 신뢰성 있는 서비스 운영이죠.

Cloudflare의 ‘How We Built It’ 블로그를 보면, 대규모 분산 시스템에서 시뮬레이션 도구와 자동화 테스트가 서비스 신뢰성 확보에 얼마나 중요한지 잘 설명합니다. DoorDash 역시 비슷한 맥락에서 시뮬레이터를 클라우드 기반 분산 환경에 배포하고, 테스트 결과를 실시간 모니터링하며 문제 발생 시 빠르게 대응하는 체계를 갖췄습니다[Cloudflare Blog - How We Built It](https://blog.cloudflare.com/tag/how-we-built-it/).

실제로 이런 시스템을 구축하면 다음과 같은 장점이 있습니다:

- 챗봇 릴리스 전 다양한 시나리오를 자동으로 검증해 품질 보장
- 문제 발생 시 원인 분석과 수정이 빠름
- 신규 기능 테스트 주기가 단축되어 빠른 개선 가능

## 정리하며: DoorDash LLM 시뮬레이터에서 얻은 실전 교훈

DoorDash 사례를 보며 느낀 점을 몇 가지 정리해볼게요.

- **LLM 대화 시뮬레이터는 고객 지원 챗봇 테스트에 필수적이다.** 다양한 고객 의도와 상황을 자동 생성해 챗봇의 대응력을 폭넓게 검증할 수 있다.

- **OpenAI API 같은 LLM 서비스는 백엔드에 쉽게 통합 가능하며, 대규모 테스트 자동화에 최적화되어 있다.** TypeScript 5.x와 조합하면 안정적인 코드 관리도 가능하다.

- **프롬프트 설계에 시간과 노력을 아끼지 말자.** 시뮬레이터의 대화 품질이 곧 테스트 품질로 직결된다.

- **분산 시스템 환경에서 신뢰성 높은 테스트 자동화 체계를 구축해야 한다.** 그래야 실제 서비스 품질을 유지하면서 빠르게 개선할 수 있다.

DoorDash가 직접 공개한 구체적인 구현 세부사항은 제한적이지만, 공개된 기술과 사례를 참고해 우리 시스템에도 충분히 적용할 수 있는 아이디어가 많습니다. 특히 TypeScript 5.x의 타입 안정성 덕분에 대규모 테스트 코드를 유지보수하기 훨씬 수월해졌다는 점은 개인적으로도 매우 와닿았어요.

앞으로 고객 지원 챗봇을 운영하거나 개발하는 분들은 LLM 기반 대화 시뮬레이터를 꼭 한 번 도입해 보시길 추천합니다. 직접 써보면 "아, 이게 진짜 고객 말투를 이해하는구나" 하는 감이 확 옵니다.
