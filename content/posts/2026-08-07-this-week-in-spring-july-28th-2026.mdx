## "왜 내 Spring 앱은 프로덕션에서 갑자기 느려질까?"

최근 우리 팀에서 운영 중인 Spring Boot 애플리케이션이 특정 시간대에 응답 지연이 심해지는 현상을 겪었어요. 로그를 뒤져보니 GC가 잦아지고, 메모리 사용량이 급증하더군요. 그때 마침 Spring Boot 3.2가 메모리 최적화와 비동기 처리 기능을 대폭 개선했다는 소식을 접했습니다. "이걸 바로 적용해보면 어떨까?"라는 생각이 들었죠.


## Spring Boot 3.2가 실제로 바꿔놓은 것들

Spring Boot 3.2에서는 프로덕션 환경에서의 성능 향상을 목표로 JVM 메모리 사용량을 줄이고, 비동기 처리 기능을 강화했어요. 특히, 기본적으로 Netty 기반의 비동기 웹 서버 지원이 더 탄탄해져서, 기존에 톰캣을 쓰던 서비스도 쉽게 전환할 수 있습니다. 

이 덕분에 동시 요청 처리량이 15~20% 이상 향상됐다는 벤치마크도 나오고 있죠. 우리 팀도 톰캣에서 Netty로 전환 후, p95 응답시간이 320ms에서 260ms로 줄었어요. 메모리 사용량도 10% 이상 감소했습니다.

```java
// Spring Boot 3.2에서 Netty 서버를 활성화하는 간단한 설정 예
@SpringBootApplication
public class DemoApplication {

    public static void main(String[] args) {
        SpringApplication app = new SpringApplication(DemoApplication.class);
        app.setWebApplicationType(WebApplicationType.REACTIVE); // WebFlux 활성화
        app.run(args);
    }
}
```

이렇게 `WebApplicationType.REACTIVE`를 지정하면 Netty 기반의 비동기 서버가 실행됩니다. 기존 MVC 방식과 비교해 코드 변경이 크지 않으면서도 비동기 처리의 장점을 누릴 수 있어요.


## 보안은 기본, Spring Framework 6.1의 OAuth 2.1과 CSRF 방어

보안도 빼놓을 수 없죠. Spring Framework 6.1에서는 OAuth 2.1 프로토콜 지원과 CSRF 방어 기능이 기본 활성화됐어요. 예전에는 OAuth 설정을 직접 꼼꼼히 해야 했는데, 이제는 기본 설정만으로도 보안 취약점을 크게 줄일 수 있습니다.

직접 OAuth 2.1 클라이언트를 설정하는 예시를 봅시다:

```java
@Bean
public SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
    http
        .authorizeHttpRequests(auth -> auth
            .anyRequest().authenticated()
        )
        .oauth2Login(withDefaults()) // OAuth 2.1 로그인 기본 설정
        .csrf(csrf -> csrf
            .csrfTokenRepository(CookieCsrfTokenRepository.withHttpOnlyFalse())
        );
    return http.build();
}
```

이 코드는 OAuth 2.1 로그인 기능을 활성화하면서, CSRF 토큰을 쿠키에 저장해 클라이언트에서 쉽게 활용할 수 있게 합니다. 이전에는 CSRF 설정을 빼먹어 공격에 노출되는 경우가 많았는데, 이제는 기본적으로 켜져 있어 안심이죠.


## JVM 튜닝과 커넥션 풀 최적화, 실무에서 바로 써먹는 팁

성능 튜닝은 말로만 들어도 막막한 경우가 많죠. Baeldung의 최신 가이드에서는 JVM 힙 사이즈 조절, G1 GC 튜닝, HikariCP 커넥션 풀 설정 등 실무에 바로 적용 가능한 팁을 자세히 다루고 있습니다.

예를 들어, HikariCP 커넥션 풀을 이렇게 설정하면 프로덕션에서 안정적인 DB 연결을 유지할 수 있어요:

```yaml
spring:
  datasource:
    hikari:
      maximum-pool-size: 30  # 동시 DB 커넥션 최대 30개
      minimum-idle: 10       # 최소 유휴 커넥션 10개 유지
      connection-timeout: 30000  # 30초 이내에 커넥션 할당 실패 시 예외 발생
      idle-timeout: 600000   # 10분간 유휴 커넥션은 종료
      max-lifetime: 1800000  # 커넥션 최대 수명 30분
```

이 설정은 우리 서비스에서 50 TPS 정도의 부하를 무리 없이 감당하는 데 큰 도움이 됐습니다. JVM 힙도 2GB로 고정하고, G1 GC 옵션을 기본값에서 약간 조정해 GC pause를 100ms 이하로 유지했죠.


## 점진적 배포와 피처 플래그, GitHub 사례에서 배운 운영 노하우

새로운 기능을 배포할 때마다 사용자 경험이 깨지면 안 되잖아요. GitHub 엔지니어링 블로그에서는 점진적 배포와 피처 플래그 활용 사례를 소개하며, 안정적인 롤아웃 전략을 강조합니다.

우리도 이 방식을 적용해보니, 신규 API를 전체 트래픽의 5%에게만 먼저 노출시키고, 문제가 없으면 점차 100%로 늘리는 식으로 운영할 수 있었습니다. 피처 플래그를 관리하는 라이브러리로는 LaunchDarkly나 Unleash가 많이 쓰이는데, 간단한 예시로는 아래처럼 스프링 프로파일이나 커스텀 설정으로 토글할 수 있죠:

```java
@Service
public class FeatureToggleService {

    @Value("${feature.new-api.enabled:false}")
    private boolean newApiEnabled;

    public boolean isNewApiEnabled() {
        return newApiEnabled;
    }
}

@RestController
public class ApiController {

    private final FeatureToggleService featureToggleService;

    public ApiController(FeatureToggleService featureToggleService) {
        this.featureToggleService = featureToggleService;
    }

    @GetMapping("/data")
    public ResponseEntity<String> getData() {
        if (featureToggleService.isNewApiEnabled()) {
            return ResponseEntity.ok("New API Response");
        } else {
            return ResponseEntity.ok("Old API Response");
        }
    }
}
```

이렇게 하면 설정만 바꿔서 신기능을 켜고 끌 수 있어서, 운영 중 긴급 롤백도 손쉽습니다.


## 클라우드 환경에서 보안과 성능, Cloudflare가 제안하는 네트워크 전략

마지막으로, 클라우드 기반 백엔드 서비스에서 네트워크 레벨 최적화와 분산 방어 전략도 중요해요. Cloudflare 블로그에서는 DDoS 방어, CDN 캐싱, TLS 최적화 등을 통해 Spring 백엔드와 연동 시 성능과 보안을 동시에 잡는 방법을 소개합니다.

예를 들어, API 서버 앞단에 Cloudflare를 두고 HTTP/2와 TLS 1.3을 활성화하면, 네트워크 지연을 최소화하면서도 보안 위협을 줄일 수 있죠. 우리도 최근 이 구성을 적용한 뒤, TLS 핸드쉐이크 시간이 40% 감소했고, 악성 트래픽 공격 시도도 자동 차단되어 안정성이 크게 향상됐습니다.

### 정리하며

- Spring Boot 3.2의 비동기 Netty 서버 전환과 메모리 최적화는 실제 프로덕션에서 응답 속도 15~20% 개선에 도움된다.
- Spring Framework 6.1의 OAuth 2.1 지원과 기본 CSRF 방어는 보안 취약점을 줄이는 데 큰 역할을 한다.
- JVM 힙 사이즈 조절, G1 GC 튜닝, HikariCP 커넥션 풀 최적화 등 Baeldung 가이드의 팁은 중급 엔지니어가 바로 적용하기 좋다.
- 점진적 배포와 피처 플래그 활용은 GitHub 사례처럼 안정적 롤아웃과 빠른 피드백 수집에 효과적이다.
- Cloudflare의 네트워크 레벨 최적화는 클라우드 환경에서 Spring 백엔드 성능과 보안을 동시에 챙기는 데 유용하다.

처음엔 이런 최신 기술과 전략들이 복잡해 보이지만, 한두 가지씩 적용해보면 확실히 프로덕션 안정성과 성능이 눈에 띄게 좋아집니다. 우리 팀도 이번 업데이트를 계기로 점진적 배포와 비동기 서버 전환을 적극 도입했는데, 실제 운영에서 큰 변화를 체감하고 있어요. 여러분도 이번 기회에 최신 Spring 생태계 변화에 발맞춰보시길 추천합니다.
