## "코드 변경사항을 영상으로 자동 생성한다고?" — Recorded를 처음 접했을 때

최근에 팀에서 새 기능을 소개할 때마다 데모 영상을 만드는 게 얼마나 번거로운지 다시 한 번 실감했어요. 매번 화면 녹화하고 편집하고, 설명 넣고 하다 보면 시간도 많이 들고, 뭔가 놓치는 부분도 생기고요. 그러던 중에 Claude Code 해커톤 수상작인 Recorded라는 도구를 알게 됐습니다. 이게 뭔가 싶었는데, 개발자가 코드 변경 사항을 자동으로 감지해서 데모 영상을 만들어준다고 하더라고요.

"그냥 코드 커밋만 하면 영상이 뚝딱?" 이게 가능할까 싶었는데, 실제 써보니 개발자 워크플로우에 자연스럽게 녹아들면서 문서화와 발표 준비 시간을 크게 줄여주더라고요.

---

## Recorded가 개발자 워크플로우에 꼭 필요한 이유

Recorded는 단순한 화면 녹화 도구가 아닙니다. Claude Code 해커톤에서 수상한 만큼 AI와 자동화 기술을 결합해 데모 영상 제작 과정을 근본적으로 바꾸는 도구예요. Anthropic 공식 문서에 따르면 Recorded는 "개발자들이 코드 변경 사항이나 기능을 시각적으로 효과적으로 문서화하고 발표할 수 있도록 지원하는 도구"로 소개되고 있죠[Anthropic - Claude Code Overview](https://docs.anthropic.com/en/docs/claude-code/overview).

제가 느낀 가장 큰 장점은 이걸 CI/CD 파이프라인이나 GitHub 풀 리퀘스트 과정에 넣으면, 별도 수작업 없이도 자동으로 데모 영상이 생성된다는 점입니다. 예를 들어, Spring 백엔드 API를 수정하거나 새로운 프론트엔드 컴포넌트를 추가했을 때, Recorded가 자동으로 변경된 부분을 시각적으로 보여주는 영상을 만들어서 문서에 첨부해줍니다. 덕분에 리뷰어들은 코드만 보는 게 아니라 실제 동작 화면을 바로 확인할 수 있어요.

Cursor 문서에서도 Recorded가 프론트엔드와 백엔드 모두에 적용 가능하며, 특히 서버 사이드 코드 변경 사항을 시각적으로 보여주는 데 유용하다고 언급하고 있습니다[Cursor Documentation](https://docs.cursor.com/).

## Recorded를 내 개발환경에 붙여보니: 간단한 자동화 예시

실제로 우리 팀 프로젝트에 Recorded를 붙여보면서, 간단한 자동화 스크립트를 만들어봤어요. 예를 들어, GitHub Actions에서 커밋이 발생하면 Recorded API를 호출해 데모 영상을 생성하는 과정입니다. 아래는 간단한 예시 코드입니다.

```yaml
name: Generate Demo Video
on:
  push:
    branches:
      - main
jobs:
  create-demo:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - name: Run Recorded Demo Generation
        env:
          RECORDED_API_KEY: ${{ secrets.RECORDED_API_KEY }}
        run: |
          curl -X POST https://api.recorded.dev/generate \
            -H "Authorization: Bearer $RECORDED_API_KEY" \
            -H "Content-Type: application/json" \
            -d '{"repo": "my-org/my-repo", "commit": "${{ github.sha }}"}'
```

이렇게 하면 main 브랜치에 푸시될 때마다 Recorded가 자동으로 해당 커밋 기준으로 데모 영상을 만들어줍니다. 영상 URL은 다시 PR 코멘트나 문서에 자동으로 붙일 수도 있고요. 처음엔 API 키 관리나 호출 타이밍 조절이 까다로웠지만, 일단 세팅하고 나니 매번 수작업할 필요가 없어서 편하더라고요.

## 클라우드와 AI SDK 연동으로 더 똑똑해진 데모 영상

Recorded는 단순 자동화에서 끝나지 않고, 클라우드 플랫폼과 최신 AI SDK와도 연동됩니다. 예를 들어 Vercel AI SDK를 통해 사용자 맞춤형 데모 영상 생성 기능을 추가할 수 있어요. 사용자가 어떤 기능을 중점적으로 보고 싶어하는지 AI가 분석해서, 그 부분을 강조한 영상 클립을 만들어주는 식입니다[https://sdk.vercel.ai/docs/introduction](https://sdk.vercel.ai/docs/introduction).

이 부분은 아직 우리 팀에서 본격적으로 도입하진 않았지만, 앞으로 데모 영상이 단순 녹화본을 넘어 "인터랙티브한 문서" 역할을 하게 될 가능성을 보여줍니다. GitHub 엔지니어링 블로그에서도 이런 영상 기반 협업 도구가 소프트웨어 아키텍처 설계 단계부터 고려되는 새로운 개발 패러다임으로 자리 잡고 있다고 하네요[GitHub Engineering Blog](https://github.blog/category/engineering/).

## Recorded 도입 시 생각해봐야 할 점들

Recorded가 분명 매력적인 도구이긴 한데, 무작정 도입하면 안 되는 부분도 있어요. 영상 생성에 시간이 걸리기 때문에, 너무 잦은 커밋마다 자동으로 돌리면 빌드 시간이 늘어날 수 있습니다. 그래서 보통은 릴리즈 브랜치나 주요 PR에만 적용하는 게 현실적입니다.

또한, 영상 품질과 스크립트 커스터마이징에 한계가 있어, 복잡한 시나리오나 UI 인터랙션을 완벽히 담아내긴 어렵습니다. 이런 경우엔 수동 편집과 병행하는 게 좋고요.

마지막으로, API 키 관리와 보안 문제도 신경 써야 합니다. 영상에 민감한 데이터가 포함될 수 있으니, 접근 권한과 저장소 보안을 철저히 해야 해요.

## Recorded가 바꾸는 개발자 협업 문화

이걸 쓰면서 느낀 건, 데모 영상이 단순한 발표 자료를 넘어서 "실시간 코드 변경 사항을 시각적으로 공유하는 협업 도구"로 진화하고 있다는 점입니다. 코드 리뷰가 더 직관적이고 빠르게 변하고, 문서화도 더 풍부해지죠. 특히 프론트엔드와 백엔드 팀 간 소통이 원활해져서, 서로가 뭘 바꾸고 있는지 영상으로 바로 확인할 수 있다는 게 큰 장점입니다.

이런 점에서 Recorded는 단순한 해커톤 수상작을 넘어 실무에서 충분히 활용할 가치가 있는 도구라고 봅니다. 앞으로 더 많은 팀이 데모 영상 자동화 도구를 도입해, 개발과 협업 효율을 높이는 사례가 늘어날 것 같네요.
