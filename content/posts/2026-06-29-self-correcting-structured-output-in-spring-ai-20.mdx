### AI 출력이 엉망일 때, 백엔드에서 어떻게 버티고 있나요?

우리 팀도 최근에 AI 모델을 백엔드에 붙이면서 꽤 골머리를 앓았어요. AI가 JSON 형식으로 결과를 내줘야 하는데, 가끔은 키가 빠지거나 값이 이상하게 나오고, 심지어는 포맷 자체가 깨져서 파싱조차 안 되는 경우도 있었죠. 클라이언트에 그대로 내려보내면 당장 에러 터지고, 사용자 경험이 뚝 떨어지니 어떻게든 백엔드에서 걸러내고 고쳐야 했어요.

그냥 "AI가 잘못했으니 다시 요청하자"라고 하면 간단할 것 같지만, 호출 비용도 만만치 않고, 응답 지연도 커지고... 그래서 Spring AI 2.0에서 제공하는 self-correcting structured output 패턴을 적극적으로 도입해봤습니다.

---

## Spring AI 2.0에서 "Self-Correcting Structured Output"이란 뭘까?

간단히 말하면, AI가 내놓는 결과를 JSON, XML 같은 구조화된 데이터로 받고, 그 데이터가 우리가 기대한 형식과 내용에 맞는지 백엔드에서 자동으로 검증하고, 문제가 있으면 재요청이나 수정 로직을 돌려서 최대한 정확한 결과를 확보하는 패턴이에요. 

이걸 직접 구현하려면 꽤 손이 많이 가는데, Spring AI 2.0은 Spring Framework의 핵심 기술들을 활용해서 이 과정을 훨씬 수월하게 만들어줍니다. 예를 들어 Bean Validation으로 출력 데이터 무결성을 체크하고, AOP(Aspect-Oriented Programming)를 써서 검증 실패 시 자동 재처리 로직을 깔끔하게 분리할 수 있죠. 

이 덕분에 AI 출력 신뢰도가 크게 올라가고, 백엔드 시스템 전체의 견고성도 덩달아 좋아집니다.[Spring Boot Reference Documentation](https://docs.spring.io/spring-boot/reference/), [Spring Framework - Core Technologies](https://docs.spring.io/spring-framework/reference/core.html)

## 실제로 어떻게 검증하고 고치나요? Bean Validation과 AOP 활용법

우리 팀이 쓴 예를 들어볼게요. AI가 내놓는 JSON 결과를 `AiResponse`라는 DTO로 받고, 각 필드에 `@NotNull`, `@Pattern` 같은 Bean Validation 애노테이션을 붙입니다. 

```java
@Data
public class AiResponse {
    @NotNull
    private String id;

    @NotNull
    @Pattern(regexp = "\\d{4}-\\d{2}-\\d{2}")
    private String date;

    @NotNull
    private Map<String, Object> data;
}
```

그리고 AOP를 써서 컨트롤러나 서비스 계층에서 AI 호출 후 이 DTO 검증을 자동으로 수행하도록 했어요. 만약 검증에 실패하면, AOP Advice에서 재요청 로직을 트리거하거나, 간단한 수정 로직(예: 날짜 포맷 보정)을 실행하게끔 했죠.

```java
@Aspect
@Component
public class AiResponseValidationAspect {

    @Around("execution(* com.example.ai.AiService.callAi(..))")
    public Object validateAndCorrect(ProceedingJoinPoint pjp) throws Throwable {
        Object result = pjp.proceed();

        if (result instanceof AiResponse) {
            AiResponse response = (AiResponse) result;
            Set<ConstraintViolation<AiResponse>> violations = validator.validate(response);
            if (!violations.isEmpty()) {
                // 간단한 수정 시도
                correctResponse(response);
                // 재검증
                violations = validator.validate(response);
                if (!violations.isEmpty()) {
                    // 재요청 로직
                    result = pjp.proceed();
                }
            }
        }
        return result;
    }

    private void correctResponse(AiResponse response) {
        // 예: 날짜 포맷이 틀렸으면 오늘 날짜로 대체
        if (response.getDate() == null || !response.getDate().matches("\\d{4}-\\d{2}-\\d{2}")) {
            response.setDate(LocalDate.now().toString());
        }
    }

    @Autowired
    private Validator validator;
}
```

이렇게 하면 AI가 이상한 결과를 내도 백엔드가 알아서 잡아주니, 시스템 전체가 훨씬 안정적이에요.[Spring Framework - Core Technologies](https://docs.spring.io/spring-framework/reference/core.html)

## 대규모 요청에도 끄떡없는 성능 유지 비법

이런 검증·수정 로직을 넣으면 당연히 백엔드 부하가 늘어나지 않을까 걱정했는데, Spring Boot 성능 튜닝 가이드 덕분에 비동기 처리와 캐싱 전략을 병행해서 문제를 해결했어요.[Baeldung - Spring Boot Performance Tuning](https://www.baeldung.com/spring-boot-performance)

예를 들어, AI 출력 검증은 `CompletableFuture`를 이용해 비동기로 처리하고, 이미 검증된 결과는 Redis 캐시에 저장해서 재검증 비용을 줄였죠. 

```java
public CompletableFuture<AiResponse> callAiAsync(String prompt) {
    return CompletableFuture.supplyAsync(() -> aiClient.call(prompt))
        .thenApply(response -> {
            if (!cacheManager.getCache("aiResponses").get(response.getId(), AiResponse.class).isPresent()) {
                validateAndCache(response);
            }
            return response;
        });
}

private void validateAndCache(AiResponse response) {
    Set<ConstraintViolation<AiResponse>> violations = validator.validate(response);
    if (violations.isEmpty()) {
        cacheManager.getCache("aiResponses").put(response.getId(), response);
    }
}
```

이렇게 하면 AI 호출이 많아져도 검증 로직이 병목이 되지 않고, 응답 지연도 200ms 이내로 유지할 수 있었어요.

## 프로덕션에서 꼭 챙겨야 할 보안과 롤아웃 전략

AI 통합은 단순히 기능 구현만큼이나 보안과 안정적인 배포 전략도 중요합니다. GitHub 엔지니어링 블로그에서 강조하는 것처럼, Canary 배포를 통해 새로운 self-correcting 로직을 점진적으로 적용하고, 문제가 생기면 신속하게 롤백할 수 있어야 해요.[GitHub Engineering Blog](https://github.blog/category/engineering/)

그리고 AI 출력 데이터는 민감한 정보가 포함될 수 있으니, Spring Security를 이용해 세밀한 권한 제어와 데이터 암호화도 필수입니다. 

예를 들어, AI 출력 결과를 저장하거나 조회하는 API에 대해 OAuth2 인증과 역할 기반 권한 체크를 적용하는 게 기본이고, 로그에는 민감 정보가 남지 않도록 주의해야 합니다.

## 프롬프트 설계부터 피드백 루프까지, AI 출력 품질을 높이는 팁

AI 출력 품질을 백엔드에서만 책임질 수는 없죠. OpenAI API 문서와 Anthropic의 프롬프트 엔지니어링 가이드에 따르면, 명확한 출력 포맷을 프롬프트에 명시하고, 반복적인 피드백 루프를 설계하는 게 핵심입니다.[OpenAI API Documentation](https://platform.openai.com/docs/overview), [Anthropic - Prompt Engineering Guide](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/overview)

예를 들어, 프롬프트에 "아래 JSON 스키마에 맞춰서 출력해줘"라고 명시하거나, 출력 결과가 검증 실패 시 AI에게 다시 수정 요청을 보내는 식이죠. 

이런 프로세스를 백엔드의 self-correcting 로직과 결합하면, AI 통합 시스템의 신뢰도가 훨씬 더 올라갑니다.

### 마무리하며

처음엔 AI 출력 검증과 수정 로직이 별거 아닌 것 같지만, 실제로 대규모 서비스에 붙여보면 시스템 안정성에 미치는 영향이 엄청납니다. 

- Spring AI 2.0과 Spring Framework의 Bean Validation, AOP를 적극 활용해 보세요.
- 비동기 처리와 캐싱으로 성능 저하를 막는 것도 꼭 필요합니다.
- 보안과 롤아웃 전략도 잊지 말고, Canary 배포와 권한 제어를 꼭 챙기세요.
- 프롬프트 설계와 반복 피드백 루프를 통해 AI 출력 품질을 근본부터 개선하는 것도 중요합니다.

이렇게 하면 AI 출력 문제로 인한 서비스 장애를 크게 줄일 수 있고, 사용자에게 더 신뢰받는 서비스를 만들 수 있을 거예요.
