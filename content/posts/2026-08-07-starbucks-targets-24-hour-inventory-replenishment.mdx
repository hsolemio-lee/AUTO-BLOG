## ‘오늘 주문한 재료가 내일 매장에 도착한다?’ 스타벅스가 꿈꾸는 24시간 재고 보충

스타벅스가 최근 24시간 내 재고 보충을 목표로 공급망 혁신에 뛰어들었다는 소식을 들었을 때, 솔직히 말해 ‘그게 가능해?’ 싶었습니다. 매장마다 수백 가지 아이템을 실시간으로 감지하고, 주문부터 배송까지 하루 만에 끝내려면 시스템이 얼마나 치밀해야 할까요? 이건 단순히 물류망만 빠르다고 되는 게 아니라, 재고와 주문 데이터를 실시간으로 처리하고 예측하는 IT 인프라가 뒷받침되어야 가능한 일입니다.

이 글에서는 스타벅스가 목표하는 24시간 재고 보충 전략을 우리 백엔드 엔지니어링 관점에서 어떻게 구현할 수 있을지, 특히 클라우드 기반 SCM 통합과 이벤트 기반 마이크로서비스 아키텍처를 중심으로 이야기해보겠습니다.


## 클라우드 기반 SCM 통합, 24시간 보충의 기본기

실시간 재고 및 주문 처리 최적화를 위해서는 공급망 관리(SCM) 시스템이 클라우드 플랫폼과 긴밀히 통합되어야 합니다. Microsoft의 Dynamics 365 SCM 사례를 보면, 클라우드 인프라 위에서 재고, 주문, 운송 정보를 한데 모아 실시간으로 분석하고 의사결정을 자동화합니다. 이를 통해 24시간 내 재고 보충 목표를 달성하는 데 필수적인 실시간 데이터 흐름과 확장성을 확보하죠[Microsoft Learn - Dynamics 365 Supply Chain Management](https://learn.microsoft.com/en-us/dynamics365/supply-chain/).

클라우드의 장점은 단순히 서버를 빌리는 게 아니라, 데이터 파이프라인과 AI 분석 도구가 내장되어 있다는 점입니다. 예를 들어, 재고 변동이 감지되면 즉시 관련 서비스에 이벤트를 발행하고, 자동으로 주문 요청이 생성되어 물류 파트너와 연동됩니다. 이런 실시간 반응 속도가 24시간 보충의 핵심입니다.


## AI와 머신러닝으로 수요 예측과 재고 최적화까지

스타벅스처럼 수많은 매장과 SKU(Stock Keeping Unit)를 관리할 때는 단순 재고 현황 파악만으론 부족합니다. Oracle SCM 솔루션은 AI와 머신러닝을 활용해 과거 판매 데이터, 계절성, 프로모션 효과까지 반영한 수요 예측 모델을 돌립니다. 이 덕분에 재고 부족이나 과잉을 줄이고, 주문 이행 속도를 높이죠[Oracle Docs - SCM and Manufacturing](https://docs.oracle.com/en/cloud/saas/supply-chain-and-manufacturing/).

우리도 비슷한 AI 모델을 백엔드에 통합할 수 있습니다. 예를 들어, Python 기반 머신러닝 모델을 별도 서비스로 운영하고, 재고 상태 변화 이벤트가 발생할 때마다 예측 결과를 받아 재고 보충 우선순위를 조정하는 거죠. 이렇게 하면 단순히 현재 재고만 보는 게 아니라, 미래 수요까지 반영한 ‘스마트’ 재고 관리가 가능합니다.


## 모듈화된 아키텍처로 다양한 데이터 소스 실시간 통합하기

SAP SCM 플랫폼은 모듈화된 아키텍처 덕분에 POS(Point of Sale), ERP, 물류 시스템 등 다양한 데이터 소스를 실시간으로 통합하고 분석합니다. 이를 통해 재고 보충과 주문 처리 효율성을 극대화하는데, 이는 우리 시스템 설계에도 시사점이 큽니다[ SAP Help Portal - Supply Chain Management](https://help.sap.com/docs/SAP_SUPPLY_CHAIN_MANAGEMENT).

실제로는 각 매장 POS 시스템에서 발생하는 판매 데이터, 창고 재고 현황, 배송 상태 등 서로 다른 시스템에서 온 데이터를 이벤트 스트림으로 처리합니다. 이때 Kafka 같은 메시지 큐를 활용해 비동기 이벤트를 처리하면 확장성과 내결함성을 확보할 수 있죠.


## 이벤트 기반 마이크로서비스로 실시간 주문 처리 속도 높이기

백엔드 엔지니어링 관점에서, 실시간 재고 및 주문 처리 시스템은 이벤트 기반 아키텍처와 마이크로서비스 패턴이 필수입니다. GitHub 엔지니어링 블로그 사례를 보면, 주문, 결제, 재고 관리 등 핵심 기능을 독립된 서비스로 분리하고, 이벤트 버스를 통해 느슨하게 연결해 빠르게 확장하고 장애에 강한 시스템을 만들었죠[GitHub Engineering Blog](https://github.blog/category/engineering/).

간단한 예를 들어볼게요. 주문 서비스가 주문 생성 이벤트를 발행하면, 재고 서비스는 이를 받아 재고를 즉시 차감하고, 재고 부족 시 보충 요청 이벤트를 발행합니다. 이 이벤트는 물류 서비스가 구독해 배송 일정을 조정하는 식입니다. 이렇게 하면 주문부터 배송까지 병렬로 처리되면서도 각 서비스는 독립적으로 운영할 수 있어요.


```typescript
// TypeScript로 간단한 이벤트 발행 예시
interface OrderCreatedEvent {
  orderId: string;
  items: { sku: string; quantity: number }[];
  createdAt: string;
}

class EventBus {
  private subscribers: { [eventType: string]: ((event: any) => void)[] } = {};

  subscribe(eventType: string, handler: (event: any) => void) {
    if (!this.subscribers[eventType]) {
      this.subscribers[eventType] = [];
    }
    this.subscribers[eventType].push(handler);
  }

  publish(eventType: string, event: any) {
    (this.subscribers[eventType] || []).forEach(handler => handler(event));
  }
}

const eventBus = new EventBus();

// 재고 서비스에서 주문 생성 이벤트 구독
eventBus.subscribe('OrderCreated', (event: OrderCreatedEvent) => {
  event.items.forEach(item => {
    console.log(`재고 차감 요청: SKU=${item.sku}, 수량=${item.quantity}`);
    // 실제 재고 차감 로직 호출
  });
});

// 주문 서비스에서 주문 생성 시 이벤트 발행
const newOrder: OrderCreatedEvent = {
  orderId: 'order123',
  items: [
    { sku: 'coffee-beans-1kg', quantity: 2 },
    { sku: 'milk-500ml', quantity: 1 },
  ],
  createdAt: new Date().toISOString(),
};
eventBus.publish('OrderCreated', newOrder);
```

이 예시는 단순하지만, 실제 시스템에서는 Kafka, RabbitMQ 같은 메시지 큐와 함께 사용해 장애 복구, 메시지 재처리, 순서 보장 같은 복잡한 문제를 해결합니다.


## 현실적인 한계와 우리가 고민해야 할 점들

물론 24시간 내 재고 보충은 이상적이지만, 현실은 쉽지 않습니다. 물류 인프라, 공급업체와의 협력, 데이터 품질 문제 등 비기술적 요소도 큽니다. 백엔드 시스템만 완벽해도, 외부 변수에 의해 목표 달성이 어려울 수 있죠.

또 이벤트 기반 마이크로서비스는 분산 시스템 특성상 데이터 일관성 문제, 장애 복구 복잡성, 운영 난이도가 올라갑니다. 따라서 각 서비스 간 계약(API 스펙)과 이벤트 스키마를 엄격히 관리하고, 장애 시 롤백 전략도 꼼꼼히 설계해야 합니다.


## 우리 팀에서 바로 적용해볼 수 있는 작은 변화들

- **재고 변경 이벤트 실시간 발행**: 기존 배치 처리 방식을 줄이고, 재고 변경 시점마다 이벤트를 발행해 빠른 반응 체계 구축
- **클라우드 메시지 큐 도입**: AWS SQS, Azure Service Bus 같은 관리형 메시지 큐로 이벤트 처리 안정성 확보
- **간단한 수요 예측 모델 적용**: 과거 판매 데이터를 활용해 Python이나 Node.js 기반 예측 서비스 프로토타입 제작
- **서비스별 독립 배포 환경 마련**: 마이크로서비스로 분리해 각 서비스별 배포 주기 단축 및 장애 영향 최소화


스타벅스가 24시간 재고 보충을 목표로 삼은 건 단순히 물류 혁신 뿐 아니라, 실시간 데이터 처리와 AI 기반 예측을 결합한 SCM 혁신 덕분입니다. 우리도 이 사례에서 배워, 실시간성과 확장성을 고려한 백엔드 아키텍처 설계에 집중해보면 좋겠습니다.
