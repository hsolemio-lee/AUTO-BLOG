## 페이지 전환할 때마다 전체 페이지가 리로드되는 게 아직도 답인가요?

요즘 웹 앱 개발하면서 느낀 건데, SPA가 아닌 MPA 환경에서 페이지 전환할 때마다 전체 페이지가 새로고침 되는 경험, 진짜 너무 답답하잖아요? 네트워크가 느리거나 모바일 환경이라면 더더욱요. 그런데 최근에 Navigation API가 베이스라인으로 새롭게 지원되면서, 이 문제를 꽤 깔끔하게 해결할 수 있는 길이 열렸더라고요.

내가 직접 써보면서 느낀 건, 이 API 덕분에 기존 SPA처럼 무거운 라우팅 라이브러리 없이도 사용자 경험을 대폭 개선할 수 있다는 점이에요. 게다가 점진적 향상 전략 덕분에 기존 MPA에도 무리 없이 적용 가능해서, 점차적으로 마이그레이션하기에도 부담이 적습니다.

## Navigation API가 뭔데, 기존 방식과 뭐가 다른 걸까?

기존에 우리가 페이지를 이동할 때는 보통 브라우저가 전체 페이지를 다시 불러오는 방식이었죠. 그러다 보니 HTML, CSS, JS를 전부 새로 받아야 하고, 렌더링도 다시 해야 하니 느릴 수밖에 없었어요.

Navigation API는 이 과정을 완전히 바꿔줍니다. 페이지 전환 시 전체를 리로드하지 않고, 필요한 부분만 교체하거나 업데이트할 수 있도록 브라우저 차원에서 네비게이션 이벤트와 관련 리소스 관리를 지원해요. 덕분에 네트워크 트래픽과 렌더링 비용이 줄고, 사용자 입장에선 훨씬 부드럽고 빠른 전환을 체감할 수 있죠.

GitHub 엔지니어링 블로그에 따르면, 이 API를 활용하면 페이지 전환 성능이 크게 향상되었다고 해요. 실제로 페이지가 완전히 새로고침되는 대신, 필요한 데이터만 받아서 화면을 갱신하니 체감 속도가 30~50% 이상 빨라졌다는 사례도 있답니다[GitHub Engineering Blog](https://github.blog/category/engineering/).

## 네트워크 환경이 안 좋아도 UX가 쾌적해지는 비밀

내가 특히 감탄한 부분은 네트워크 지연이 심한 환경에서의 부드러운 전환 효과예요. 예전 같으면 느린 네트워크 때문에 페이지가 깜빡이거나 로딩 화면이 오래 떠서 답답했는데, Navigation API는 네비게이션 이벤트를 세밀하게 제어할 수 있어서 로딩 상태를 효과적으로 다룰 수 있더라고요.

Cloudflare 엔지니어들이 실제로 이 API를 도입해서 UX 품질이 눈에 띄게 개선된 사례를 공유했는데, 네트워크가 불안정한 상황에서도 사용자가 페이지 전환을 거의 끊김 없이 느낄 수 있었다고 해요. 이건 실제로 겪어보면 진짜 체감이 확 옵니다[Cloudflare Blog - How We Built It](https://blog.cloudflare.com/tag/how-we-built-it/).

예를 들어, 네비게이션이 시작되면 로딩 인디케이터를 띄우고, 필요한 데이터가 도착하는 즉시 화면 일부만 교체하는 패턴을 쓸 수 있는데, 이 과정이 기존처럼 전체 페이지가 리로드되는 것보다 훨씬 자연스럽고 빠릅니다.

## 컴포넌트 구조와 상태 관리를 깔끔하게 분리하는 법

이 API를 쓰면서 개인적으로 가장 신경 쓴 부분은 상태 관리와 라우팅 로직을 어떻게 깔끔하게 분리할까 하는 점이었어요. Navigation API는 네비게이션 이벤트를 브라우저에서 직접 다루기 때문에, 기존의 라우터 라이브러리와는 다르게 상태 관리와 라우팅을 분리하는 설계가 가능해졌죠.

Martin Fowler의 아키텍처 가이드에 따르면, 이런 분리 덕분에 컴포넌트가 더 재사용 가능해지고 유지보수성이 크게 향상된다고 합니다. 예를 들어, Navigation API 이벤트를 구독하는 별도의 훅이나 서비스 레이어를 만들어서, 라우팅과 상태 업데이트를 독립적으로 관리하는 패턴이 권장돼요[Martin Fowler - Software Architecture Guide](https://martinfowler.com/architecture/).

아래는 React 환경에서 Navigation API 이벤트를 활용하는 간단한 예시입니다.

```jsx
import { useEffect, useState } from 'react';

function useNavigation() {
  const [isNavigating, setIsNavigating] = useState(false);

  useEffect(() => {
    function onStart() {
      setIsNavigating(true);
    }
    function onFinish() {
      setIsNavigating(false);
    }

    if ('navigation' in window) {
      window.navigation.addEventListener('navigate', onStart);
      window.navigation.addEventListener('navigatesuccess', onFinish);
      window.navigation.addEventListener('navigateerror', onFinish);
    }

    return () => {
      if ('navigation' in window) {
        window.navigation.removeEventListener('navigate', onStart);
        window.navigation.removeEventListener('navigatesuccess', onFinish);
        window.navigation.removeEventListener('navigateerror', onFinish);
      }
    };
  }, []);

  return isNavigating;
}

export default useNavigation;
```

이 훅을 통해 네비게이션 상태를 컴포넌트에서 쉽게 관리할 수 있고, 로딩 UI나 상태 기반 렌더링을 자연스럽게 구현할 수 있죠. 이런 구조가 코드도 깔끔하고 테스트하기에도 좋더라고요.

## SPA가 아니어도, 점진적 향상 전략으로 도입할 수 있다

사실 SPA가 아닌 기존 MPA 프로젝트에 SPA 스타일의 부드러운 네비게이션을 넣는 건 꽤 골치 아픈 작업이었어요. 그런데 Navigation API는 브라우저 레벨에서 지원되는 표준 API라서, 점진적으로 도입하면서 기존 페이지 구조를 크게 바꾸지 않아도 된다는 점이 큰 장점이에요.

InfoQ 아키텍처 기사에 따르면, 이 API는 점진적 향상(progressive enhancement) 전략에 부합해, 점차적으로 기능을 추가하거나 교체하면서도 기존 사용자 경험을 해치지 않는다고 합니다. 즉, 기존 MPA에 부담 없이 네비게이션 성능과 UX를 개선할 수 있다는 뜻이죠[InfoQ - Software Architecture & Design](https://www.infoq.com/architecture-design/).

실제로 우리 팀 프로젝트에도 Navigation API를 도입해봤는데, 기존 페이지는 그대로 두고 네비게이션 이벤트만 훅으로 감싸서 필요한 부분만 업데이트하는 식으로 점진적으로 전환했습니다. 덕분에 큰 리팩토링 없이도 사용자 체감 속도가 눈에 띄게 좋아졌어요.

## 내가 겪은 한계와 앞으로 기대하는 점

물론 아직 완벽한 솔루션은 아닙니다. 예를 들어, 브라우저 지원이 아직 완전하지 않고, 일부 구형 환경에서는 폴백 처리가 필요해요. 그리고 Navigation API가 네비게이션 이벤트를 다루는 데는 강력하지만, 복잡한 라우팅 상태나 인증 플로우를 완전히 대체하기엔 한계가 있죠.

또한, 서버 사이드 렌더링(SSR)과 조합할 때는 상태 동기화 문제를 잘 관리해야 합니다. 하지만 이런 단점들은 앞으로 점점 개선될 거라고 생각하고, 지금부터라도 익혀두면 분명 큰 도움이 될 거예요.

## 직접 써보면서 느낀 실전 팁

- **네비게이션 이벤트에 따른 UI 상태 관리**: 위 예시처럼 네비게이션 시작/종료 이벤트를 잡아서 로딩 인디케이터를 자연스럽게 제어하세요.
- **상태 관리와 라우팅 분리**: Navigation API 이벤트는 라우팅 신호로만 쓰고, 상태 업데이트는 별도 훅이나 컨텍스트에서 관리하는 게 유지보수에 좋습니다.
- **점진적 도입**: 기존 MPA 프로젝트라면 한꺼번에 바꾸려 하지 말고, 핵심 페이지부터 Navigation API를 적용해보세요.
- **폴백 처리 필수**: 아직 지원하지 않는 브라우저를 위해 기존 네비게이션 방식도 병행 유지해야 합니다.

---

Navigation API는 이제 막 베이스라인으로 도입된 신기술이지만, 실제로 써보면 기존 네비게이션 방식과는 차원이 다른 성능과 UX 개선을 경험할 수 있습니다. 특히 네트워크가 느리거나 모바일 환경에서 진가가 발휘되고, 컴포넌트 구조도 깔끔하게 정리할 수 있어서 앞으로 웹 개발 패턴에 큰 변화를 가져올 거라 확신해요.

동료 개발자분들도 꼭 한번 직접 써보고, 자신만의 패턴을 만들어 보시길 추천합니다. 점진적 향상과 상태 관리 분리라는 키워드만 기억해도 충분히 좋은 출발점이 될 거예요.
