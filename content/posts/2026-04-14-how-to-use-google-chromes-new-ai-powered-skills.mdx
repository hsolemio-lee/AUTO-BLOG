### AI가 브라우저에 들어온다니, 백엔드 입장에선 뭘 준비해야 할까?

얼마 전 Google Chrome이 AI ‘Skills’라는 기능을 내놓았다는 소식을 접했을 때, 솔직히 처음엔 ‘프론트엔드 얘기 아닌가?’ 싶었어요. 그런데 곰곰이 생각해보니, AI를 브라우저에 직접 붙인다는 건 백엔드 서버와의 협업 없이는 불가능하다는 거죠. 특히 AI 모델 호출, 응답 처리, API 관리 등은 결국 백엔드가 책임져야 할 부분이 많기 때문입니다.

그래서 이번 글에서는 실제로 우리 팀이 Chrome의 AI ‘Skills’ 같은 기능을 백엔드에 통합하면서 겪은 시행착오와 배운 점들을 풀어보려고 해요. 단순히 ‘어떻게 쓰는지’가 아니라, 백엔드 아키텍처와 API 설계, 그리고 운영 관점에서 꼭 챙겨야 할 부분들을 중심으로요.

## AI 프롬프트 최적화 없이는 API 비용과 지연이 눈덩이처럼 불어난다

AI 모델에 요청을 보낼 때, 무작정 텍스트를 던지면 비용도 많이 들고 응답 시간도 길어져요. 우리도 처음엔 이걸 몰라서 ‘일단 다 보내보자’ 했는데, 클라우드 비용이 한 달 만에 3배로 뛰는 걸 보고 깜짝 놀랐죠.

그래서 찾아본 게 바로 ‘프롬프트 엔지니어링’입니다. Anthropic의 가이드에 따르면, AI에게 필요한 최소한의 정보만 정확히 전달하는 게 핵심이에요. 예를 들어, 사용자가 브라우저에서 ‘이 페이지 요약해줘’라고 했을 때, 단순히 전체 HTML을 보내는 게 아니라 핵심 텍스트만 추출해서 보내는 식이죠.

```java
// Spring Boot에서 AI 프롬프트를 최적화해서 보내는 간단한 예
@RestController
public class AiController {

    @PostMapping("/api/ai/skill")
    public ResponseEntity<String> useAiSkill(@RequestBody UserRequest request) {
        String prompt = optimizePrompt(request.getPageContent());
        String aiResponse = callAiModel(prompt);
        return ResponseEntity.ok(aiResponse);
    }

    private String optimizePrompt(String content) {
        // 불필요한 태그 제거, 핵심 문장만 추출 등
        return content.replaceAll("<[^>]*>", "")
                      .substring(0, Math.min(1000, content.length()));
    }

    private String callAiModel(String prompt) {
        // OpenAI API 호출 코드 (동기 호출 예시)
        // 실제론 비동기로 처리하는 게 좋음
        return "AI 응답 예시";
    }
}
```

이렇게 하면 요청 크기를 줄여서 네트워크 비용과 지연 시간을 크게 줄일 수 있어요. 프롬프트 엔지니어링은 단순히 ‘좋은 질문 만들기’가 아니라, 백엔드 비용과 성능을 좌우하는 핵심 작업이라는 점, 꼭 기억하세요.[Anthropic - Prompt Engineering Guide](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/overview)

## AI 기능을 위한 백엔드 아키텍처, 마이크로서비스와 API 게이트웨이가 답이다

Chrome의 AI ‘Skills’처럼 프론트엔드에서 AI 호출이 많아지면, 백엔드 서버는 그만큼 확장성과 안정성을 갖춰야 합니다. 우리 팀도 초반에 단일 서버에 AI API 호출을 몰아넣었다가, 트래픽 폭주에 서버가 다운되는 걸 겪었죠.

Martin Fowler가 말한 것처럼, AI 기능은 별도의 마이크로서비스로 분리하고, API 게이트웨이를 통해 요청을 관리하는 게 정석입니다. 이렇게 하면 AI 모델 호출 부하를 독립적으로 조절할 수 있고, 장애가 나도 전체 서비스에 영향이 덜 가요.[Martin Fowler - Software Architecture Guide](https://martinfowler.com/architecture/)

예를 들어, AI 스킬 호출을 처리하는 마이크로서비스를 Spring Boot로 만들고, API 게이트웨이에서 인증, 라우팅, 속도 제한 등을 처리하는 구조입니다.

```yaml
# 간단한 API 게이트웨이 설정 예 (Spring Cloud Gateway)
spring:
  cloud:
    gateway:
      routes:
      - id: ai-skill-service
        uri: lb://AI-SKILL-SERVICE
        predicates:
        - Path=/api/ai/**
        filters:
        - StripPrefix=1
        - RequestRateLimiter=redis-rate-limiter[10,20]
```

이렇게 하면 초당 10건 기본, 최대 20건까지 요청을 제한해 과부하를 방지할 수 있어요. 물론, 복잡도가 늘고 운영 부담이 커지는 단점도 있지만, AI 기능이 서비스 핵심이라면 반드시 투자해야 할 부분입니다.

## AI 모델 호출은 비동기 처리로 사용자 경험 살리기

Chrome AI ‘Skills’가 실시간으로 답변을 주는 것 같지만, 사실 백엔드에서는 AI 모델 호출이 꽤 무거운 작업이에요. 우리도 처음엔 동기 호출로 구현했다가, 응답 지연 때문에 사용자 불만이 폭증했죠.

그래서 Spring의 `@Async`와 메시지 큐를 도입해 비동기 처리로 전환했습니다. 예를 들어, 사용자가 요청을 보내면 바로 202 Accepted를 반환하고, AI 모델 호출 결과는 WebSocket이나 SSE(Server-Sent Events)로 푸시하는 방식이죠.

```java
@Service
public class AiSkillService {

    @Async
    public CompletableFuture<String> callAiModelAsync(String prompt) {
        // AI 호출 코드
        String result = callAiModel(prompt);
        return CompletableFuture.completedFuture(result);
    }
}

@RestController
public class AiController {

    @Autowired
    private AiSkillService aiSkillService;

    @PostMapping("/api/ai/skill-async")
    public ResponseEntity<String> handleRequest(@RequestBody UserRequest request) {
        String prompt = optimizePrompt(request.getPageContent());
        aiSkillService.callAiModelAsync(prompt);
        return ResponseEntity.accepted().body("처리 중입니다.");
    }
}
```

이런 비동기 구조는 초기 구현이 복잡하고, 상태 관리가 까다롭지만, 사용자 체감 속도를 획기적으로 개선할 수 있습니다.[GitHub Engineering Blog](https://github.blog/category/engineering/)

## AI 공급망 관리, 보안과 버전 관리는 절대 소홀히 하지 말자

AI 모델과 클라우드 서비스에 의존도가 높아지면, 공급망 관리가 곧 서비스 안정성으로 직결됩니다. 우리도 한 번 AI 모델 업데이트 후 API 스펙이 바뀌어 서비스가 멈춘 경험이 있어요.

Cloudflare 사례를 참고하면, AI 모델과 클라우드 API의 신뢰성 점검, 보안 패치 적용, 그리고 롤백 전략을 반드시 마련해야 합니다. 특히 AI 모델 버전별 테스트 환경을 따로 두고, 점진적 배포를 통해 문제 발생 시 빠르게 이전 버전으로 복구하는 게 필수입니다.[Cloudflare Blog - How We Built It](https://blog.cloudflare.com/tag/how-we-built-it/)

또한, OpenAI API 문서에 따르면 인증 토큰 관리, 요청 제한, 오류 처리 로직을 꼼꼼히 구현해야 하니, 백엔드 개발자가 API 문서를 꼼꼼히 읽고 반영하는 게 중요해요.[OpenAI API Documentation](https://platform.openai.com/docs/overview)

### 마치며: AI 브라우저 기능, 백엔드가 얼마나 준비됐냐에 따라 체감 품질이 달라진다

Chrome AI ‘Skills’ 같은 기능은 겉으로 보면 프론트엔드 혁신 같지만, 사실 백엔드에서 얼마나 튼튼하게 설계하고 운영하느냐가 성공의 열쇠입니다. 프롬프트 최적화, 마이크로서비스 아키텍처, 비동기 처리, 그리고 철저한 공급망 관리까지, 놓치면 비용 폭탄과 사용자 불만으로 돌아오니까요.

개인적으로는 처음엔 AI 통합이 ‘그냥 API 하나 붙이는 거’라고 생각했는데, 실제로 해보니 서비스 전반에 걸친 아키텍처 고민과 운영 전략이 필수라는 걸 뼈저리게 느꼈습니다.

앞으로 AI가 더 많은 브라우저 기능과 서비스에 녹아들 텐데, 우리 백엔드 개발자들도 미리 준비해두면 좋겠습니다. 여러분도 AI 통합 프로젝트가 있다면, 프롬프트부터 아키텍처, 운영까지 차근차근 점검해보세요. 생각보다 복잡하지만, 그만큼 배울 게 많고 보람도 큽니다.
