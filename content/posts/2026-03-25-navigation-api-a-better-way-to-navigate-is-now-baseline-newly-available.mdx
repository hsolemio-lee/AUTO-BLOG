### "왜 페이지 전환이 이렇게 느리지?" — 우리 팀이 Navigation API에 눈을 돌린 이유

몇 달 전, 우리 프론트엔드 팀은 사용자 피드백에서 페이지 전환 속도가 너무 느리다는 얘기를 자주 들었어요. SPA 특성상 초기 로딩은 빠르지만, 페이지 이동마다 네트워크 요청과 상태 관리가 복잡해져서 체감 성능이 떨어지더군요. 기존 라우팅 라이브러리를 계속 다듬어봤지만 한계가 명확했죠. 그러다 최근에 나온 Navigation API 소식을 접하고 직접 적용해봤는데, 생각보다 훨씬 효과적이라 공유하려 합니다.

---

## Navigation API가 기존 라우팅과 어떻게 다른가?

우리가 흔히 쓰는 React Router, Vue Router 같은 라이브러리는 URL 변경에 따른 컴포넌트 렌더링과 상태 관리를 개발자가 직접 신경 써야 하는 경우가 많죠. 반면 Navigation API는 브라우저 차원에서 페이지 이동 이벤트를 세밀하게 컨트롤할 수 있게 해줘서, 다음과 같은 장점이 있습니다:

- **비동기 네비게이션 제어:** 네트워크 요청과 렌더링 타이밍을 직접 조절할 수 있어, 불필요한 리렌더링을 줄이고 사용자 체감 속도를 개선합니다.
- **상태 관리 통합:** 페이지 전환 중에도 상태를 자연스럽게 유지하거나 초기화하는 로직이 단순해집니다.
- **라우팅 로직 단순화:** 복잡한 조건문과 상태 추적 없이도 페이지 전환 흐름을 깔끔하게 관리할 수 있죠.

Cloudflare도 이 API를 도입하면서 네트워크 요청 최적화와 빠른 렌더링 덕분에 사용자 체감 속도가 크게 향상됐다고 합니다[Cloudflare Blog](https://blog.cloudflare.com/tag/how-we-built-it/). 실제로 써보니, 페이지 전환 시점에 필요한 데이터만 골라서 비동기로 받아오고, 렌더링 타이밍도 조절할 수 있어 체감 성능이 확실히 좋아졌어요.


## Navigation API를 써서 라우팅 코드를 이렇게 바꿨습니다

간단한 예제로, React 프로젝트에서 Navigation API를 어떻게 적용하는지 보여드릴게요. 아래 코드는 페이지 이동 시 데이터를 비동기 로드하고, 로딩 상태를 관리하는 기본 패턴입니다.

```jsx
import React, { useState, useEffect } from 'react';

function useNavigationData(url) {
  const [data, setData] = useState(null);
  const [loading, setLoading] = useState(false);

  useEffect(() => {
    let isMounted = true;
    async function fetchData() {
      setLoading(true);
      try {
        // Navigation API의 navigation 객체를 활용해 네비게이션 이벤트 감지
        const response = await fetch(url);
        const result = await response.json();
        if (isMounted) setData(result);
      } catch (e) {
        console.error('데이터 로드 실패', e);
      } finally {
        if (isMounted) setLoading(false);
      }
    }
    fetchData();

    return () => {
      isMounted = false;
    };
  }, [url]);

  return { data, loading };
}

export default function Page({ url }) {
  const { data, loading } = useNavigationData(url);

  if (loading) return <div>로딩 중...</div>;
  if (!data) return <div>데이터가 없습니다.</div>;

  return <div>{JSON.stringify(data)}</div>;
}
```

이 예시는 Navigation API가 제공하는 `navigation` 객체를 직접 사용해 네비게이션 이벤트를 감지하고, 필요한 데이터만 비동기로 받아오는 기본 구조입니다. 기존에는 페이지 전환마다 모든 데이터를 미리 불러오거나, 복잡한 상태 관리 로직을 짜야 했지만, 이 API 덕분에 훨씬 깔끔해졌죠.

Martin Fowler도 이런 단순화가 유지보수성과 생산성 향상으로 이어진다고 강조합니다[Martin Fowler](https://martinfowler.com/architecture/).


## SPA에서 Navigation API가 특히 빛나는 이유

대규모 SPA는 복잡한 상태 관리와 데이터 페칭 때문에 페이지 전환이 무겁고, 사용자 경험이 쉽게 저하되기 마련입니다. Navigation API는 이런 문제를 다음과 같이 해결해줍니다:

- **부분적 데이터 페칭:** 전체 페이지를 다시 로드하지 않고, 필요한 부분 데이터만 비동기로 가져와 렌더링 부담을 줄입니다.
- **상태 유지와 초기화 조절:** 페이지 전환 시점에 기존 상태를 유지할지 초기화할지 선택적으로 처리 가능해, 예를 들어 폼 입력값이나 스크롤 위치 관리가 쉬워집니다.
- **네비게이션 이벤트 훅 제공:** 개발자가 페이지 이동 흐름을 세밀하게 제어할 수 있어, 사용자 맞춤형 UX 구현이 용이해집니다.

InfoQ에서도 Navigation API가 SPA에서 안정적인 사용자 경험을 보장하는 데 효과적이라고 평가했습니다[InfoQ](https://www.infoq.com/architecture-design/).


## Navigation API를 도입할 때 주의할 점

처음엔 이게 별거 아닌 것 같지만, 실제 도입 과정에서 몇 가지 고려할 점이 있더라고요.

- **브라우저 지원 현황:** 최신 브라우저 중심으로 지원되기 때문에, 구형 브라우저 호환성 체크가 필요합니다.
- **기존 라우터와의 충돌 가능성:** 기존 라우팅 라이브러리와 함께 쓸 경우 이벤트 중복 처리나 상태 관리 충돌이 발생할 수 있어, 점진적 도입 전략이 필요합니다.
- **복잡한 상태 관리 시나리오:** Navigation API가 상태 관리를 단순화하지만, 매우 복잡한 비즈니스 로직이 얽힌 경우에는 별도의 상태 관리 라이브러리와 병행하는 게 더 나을 수 있습니다.

이 부분은 우리 팀도 초기 도입 시 겪었던 시행착오라, 충분히 테스트 환경에서 검증하는 걸 추천드려요.


## 내비게이션 성능 개선, 이렇게 시작하세요

1. **브라우저 지원 확인:** 주요 타깃 브라우저에서 Navigation API 지원 여부를 먼저 점검하세요.
2. **기존 라우팅 코드 리팩토링:** 페이지 전환 로직을 Navigation API 이벤트 기반으로 변경해보세요.
3. **비동기 데이터 페칭 분리:** 페이지 전환 시 필요한 데이터만 골라서 비동기로 로드하도록 구조를 개선합니다.
4. **상태 관리 정책 수립:** 페이지 전환 시 상태 유지/초기화 전략을 명확히 해 사용자 경험을 최적화하세요.
5. **점진적 도입 및 모니터링:** 전체 프로젝트에 한꺼번에 적용하기보다, 일부 페이지부터 적용하고 성능 및 사용자 피드백을 모니터링하세요.

Navigation API는 단순히 새 기능이 아니라, 프론트엔드 내비게이션 패러다임을 바꿀 수 있는 도구입니다. 우리 팀도 적용 후 유지보수가 쉬워지고, 사용자 체감 성능이 눈에 띄게 좋아져서 아주 만족하고 있습니다. 여러분도 꼭 한번 시도해보시길 추천드려요.

추가로, 배포 전에는 성능과 안정성뿐 아니라 로그 품질까지 확인해야 합니다. 에러 로그가 충분히 구조화되어 있지 않으면 원인 분석 시간이 길어지고, 같은 장애가 반복될 가능성이 높아집니다. 배포 후 24시간 관찰 구간에서 경보 임계치를 임시로 강화해 두는 것도 실무에서 자주 쓰는 방법입니다.
