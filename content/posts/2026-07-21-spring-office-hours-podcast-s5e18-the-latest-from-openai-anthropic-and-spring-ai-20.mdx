## AI 모델 호출, 그냥 REST API 호출과 뭐가 다를까?

최근에 우리 팀에서 OpenAI GPT와 Anthropic Claude API를 Spring Boot 백엔드에 붙이는 작업을 하면서 느낀 점인데, 단순히 REST API 호출이라고 생각하면 큰 오산이에요. AI 모델 호출은 호출 빈도, 응답 지연, 토큰 사용량 등 고려할 게 한두 가지가 아니거든요. 

특히 Spring AI 2.0이 나온 이후로는 OpenAI와 Anthropic API와의 통합이 훨씬 수월해졌지만, 그 안에 숨겨진 최적화 포인트들이 꽤 많습니다. 이번 에피소드에서 다룬 내용을 바탕으로, 내가 직접 겪은 시행착오와 팁을 공유해볼게요.


## Spring AI 2.0, 진짜로 뭐가 달라졌나?

Spring AI 2.0은 단순한 API 래퍼가 아니라, Spring Boot의 최신 기능을 십분 활용해 AI 모델 호출과 응답 처리를 최적화하는 데 초점을 맞췄어요. 예를 들어, 자동 구성(auto-configuration)을 통해 OpenAI, Anthropic 클라이언트를 빈으로 등록해주고, 의존성 주입으로 쉽게 호출할 수 있죠.[Spring Boot Reference Documentation](https://docs.spring.io/spring-boot/reference/)

내가 직접 써보니, 이전 버전에서는 API 키 관리나 HTTP 클라이언트 설정을 일일이 해줘야 했는데, 2.0부터는 기본적인 타임아웃, 커넥션 풀링, 비동기 호출 옵션까지 기본 제공돼서 생산성이 크게 올랐습니다. 

예를 들어, 아래처럼 `OpenAIClient`를 주입받아 간단히 텍스트 생성 요청을 할 수 있어요:

```java
@Service
public class ChatService {

    private final OpenAIClient openAIClient;

    public ChatService(OpenAIClient openAIClient) {
        this.openAIClient = openAIClient;
    }

    public String generateResponse(String prompt) {
        var completionRequest = CompletionRequest.builder()
            .model("gpt-4o-mini")
            .prompt(prompt)
            .maxTokens(150)
            .build();

        var response = openAIClient.completions().create(completionRequest);
        return response.choices().get(0).text();
    }
}
```

이 코드 한 줄 한 줄이 Spring AI 2.0의 자동 구성과 함께 돌아가서, 별도 HTTP 클라이언트 설정을 신경 쓸 필요가 없더라고요. 


## Anthropic Claude API, 프롬프트 엔지니어링이 왜 이렇게 중요한지

Anthropic Claude 모델은 OpenAI GPT와는 조금 다른 철학과 API 구조를 가지고 있어요. 특히 프롬프트 엔지니어링이 훨씬 더 체계적이고 중요하다는 점이 인상적이었죠.[Anthropic - Prompt Engineering Guide](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/overview)

내가 직접 Anthropic API를 쓸 때는, 단순히 텍스트를 던지는 게 아니라, "시스템 메시지"와 "사용자 메시지"를 명확히 분리하고, 모델에게 기대하는 행동을 구체적으로 지시하는 게 생산성 향상에 큰 도움이 됐어요. 예를 들어, 아래처럼 프롬프트를 구성합니다:

```java
var messages = List.of(
    new HumanMessage("You are a helpful assistant that summarizes technical articles."),
    new HumanMessage(userInput)
);

var chatRequest = ChatRequest.builder()
    .model("claude-v1")
    .messages(messages)
    .maxTokensToSample(200)
    .build();

var response = anthropicClient.chat().create(chatRequest);
```

이렇게 하면 Claude가 더 일관성 있는 답변을 주고, API 호출 비용과 응답 시간도 최적화할 수 있더라고요. 


## Spring Framework 코어 기술이 AI 통합에 주는 이점

Spring AI 2.0은 Spring Framework의 핵심 기술, 특히 의존성 주입(DI)과 AOP(관점 지향 프로그래밍)를 적극 활용해요.[Spring Framework - Core Technologies](https://docs.spring.io/spring-framework/reference/core.html)

내가 느낀 장점은 다음과 같아요:

- **모듈화**: AI 서비스 구현을 별도 컴포넌트로 분리해 테스트와 유지보수가 쉬워짐
- **트랜잭션 관리**: AI 호출 전후에 필요한 DB 트랜잭션과 연계 가능
- **비동기 처리**: `@Async`와 같은 Spring 기능으로 AI 호출을 비동기로 처리해 응답 시간 단축

특히 비동기 호출은 성능 튜닝에 큰 도움이 됐는데, 실제로 AI 모델 호출 시 200~300ms 정도 응답 지연이 발생하는 걸 고려하면, 동기 호출만으로는 서비스 전체 지연이 커질 수밖에 없거든요.


## 비동기 호출과 커넥션 풀링, 이거 안 하면 후회합니다

Baeldung 튜토리얼을 참고해서[Baeldung - Spring Boot Performance Tuning](https://www.baeldung.com/spring-boot-performance), Spring Boot에서 AI API 호출 시 꼭 비동기 패턴과 HTTP 커넥션 풀링을 적용했어요. 

내가 적용한 설정 예시는 이렇습니다:

```yaml
spring:
  http:
    client:
      connection-pool:
        max-total: 50
        max-per-route: 20
  task:
    execution:
      pool:
        core-size: 10
        max-size: 20
        queue-capacity: 100
```

그리고 AI 호출 서비스에 `@Async`를 붙여서, 호출 스레드를 분리했죠:

```java
@Async
public CompletableFuture<String> asyncGenerateResponse(String prompt) {
    return CompletableFuture.completedFuture(generateResponse(prompt));
}
```

이렇게 하면, 백엔드가 AI 호출 지연에 묶이지 않고 다른 작업을 병렬 처리할 수 있어서 전체 처리량이 30% 이상 개선됐어요. 물론, 비동기 호출은 예외 처리와 응답 타임아웃 관리가 까다로울 수 있으니 주의해야 합니다.


## 실제 운영 환경에서 마주친 문제와 대응

우리 팀은 처음에 AI 호출 실패 시 재시도 로직을 너무 단순하게 짰다가, API 호출 폭주로 인한 비용 폭증과 지연 문제를 겪었어요. 그래서 다음과 같은 패턴을 도입했습니다:

- **서킷 브레이커**: 일정 실패율 이상이면 잠시 호출 중단
- **백오프 재시도**: 재시도 시 지수 백오프 적용
- **요청 큐잉**: 한 번에 처리하는 요청 수 제한

Spring AI 2.0은 이런 패턴을 직접 제공하지는 않지만, Spring Boot와 Resilience4j 같은 라이브러리와 조합하면 쉽게 구현할 수 있습니다.


## 마무리하며: AI API 통합, 그냥 붙이지 마세요

처음엔 "AI API 그냥 REST 호출하면 되지" 싶었는데, 실제로는 AI 모델 특성에 맞춘 프롬프트 설계, 호출 최적화, 비동기 처리, 장애 대응 등 고려할 게 많더군요. Spring AI 2.0은 이런 복잡함을 많이 덜어주지만, 그래도 내부 동작 원리를 이해하고 튜닝하는 게 생산성과 안정성에 큰 차이를 만듭니다.

내가 추천하는 접근법은 다음과 같아요:

1. Spring AI 2.0의 자동 구성과 클라이언트 기능부터 잘 익히기
2. OpenAI와 Anthropic 각각의 API 문서와 프롬프트 가이드 꼼꼼히 읽기
3. 비동기 호출과 커넥션 풀링 설정으로 성능 튜닝하기
4. 장애 대응 패턴(서킷 브레이커, 백오프 등) 반드시 적용하기

이렇게 하면 AI 모델을 활용하는 백엔드가 훨씬 견고하고 확장성 있게 운영될 겁니다.
