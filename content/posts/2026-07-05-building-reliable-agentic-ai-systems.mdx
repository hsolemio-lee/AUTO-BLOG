에이전트 AI를 프로덕션에 올릴 때, 정말 골치 아픈 문제들이 줄줄이 따라오죠. "왜 갑자기 응답이 느려졌지?" "이 프롬프트가 왜 의도와 다르게 동작하는 거야?" 같은 고민 말입니다. 저도 몇 달 전 비슷한 문제를 겪으면서, 단순히 모델 API 호출만 잘한다고 끝나는 게 아니라는 걸 뼈저리게 느꼈어요. 그래서 이번 글에선 OpenAI API와 Anthropic의 프롬프트 및 코드 실행 아키텍처를 중심으로, 실무에서 에이전트 AI 시스템을 어떻게 신뢰성 있게 구축하고 점진적으로 마이그레이션할 수 있는지 공유해보려 합니다.


## OpenAI API 아키텍처, 왜 확장성과 안정성이 핵심일까?

OpenAI API를 처음 쓰면 그냥 "POST /v1/chat/completions" 호출하는 게 다인 줄 알게 되는데, 실제로는 그 뒤에 꽤 복잡한 아키텍처가 숨어 있어요. OpenAI 문서에 따르면, API는 여러 엔드포인트와 인증 메커니즘으로 구성돼 있어 확장성과 안정성을 보장합니다. 예를 들어, API 키 기반 인증은 물론이고, 각 요청에 대해 세밀한 쿼터 관리와 에러 핸들링 로직까지 갖추고 있죠[OpenAI API Documentation](https://platform.openai.com/docs/overview).

이게 왜 중요하냐면, 에이전트 AI는 보통 수많은 요청을 병렬로 처리해야 하고, 갑작스러운 트래픽 변동에도 견뎌야 하거든요. 저희 팀도 한때 API 호출이 몰리면서 429 Too Many Requests 에러가 자주 났는데, 요청 재시도 로직과 백오프 전략을 꼼꼼히 넣으니 안정성이 크게 올라갔습니다. 특히 500ms 이하 응답 시간을 목표로 삼았는데, 이걸 넘으면 사용자 경험이 급격히 떨어지더라고요.


## 프롬프트 설계, Anthropic 가이드에서 배운 명확함의 힘

프롬프트가 AI의 행동을 좌우한다는 말, 다들 들어보셨죠? Anthropic의 프롬프트 엔지니어링 가이드는 이걸 체계적으로 풀어줍니다. 명확하고 구조화된 프롬프트를 설계하면 AI가 의도를 제대로 파악하고, 오류도 줄어든다고 하네요[Anthropic - Prompt Engineering Guide](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/overview).

예를 들어, 저희는 "사용자 질문에 간결하고 정확하게 답하라"는 식으로 애매한 지시 대신, 단계별로 조건을 나누고, 기대하는 출력 포맷까지 명시하는 방식을 썼어요. 이렇게 하니 이전보다 오답률이 15% 감소했고, 불필요한 재호출도 줄었습니다.

```python
# Anthropic 스타일 프롬프트 예시
prompt = """
You are an assistant that answers questions concisely and factually.
When you don't know the answer, say 'I don't know'.
Format your answers as bullet points.
User question: {user_question}
"""

response = call_anthropic_api(prompt)
```

이게 처음엔 별거 아닌 것 같지만, 실제로는 AI가 헷갈릴 여지를 최대한 줄이는 게 핵심입니다.


## 코드 실행과 검증, Anthropic Claude Code가 제시하는 안전한 경로

에이전트 AI가 단순 대화만 하는 게 아니라 코드 생성과 실행까지 맡으면, 안전성과 신뢰성이 훨씬 중요해집니다. Anthropic Claude Code 문서에서는 이런 요구를 충족하기 위해 아키텍처 설계와 코드 검증 전략을 상세히 다루고 있어요[Anthropic - Claude Code Overview](https://docs.anthropic.com/en/docs/claude-code/overview).

저희는 AI가 생성한 코드를 바로 실행하기 전에, 샌드박스 환경에서 테스트하고, 정적 분석 도구로 위험한 패턴을 걸러내는 방식을 도입했습니다. 아래는 Python 코드 실행 시 위험한 함수 호출을 제한하는 간단한 예시입니다.

```python
import ast

class SafeCodeChecker(ast.NodeVisitor):
    forbidden_calls = {'exec', 'eval', 'open', 'import'}

    def visit_Call(self, node):
        func_name = getattr(node.func, 'id', None)
        if func_name in self.forbidden_calls:
            raise ValueError(f"Forbidden function call detected: {func_name}")
        self.generic_visit(node)


def is_code_safe(code_str):
    tree = ast.parse(code_str)
    checker = SafeCodeChecker()
    try:
        checker.visit(tree)
        return True
    except ValueError as e:
        print(e)
        return False

# AI가 생성한 코드 예시
generated_code = """
print('Hello World')
exec('print(2+2)')
"""

if is_code_safe(generated_code):
    exec(generated_code)
else:
    print("코드 실행이 차단되었습니다.")
```

이런 검증 절차를 안 하면, 예상치 못한 보안 문제나 시스템 장애로 이어질 수 있으니 꼭 필요합니다.


## 기존 시스템과 충돌 없이 AI 시스템을 도입하려면 Cursor 같은 툴이 도움된다

에이전트 AI를 새로 도입할 때, 기존 백엔드와 프론트엔드 간 연동 문제도 골치 아픈데요. Cursor는 이런 점을 잘 고려한 개발 도구로, 점진적 마이그레이션과 호환성 확보를 지원합니다[Cursor Documentation](https://docs.cursor.com/).

저희 팀은 기존 REST API를 완전히 버리지 않고, Cursor를 이용해 AI 관련 기능만 별도 마이크로서비스로 분리했어요. 덕분에 한꺼번에 대규모 리팩터링 없이도 AI 기능을 안정적으로 배포할 수 있었습니다. 물론 초기 설정과 학습 곡선이 있어서, 신규 팀원 온보딩 시 충분한 문서화가 필요하더라고요.


## GitHub Copilot과 Vercel AI SDK, 개발 생산성과 배포 안정성 사이에서

마지막으로 개발 생산성을 높이면서 코드 품질을 유지하는 것도 중요합니다. GitHub Copilot은 AI 기반 코드 보조 도구로, 반복적인 코드 작성 시간을 줄여주지만 무분별하게 의존하면 코드 일관성이나 보안 문제가 생길 수 있어요[GitHub Copilot Documentation](https://docs.github.com/en/copilot).

그리고 Vercel AI SDK는 클라우드 기반 AI 앱 구축에 최적화된 프레임워크로, 프론트엔드와 백엔드 통합, 확장성, 안정적인 배포를 위한 아키텍처 설계 요소를 제공합니다[Vercel AI SDK Documentation](https://sdk.vercel.ai/docs/introduction). 저희는 이를 활용해 서버리스 환경에서 AI 모델 호출과 UI를 매끄럽게 연결했는데, 트래픽 급증에도 무리 없이 대응하는 경험을 했습니다.
