### "페이지가 멈추는 느낌, 네비게이션 지연, 다들 겪어봤죠?"

요즘 웹앱을 쓰다 보면 페이지 이동할 때마다 깜빡임이나 로딩 지연 때문에 답답할 때가 많습니다. 특히 SPA라고 해도 초기 데이터 페칭이나 상태 변경으로 인해 체감 성능이 떨어지는 경우가 많죠. 저도 최근에 이 문제 때문에 골머리를 앓다가 최신 Navigation API를 적용해봤는데, 결과가 꽤 놀라웠습니다. 오늘은 그 경험을 공유하려고 해요.

---

## Navigation API가 기존 네비게이션과 어떻게 다른가요?

기존 웹 네비게이션은 브라우저가 페이지 전체를 새로 불러오는 방식이었죠. 그래서 SPA가 부상하면서, 클라이언트에서 라우팅을 직접 제어해 불필요한 전체 리로드를 막고 사용자 경험을 개선했습니다. 그런데 이 과정에서 브라우저 기본 네비게이션 이벤트와 충돌하거나, 상태 관리가 복잡해지는 문제가 있었습니다.

최신 Navigation API는 브라우저가 제공하는 네비게이션 이벤트를 좀 더 세밀하게 제어할 수 있게 해주면서, 불필요한 리로드 없이도 네비게이션 흐름을 자연스럽게 관리할 수 있도록 설계됐습니다. GitHub 엔지니어링 블로그에 따르면 이 API는 네비게이션 성능을 크게 향상시키고 사용자 경험을 최적화하는 데 중점을 두고 있다고 해요[GitHub Engineering Blog](https://github.blog/category/engineering/).

---

## Navigation API로 SPA 네비게이션을 부드럽게 만드는 법

실제로 Navigation API를 적용할 때 가장 중요한 점은 브라우저 기본 이벤트를 적절히 활용하는 겁니다. 예를 들어, `navigation` 이벤트를 통해 사용자가 페이지를 이동할 때 발생하는 네비게이션 상태를 감지할 수 있어요. 이를 활용하면 SPA에서 불필요한 전체 페이지 리로드를 막고, 필요한 데이터만 비동기로 가져와 화면을 갱신할 수 있죠.

간단한 예제를 볼게요:

```javascript
// SPA에서 Navigation API 활용 예시
window.navigation.addEventListener('navigate', event => {
  event.intercept({
    async handler() {
      // 이동할 URL
      const url = event.destination.url;
      // 필요한 데이터만 비동기로 가져오기
      const data = await fetch(`/api/data?path=${new URL(url).pathname}`).then(res => res.json());
      
      // 화면 업데이트 로직
      updatePageContent(data);
    }
  });
});

function updatePageContent(data) {
  const content = document.getElementById('content');
  content.textContent = JSON.stringify(data);
}
```

이 코드는 사용자가 네비게이션을 시도할 때 전체 페이지 리로드 없이 필요한 데이터만 가져와서 화면을 갱신합니다. 덕분에 체감 속도가 훨씬 빨라지고, 네트워크 비용도 줄일 수 있죠.

## Cloudflare가 Navigation API로 경험한 성능 개선 사례

Cloudflare는 자사 블로그에서 Navigation API 도입 후 네트워크 요청 최적화와 리소스 선로딩 전략이 크게 개선됐다고 밝혔습니다[Cloudflare Blog - How We Built It](https://blog.cloudflare.com/tag/how-we-built-it/). 구체적으로, 페이지 전환 시 필요한 리소스만 선별적으로 미리 불러와서 전체 로딩 속도가 30% 이상 빨라졌다고 하네요.

이 사례를 참고해 우리 프로젝트에도 선로딩 전략을 적용해봤는데, 다음과 같은 점들이 인상적이었어요:

- **필요한 리소스만 선별적 로딩:** 예를 들어, 다음 페이지에 필요한 이미지나 스크립트를 네비게이션 이벤트 발생 시점에 미리 불러옵니다.
- **캐싱과 비동기 페칭 조합:** 이미 캐시에 있는 데이터는 즉시 렌더링하고, 새로 필요한 데이터만 비동기로 가져와 지연 시간을 최소화합니다.

이런 전략 덕분에 사용자 인터랙션 시 지연이 눈에 띄게 줄었고, 페이지 전환이 훨씬 자연스러워졌습니다.

## Navigation API를 도입할 때 아키텍처적으로 고려해야 할 점

Martin Fowler의 아키텍처 가이드에 따르면 Navigation API는 모듈화된 컴포넌트 설계와 상태 관리 일관성을 유지하는 데 큰 도움이 됩니다[Martin Fowler - Software Architecture Guide](https://martinfowler.com/architecture/). 하지만 반대로, 기존 라우팅 로직과 충돌하지 않도록 설계하는 게 중요해요.

예를 들어, 상태 관리 라이브러리(리덕스, Recoil 등)와 Navigation API 이벤트를 연동할 때는 다음을 주의해야 합니다:

- **상태 동기화:** 네비게이션 이벤트와 상태 변화를 일관되게 관리하지 않으면 UI가 엉키거나 예기치 않은 버그가 발생할 수 있습니다.
- **모듈 분리:** 네비게이션 관련 로직을 별도의 모듈로 분리해 유지보수성을 높이고, 테스트 커버리지를 확보하세요.

이 부분은 처음엔 별거 아닌 것 같지만, 실제 운영 환경에서 문제가 터지면 디버깅 난이도가 급격히 올라갑니다.

---

## Navigation API 최적화할 때 꼭 챙겨야 할 캐싱과 비동기 전략

InfoQ 아키텍처 기사에 따르면 Navigation API 최적화는 캐싱 전략과 비동기 데이터 페칭의 조합이 핵심이라고 합니다[InfoQ - Software Architecture & Design](https://www.infoq.com/architecture-design/). 제가 적용해본 경험도 크게 다르지 않았어요.

- **캐싱은 최대한 활용하되, 최신성 보장 필요:** 예를 들어, `Cache-Control` 헤더를 적절히 설정해 자주 변하지 않는 데이터는 캐시에서 바로 읽고, 변동이 잦은 데이터는 백그라운드에서 새로고침합니다.
- **비동기 페칭은 네비게이션 이벤트와 연동:** 위 코드 예시처럼 네비게이션 시작 시점에 필요한 데이터만 비동기로 불러와서 렌더링 지연을 최소화합니다.

이렇게 하면 사용자 입장에서는 페이지가 거의 즉시 반응하는 것처럼 느껴지고, 서버 부하도 분산할 수 있어요.

## 마치며: Navigation API, 꼭 써봐야 하는 이유와 주의할 점

처음 Navigation API를 접했을 때는 "이게 과연 얼마나 효과적일까?" 싶었는데, 직접 적용해보니 확실히 체감 성능이 달라졌습니다. 특히 SPA에서 브라우저 기본 네비게이션 이벤트를 제대로 활용하면, 불필요한 리로드를 막고 데이터 페칭 타이밍을 최적화할 수 있어서 사용자 경험이 한층 부드러워집니다.

하지만 무턱대고 적용하기보다는 아래 사항을 꼭 챙기세요:

- 기존 라우팅 시스템과 충돌하지 않도록 설계하기
- 상태 관리와 네비게이션 이벤트를 일관되게 동기화하기
- 캐싱 전략과 비동기 페칭을 조합해 지연 시간 최소화하기
- 리소스 선로딩을 적절히 활용해 초기 로딩 속도 개선하기

이걸 잘 지키면, 네비게이션 성능이 2배 이상 개선되는 경험을 할 수 있을 겁니다. 실제로 우리 팀은 이걸 적용한 후 사용자 이탈률이 눈에 띄게 줄었어요.

앞으로도 Navigation API는 프론트엔드 네비게이션의 새로운 표준으로 자리 잡을 것 같으니, 꼭 한번 직접 써보시길 추천합니다.
