## "이게 진짜 가능해?" Spring AI 2.0과 OpenAI, Anthropic API를 만났을 때

최근에 우리 팀에서 AI 챗봇 백엔드를 만들면서 가장 많이 들었던 질문 중 하나가 “Spring에서 OpenAI 같은 AI API를 어떻게 효율적으로 쓸 수 있나요?”였어요. 사실, OpenAI API는 편리하지만 호출 빈도 조절, 토큰 사용량 관리, 에러 핸들링 같은 부분에서 생각보다 까다로운 점이 많거든요. 그런데 Spring AI 2.0이 등장하면서 이런 고민들이 꽤 많이 줄었더라고요. 이번 에피소드에서 다룬 내용을 기반으로, OpenAI와 Anthropic의 Claude 모델을 Spring Boot 백엔드에 통합하는 최신 전략을 정리해봤습니다.


## Spring AI 2.0, 뭘 새로 담았길래 이렇게 편해졌을까?

Spring AI 2.0은 OpenAI와 Anthropic API 통합을 위해 새로운 스타터와 구성 옵션을 대폭 강화했어요. 예전에는 직접 RestTemplate이나 WebClient를 써서 API 호출을 직접 구현해야 했는데, 이제는 Spring Boot 3.0 이상에서 제공하는 `spring-ai-starter`를 쓰면 기본적인 인증, 요청, 응답 파싱이 훨씬 간단해졌죠. 

특히 비동기 호출 지원과 Bean 설정을 통한 커스텀 튜닝이 핵심이에요. 예를 들어, OpenAI API 호출 시 `WebClient` 기반의 비동기 호출을 기본으로 제공해서, 대량 요청이 들어와도 스레드가 막히지 않도록 설계되어 있습니다. 그리고 Bean으로 타임아웃, 리트라이 정책, 에러 핸들러를 직접 주입할 수 있어서 상황에 맞게 아주 세밀한 조절이 가능해졌죠.

```java
@Configuration
public class OpenAIConfig {

    @Bean
    public OpenAIClient openAIClient(WebClient.Builder webClientBuilder) {
        return OpenAIClient.builder()
            .apiKey("${openai.api.key}")
            .webClient(webClientBuilder
                .baseUrl("https://api.openai.com/v1")
                .build())
            .timeout(Duration.ofSeconds(10))
            .build();
    }
}

@Service
public class ChatService {

    private final OpenAIClient openAIClient;

    public ChatService(OpenAIClient openAIClient) {
        this.openAIClient = openAIClient;
    }

    public Mono<String> getChatCompletion(String prompt) {
        ChatCompletionRequest request = ChatCompletionRequest.builder()
            .model("gpt-4")
            .messages(List.of(new ChatMessage("user", prompt)))
            .build();

        return openAIClient.chatCompletion(request)
            .map(response -> response.getChoices().get(0).getMessage().getContent());
    }
}
```

이 코드에서 보듯, `OpenAIClient`를 빈으로 등록하고, `Mono<String>` 형태로 비동기 응답을 받아서 리액티브하게 처리할 수 있습니다. 이런 구조 덕분에 대규모 트래픽도 무리 없이 소화할 수 있죠.


## Anthropic Claude 모델과 Spring AI 2.0의 만남: 프롬프트 엔지니어링이 쉬워졌다

Anthropic의 Claude 모델은 OpenAI와는 또 다른 프롬프트 작성법이 필요해요. 그런데 Spring AI 2.0은 Anthropic의 프롬프트 엔지니어링 가이드에 맞춘 템플릿 기능을 제공합니다. 덕분에 복잡한 프롬프트를 깔끔하게 관리할 수 있죠.

예를 들어, Anthropic 가이드에 따르면 프롬프트에 명확한 역할 지시와 컨텍스트를 주는 게 중요합니다. Spring AI 2.0에서는 이런 템플릿을 `PromptTemplate` 빈으로 등록해 재사용할 수 있어요.

```java
@Bean
public PromptTemplate anthropicPromptTemplate() {
    return PromptTemplate.builder()
        .template("You are a helpful assistant. Answer the question clearly: {{question}}")
        .build();
}

public Mono<String> askClaude(String question) {
    String prompt = anthropicPromptTemplate.render(Map.of("question", question));
    // AnthropicClient는 OpenAIClient와 비슷한 구조
    return anthropicClient.completePrompt(prompt)
        .map(CompletionResponse::getText);
}
```

이렇게 하면 프롬프트를 하드코딩하지 않고, 버전별로 관리하거나 A/B 테스트도 쉽게 할 수 있습니다. 프롬프트 튜닝이 반복되는 AI 서비스에서는 이게 꽤 큰 시간 절약이 돼요.


## OpenAI API 호출 시 토큰과 호출 빈도, 어떻게 관리해야 할까?

OpenAI API를 백엔드에서 직접 호출하다 보면 가장 골치 아픈 게 토큰 사용량과 호출 빈도 관리입니다. 토큰이 과다 사용되면 비용 폭탄 맞기 쉽고, 호출이 너무 잦으면 API 제한에 걸리기 쉬워서요.

Spring Boot Actuator와의 통합이 여기서 빛을 발합니다. `spring-ai-starter`는 API 호출 메트릭을 Actuator에 노출해서, Prometheus 같은 모니터링 도구와 연동하기 좋아요. 이를 통해 실시간으로 호출량과 토큰 사용량을 모니터링하고, 경고 임계값을 설정할 수 있습니다.

```yaml
management:
  endpoints:
    web:
      exposure:
        include: health,metrics,openai
spring:
  ai:
    openai:
      api-key: ${OPENAI_API_KEY}
      max-tokens: 2048
      rate-limit:
        max-requests-per-minute: 60
```

위처럼 설정하면, 초당 1건 정도로 호출을 제한할 수 있고, 토큰 최대 사용량도 조절할 수 있죠. 실제 운영 환경에서는 이 수치를 API 사용 패턴에 맞춰서 조절하는 게 관건입니다.


## JVM 튜닝과 커넥션 풀 최적화, AI API 호출에도 꼭 필요하다

AI API 호출은 네트워크 IO가 많고, 비동기 처리가 기본이라 JVM 메모리 설정과 커넥션 풀 관리가 성능에 직결됩니다. Baeldung에서 소개하는 Spring Boot 성능 튜닝 가이드를 참고하면, 다음과 같은 팁이 실무에서 꽤 유용해요:

- JVM 힙 메모리는 기본 512MB 이상, AI 모델 호출이 많으면 2GB 이상 권장
- `WebClient` 커넥션 풀 크기는 기본 50~100 사이로 시작해서 트래픽에 맞게 조절
- 비동기 스케줄러 쓰면 호출 지연 최소화 가능

```java
@Bean
public WebClient webClient() {
    return WebClient.builder()
        .clientConnector(new ReactorClientHttpConnector(
            HttpClient.create()
                .tcpConfiguration(tcpClient ->
                    tcpClient.option(ChannelOption.CONNECT_TIMEOUT_MILLIS, 5000)
                             .doOnConnected(conn ->
                                 conn.addHandlerLast(new ReadTimeoutHandler(10))
                                     .addHandlerLast(new WriteTimeoutHandler(10)))))
        )
        .build();
}
```

이렇게 타임아웃을 명확히 설정해두면, 네트워크 문제로 인한 무한 대기 상태를 방지할 수 있습니다. 물론 너무 짧게 잡으면 순간적인 네트워크 지연에도 실패가 잦아지니, 적절한 밸런스가 중요해요.


## Spring 코어 기술을 활용해 AI 통합 코드 유지보수성 높이기

마지막으로, Spring의 의존성 주입(DI), AOP, 트랜잭션 관리 같은 코어 기술을 AI API 통합에도 적극 활용하세요. 예를 들어, API 호출 전후에 공통 로깅이나 호출 횟수 카운팅을 AOP로 처리하면 코드가 훨씬 깔끔해집니다.

```java
@Aspect
@Component
public class OpenAIApiLoggingAspect {

    @Around("execution(* com.example.ai.ChatService.*(..))")
    public Object logApiCall(ProceedingJoinPoint joinPoint) throws Throwable {
        long start = System.currentTimeMillis();
        Object result = joinPoint.proceed();
        long duration = System.currentTimeMillis() - start;
        System.out.println("OpenAI API 호출 메서드: " + joinPoint.getSignature().getName() + ", 소요 시간: " + duration + "ms");
        return result;
    }
}
```

이런 방식을 쓰면 AI 관련 로직과 부가 기능을 분리할 수 있어서, 나중에 API 변경이나 확장에도 훨씬 유연하게 대응할 수 있습니다.

Spring AI 2.0과 OpenAI, Anthropic API 통합은 단순히 API 호출을 편하게 하는 수준을 넘어, 대규모 서비스에서 안정적이고 효율적으로 AI 기능을 운영할 수 있는 기반을 마련해줬어요. 물론, API 호출 비용과 호출 제한, 프롬프트 튜닝, JVM과 네트워크 설정 같은 현실적인 고민들은 여전히 남아 있습니다. 

하지만 이번 에피소드에서 다룬 최신 기능과 실무 팁들을 적용하면, 기존보다 훨씬 빠르고 안정적으로 AI 백엔드를 구축할 수 있을 겁니다. 

실제로 저희 팀도 `spring-ai-starter`를 도입하고, Actuator 기반 모니터링과 프롬프트 템플릿을 활용하면서 AI 서비스 운영이 한결 수월해졌어요. 여러분도 꼭 한번 시도해보시길 추천합니다.
