## 갑자기 페이지가 리로드되면서 UX가 뚝 떨어질 때, 어떻게 해야 할까?

웹 앱을 개발하다 보면 사용자가 링크를 클릭하거나 버튼을 눌러 페이지가 전환될 때마다 전체 페이지가 리로드되면서 깜빡임이 생기는 걸 경험했을 거예요. 특히 SPA가 아닌 전통적인 다중 페이지 애플리케이션에서는 이런 현상이 더 자주 발생하죠. 사용자 입장에선 느리고 답답한 경험이 될 수밖에 없습니다.

그런데 최근에 Baseline으로 정식 제공되기 시작한 Navigation API 덕분에 이런 문제를 훨씬 자연스럽게 해결할 수 있는 길이 열렸어요. 이 API는 기존의 window.location 기반 네비게이션을 대체하면서, 비동기 페이지 로딩과 상태 관리 최적화를 지원해 페이지 전환 성능과 UX를 크게 끌어올릴 수 있습니다.

이번 글에서는 Navigation API가 왜 주목받는지, 그리고 실제 프로젝트에 어떻게 적용할 수 있는지 구체적인 코드 예제와 함께 이야기해볼게요.

## Navigation API가 기존 네비게이션과 다른 점은 뭘까?

기존에 우리가 페이지를 이동할 때 썼던 건 주로 `window.location.href` 변경이나 `history.pushState` 같은 브라우저 API였어요. 그런데 이 방식들은 페이지 전체를 새로 불러오거나, SPA라도 상태 관리가 복잡해질 수밖에 없었죠.

Navigation API는 이런 문제를 해결하기 위해 다음과 같은 기능을 제공합니다:

- **비동기 네비게이션 제어**: 페이지 이동을 명령할 때 비동기 작업(예: 데이터 페칭)을 네비게이션 이벤트와 자연스럽게 연결할 수 있어요.
- **이벤트 리스너로 네비게이션 흐름 세밀 제어**: `navigate`, `navigateerror`, `navigatesuccess` 같은 이벤트를 통해 네비게이션 상태를 감지하고 커스텀 로딩 UI를 띄우거나, 실패 시 복구 로직을 적용할 수 있습니다.
- **SPA와 MPA 모두 지원**: 싱글 페이지 앱뿐 아니라 전통적인 다중 페이지 앱에서도 쓸 수 있어, 점진적 도입이 가능해요.

이 덕분에 기존에 페이지 리로드로 인한 깜빡임이나 느린 반응 속도를 크게 줄이고, 사용자에게 더 부드럽고 빠른 네비게이션 경험을 제공할 수 있죠.[GitHub Engineering Blog](https://github.blog/category/engineering/)

## 실제로 Navigation API를 어떻게 써야 할까? 코드로 맛보기

아래는 Navigation API의 `navigate` 메서드를 활용해 특정 URL로 이동하면서, 네비게이션 시작과 완료 시점에 커스텀 로딩 화면을 표시하는 간단한 예제입니다.

```js
// 로딩 UI 토글 함수
function setLoading(isLoading) {
  const loader = document.getElementById('loading-indicator');
  if (loader) loader.style.display = isLoading ? 'block' : 'none';
}

// 네비게이션 이벤트 리스너 등록
const navigation = window.navigation;

navigation.addEventListener('navigate', (event) => {
  setLoading(true); // 네비게이션 시작
  // 비동기 데이터 로딩 등 필요한 작업을 여기서 처리 가능
  event.intercept({
    async handler() {
      try {
        // 예: 새 페이지 데이터 fetch
        await fetch(event.destination.url);
        event.commit(); // 네비게이션 완료
      } catch (err) {
        console.error('Navigation failed:', err);
        event.abort(); // 네비게이션 중단
      }
    }
  });
});

navigation.addEventListener('navigatesuccess', () => {
  setLoading(false); // 네비게이션 성공 시 로딩 종료
});

navigation.addEventListener('navigateerror', () => {
  setLoading(false); // 실패 시에도 로딩 종료
  alert('페이지 이동에 실패했습니다. 다시 시도해주세요.');
});

// 버튼 클릭 시 네비게이션 호출 예
document.getElementById('go-to-about').addEventListener('click', () => {
  navigation.navigate('/about');
});
```

이 코드를 보면, 네비게이션이 시작되면 로딩 UI를 띄우고, 비동기 작업이 끝나면 네비게이션을 완료하는 흐름을 직접 제어할 수 있죠. 기존에는 이런 세밀한 제어가 어려웠는데, Navigation API 덕분에 가능해졌습니다.

이 패턴을 활용하면, 네트워크 상태에 따라 로딩 표시를 최적화하거나, 실패 시 사용자에게 적절한 피드백을 줄 수 있어 UX가 크게 향상됩니다.

## Navigation API가 클라우드 환경에서 더 빛나는 이유

대규모 서비스나 클라우드 플랫폼 환경에서는 네트워크 지연 시간과 서버-클라이언트 간 데이터 동기화가 중요한 이슈입니다. Navigation API는 이런 환경에서 다음과 같은 장점을 제공합니다:

- **네트워크 지연 최소화**: 비동기 네비게이션 처리 덕분에 필요한 데이터만 선별적으로 불러오고, 불필요한 전체 페이지 리로드를 방지합니다.
- **데이터 동기화 효율화**: 네비게이션 이벤트 훅을 활용해 서버에서 최신 상태를 받아오거나, 캐시된 데이터를 적절히 활용할 수 있어 트래픽과 응답 속도를 최적화합니다.
- **히스토리 API와 자연스러운 연동**: 뒤로가기, 앞으로가기 버튼을 눌렀을 때도 부드럽고 일관된 동작을 보장해 사용자 혼란을 줄입니다.

Cloudflare 같은 대규모 클라우드 인프라 운영사도 이 API를 활용해 안정적인 네비게이션 경험을 제공하는 사례가 보고되고 있어요.[Cloudflare Blog - How We Built It](https://blog.cloudflare.com/tag/how-we-built-it/)

## 도입 전 꼭 알아둬야 할 현실적인 고려사항

처음 Navigation API를 접하면 마치 만능 해결책처럼 보이지만, 현실에서는 몇 가지 주의할 점이 있습니다:

- **브라우저 지원 현황**: 아직 모든 브라우저에서 완벽히 지원하지는 않아요. 따라서 폴리필이나 대체 로직을 준비해야 합니다.
- **기존 코드와의 충돌 가능성**: 기존에 `window.location`이나 `history` API를 직접 조작하는 코드가 많다면, 네비게이션 흐름이 꼬일 수 있어요. 점진적 도입과 충분한 테스트가 필수입니다.
- **복잡한 상태 관리**: 네비게이션 이벤트를 직접 다루면서 상태 관리가 복잡해질 수 있습니다. 특히 비동기 작업 실패 처리, 중복 네비게이션 방지 로직 등을 꼼꼼히 구현해야 해요.
- **SEO와 SSR 고려**: 서버 사이드 렌더링 환경에서는 네비게이션 API가 클라이언트 전용이기 때문에, 초기 로딩과 SEO 최적화 전략은 별도로 신경 써야 합니다.

Martin Fowler도 네비게이션 관련 아키텍처를 설계할 때 이런 트레이드오프를 신중히 고려하라고 조언합니다.[Martin Fowler - Software Architecture Guide](https://martinfowler.com/architecture/)

## 내 프로젝트에 Navigation API를 적용할 때 꼭 기억할 점

- **로딩 UI는 필수**: 네비게이션 시작과 완료 시점을 명확히 잡고, 사용자에게 현재 상태를 알려주는 UI를 꼭 넣으세요.
- **비동기 데이터 페칭 최적화**: 네비게이션 이벤트 핸들러 안에서 필요한 데이터만 선별적으로 불러오도록 하여 네트워크 부담을 줄이세요.
- **이벤트 리스너는 꼭 해제**: SPA 환경에서는 네비게이션 이벤트 리스너를 컴포넌트 라이프사이클에 맞춰 적절히 등록/해제하지 않으면 메모리 누수가 발생할 수 있습니다.
- **점진적 도입 권장**: 전체 앱에 한꺼번에 적용하기보단, 특정 페이지나 기능 단위로 도입해 문제를 최소화하세요.

이렇게만 해도 기존 네비게이션보다 훨씬 부드럽고 빠른 사용자 경험을 줄 수 있습니다.

---

요약하자면, Navigation API는 프론트엔드 네비게이션을 한 단계 업그레이드할 수 있는 강력한 도구입니다. 비동기 네비게이션 제어, 세밀한 이벤트 핸들링, SPA와 MPA 모두 지원하는 유연성 덕분에, 사용자 경험과 성능 모두 잡을 수 있죠.

하지만 아직은 브라우저 호환성과 기존 코드와의 충돌 같은 현실적인 문제도 있으니, 충분한 테스트와 점진적 도입을 권장합니다. 여러분도 다음 프로젝트에서 Navigation API를 써서 더 나은 네비게이션 경험을 만들어 보세요!
