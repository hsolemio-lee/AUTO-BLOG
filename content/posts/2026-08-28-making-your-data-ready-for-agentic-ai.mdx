### AI가 내 데이터를 ‘이해’하지 못할 때 생기는 골치

최근에 우리 팀에서 Agentic AI를 도입하면서 겪은 일이에요. AI가 우리 데이터를 받아서 작업을 수행하는데, 의도와 전혀 다르게 결과가 나오더라고요. 원인을 파고들다 보니, 데이터 구조가 너무 막연하고 일관성이 없어서 AI가 정확히 해석하지 못하는 상황이었죠. 이 경험 하나만으로도 데이터 준비가 얼마나 중요한지 뼈저리게 느꼈습니다.

Agentic AI는 단순한 챗봇이 아니라, 자율적 판단과 행동이 가능한 AI를 말하는데요. 이 AI와 잘 통합하려면 데이터가 명확한 구조와 일관된 스키마를 가져야 합니다. 그래야 AI가 API 호출 시 데이터를 정확히 해석하고 처리할 수 있거든요[OpenAI API Documentation](https://platform.openai.com/docs/overview).

## Agentic AI와 데이터 스키마, 왜 이렇게 까다로울까?

일단 Agentic AI는 복잡한 명령어를 처리하고, 여러 API를 조합해 자율적으로 작업을 수행합니다. 이때 데이터가 중구난방이면 AI가 "이게 뭔 소리지?" 하면서 엉뚱한 행동을 하죠. 예를 들어, 날짜 형식이 일정하지 않거나, 필수 필드가 누락되면 AI가 오류를 내거나 잘못된 판단을 합니다.

우리 팀은 JSON 스키마를 엄격히 정의하고, API 계약(API contract)을 통해 프론트엔드와 백엔드 간 데이터 인터페이스를 명확히 했어요. 이렇게 하니 유지보수가 훨씬 쉬워지고, AI가 데이터를 해석하는 데 혼란이 줄어들더라고요. 이런 접근법은 GitHub Copilot 문서에서도 명확한 API 계약이 시스템 복잡도를 줄인다고 강조합니다[GitHub Copilot Documentation](https://docs.github.com/en/copilot).

## 프롬프트 엔지니어링과 데이터 우선순위 정하기

프롬프트 엔지니어링 단계에서 데이터를 어떻게 준비하느냐가 AI가 의도한 작업을 제대로 수행하는 데 결정적입니다. 예를 들어, 자연어 프롬프트에 너무 많은 정보를 한꺼번에 넣으면 AI가 핵심을 놓칠 수 있어요. 그래서 중요한 정보부터 우선순위를 정하고, 명확하게 표현하는 게 필수입니다.

우리 팀은 프롬프트에 들어갈 데이터를 계층화해서, 핵심 명령어와 부가 정보를 분리했습니다. 이렇게 하면 AI가 명령어를 우선적으로 인식하고, 부가 정보는 참고용으로 활용하죠. Anthropic의 프롬프트 엔지니어링 가이드에서 이런 우선순위와 명확성의 중요성을 잘 설명하고 있습니다[Anthropic - Prompt Engineering Guide](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/overview).

## 기존 데이터베이스를 Agentic AI 친화적으로 바꾸는 현실적인 방법

여기서 가장 골치 아픈 부분이 기존 데이터 마이그레이션입니다. 기존 DB 스키마가 AI가 요구하는 형식과 다르면, 변환 작업이 필수인데요. 이 과정에서 데이터 무결성과 연속성을 유지하는 게 핵심입니다. 단순히 스키마를 바꾸는 것뿐 아니라, 데이터 손실 없이 이전하는 게 쉽지 않거든요.

우리 팀은 Cursor라는 툴과 자체 스크립트를 활용해 단계별 마이그레이션을 진행했습니다. 예를 들어, 날짜 필드를 ISO 8601 형식으로 통일하고, 중복된 필드를 제거했죠. 마이그레이션 중에는 항상 백업을 철저히 하고, 변경 전후 데이터를 비교 검증하는 절차를 넣었습니다.

이런 전략은 Cursor Documentation에서도 권장하는 방식입니다[Cursor Documentation](https://docs.cursor.com/).

## 클라우드 환경에서 AI 데이터 파이프라인 자동화와 확장성 고려하기

Agentic AI를 클라우드에서 운영할 때는 데이터 파이프라인 자동화와 확장성이 정말 중요합니다. 실시간 데이터 처리와 AI 응답 속도를 최적화하려면, 데이터 흐름을 최대한 자동화하고 병목을 줄여야 하거든요.

우리는 Vercel AI SDK를 활용해 서버리스 환경에서 데이터 파이프라인을 구축했습니다. 예를 들어, 데이터가 들어오면 자동으로 전처리하고, AI 모델에 전달하는 과정을 이벤트 기반으로 처리해서 지연 시간을 30% 이상 줄였어요.

이런 접근법은 Vercel AI SDK Documentation에서 소개하는 확장성 좋은 아키텍처 설계와도 일치합니다[Vercel AI SDK Documentation](https://sdk.vercel.ai/docs/introduction).

## Claude Code에서 배우는 데이터와 명령어 분리 아키텍처

Anthropic의 Claude Code 모델은 데이터 구조를 계층화하고, 명령어와 데이터 조작을 분리하는 아키텍처를 추천합니다. 이게 왜 중요하냐면, 명령어가 데이터 구조에 섞여 있으면 AI가 혼란스러워서 작업 효율이 떨어지거든요.

우리도 이 방식을 참고해, 명령어는 별도의 JSON 필드에 넣고, 데이터는 또 다른 필드에 두는 구조로 바꿨습니다. 이렇게 하니 AI가 명령어를 빠르게 파악하고, 데이터 조작도 명확해져서 개발 속도가 빨라졌어요.

아래는 간단한 예시입니다.

```json
{
  "command": "updateUserEmail",
  "parameters": {
    "userId": "12345",
    "newEmail": "new.email@example.com"
  },
  "metadata": {
    "timestamp": "2024-06-10T14:30:00Z"
  }
}
```

이 구조는 명령어(`command`)와 파라미터(`parameters`)를 분리해 AI가 명확히 이해할 수 있게 돕습니다. Anthropic 문서에서 이 패턴을 권장하는 이유가 바로 여기에 있습니다[Anthropic - Claude Code Overview](https://docs.anthropic.com/en/docs/claude-code/overview).

## 마치며: 데이터 준비가 AI 성공의 반이다

처음엔 데이터 준비가 별거 아닌 것 같지만, Agentic AI와 통합하려면 이 부분에 꽤 공을 들여야 합니다. 데이터 스키마를 명확히 하고, API 계약을 엄격히 하며, 프롬프트에 들어갈 데이터 우선순위를 고민하고, 마이그레이션 전략을 세우는 게 필수죠.

그리고 클라우드 환경에서 확장성과 자동화를 고려한 아키텍처 설계도 빼놓을 수 없습니다. 이런 과정을 거쳐야만 AI가 우리 의도를 정확히 이해하고, 기대하는 결과를 낼 수 있어요.

실제 프로젝트에서 겪은 시행착오가 많았지만, 덕분에 지금은 AI와 데이터가 훨씬 잘 맞물려 돌아갑니다. 여러분도 Agentic AI 도입 시 데이터 준비에 충분한 시간을 투자해 보세요. 분명히 그만한 가치가 있을 겁니다.
