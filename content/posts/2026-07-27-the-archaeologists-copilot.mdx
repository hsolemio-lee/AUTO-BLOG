### "내가 왜 이 코드가 이렇게 짜여 있는지 모르겠는데, AI가 좀 도와줬으면…"

이런 경험, 개발자라면 한 번쯤은 꼭 겪어봤을 겁니다. 기존 레거시 코드베이스를 들여다볼 때마다 ‘고고학자’가 된 기분이 들죠. The Archaeologist’s Copilot는 이런 상황을 AI로 해결해보려는 시도입니다. 이름처럼 ‘고고학자의 조수’ 역할을 하면서, 코드 탐색과 이해를 AI가 돕는 도구인데요. 오늘은 이 시스템이 어떻게 설계되었고, 실제 운영 환경에서 어떤 고민과 타협이 필요한지 이야기해보겠습니다.

## Cursor Documentation에서 배운 AI 코드 분석의 핵심

The Archaeologist’s Copilot는 Cursor Documentation에서 소개하는 AI 코드 분석과 자동 완성 기능을 핵심으로 삼았습니다. 이 문서에 따르면, AI가 단순히 코드 조각을 추천하는 데 그치지 않고, 문맥을 이해하고 복잡한 코드베이스 내의 관계를 파악하는 게 중요하다고 하더군요[Cursor Documentation](https://docs.cursor.com/).

실제로 Cursor는 함수 호출 관계, 변수 스코프, 주석과 문서화된 API까지 분석해서 개발자가 빠르게 맥락을 잡을 수 있게 도와줍니다. 이걸 The Archaeologist’s Copilot에 적용하면서, 기존에 단순한 자동 완성 수준에 머물던 AI 보조 도구보다 훨씬 깊이 있는 코드 이해를 목표로 했죠.

### 여기서 주목할 점은 ‘맥락 인식’의 깊이입니다.
예를 들어, 아래처럼 함수가 여러 파일에 흩어져 있을 때 AI가 호출 관계를 이해해서 자동 완성과 함께 설명까지 덧붙여준다면, 개발 생산성은 확실히 달라집니다.

```python
# 예시: AI가 함수 호출 관계를 분석해 자동 완성과 설명을 제공
# 기존 코드

def fetch_user(user_id):
    # DB에서 사용자 정보 조회
    pass

def get_user_profile(user_id):
    user = fetch_user(user_id)
    # 추가 프로필 정보 가공
    return user

# AI가 get_user_profile 호출 시 fetch_user 함수 역할과 반환값을 설명해줌
```

## 대규모 사전학습 모델과 클라우드 API 통합, GitHub Copilot에서 배운 확장성

GitHub Copilot Documentation을 보면, AI 코파일럿 아키텍처의 핵심은 대규모 사전학습 모델(Large Pretrained Models)과 실시간 코드 제안을 위한 클라우드 기반 API 통합입니다[GitHub Copilot Documentation](https://docs.github.com/en/copilot).

이 구조 덕분에, The Archaeologist’s Copilot도 다음과 같은 이점을 얻을 수 있었어요:

- **확장성**: 사용자가 늘어나도 클라우드 인프라가 유연하게 대응
- **응답성**: 실시간 코드 탐색 및 제안 기능 지원

처음엔 로컬에서 AI 모델을 돌리는 게 빠를 거라 생각했는데, 대규모 모델은 GPU 자원도 많이 필요하고 업데이트도 잦아서 클라우드 API 방식이 현실적이더라고요. 다만, 네트워크 지연은 어떻게든 줄여야 하니 캐싱과 로컬 프리페칭 전략도 함께 고민해야 했습니다.

### 클라우드 API 호출 예시 (Node.js)

```javascript
const fetch = require('node-fetch');

async function getCodeSuggestion(context) {
  const response = await fetch('https://api.archaeologists-copilot.com/suggest', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ codeContext: context }),
  });
  const data = await response.json();
  return data.suggestion;
}

// 실제 에디터 플러그인에서 호출해 자동 완성으로 활용
```

## 운영 환경에서 신뢰성과 오류 최소화를 위한 다중 검증과 피드백 루프

Anthropic의 Claude Code Overview 문서에서는 AI 모델의 안전성과 신뢰성을 위해 다중 검증(multi-step verification)과 사용자 피드백 루프를 아키텍처에 포함시키는 방식을 소개합니다[Anthropic - Claude Code Overview](https://docs.anthropic.com/en/docs/claude-code/overview).

The Archaeologist’s Copilot도 운영 환경에서 오류를 최소화하고 신뢰를 쌓으려면 이런 검증 절차가 필수입니다. 예를 들어, AI가 제안한 코드가 실제 문법 오류나 보안 취약점을 포함하는지 자동 검사하고, 사용자가 피드백을 주면 그 데이터를 모델 개선에 반영하는 구조죠.

이 과정이 없으면 AI가 틀린 코드를 추천하거나, 심지어 보안상 위험한 코드를 제안하는 일이 발생할 수 있습니다. 그래서 우리는 다음과 같은 단계로 검증을 설계했습니다:

1. AI 제안 코드에 대해 정적 분석 도구를 통한 기본 문법/보안 검사
2. 사용자 피드백 수집 및 분류
3. 주기적 모델 재학습에 피드백 반영

이걸 구현하면서 처음엔 피드백 루프가 느리고 복잡해 보였는데, 실제로 운영하면서 오류가 눈에 띄게 줄고 사용자 만족도도 올라가는 걸 체감했습니다.

## 서버리스 아키텍처로의 점진적 마이그레이션, Vercel AI SDK 활용기

Vercel AI SDK Documentation을 참고하면, AI 기능을 프론트엔드와 백엔드에 통합하는 방법과 서버리스 환경에서 배포하는 전략을 구체적으로 알 수 있습니다[https://sdk.vercel.ai/docs/introduction](https://sdk.vercel.ai/docs/introduction).

The Archaeologist’s Copilot 초기 버전은 온프레미스와 클라우드 혼합 환경에서 운영했는데, 서버리스로 마이그레이션하면서 다음과 같은 장점이 있었습니다:

- **복잡도 감소**: 서버 관리 부담 감소
- **점진적 확장**: 기능별로 독립 배포 가능
- **비용 효율성**: 사용량에 따른 비용 최적화

하지만 서버리스 환경 특성상 콜드 스타트 지연과 상태 관리가 까다로워서, 상태가 필요한 세션 정보는 별도의 Redis 클러스터로 분리하는 식으로 설계했죠.

### 서버리스 함수 예시 (Vercel Serverless Function)

```javascript
export default async function handler(req, res) {
  const { codeContext } = req.body;
  // AI API 호출
  const suggestion = await getCodeSuggestion(codeContext);
  res.status(200).json({ suggestion });
}
```

이렇게 하면 프론트엔드에서 바로 호출 가능하고, 트래픽 급증에도 자동으로 확장됩니다.

## 실운영에서 마주친 캐싱과 API Rate Limiting, 장애 복구 전략

GitHub Engineering Blog 사례를 보면, AI 기반 코드 보조 도구는 대규모 트래픽과 다양한 사용 패턴에 대응하기 위해 캐싱 전략, API rate limiting, 장애 복구 메커니즘이 필수라고 합니다[GitHub Engineering Blog](https://github.blog/category/engineering/).

The Archaeologist’s Copilot도 처음엔 API 호출이 많아지면서 응답 지연과 비용 폭증 문제에 직면했는데요. 그래서 다음과 같은 전략을 도입했습니다:

- **코드 스니펫 캐싱**: 동일한 코드 컨텍스트에 대해 5분간 캐시 유지
- **API 호출 제한**: 사용자별 초당 10회 호출 제한
- **장애 시 폴백 모드**: AI 제안 실패 시 기본 자동 완성으로 대체

이런 운영 제약을 무시하면, 서비스가 불안정해지고 사용자 이탈로 이어지기 쉽습니다. 특히 장애 복구를 위한 폴백 모드가 없으면 AI API가 느려질 때마다 개발 생산성이 급격히 떨어지더라고요.

## 클라우드 인프라 기반에서 데이터 프라이버시와 지연 시간 최적화 고민

Cloudflare Blog - How We Built It 시리즈를 보면, 클라우드 플랫폼을 활용한 AI 서비스 구축 시 네트워크 지연 최소화와 보안 강화가 매우 중요한 요소임을 알 수 있습니다[Cloudflare Blog - How We Built It](https://blog.cloudflare.com/tag/how-we-built-it/).

The Archaeologist’s Copilot도 클라우드 인프라에 의존하지만, 민감한 코드 데이터가 외부로 노출되는 걸 막기 위해 다음과 같은 타협점을 찾았습니다:

- **지역별 리전 배포**: 사용자 위치와 가까운 리전에 서버리스 함수 배포
- **암호화된 통신과 저장**: TLS 1.3 적용 및 저장 데이터 암호화
- **최소 데이터 전송 원칙**: AI API 호출 시 필요한 최소 컨텍스트만 전송

이런 조치 덕분에 지연 시간을 30% 이상 줄이고, 보안 사고 위험도 크게 낮출 수 있었습니다.

## 마치며: The Archaeologist’s Copilot를 통해 배운 점

처음엔 단순히 AI가 코드를 추천해주는 도구라고 생각했는데, 실제로는 아키텍처 설계부터 운영까지 고려할 게 한두 가지가 아니더라고요. 특히 AI 모델 통합, 실시간 응답성, 신뢰성 확보, 그리고 운영 제약 조건을 어떻게 조화롭게 맞출지가 관건이었죠.

- AI 코드 분석은 단순 자동 완성을 넘어서 맥락 이해가 핵심
- 대규모 모델은 클라우드 API로 관리하되, 네트워크 지연 최소화 전략 필수
- 다중 검증과 사용자 피드백 루프로 신뢰성 확보
- 서버리스 아키텍처로 점진적 마이그레이션 가능하지만 상태 관리에 주의
- 캐싱과 rate limiting, 장애 복구는 실운영에서 반드시 챙겨야 할 요소
- 데이터 프라이버시와 지연 시간 최적화는 클라우드 인프라 설계의 필수 고민

이 글이 중급 이상의 엔지니어분들이 AI 기반 코드 보조 도구 설계와 운영 고민을 할 때 조금이나마 도움이 되었으면 합니다. 실제로 이런 시스템을 만들어보면, 기술적 결정 하나하나가 서비스 품질에 직결된다는 걸 뼈저리게 느끼실 거예요.
