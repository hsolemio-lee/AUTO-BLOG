## AI 모델을 우리 서비스에 어떻게 붙이지? 고민부터 시작

최근에 우리 팀에서 AI 기능을 백엔드에 붙여야 하는데, OpenAI랑 Anthropic API가 워낙 잘 나오다 보니 "도대체 어떻게 시작해야 할까?"라는 질문이 많았어요. 특히 Spring Boot 3부터 AI 통합 지원이 강화됐다고 해서, 이걸 실제 서비스에 적용하려면 어떤 점을 주의해야 할지 궁금했죠.

처음엔 그냥 REST API 호출하는 거라 간단할 줄 알았는데, 막상 해보니 비동기 처리, 보안, 성능 튜닝까지 고려할 게 한두 가지가 아니더라고요. 이번 글에서는 제가 직접 써보고 겪은 경험을 바탕으로, 최신 OpenAI와 Anthropic Claude 모델을 Spring 백엔드에 잘 붙이는 법을 풀어봅니다.


## Spring Boot 3 이상에서 AI API 연동이 쉬워진 이유

Spring Boot 3.0부터는 OpenAI와 Anthropic API를 쉽게 통합할 수 있도록 AI 지원 기능이 공식적으로 확장됐어요. 예를 들어, AI 모델 호출용 클라이언트 라이브러리도 제공하고, DI(의존성 주입)로 관리할 수 있게 설계되어 있죠. 덕분에 기존 REST 호출 코드를 직접 짜는 것보다 훨씬 깔끔하고 유지보수하기 편해졌어요.

이 기능 덕분에 개발자는 AI 모델 호출 로직을 별도의 서비스로 분리하고, 필요할 때만 주입해서 쓸 수 있습니다. 덕분에 테스트도 쉽고, 트랜잭션이나 예외처리도 Spring AOP로 일괄 관리할 수 있죠. 실제로 우리 팀에서는 AI 호출 부분을 `@Service` 빈으로 만들어서, 호출 실패 시 재시도 로직과 로깅을 AOP로 처리하고 있어요.


## WebClient로 OpenAI API 비동기 호출하기

OpenAI API는 RESTful 인터페이스를 제공하는데, Spring WebClient를 사용해서 비동기 방식으로 호출하는 게 요즘 트렌드입니다. WebClient는 넌블로킹 방식이라, AI API 호출이 느려도 우리 서비스의 다른 요청 처리에 영향을 덜 주거든요.

우리 서비스에서는 아래처럼 WebClient를 빈으로 등록하고, OpenAI 호출용 서비스에서 재사용하고 있어요:

```java
@Configuration
public class OpenAIConfig {
    @Bean
    public WebClient openAIWebClient(@Value("${openai.api.base-url}") String baseUrl,
                                     @Value("${openai.api.key}") String apiKey) {
        return WebClient.builder()
                .baseUrl(baseUrl)
                .defaultHeader(HttpHeaders.AUTHORIZATION, "Bearer " + apiKey)
                .build();
    }
}

@Service
public class OpenAIService {
    private final WebClient webClient;

    public OpenAIService(WebClient openAIWebClient) {
        this.webClient = openAIWebClient;
    }

    public Mono<String> getChatCompletion(String prompt) {
        return webClient.post()
                .uri("/v1/chat/completions")
                .bodyValue(Map.of(
                        "model", "gpt-4",
                        "messages", List.of(Map.of("role", "user", "content", prompt))
                ))
                .retrieve()
                .bodyToMono(JsonNode.class)
                .map(response -> response.path("choices").get(0).path("message").path("content").asText());
    }
}
```

이렇게 하면 호출 결과를 `Mono<String>`으로 받아서, 필요할 때 구독(subscribe)하거나, 다른 비동기 흐름과 결합할 수 있어요. 특히 AI 호출이 느릴 때도 스레드가 블로킹되지 않아서 서버 자원 효율이 크게 올라갑니다.


## Anthropic Claude API, 프롬프트 설계와 보안 고려사항

Anthropic Claude 모델은 OpenAI와 달리 프롬프트 엔지니어링 가이드가 꽤 상세하게 나와 있어요. 입력값을 잘 설계해야 AI가 안전하고 예측 가능한 답변을 줍니다. 예를 들어, 부적절한 응답을 걸러내는 필터링 역할을 프롬프트에 넣거나, 의도한 맥락을 명확히 전달하는 식이죠.

우리 팀도 Anthropic API를 도입하면서, 프롬프트 템플릿을 별도 관리하고, 입력값 검증 로직을 강화했어요. 그래야 악의적이거나 오류가 섞인 요청으로부터 서비스가 흔들리지 않거든요.

보안 측면에서는 API 키 관리가 가장 중요합니다. Spring Boot 환경설정에서 키를 직접 코드에 두지 말고, Vault 같은 비밀관리 시스템을 통해 주입하는 걸 권장합니다. 그리고 요청 제한(rate limiting)과 로깅, 모니터링 체계도 반드시 갖춰야 해요. Spring Security와 연동하면 인증·인가 처리도 자연스럽게 할 수 있고, 무단 접근 위험을 크게 줄일 수 있습니다.


## 프로덕션에서 AI 호출 성능 최적화, 우리 팀이 적용한 팁

AI API 호출은 비용과 응답 속도 모두 중요합니다. 우리 서비스는 하루 평균 10만 건 이상의 AI 요청이 오는데, 여기서 튜닝을 안 하면 비용 폭탄 맞기 딱 좋아요.

우선 스레드 풀 크기를 적절히 조절했어요. 기본값으로 두면 WebClient가 감당 못하는 경우가 많더라고요. 예를 들어, `spring.task.execution.pool.core-size=50` 정도로 맞추고, 최대 스레드 수도 100까지 늘렸죠.

또 HTTP 연결 재사용도 필수입니다. WebClient 기본 설정에 커넥션 풀을 활성화해서, 매번 TCP 연결을 새로 안 하도록 했어요. 이걸 안 하면 매 요청마다 핸드셰이크 비용이 커서 지연이 늘어납니다.

그리고 AI 응답 결과 중 자주 쓰이는 부분은 Redis 캐시로 저장해 재호출을 줄였어요. 캐시 TTL은 5분 정도로 짧게 두고, 최신성을 유지하면서도 비용을 절감하는 선에서 타협했습니다.

이런 최적화 덕분에 평균 응답 지연이 300ms 이하로 떨어졌고, 월간 API 비용도 20% 이상 절감하는 효과를 봤습니다.


## Spring DI와 AOP로 AI 호출 로직을 깔끔하게 관리하는 법

AI API 호출 코드는 예외 처리, 로깅, 트랜잭션 관리가 복잡해질 수밖에 없어요. 그래서 우리 팀은 Spring DI로 AI 서비스 빈을 분리하고, AOP로 공통 관심사를 처리합니다.

예를 들어, 호출 실패 시 3회 재시도하는 로직을 AOP Advice로 만들고, 호출 전후로 요청 로그와 응답 시간을 기록하는 것도 AOP로 처리하죠. 이렇게 하면 AI 호출 서비스 코드는 핵심 비즈니스 로직에 집중할 수 있어서 유지보수가 훨씬 쉬워집니다.

```java
@Aspect
@Component
public class AIServiceAspect {

    @Around("execution(* com.example.ai.OpenAIService.*(..))")
    public Object aroundAIService(ProceedingJoinPoint pjp) throws Throwable {
        int maxRetries = 3;
        int attempt = 0;
        Throwable lastException = null;

        while (attempt < maxRetries) {
            try {
                long start = System.currentTimeMillis();
                Object result = pjp.proceed();
                long duration = System.currentTimeMillis() - start;
                System.out.println("AI 호출 성공, 소요 시간: " + duration + "ms");
                return result;
            } catch (Throwable t) {
                lastException = t;
                attempt++;
                System.out.println("AI 호출 실패, 재시도 " + attempt + "회");
            }
        }
        throw lastException;
    }
}
```

이런 구조가 처음엔 복잡해 보이지만, 실제로 운영하면서 장애 대응이 훨씬 수월해지는 걸 느꼈어요.


## 마무리하며: AI 통합, "그냥 붙이기"는 이제 그만

AI API를 백엔드에 붙이는 건 단순히 HTTP 호출 몇 줄로 끝나지 않아요. 특히 OpenAI와 Anthropic 같은 최신 모델을 쓸 때는, Spring Boot 3의 AI 지원 기능을 적극 활용해서 안정성, 성능, 보안을 모두 챙겨야 합니다.

우리 팀 경험으로는,

- WebClient 비동기 호출로 서버 자원 효율 극대화
- DI와 AOP로 호출 로직 모듈화 및 예외 일관 처리
- 프롬프트 설계와 입력 검증으로 AI 응답 신뢰성 확보
- API 키 관리, 요청 제한, 로깅으로 보안 강화
- 스레드 풀 조절과 커넥션 재사용, 캐싱으로 비용과 지연 최소화

이 다섯 가지가 프로덕션 환경에서 AI를 잘 쓰는 핵심 포인트였습니다.

물론, AI 모델 자체가 계속 업데이트되고, API 스펙도 변할 테니 꾸준히 문서와 사례를 모니터링하는 것도 잊지 마세요. 이번 S5E18 팟캐스트에서 나온 최신 소식과 팁들이 큰 도움이 될 거예요.
