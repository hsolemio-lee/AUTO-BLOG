## "이 출력, 워터마크가 있을까?" 실제로 구분할 수 있을까?

최근 AI 챗봇을 서비스하면서, "내가 받은 텍스트가 워터마크된 건지 아닌지 어떻게 알 수 있을까?"라는 질문을 자주 받습니다. 워터마킹은 AI 출력의 출처를 추적하거나 무단 복제를 막기 위한 중요한 수단인데, 백엔드 엔지니어 입장에선 이걸 감지하고 적절히 처리하는 게 꽤 까다로운 문제입니다.

실제로 OpenAI API 문서에도 워터마킹 탐지를 위한 공식 엔드포인트나 기능은 없어요. 대신 출력 텍스트 패턴을 분석하거나 후처리 알고리즘을 직접 구현하는 방식이 주로 쓰입니다[OpenAI API Documentation](https://platform.openai.com/docs/overview).

이번 글에서는 워터마킹된 LLM 출력물을 백엔드에서 실무적으로 어떻게 감지하고, 처리할 수 있는지 제가 직접 겪은 경험과 참고할 만한 자료를 토대로 정리해봤습니다.

---

## 워터마킹된 LLM 출력, 왜 탐지가 어려운가?

워터마킹은 보통 사람이 눈치채기 어려운 미묘한 텍스트 패턴이나 통계적 특징으로 삽입됩니다. 예를 들어, 특정 단어의 선택 빈도나 문장 구조, 심지어 문장 간 연결성에서 미묘한 차이를 둡니다. 

하지만 이런 패턴은 외부에서 보면 거의 노이즈 수준이라, 단순히 "이 단어가 들어있으면 워터마크"라고 단정하기 어렵죠. 게다가 OpenAI 같은 대형 모델 제공사는 워터마킹 탐지 전용 API를 공개하지 않으니, 백엔드에서 직접 탐지 로직을 만들어야 합니다.

Anthropic의 프롬프트 엔지니어링 가이드를 보면, 워터마킹을 직접 다루진 않지만 출력 통제와 검증을 위한 프롬프트 설계가 중요하다고 합니다. 이는 간접적으로 워터마킹 탐지에 활용할 수 있는 아이디어를 제공합니다[Anthropic - Prompt Engineering Guide](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/overview).

즉, 워터마킹 탐지는 '출력 텍스트의 패턴'과 '통계적 특성'을 찾아내는 문제라고 보면 됩니다.

## 백엔드에서 워터마킹된 출력 탐지, 어떻게 시작할까?

저는 보통 다음 3단계 접근법을 추천합니다.

1. **패턴 매칭**: 워터마크 삽입에 사용된 고유 단어나 문장 패턴을 정규표현식이나 키워드 검색으로 탐지합니다.
2. **통계적 분석**: 텍스트 내 단어 분포, 문장 길이, 특정 문법 구조 빈도 등 통계치를 계산해 평소 출력과 차이를 비교합니다.
3. **커스텀 후처리 모듈**: 머신러닝 기반 분류기를 만들어 워터마크 유무를 예측하도록 학습시키는 방법입니다.

예를 들어, 아래는 Python으로 간단한 키워드 기반 워터마크 탐지 코드입니다. 실제로는 훨씬 복잡한 후처리 로직과 통계 분석을 결합해서 사용합니다.

```python
# 워터마크 의심 단어 리스트
watermark_keywords = ['[WM]', '<wm>', 'Ⓦ']

def is_watermarked(text: str) -> bool:
    for keyword in watermark_keywords:
        if keyword in text:
            return True
    return False

# 테스트
sample_output = "이 텍스트는 예시입니다. [WM]"
print(is_watermarked(sample_output))  # True
```

이 코드는 워터마크가 명시적으로 포함된 경우에만 탐지 가능하지만, 실제 서비스에선 통계적 특성 분석과 결합해 탐지 정확도를 높여야 합니다.

## 대규모 시스템에서 워터마크 탐지, 무조건 자동화가 답일까?

Cloudflare 기술 블로그를 보면, 대규모 분산 시스템에서는 출력 데이터에 메타데이터를 삽입하거나 내부 툴로 워터마킹된 콘텐츠를 탐지하는 사례가 많습니다[Cloudflare Blog - How We Built It](https://blog.cloudflare.com/tag/how-we-built-it/). 

하지만 자동화만으로 완벽한 탐지는 어렵고, 탐지 실패 시 후속 조치 방안도 마련해야 합니다. 예를 들어, 워터마크가 의심되는 출력에 대해 로그를 남기고, 관리자에게 알림을 보내거나, 사용자에게 재생성을 요청하는 정책을 둘 수 있죠.

또한, 워터마크 탐지 로직이 너무 엄격하면 정상 출력까지 차단하는 False Positive 문제가 발생할 수 있으니, 탐지 민감도를 조절하는 것도 중요합니다.

## 워터마크 탐지 후, 백엔드에서 어떻게 처리해야 할까?

워터마킹이 확인되면 어떤 정책을 적용할지 미리 정해두는 게 좋습니다. 예를 들어:

- **출력 로그 기록 및 감사**: 워터마크가 있는 출력은 별도 DB에 저장해 추후 감사 및 분석에 활용
- **사용자 알림**: 워터마크 포함 여부를 API 응답에 메타데이터로 추가해 클라이언트에 알림
- **출력 재생성 요청**: 워터마크가 포함된 출력은 재생성하거나 다른 모델에 재요청

아래는 Node.js Express 백엔드에서 워터마크 탐지 후 메타데이터를 붙여 응답하는 예시입니다.

```javascript
const express = require('express');
const app = express();

const watermarkKeywords = ['[WM]', '<wm>', 'Ⓦ'];

function isWatermarked(text) {
  return watermarkKeywords.some(keyword => text.includes(keyword));
}

app.post('/generate', express.json(), (req, res) => {
  const generatedText = req.body.generatedText; // 실제론 LLM API 호출 결과
  const watermarked = isWatermarked(generatedText);

  res.json({
    text: generatedText,
    metadata: { watermarked }
  });
});

app.listen(3000, () => console.log('Server running on port 3000'));
```

이렇게 하면 프론트엔드나 다른 서비스가 워터마크 여부를 쉽게 확인하고, 필요하면 별도의 정책을 적용할 수 있습니다.

## 워터마킹 탐지, 앞으로 어떻게 발전할까?

현재는 워터마크 탐지가 주로 후처리 알고리즘과 통계적 분석에 의존하지만, 앞으로는 AI 모델 자체에 워터마크 탐지 기능이 내장되거나, API 차원에서 공식 지원하는 기능이 나오지 않을까 기대합니다. 

하지만 당분간은 백엔드에서 직접 탐지 로직을 구현하고, 탐지 실패에 대비한 정책을 마련하는 게 현실적인 대응책입니다.

그리고 워터마킹은 보안과 무결성 유지에 중요한 역할을 하므로, 백엔드 엔지니어가 워터마킹 탐지 원리와 처리법을 이해하는 게 필수입니다.

### 개인적인 경험 한마디

처음엔 워터마킹 탐지 로직이 별거 아닌 것 같았는데, 실제 서비스에 적용해보니 탐지 실패와 오탐 문제 때문에 꽤 골치 아팠습니다. 특히 워터마크 패턴이 계속 바뀌거나, 모델 출력 스타일이 달라지면 탐지 로직도 계속 손봐야 하더라고요. 그래서 자동화와 수동 모니터링을 적절히 섞는 게 중요하다는 교훈을 얻었습니다.
