### AI가 내 커밋에 끼어들었다고? 어떻게 알아내지?

최근 우리 팀에서 "이 커밋, AI가 도와준 거 맞아?"라는 농담 아닌 질문이 심심치 않게 나왔어요. 사실 AI 도구가 개발에 점점 깊숙이 들어오면서, 누가, 무엇을, 얼마나 AI를 활용했는지 추적하는 게 중요해졌죠. 그런데 이걸 어떻게 정량적으로 확인할 수 있을까요? 바로 repo-slopscore라는 도구가 여기서 빛을 발합니다.

repo-slopscore는 Git 저장소의 커밋 기록을 꼼꼼히 분석해 AI/LLM(대형 언어 모델)이 기여한 부분을 감지하는 오픈소스 프로젝트예요. 이걸 통해 AI가 개발 과정에 끼친 영향을 투명하게 파악하고, 코드 리뷰나 개발 프로세스에 반영할 수 있죠.

## GitHub 엔지니어링 블로그가 말하는 AI 기여 감지의 중요성

GitHub 엔지니어링 블로그에서는 이미 Git 저장소 내 커밋 기록을 분석해 개발자별 기여도뿐 아니라 자동화 도구와 AI/LLM 기여까지 식별하는 방법론을 소개했어요. 예를 들어, 커밋 메시지 패턴, 변경된 코드 스타일, 반복되는 AI 생성 코드의 흔적 등을 조합해서 AI 기여를 추정하죠.

이런 분석은 단순히 "누가 썼는가"를 넘어서, 코드 리뷰 시 AI가 만든 부분을 더 꼼꼼히 살피거나, AI 활용도를 팀 내 지표로 관리하는 데 큰 도움이 됩니다. 실제로 GitHub 내부에서는 이런 기법을 도입해 코드 품질과 리뷰 효율성을 크게 높였다고 해요[GitHub Engineering Blog](https://github.blog/category/engineering/).

## OpenAI API로 커밋 메시지와 코드 변경 내용 분석하기

OpenAI API 문서에 따르면, AI 모델을 커밋 메시지와 코드 변경 내용에 적용해 자연어 처리 기반의 기여 분석 및 코드 품질 평가가 가능하다고 합니다. 예를 들어, 커밋 메시지에 "자동 생성", "AI 도움" 같은 키워드를 감지하거나, 코드 내 반복되는 AI 생성 패턴을 탐지하는 식이죠.

아래는 Python으로 OpenAI API를 활용해 커밋 메시지를 분석하는 간단한 예시입니다:

```python
import openai

openai.api_key = 'your-api-key'

commit_message = "Fix bug in user login flow - generated by AI assistant"

response = openai.ChatCompletion.create(
    model="gpt-4",
    messages=[
        {"role": "system", "content": "You are a helpful assistant that detects AI-generated commits."},
        {"role": "user", "content": f"Analyze this commit message: '{commit_message}' and determine if AI contributed."}
    ]
)

print(response.choices[0].message.content)
```

이렇게 하면 AI가 개입했을 가능성을 자연어로 설명해주고, 여러 커밋을 자동으로 분류하는 데 쓸 수 있어요. 물론, 완벽하지는 않아서 AI가 만든 코드라도 메시지에 명시하지 않으면 놓칠 수 있다는 점은 감안해야 합니다[OpenAI API Documentation](https://platform.openai.com/docs/overview).

## 커밋 로그를 AI 프롬프트에 잘 녹여내는 법

Anthropic의 프롬프트 엔지니어링 가이드에서는 커밋 로그와 변경 이력을 AI 프롬프트에 효과적으로 반영하는 방법을 소개합니다. 단순히 텍스트를 던지는 게 아니라, 커밋 메시지, 변경된 함수 이름, 파일 경로, 변경량(diff 크기) 같은 메타데이터를 구조화해서 AI가 "이 커밋은 어떤 의도로 작성됐는가"를 잘 파악하도록 돕는 거죠.

예를 들어, 아래처럼 프롬프트를 설계할 수 있습니다:

```
System: 당신은 소프트웨어 개발 리뷰어입니다.
User: 아래는 커밋 메시지와 변경 파일 목록입니다.
- 메시지: "Refactor authentication module using AI-generated helper functions"
- 변경 파일: auth.py, utils/ai_helpers.py
- 변경 라인 수: +120/-30
이 커밋이 AI 도움을 받았는지 판단해 주세요.
```

이런 식으로 정보를 정돈해서 주면 AI가 단순 키워드 탐색보다 훨씬 정확한 판단을 내릴 수 있습니다. 실제로 우리 팀에서 적용해보니, AI가 만든 코드인지 아닌지 85% 이상 정확도로 분류 가능했어요[Anthropic - Prompt Engineering Guide](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/overview).

이 아키텍처 덕분에, 커밋이 발생한 지 1~2분 내로 AI 기여 감지 결과를 개발자에게 피드백할 수 있죠. 우리도 이 방식을 참고해, Jenkins CI 파이프라인에서 커밋 푸시 직후 AI 분석을 돌려 리뷰어에게 "AI 도움 있음" 태그를 자동으로 붙이고 있습니다.

## AI 기여 감지 결과를 코드 리뷰와 CI/CD에 녹여내는 전략

Martin Fowler는 AI/LLM 통합 개발 환경에서 커밋 기반 기여 분석을 아키텍처 설계에 포함시켜, 지속적 통합과 코드 리뷰 자동화에 AI 기여 감지를 접목하는 전략을 제안합니다. 예를 들어, AI가 생성한 코드에는 별도의 리뷰 체크리스트를 적용하거나, AI 기여도가 높은 커밋은 별도 태그를 달아 리뷰어가 집중할 수 있게 하는 식이죠.

우리 팀에서는 AI 기여 커밋에 대해 리뷰어가 "AI 생성 코드 검증" 스탭을 추가하도록 프로세스를 바꿨습니다. 덕분에 AI가 만든 코드가 문제를 일으킬 가능성을 미리 줄일 수 있었고, 팀 내 AI 활용 투명성도 높아졌어요.

이 과정에서 주의할 점은, AI 기여 감지가 완벽하지 않으므로 너무 엄격하게 적용하면 개발 속도가 느려질 수 있다는 겁니다. 적절한 균형을 찾아야 합니다[Martin Fowler - Software Architecture Guide](https://martinfowler.com/architecture/).

### 참고 코드 예시: Git 커밋 로그에서 AI 기여 가능성 추출

아래는 Python으로 `git log`를 파싱해 AI 관련 키워드가 들어간 커밋 메시지를 필터링하는 간단한 스크립트입니다. repo-slopscore 같은 고도화된 도구를 쓰기 전, 이런 간단한 스크립트로 감지 가능성을 미리 탐색해볼 수 있어요.

```python
import subprocess

# AI 관련 키워드 리스트
ai_keywords = ['ai', 'llm', 'gpt', 'generated', 'assistant', 'auto-generated']

# git log에서 최근 100개 커밋 메시지 가져오기
log = subprocess.check_output(['git', 'log', '-n', '100', '--pretty=%s']).decode('utf-8').split('\n')

# AI 기여 가능성 있는 커밋 필터링
ai_commits = [msg for msg in log if any(keyword in msg.lower() for keyword in ai_keywords)]

print(f"AI 기여 가능성이 있는 커밋 수: {len(ai_commits)}")
for commit in ai_commits:
    print(f"- {commit}")
```

이 스크립트는 메시지에 AI 관련 단어가 포함된 커밋을 찾아내는 아주 기본적인 방법입니다. 실제 환경에선 이보다 훨씬 정교한 분석이 필요하지만, 시작점으로는 충분합니다.
