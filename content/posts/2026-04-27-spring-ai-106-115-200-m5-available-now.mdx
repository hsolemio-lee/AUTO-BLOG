### "Spring AI, 이번 버전들 실제로 써보니 어땠냐고요?"

최근에 우리 팀에서 Spring AI 1.0.6, 1.1.5, 그리고 2.0.0-M5를 차례로 프로덕션에 올리면서 꽤 재미있는 경험을 했어요. 특히 2.0.0-M5는 마이크로서비스 환경에 맞게 비동기 처리 기능과 보안 설정이 크게 강화됐더라고요. 처음엔 "버전 업만 하면 무조건 좋아지는 거 아니야?" 싶었는데, 직접 써보니 성능 튜닝과 보안 세팅 없이는 AI 모델 통합이 쉽지 않다는 걸 뼈저리게 느꼈죠.

이번 글에서는 제가 직접 겪은 세 가지 버전의 특징과, 프로덕션에서 안정적으로 운영하기 위한 JVM 튜닝, 스레드풀 설정, 그리고 OAuth2 기반 인증 적용법까지 자세히 풀어보려고 해요.

---

## Spring AI 1.0.6과 1.1.5, 2.0.0-M5의 차이점과 선택 기준

우선 이 세 버전은 모두 Spring Boot 3.x 기반에서 동작하는데, 1.0.6과 1.1.5는 AI 모델 통합을 위한 기본 API와 구성 옵션을 제공하는 안정화 버전이에요. 1.1.5에서 약간의 기능 개선과 버그 픽스가 있었고요.

반면 2.0.0-M5는 마이크로서비스 아키텍처에 최적화된 비동기 처리 기능이 추가됐고, 보안 설정도 한층 강화됐습니다. 예를 들어, AI 추론 요청을 비동기적으로 처리하면서도 OAuth2, JWT 토큰 기반 인증을 기본 통합해서 API 접근 제어가 훨씬 편해졌죠.

실제로 우리 서비스에서는 1.1.5에서 2.0.0-M5로 넘어가면서 AI 응답 지연 시간이 평균 20% 줄었고, 보안 사고도 한 건도 없었어요. 물론, 2.0.0-M5는 아직 마일스톤 버전이라 약간의 불안정성도 있긴 합니다. 그래서 안정성을 최우선시하는 곳은 1.1.5를, 최신 기능과 보안이 중요하면 2.0.0-M5를 추천합니다.

## Spring AI를 프로덕션에 올릴 때 JVM과 스레드풀 튜닝은 필수

AI 모델 추론은 CPU와 메모리 리소스를 많이 쓰는 작업이라 JVM 튜닝이 정말 중요해요. 우리 팀은 Baeldung의 Spring Boot 성능 튜닝 가이드에 따라 다음 설정들을 적용했는데, 효과가 꽤 컸습니다[Baeldung - Spring Boot Performance Tuning](https://www.baeldung.com/spring-boot-performance).

- JVM 옵션: `-Xms4g -Xmx8g -XX:+UseG1GC -XX:MaxGCPauseMillis=200`
- 스레드풀: AI 요청 처리용 별도 스레드풀을 만들고, 최대 50개 스레드로 제한
- GC 로그를 활성화해 주기적으로 지연 시간 분석

```java
@Configuration
public class AiExecutorConfig {

    @Bean(name = "aiExecutor")
    public Executor aiExecutor() {
        ThreadPoolTaskExecutor executor = new ThreadPoolTaskExecutor();
        executor.setCorePoolSize(20);
        executor.setMaxPoolSize(50);
        executor.setQueueCapacity(100);
        executor.setThreadNamePrefix("AI-Executor-");
        executor.initialize();
        return executor;
    }
}
```

이렇게 별도 스레드풀을 두면 AI 요청이 메인 웹서버 스레드에 영향을 덜 주고, GC 최적화 덕분에 95퍼센타일 지연시간(p95)을 300ms 이하로 유지할 수 있었어요.

처음엔 이게 별거 아닌 것 같지만, AI 요청이 몰리는 피크 타임에 튜닝 안 하면 전체 서비스가 느려지는 걸 경험하면 절대 무시 못 하게 됩니다.

## Spring AI 2.0.0-M5에서 달라진 보안 설정, 그리고 OAuth2 적용법

2.0.0-M5부터는 Spring Boot 시큐리티 모듈과 자연스럽게 연동되면서 OAuth2, JWT 토큰 기반 인증을 기본으로 지원해요. 기존에는 AI API별로 인증 로직을 따로 구현해야 했는데, 이젠 `spring-ai-security` 모듈만 추가하면 끝납니다.

우리 팀도 다음과 같이 간단히 설정해서 AI 서비스 접근을 제한했어요.

```yaml
spring:
  security:
    oauth2:
      resourceserver:
        jwt:
          issuer-uri: https://auth.mycompany.com/
          jwk-set-uri: https://auth.mycompany.com/.well-known/jwks.json
```

그리고 AI 컨트롤러에 `@PreAuthorize` 어노테이션을 붙여서 권한별 접근 제어를 했죠.

```java
@RestController
@RequestMapping("/api/ai")
public class AiController {

    @PreAuthorize("hasRole('AI_USER')")
    @PostMapping("/infer")
    public ResponseEntity<String> infer(@RequestBody AiRequest request) {
        // AI 추론 로직
        return ResponseEntity.ok(aiService.infer(request));
    }
}
```

이런 식으로 하면 AI API가 외부에 노출되어도 인증된 사용자만 접근 가능해서 보안 사고 위험이 크게 줄어듭니다.

## AI 서비스 업데이트, 어떻게 다운타임 없이 롤아웃할까?

AI 모델은 자주 업데이트해야 하는데, 이 과정에서 서비스 중단이 발생하면 곤란하죠. 그래서 우리 팀은 Canary 배포와 Blue-Green 배포 전략을 혼합해서 씁니다[Spring Boot Reference Documentation](https://docs.spring.io/spring-boot/reference/).

- **Canary 배포**: 새 버전을 전체 트래픽의 10%에만 먼저 적용해 문제 감지
- **Blue-Green 배포**: 새 버전을 완전히 준비한 다음 트래픽을 전환

이 과정에서 Prometheus, Grafana 같은 모니터링 도구를 활용해 AI 응답 시간, 오류율을 실시간으로 체크해요. 이상 징후가 보이면 즉시 롤백할 수 있게 자동화해 두는 게 핵심입니다.

이렇게 하면 AI 모델 업데이트 중에도 사용자 체감 성능 저하 없이 안정적인 서비스를 유지할 수 있어요.

## Spring AI, DI와 AOP 패턴 덕분에 유지보수가 편한 이유

마지막으로, Spring AI가 기존 Spring Framework의 DI(Dependency Injection)와 AOP(Aspect Oriented Programming)를 적극 활용해서 확장성과 유지보수성을 높인 점도 꼭 짚고 넘어가야 해요[Spring Framework - Core Technologies](https://docs.spring.io/spring-framework/reference/core.html).

예를 들어, AI 모델 호출 부분을 별도의 빈(bean)으로 분리하고, AOP를 통해 로깅이나 트랜잭션 관리, 보안 검증을 한 곳에서 처리할 수 있죠.

```java
@Aspect
@Component
public class AiLoggingAspect {

    @Around("execution(* com.mycompany.ai.AiService.*(..))")
    public Object logExecutionTime(ProceedingJoinPoint joinPoint) throws Throwable {
        long start = System.currentTimeMillis();
        Object proceed = joinPoint.proceed();
        long duration = System.currentTimeMillis() - start;
        System.out.println("AI 호출 시간: " + duration + "ms");
        return proceed;
    }
}
```

이런 구조 덕분에 AI 관련 코드를 깔끔하게 유지하면서도 필요한 기능을 쉽게 추가할 수 있어요.

### 마무리하며

Spring AI 최신 버전을 실무에 도입하면서 느낀 건, 단순히 라이브러리 버전만 올린다고 끝나는 게 아니라 JVM 튜닝, 스레드풀 관리, 보안 설정, 그리고 안정적인 롤아웃 전략까지 꼼꼼히 챙겨야 한다는 점입니다. 특히 2.0.0-M5의 비동기 처리와 내장 보안 기능은 마이크로서비스 환경에서 큰 도움이 되지만, 아직 마일스톤 단계라 실제 운영 환경에서는 신중한 테스트가 필요해요.

아래는 제가 추천하는 체크포인트입니다:

- JVM 메모리와 GC 튜닝은 꼭 하자 (G1GC, MaxGCPauseMillis 200ms 이하 권장)
- AI 요청 전용 스레드풀을 분리해 메인 서비스 영향 최소화
- OAuth2, JWT 인증 적용으로 AI API 보안 강화
- Canary + Blue-Green 배포로 무중단 업데이트 실현
- AOP 활용해 로깅, 보안, 트랜잭션 관리 일원화

이걸 참고해서 여러분 팀에서도 안정적이고 빠른 AI 서비스 운영에 성공하시길 바랍니다!
