## "AI 기능 넣었는데 왜 이렇게 느리지?"

최근 우리 팀에서 Spring AI 2.0.0-M8 버전을 도입했는데, 처음에 AI 호출 지연 때문에 고생을 좀 했어요. "이거 AI 서비스가 원래 느린가?" 하면서 말이죠. 그런데 자세히 들여다보니 Spring Boot 3.x의 최신 성능 최적화 기능을 제대로 활용하지 못한 게 문제였더라고요. 이 글에서는 내가 직접 겪은 시행착오와 함께 Spring AI 2.0.0-M8을 백엔드에 잘 녹여내는 방법을 공유하려고 합니다.

---

## Spring AI 2.0.0-M8, 왜 최신 Spring Boot 3.x 기반이 중요한가

Spring AI 2.0.0-M8은 Spring Boot 3.x 위에서 돌아가도록 설계되었어요. 이게 왜 중요하냐면, Spring Boot 3.x가 제공하는 성능 최적화와 보안 강화 기능을 그대로 누릴 수 있기 때문입니다. 예를 들어, 최신 버전에서는 네이티브 이미지 지원, 리액티브 프로그래밍 개선, 그리고 강화된 보안 설정이 기본으로 제공되죠.

실제로 Spring Boot Reference Documentation에서 권장하는 JVM 튜닝과 메모리 관리, 그리고 HTTP/2 지원 같은 기능들이 Spring AI의 AI 서비스 호출에도 그대로 적용됩니다. 즉, AI API 호출이 많은 환경에서도 지연 시간을 줄이고 안정적인 운영이 가능해집니다[Spring Boot Reference Documentation](https://docs.spring.io/spring-boot/reference/).

## Spring Framework 코어 기술로 AI 기능을 백엔드에 자연스럽게 녹이는 법

Spring AI 2.0.0-M8은 Spring Framework의 핵심 기술들을 적극 활용합니다. 예를 들어, DI(Dependency Injection), AOP(Aspect-Oriented Programming), 그리고 이벤트 기반 비동기 처리 같은 것들이죠. 이 덕분에 AI 모델 호출 로직을 기존 서비스에 무리 없이 통합할 수 있었습니다.

우리 팀에서는 AI 요청을 서비스 레이어에서 직접 호출하는 대신, 별도의 AI 서비스 클래스를 만들어 관리했어요. 이렇게 하면 나중에 AI 모델이 바뀌거나 API가 변경되어도 서비스 레이어 코드를 크게 손대지 않아도 됩니다.

```java
@Service
public class AiService {

    private final OpenAIClient openAIClient;

    public AiService(OpenAIClient openAIClient) {
        this.openAIClient = openAIClient;
    }

    @Async
    public CompletableFuture<String> generateResponse(String prompt) {
        // OpenAI API 호출
        return CompletableFuture.supplyAsync(() -> openAIClient.chatCompletion(prompt));
    }
}
```

이 예시는 비동기 호출을 적용한 건데, Spring의 `@Async`와 `CompletableFuture`를 써서 호출 지연을 줄이는 동시에, 메인 쓰레드가 막히지 않도록 했죠. 이런 구조는 Spring Framework - Core Technologies 문서에서 권장하는 방식이기도 합니다[Spring Framework - Core Technologies](https://docs.spring.io/spring-framework/reference/core.html).

## AI 호출 성능 튜닝, "비동기 + 캐싱" 조합이 답이다

AI API 호출이 느린 건 대부분 네트워크 지연과 모델 응답 시간 때문인데, 백엔드에서 할 수 있는 최적화는 비동기 처리와 캐싱입니다. Baeldung의 Spring Boot Performance Tuning 가이드에서도 이 두 가지를 적극 권장하고 있죠[Baeldung - Spring Boot Performance Tuning](https://www.baeldung.com/spring-boot-performance).

우리 팀은 AI 답변 중 자주 묻는 질문에 대해선 Redis 캐시를 걸었어요. 캐시 TTL(Time To Live)은 10분 정도로 설정했는데, 너무 짧으면 캐시 효과가 떨어지고 너무 길면 답변이 오래된 정보가 될 수 있으니 적절한 균형이 중요합니다.

```java
@Cacheable(value = "aiResponses", key = "#prompt", unless = "#result == null")
public String getCachedResponse(String prompt) {
    return openAIClient.chatCompletion(prompt);
}
```

이렇게 하면 동일한 프롬프트에 대해선 API 호출을 줄이고, 응답 속도를 크게 개선할 수 있었습니다. 물론 캐시가 모든 경우에 맞는 건 아니니, 실시간성이 중요한 요청은 캐시를 건너뛰도록 설계해야 해요.

## OpenAI API와 연동할 때 꼭 챙겨야 할 보안과 인증

Spring AI 2.0.0-M8은 OpenAI API 같은 외부 AI 플랫폼과 연동할 때, API 키 관리와 요청 제한 같은 보안 부분을 꼭 지켜야 합니다. OpenAI 공식 문서에서는 API 키를 환경 변수나 안전한 비밀 관리 시스템에 저장하고, 노출되지 않도록 권장하고 있어요[OpenAI API Documentation](https://platform.openai.com/docs/overview).

우리 팀은 Spring Boot의 `@ConfigurationProperties`를 활용해 API 키를 관리하고, Spring Security 필터를 통해 인증된 요청만 AI API 호출이 가능하도록 했습니다. 또한, API 호출 횟수 제한을 위해 Spring의 RateLimiter를 도입했는데, 이게 없으면 갑자기 트래픽이 몰렸을 때 API 비용 폭탄 맞기 십상입니다.

```yaml
# application.yml
openai:
  api-key: ${OPENAI_API_KEY}

spring:
  cloud:
    gateway:
      routes:
        - id: ai-route
          uri: https://api.openai.com
          predicates:
            - Path=/v1/chat/completions
          filters:
            - name: RequestRateLimiter
              args:
                redis-rate-limiter.replenishRate: 10
                redis-rate-limiter.burstCapacity: 20
```

이 설정은 초당 10건, 버스트는 20건까지 허용하는 예시입니다. 이런 정책을 꼭 넣어야 실서비스에서 안정적으로 AI API를 쓸 수 있어요.

## 프롬프트 엔지니어링, Anthropic 가이드라인을 참고하자

AI 모델의 답변 품질은 프롬프트 설계에 크게 좌우되는데, Anthropic에서 제공하는 프롬프트 엔지니어링 가이드라인이 꽤 도움이 됩니다[Anthropic - Prompt Engineering Guide](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/overview).

Spring AI 2.0.0-M8은 이런 가이드라인을 반영해 프롬프트를 모듈화하고, 재사용 가능한 구조로 설계할 수 있게 지원해요. 예를 들어, 기본 프롬프트 템플릿을 만들고, 상황에 따라 변수만 바꿔서 호출하는 식입니다.

```java
public String buildPrompt(String userQuestion) {
    String baseTemplate = "You are a helpful assistant. Answer concisely:";
    return baseTemplate + "\nQuestion: " + userQuestion;
}
```

이렇게 하면 프롬프트를 일관성 있게 관리할 수 있고, AI 응답의 정확도도 높아집니다.

## 점진적 롤아웃과 모니터링으로 AI 서비스 안정적으로 운영하기

AI 기능을 서비스에 도입할 때는 한꺼번에 전체 트래픽에 적용하기보다, 점진적으로 배포하는 게 안전합니다. GitHub Engineering Blog에서 소개하는 대규모 서비스 배포 전략과 비슷하게, Canary 배포나 Blue-Green 배포를 활용해요[GitHub Engineering Blog](https://github.blog/category/engineering/).

우리 팀도 처음에는 5% 사용자에게만 AI 기능을 오픈하고, 모니터링 도구로 응답 시간, 오류율, 비용 등을 집중 감시했어요. Prometheus와 Grafana를 활용해 AI 호출 메트릭을 실시간으로 시각화했고, 문제가 발견되면 즉시 롤백할 수 있도록 자동화했습니다.

이 과정에서 얻은 교훈은 "AI 기능이 좋아도 운영 환경에서 문제 없도록 꼼꼼히 준비해야 한다"는 점입니다. 특히 비용과 성능, 보안 세 가지를 동시에 챙기는 게 쉽지 않으니, 충분한 테스트와 모니터링이 필수죠.

## 마무리하며: Spring AI 2.0.0-M8, 백엔드에 AI를 제대로 붙이려면

처음엔 AI 기능을 넣는 게 단순히 API 호출 몇 줄 추가하는 것 같지만, 실제로는 성능, 보안, 운영까지 고려해야 할 게 한두 가지가 아닙니다. Spring AI 2.0.0-M8은 최신 Spring Boot 3.x 기반으로 만들어져서, 기존 Spring 생태계의 강력한 도구들을 그대로 활용할 수 있다는 점이 큰 장점이에요.

내가 직접 겪은 경험을 요약하면 다음과 같습니다:

- AI 호출은 비동기 처리와 캐싱으로 지연 시간을 줄여라
- API 키와 요청 제한 같은 보안 설정은 필수
- 프롬프트는 재사용 가능한 템플릿 구조로 만들어라
- 점진적 롤아웃과 실시간 모니터링으로 안정성을 확보하라

이 팁들만 잘 챙겨도 Spring AI 2.0.0-M8을 백엔드에 무리 없이, 그리고 효과적으로 통합할 수 있을 겁니다. 궁금한 점 있으면 언제든 커피 한잔 하면서 얘기해요!
