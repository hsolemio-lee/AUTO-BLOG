### "AI 기능, 그냥 붙이면 되는 줄 알았는데…"

최근 우리 팀에서 Spring AI 2.0.0-M8 버전을 도입하면서 겪은 일입니다. AI를 백엔드에 통합하는 게 생각보다 쉽지 않더라고요. 단순히 라이브러리만 추가한다고 끝나는 게 아니라, 보안부터 성능, 그리고 점진적 배포까지 신경 쓸 게 한두 가지가 아니었어요. 혹시 여러분도 Spring AI를 프로덕션에 붙이려는 중이라면, 저희 경험이 꽤 도움이 될 겁니다.

---

## Spring AI 2.0.0-M8, 뭘 새로 가져왔길래?

Spring Boot 2.0.0-M8는 AI 통합을 위한 전용 모듈과 API를 새로 포함했어요. 이전 버전까지는 AI 기능을 직접 구현하거나 외부 API를 래핑하는 데 꽤 손이 많이 갔는데, 이번 버전부터는 `spring-ai` 모듈 하나로 기본적인 AI 모델 호출부터 응답 처리까지 훨씬 수월해졌죠.

예를 들어, OpenAI나 Anthropic 같은 주요 AI 제공자와 바로 연결할 수 있는 클라이언트가 기본 제공됩니다. 덕분에 의존성 주입을 통해 AI 서비스를 깔끔하게 관리할 수 있죠. 

```java
@Service
public class AiService {

    private final OpenAIClient openAIClient;

    public AiService(OpenAIClient openAIClient) {
        this.openAIClient = openAIClient;
    }

    public String generateResponse(String prompt) {
        CompletionRequest request = CompletionRequest.builder()
            .model("gpt-4")
            .prompt(prompt)
            .maxTokens(150)
            .build();

        return openAIClient.createCompletion(request).getChoices().get(0).getText();
    }
}
```

이 코드는 Spring AI 2.0.0-M8에서 제공하는 OpenAI 클라이언트를 주입받아 간단히 텍스트 생성 요청을 보내는 예시입니다. 실제 프로덕션에서는 이보다 훨씬 복잡한 프롬프트 관리, 에러 핸들링, 비동기 처리 등이 추가되지만, 기본 틀은 이렇습니다.

## AI 서비스 보안, 토큰 관리부터 요청 제한까지

AI 모델과 통신할 때 가장 먼저 고민하는 게 인증과 보안이죠. OpenAI API 문서에서는 인증 토큰을 환경 변수나 안전한 비밀 저장소에 보관하고, 절대 코드에 하드코딩하지 말라고 권고합니다. 

우리 팀도 Spring `application.yml`에 직접 넣는 대신, AWS Secrets Manager를 통해 토큰을 가져오도록 했어요. 이렇게 하면 토큰 노출 위험을 줄일 수 있습니다.

또한, API 요청에 대한 rate limiting도 필수입니다. AI API는 호출량에 따라 비용이 크게 달라지기 때문에, 무분별한 호출을 막아야 하죠. Spring Boot에서는 `Bucket4j` 같은 라이브러리를 활용해 간단히 요청 제한을 걸 수 있습니다.

```java
@Bean
public FilterRegistrationBean<RateLimitFilter> rateLimitFilter() {
    FilterRegistrationBean<RateLimitFilter> registrationBean = new FilterRegistrationBean<>();
    registrationBean.setFilter(new RateLimitFilter(Bandwidth.simple(10, Duration.ofSeconds(1))));
    registrationBean.addUrlPatterns("/api/ai/*");
    return registrationBean;
}
```

위 예시는 초당 10회로 AI API 호출을 제한하는 필터를 등록하는 코드입니다. 이렇게 하면 갑작스러운 트래픽 폭증에도 안정적으로 대응할 수 있어요.

## JVM 튜닝과 캐싱으로 AI 호출 성능 올리기

Spring AI를 프로덕션에 붙일 때 성능 튜닝은 선택이 아니라 필수입니다. Baeldung 가이드에 따르면 JVM 힙 메모리 조절, GC 튜닝, 그리고 캐싱 전략이 핵심 포인트죠.

우리 서비스는 AI 응답을 매번 새로 받기보다는, 자주 묻는 질문 같은 경우에는 캐싱해서 API 호출 횟수를 줄였습니다. Spring Cache를 Redis와 연동해 TTL 10분으로 설정했는데, 이걸로 호출량이 30% 이상 줄었어요.

```java
@Cacheable(value = "aiResponses", key = "#prompt", unless = "#result == null")
public String cachedGenerateResponse(String prompt) {
    return generateResponse(prompt);
}
```

이렇게 캐시를 걸면, 같은 프롬프트에 대해 10분간은 API 호출 없이 캐시된 결과를 바로 반환합니다. 단, 캐시 TTL을 너무 길게 잡으면 최신 정보 반영이 늦을 수 있으니 서비스 특성에 맞게 조절해야 합니다.

또 JVM 튜닝은 GC pause 시간을 최소화하는 방향으로 설정했습니다. AI 호출이 지연되면 전체 API 응답 시간에 치명적이라, `-XX:+UseG1GC -Xms4g -Xmx4g` 같은 설정으로 안정적인 메모리 관리를 했죠.

## 프롬프트 엔지니어링, AI 반응 품질을 좌우한다

Anthropic의 프롬프트 엔지니어링 가이드를 참고하면, AI에게 명확하고 구체적인 요청을 하는 게 얼마나 중요한지 알 수 있어요. 우리 팀도 단순히 "이거 해줘" 식이 아니라, 상황 설명과 원하는 출력 형식을 명확히 적는 걸 기본 원칙으로 삼았습니다.

예를 들어, 고객 문의 자동응답 시스템에서는 이렇게 프롬프트를 구성했어요.

```java
String prompt = "너는 고객 지원 챗봇이야. 아래 문의에 대해 친절하고 간결하게 답변해줘. 문의: '" + userQuestion + "'";
```

이렇게 하면 AI가 더 일관성 있고 품질 높은 답변을 내놓더라고요. 프롬프트를 계속 실험하면서 최적화하는 과정이 꼭 필요합니다.

## Canary 배포로 AI 기능 점진 도입하기

AI 기능은 한 번에 전체 서비스에 적용하기보다는 점진적으로 롤아웃하는 게 안전합니다. GitHub 엔지니어링 블로그에서도 Canary 배포와 실시간 모니터링을 추천하는데, 우리도 이 방식을 썼어요.

처음에는 전체 트래픽의 5%에만 AI 기능을 활성화하고, 오류율과 응답 시간을 집중 모니터링했습니다. 문제가 없으면 점차 20%, 50%로 늘려가죠.

Spring Boot Actuator와 Prometheus, Grafana를 이용해 AI 호출 성공률, 지연 시간, 비용 등을 실시간으로 추적했고, 이상 징후가 발견되면 즉시 롤백할 수 있게 준비했습니다.

이 전략 덕분에 장애 없이 AI 기능을 안정적으로 서비스에 녹일 수 있었습니다.

## 직접 써보면서 느낀 한계와 앞으로 챙길 점

처음엔 Spring AI 2.0.0-M8가 너무 편리해서 "이제 AI 붙이기는 끝났다" 싶었는데, 실제 운영하면서는 여전히 고민할 게 많더라고요. 예를 들어,

- AI 호출 비용 관리: 호출량이 늘면 비용이 급증하니, 비용 모니터링 대시보드를 별도로 운영해야 합니다.
- 응답 지연 문제: AI 모델 응답이 느려지면 전체 API가 느려지므로, 비동기 호출과 타임아웃 설정이 필수입니다.
- 프롬프트 유지보수: 프롬프트가 커지면 관리가 어려워져, 별도 프롬프트 관리 시스템 개발도 고려 중입니다.

그래도 Spring AI가 제공하는 기본 틀과 Spring Framework의 강력한 DI, 보안 기능 덕분에 확장성과 안정성을 확보할 수 있었던 점은 분명한 장점입니다.

## 마무리하며

Spring AI 2.0.0-M8를 프로덕션에 붙일 때는 단순히 라이브러리 추가만으로 끝나지 않습니다. 인증 토큰 관리, 요청 제한, JVM과 캐시 튜닝, 프롬프트 최적화, 그리고 점진적 Canary 배포까지 신경 써야 하죠. 

이 글에서 공유한 실제 코드 예시와 운영 경험이 여러분 팀의 AI 도입 여정에 조금이나마 도움이 되길 바랍니다. AI는 이제 백엔드 개발의 필수 요소가 된 만큼, 안전하고 효율적인 통합 방법을 미리 고민해두는 게 무엇보다 중요합니다.
