### "내가 쓰는 라이브러리, 갑자기 왜 이상한 버전으로 바뀌었지?"

최근에 이런 경험 없으신가요? 어느 날 갑자기 배포가 실패하거나, 테스트가 깨지고, 이유를 찾아보니 의존성 라이브러리 버전이 예기치 않게 업데이트되어서였던 적. 이런 문제는 단순히 개발자의 귀찮음 차원이 아니라, 심각한 공급망 공격으로도 이어질 수 있습니다. 그리고 이걸 막기 위해 Python의 패키지 매니저인 Pip이 26.1 버전에서 의존성 쿨다운(Dependency Cooldowns)과 락파일(lockfile) 지원이라는 신기능을 내놓았죠.

오늘은 제가 직접 써보면서 느낀 점과, 어떻게 하면 실무에서 이 기능들을 잘 활용해 공급망 공격 위험을 줄이고 배포 안정성을 높일 수 있을지 이야기해보려 합니다.

---

## 의존성 쿨다운, 왜 갑자기 등장했을까?

Pip 26.1에서 가장 눈에 띄는 기능 중 하나가 바로 의존성 쿨다운입니다. 쉽게 말해, "내가 이미 설치한 패키지의 버전을 너무 자주 바꾸지 말자"는 정책이에요. 예를 들어 이전에는 `pip install`할 때마다 최신 버전이 있으면 바로 업데이트가 됐는데, 쿨다운이 적용되면 일정 시간(예: 7일) 내에는 같은 패키지의 버전 업데이트를 막아줍니다.

이게 왜 중요하냐면, 공급망 공격 시 공격자는 보통 패키지의 새 버전에 악성 코드를 몰래 심습니다. 그런데 만약 매번 최신 버전을 무조건 받는다면, 공격자가 배포한 악성 버전이 바로 우리 서비스에 들어올 수 있죠. 쿨다운을 걸어두면, 이런 급작스런 버전 변경을 방지해 의도치 않은 업데이트를 막을 수 있습니다.

실제로, 최근 몇 년간 PyPI 기반 공격 사례가 늘면서 이런 기능에 대한 요구가 커졌고, Pip 팀도 이를 반영한 셈입니다.

---

## 락파일 지원, 의존성 고정을 더 쉽게

의존성 관리를 하다 보면 `requirements.txt`만으로는 한계가 있죠. 같은 패키지라도 하위 의존성 버전이 바뀌면 결과가 달라질 수 있기 때문입니다. 그래서 여러 툴들이 락파일(`Pipfile.lock`, `poetry.lock`)을 지원해 정확한 버전 고정을 돕는데, 이번 Pip 26.1은 실험적으로 락파일 지원을 추가했습니다.

락파일을 쓰면 다음과 같은 장점이 있어요:

- 모든 개발자와 CI/CD 환경에서 같은 의존성 버전을 설치
- 배포 시점에 의존성 버전이 바뀌는 사고 방지
- 공급망 공격 시 악성 버전 유입 최소화

실제로 락파일을 활성화하려면 `pip install --use-feature=lockfile` 옵션을 붙여야 하고, `pip freeze` 같은 명령어로 락파일을 생성 및 갱신할 수 있습니다. 아직 완전한 정식 기능은 아니지만, 앞으로 표준이 될 가능성이 높습니다.

---

## 실무에서 의존성 쿨다운과 락파일을 어떻게 쓸까?

저희 팀에서는 이번 Pip 26.1 업데이트를 바로 도입해서 다음과 같은 절차를 만들었어요.

1. **쿨다운 기간 설정**: 기본 7일로 설정해, 같은 패키지 버전 업데이트가 7일 내에는 자동으로 안 되도록 했습니다. 이 기간은 프로젝트 특성에 맞게 조절 가능해요.

2. **락파일 도입**: 기존에 `requirements.txt`만 쓰던 환경에서 `pip freeze --use-feature=lockfile > requirements.lock` 명령어로 락파일을 생성하고, CI/CD 파이프라인에 락파일 적용을 의무화했습니다.

3. **새 의존성 도입 시 작은 범위 점진 배포 전략 적용**: 신규 라이브러리나 버전을 도입할 때, 전체 서버가 아닌 일부 인스턴스에만 먼저 배포해 문제 발생 시 빠르게 롤백할 수 있도록 했습니다. 이게 OpenAI 문서에서 말하는 "작은 범위의 점진적 배포 전략"과 맞닿아 있더라고요[OpenAI API Documentation](https://platform.openai.com/docs/overview).

4. **장애 및 실패 유형 계측 강화**: 실패 유형을 초기에 잘 기록해서 장애 대응 속도를 높였습니다. Anthropic 가이드에서 강조하는 부분인데, 실패 유형을 구체적으로 계측하니 문제 원인 파악이 훨씬 빨라졌어요[Anthropic - Prompt Engineering Guide](https://docs.anthropic.com/en/docs/build-with-claude/prompt-engineering/overview).

## 코드 예시: 락파일 생성과 의존성 쿨다운 설정

```bash
# Pip 26.1 설치 (가상환경 권장)
python -m pip install --upgrade pip==26.1

# 의존성 락파일 생성
pip freeze --use-feature=lockfile > requirements.lock

# 락파일 기반 설치
pip install --use-feature=lockfile -r requirements.lock

# 쿨다운 기능은 pip 설정 파일(~/.pip/pip.conf)에 아래 옵션 추가
# [install]
# dependency_cooldown = 7  # 7일간 동일 버전 유지
```

위 설정을 적용하면, 7일간은 기존에 설치된 패키지 버전을 유지하면서, 락파일 덕분에 정확한 의존성 버전으로 설치가 보장됩니다.

## 의존성 쿨다운과 락파일, 단점도 살펴보자

처음엔 이게 별거 아닌 것 같지만, 실제로 써보면 몇 가지 단점도 있습니다.

- **업데이트 지연 문제**: 쿨다운 때문에 보안 패치나 버그 픽스가 바로 반영되지 않을 수 있어요. 그래서 쿨다운 기간을 너무 길게 잡으면 오히려 위험할 수 있습니다.

- **락파일 동기화 관리 부담**: 팀원 간 락파일이 어긋나면 설치 환경이 달라져서 "내 컴퓨터에선 되는데 서버에선 안 돼" 문제가 발생할 수 있습니다. CI/CD에서 락파일 검증을 꼭 해야 합니다.

- **실험적 기능이라 버그 가능성**: 아직 완전한 정식 기능이 아니라서, pip 버전 업그레이드 시 호환성 이슈가 있을 수 있습니다.

---

## 공급망 공격 대비, 결국은 좋은 습관과 도구 조합이 답

Pip 26.1의 새로운 기능들은 공급망 보안 강화에 큰 도움이 되지만, 이것만으로 만능은 아닙니다. 저는 다음 세 가지를 꼭 같이 병행하길 권합니다.

- **정기적 의존성 감사**: `pip-audit` 같은 도구로 취약점 점검을 주기적으로 하세요.
- **배포 전 테스트 자동화 강화**: 신규 의존성 도입 시 실패 유형을 초기부터 계측해 빠르게 대응할 수 있어야 합니다.
- **점진적 배포 전략**: 위험을 분산시키는 작은 범위 배포는 장애 리스크를 확실히 줄여줍니다.

이 세 가지가 잘 맞물려야 공급망 공격을 실무에서 효과적으로 막을 수 있습니다.

---

마지막으로, 새로운 Pip 26.1 기능을 도입할 때는 팀 내 교육과 문서화도 꼭 병행하세요. 저희 팀도 처음엔 락파일 충돌 문제와 쿨다운 기간 설정 미스로 고생했는데, 문서와 가이드가 정리되니 금세 안정화됐습니다.

여러분도 이번 기회에 의존성 관리 체계를 한 단계 업그레이드해보시길 바랍니다.
